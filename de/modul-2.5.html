Startseite / Stufe 2

2.5 Dateiinformationen

Mit file, stat, ls -l, ln -s, readlink und realpath liest du den echten Typ, die Größe, die Zeiten und das Linkziel einer Datei.

Was lernst du in diesem Modul?

  • Du weißt, dass eine Endung unter Linux nur ein Name ist und file den echten Typ zeigt.
  • Du liest Größe, Rechte, Besitzer und Zeiten mit stat und ls -l.
  • Du legst symbolische Links an und findest ihr Ziel mit ls -l, readlink und realpath.

Echter Typ: file

Unter Windows erkennst du den Typ an der Endung. Unter Linux ist .jpg nur ein Name; der Inhalt kann etwas völlig anderes sein. file ignoriert die Endung und betrachtet die ersten Bytes des Inhalts.

Das hilft bei heruntergeladenen Dateien: Eine Datei namens image.jpg kann in Wahrheit ein ausführbares Programm sein.

file

Wozu dient es?
Nennt den echten Dateityp anhand des Inhalts.
Wo wird es verwendet?
Bei heruntergeladenen oder verdächtigen Dateien.
Warum ist es wichtig?
Deckt falsche Endungen und getarnte Dateien auf.
file /etc/hostname

file -i

Wozu dient es?
Gibt den Typ als MIME-Typ aus (z. B. text/plain).
Wo wird es verwendet?
In Skripten und bei der Webserver-Konfiguration.
Warum ist es wichtig?
Liefert einen kurzen, maschinenlesbaren Typ.
file -i /etc/hostname
Tipp

In der Ausgabe bedeutet ASCII text Text, ELF ein ausführbares Programm und directory einen Ordner.

Details: stat und ls -l

ls -l zeigt Typ, Rechte, Besitzer, Größe und Datum in einer Zeile. stat liefert mehr: Inode, Linkanzahl und drei Zeitstempel.

Zeiten: Access letztes Lesen, Modify letzte Änderung des Inhalts, Change letzte Änderung der Metadaten wie Rechte oder Besitzer. Das erste Zeichen zeigt den Typ: - Datei, d Ordner, l symbolischer Link.

stat

Wozu dient es?
Zeigt alle technischen Details einer Datei.
Wo wird es verwendet?
Wenn du genaue Größe, Rechte und Zeiten brauchst.
Warum ist es wichtig?
Detaillierter als ls -l.
stat ~/info/data.txt

ls -l

Wozu dient es?
Gibt eine Liste im Langformat aus.
Wo wird es verwendet?
Für einen schnellen Blick in einen Ordner.
Warum ist es wichtig?
Typ, Rechte, Besitzer, Größe und Datum in einer Zeile.
ls -l ~/info

ls -lh

Wozu dient es?
Zeigt Größen in lesbaren KB/MB.
Wo wird es verwendet?
Bei größeren Dateien.
Warum ist es wichtig?
Eine lesbare Größe statt einer Byte-Zahl.
ls -lh ~/info

ls -ld

Wozu dient es?
Listet den Ordner selbst auf, nicht seinen Inhalt.
Wo wird es verwendet?
Wenn du die Rechte eines Ordners prüfst.
Warum ist es wichtig?
Ordner-Infos, ohne ihn zu öffnen.
ls -ld ~/info
Tipp

ls -lh rundet; für exakte Bytes nutze stat oder wc -c.

Die Ausgabe von ls -l Spalte für Spalte lesen

Beispielzeile: -rw-r--r-- 1 ayse dev 2048 Mar 5 10:12 notes.txt. Spalten der Reihe nach: Typ und Rechte (- Datei, d Verzeichnis, l Link; danach rwx-Dreiergruppen für Besitzer/Gruppe/Andere), Anzahl der Links, Besitzer (ayse), Gruppe (dev), Größe in Byte (2048), Änderungszeit und Name.

Die Rechte-Dreiergruppen werden in Modul 4.x ausführlich behandelt; vorerst: r lesen, w schreiben, x ausführen. Bei einem Verzeichnis bedeutet x, dass man hineinwechseln darf.

ls -lt

Wozu dient es?
Sortiert die lange Liste nach Änderungszeit, neueste zuerst.
Wo wird es verwendet?
Wenn du in einem Ordner die zuletzt geänderte Datei suchst.
Warum ist es wichtig?
Zeigt auf einen Blick, was gerade geändert wurde.
ls -lt

ls -lS

Wozu dient es?
Sortiert die lange Liste nach Größe, größte zuerst.
Wo wird es verwendet?
Wenn du die Datei suchst, die den Speicher füllt.
Warum ist es wichtig?
Große Dateien stehen ganz oben.
ls -lS
Tipp

ls -lhS zeigt Größen lesbar (K, M) und absteigend sortiert.

Achtung

Die Größe bei Verzeichnissen ist die des Verzeichniseintrags, nicht die Summe des Inhalts; dafür du verwenden.

Symbolische Links und der echte Pfad

Ein symbolischer Link (Symlink) ist eine kleine Datei, die auf einen anderen Pfad zeigt. ls -l zeigt ihn als link.txt -> data.txt. Fehlt das Ziel, ist der Link kaputt: Er existiert, aber das Öffnen liefert einen Fehler.

Das Löschen eines Links löscht das Ziel nicht; rm link.txt entfernt nur den Link. readlink gibt das Ziel einen Schritt weit aus, realpath den vollständig aufgelösten absoluten Pfad.

ln -s

Wozu dient es?
Legt einen symbolischen Link an: zuerst das Ziel, dann der Linkname.
Wo wird es verwendet?
Für Verknüpfungen oder Versionsmarken.
Warum ist es wichtig?
Zugriff unter einem zweiten Namen ohne Kopieren.
ln -s data.txt ~/info/link.txt

readlink

Wozu dient es?
Gibt das Ziel aus, auf das ein Link zeigt.
Wo wird es verwendet?
Wenn du wissen willst, wohin ein Link führt.
Warum ist es wichtig?
In Skripten erhältst du das Ziel sauber.
readlink ~/info/link.txt

realpath

Wozu dient es?
Gibt den absoluten Pfad mit allen aufgelösten Links aus.
Wo wird es verwendet?
Bei relativen Pfaden oder Linkketten.
Warum ist es wichtig?
Zeigt den echten Speicherort der Datei.
realpath ~/info/link.txt
Achtung

Der Zielpfad ist relativ zum Ordner des Links. ln -s data.txt ~/info/link.txt funktioniert; ln -s data.txt ~/link.txt aus einem anderen Ordner erzeugt einen kaputten Link.

Name und Größe: basename, dirname, wc

basename gibt den letzten Teil eines Pfads zurück, dirname den Ordnerteil. Beides ist in Skripten zum Zerlegen von Pfaden üblich.

wc -c liefert die Größe in Bytes, wc -l die Zeilenzahl.

basename

Wozu dient es?
Gibt die letzte Komponente (Dateinamen) eines Pfads aus.
Wo wird es verwendet?
In Skripten, wenn du nur den Namen brauchst.
Warum ist es wichtig?
Du musst den Pfad nicht von Hand zerschneiden.
basename ~/info/data.txt

dirname

Wozu dient es?
Gibt den Ordnerteil eines Pfads aus.
Wo wird es verwendet?
Um den Ordner einer Datei zu finden.
Warum ist es wichtig?
Du erhältst den Ordner ohne den Dateinamen.
dirname ~/info/data.txt

wc -c

Wozu dient es?
Gibt die Byte-Anzahl einer Datei aus.
Wo wird es verwendet?
Wenn du die exakte Größe brauchst.
Warum ist es wichtig?
Exakte Größe ohne Rundung.
wc -c ~/info/data.txt

Mach es in deiner VM

Die eigentliche Praxis findet auf echtem Linux statt: Führe die Befehle in deiner eigenen virtuellen Maschine (VirtualBox, UTM oder WSL) aus und vergleiche die Ausgabe.

Probiere es auf deiner VM aus. Hier gibt es keine zerstörerischen Befehle; du legst nur kleine Testdateien in deinem Home-Verzeichnis an.

Den echten Typ finden

Führe file auf einer Textdatei, einem Programm und einem Ordner aus und füge die Ausgabe ein.

file /etc/hostname /usr/bin/ls /etc

Beispiel der erwarteten Ausgabe

/etc/hostname: ASCII text
/usr/bin/ls:  ELF 64-bit LSB pie executable, x86-64, ...
/etc:         directory
Meine Ausgabe sieht anders aus
  • Der Speicherort von ls hängt von der Distribution ab; finde ihn mit which ls.
  • Fehlt file, installiere es unter Ubuntu mit sudo apt install file, unter Rocky/Alma mit sudo dnf install file.

Die lügende Endung

Gib einer Textdatei die Endung .jpg und sieh, was file sagt.

echo hello > ~/fake.jpg
file ~/fake.jpg

Beispiel der erwarteten Ausgabe

/home/student/fake.jpg: ASCII text
Meine Ausgabe sieht anders aus
  • Dein Pfad kann /home/alice/fake.jpg sein; wichtig ist das Wort text.

Details mit stat

Finde die Zeilen Size, Modify und Change in der stat-Ausgabe.

stat ~/fake.jpg

Beispiel der erwarteten Ausgabe

  File: /home/student/fake.jpg
  Size: 6   Blocks: 8   regular file
Access: (0644/-rw-r--r--) ...
Modify: 2026-01-01 10:00:00 ...
Meine Ausgabe sieht anders aus
  • Auf einem lokalisierten System können die Bezeichnungen übersetzt sein; LANG=C stat ~/fake.jpg gibt Englisch aus.
  • Die Zeile Birth ist auf manchen Dateisystemen -.

Link und echter Pfad

Lege einen symbolischen Link an und finde das Ziel mit ls -l, readlink und realpath.

ln -s fake.jpg ~/pic_link
ls -l ~/pic_link
readlink ~/pic_link
realpath ~/pic_link

Beispiel der erwarteten Ausgabe

lrwxrwxrwx 1 student student 8 ... /home/student/pic_link -> fake.jpg
fake.jpg
/home/student/fake.jpg
Meine Ausgabe sieht anders aus
  • Fehlt -> in der ls -l-Ausgabe, prüfe die Reihenfolge bei ln -s (zuerst das Ziel, dann der Linkname).
  • Fehlt realpath, macht readlink -f ~/pic_link dasselbe.

Aufräumen

Lösche die Testdateien. Wenn es keine Fehler gab, drücke "Fertig".

ls -l ~/fake.jpg ~/pic_link
rm ~/pic_link ~/fake.jpg
Meine Ausgabe sieht anders aus
  • rm entfernt zuerst den Link, dann die Zieldatei. In umgekehrter Reihenfolge bleibt der Link kaputt, was harmlos ist.

Vorhersagen

Sage das Ergebnis zuerst voraus (im Kopf oder auf Papier), führe dann den Befehl aus. Der Unterschied zwischen Vorhersage und Ausgabe ist der beste Lernmoment.

  1. VorhersagenMittel

    Vorhersage: Wie sieht der Link in der Ausgabe von ls -l ~/info aus? Führe es aus und prüfe.

    Hinweis

    Du siehst link.txt -> data.txt und am Anfang ein l.

    Lösung
    ls -l ~/info

  2. VorhersagenMittel

    Vorhersage: Mit welchem Buchstaben beginnt die Zeile von ls -ld ~/info? Führe es aus.

    Hinweis

    Das erste Zeichen einer ls -l-Zeile zeigt den Typ: - ist eine normale Datei. Welcher Buchstabe steht für einen Ordner?

    Lösung
    ls -ld ~/info

  3. VorhersagenMittel

    Vorhersage: Was macht stat bei der nicht vorhandenen Datei ~/info/missing.txt? Führe es aus.

    Hinweis

    Es gibt einen Fehler: No such file or directory.

    Lösung
    stat ~/info/missing.txt

  4. VorhersagenSchwer

    Probiere einen kaputten Link: Lege mit ln -s nothing.txt ~/broken einen Link ohne Ziel an und führe dann cat ~/broken aus.

    Hinweis

    Der Link existiert, das Ziel nicht; cat meldet einen Fehler. (cat gibt eine Datei auf dem Bildschirm aus; Details in Modul 2.6.)

    Lösung
    ln -s nothing.txt ~/broken
cat ~/broken

Fehler finden

  1. Fehler findenMittel

    Debug: ~/info/picture.jpg ist in Wahrheit reiner Text. Benenne sie in picture.txt um.

    Hinweis

    Schau mit cat hinein, benenne dann mit mv um. (cat in Modul 2.6, mv in Modul 2.4.)

    Lösung
    mv ~/info/picture.jpg ~/info/picture.txt

Mini-Projekt

  1. Mini-ProjektMittel

    Mini-Projekt: Lege den Ordner ~/inventory an, erstelle darin v1.txt mit dem Inhalt version1, setze einen Link current auf v1.txt und prüfe mit ls -l.

    Hinweis

    Reihenfolge: mkdir, echo >, ln -s v1.txt ~/inventory/current, ls -l. (> leitet die Ausgabe in eine Datei um, Details in Modul 3.2; mkdir in Modul 2.3.)

    Lösung

echo version1 > ~/inventory/v1.txt
ln -s v1.txt ~/inventory/current
ls -l ~/inventory

Selbsttest

Woran erkennt file image.jpg den Typ einer Datei?

Unter Linux ist die Endung nur ein Name; file prüft den Inhalt.

Was zeigt die Modify-Zeit in der stat-Ausgabe?

Modify ist die Inhaltszeit, Change die Metadatenzeit, Access das letzte Lesen.

Was passiert, wenn du rm link.txt auf einen symbolischen Link ausführst?

Ein Link ist ein eigener Eintrag; sein Löschen berührt das Ziel nicht.

Welcher Befehl gibt den absoluten Pfad mit allen aufgelösten Links aus?

realpath löst relative Pfade und Linkketten auf und gibt den echten absoluten Pfad aus.

Eine Datei heißt .txt, enthält aber Binärdaten. Welcher Befehl nennt den echten Typ?

Die Endung ist nur ein Name; file prüft die ersten Bytes (Magic Number) des Inhalts.

Welcher Befehl zeigt Rechte, Besitzer, Größe und drei Zeitstempel (Access/Modify/Change)?

stat gibt die Inode-Infos detailliert aus; ls -l liefert nur eine Kurzfassung.

Welcher Befehl gibt das Ziel eines symbolischen Links aus?

readlink zeigt den im Link gespeicherten Pfad; readlink -f löst alles auf und liefert den absoluten Pfad (wie realpath).

Wie heißt ein symbolischer Link, dessen Ziel gelöscht wurde?

Wird das Ziel gelöscht, bleibt der Link, zeigt aber ins Leere: defekter Link. cat meldet „No such file“.

Warum ist ein symbolischer Link in ls -l nur wenige Bytes groß und nicht so groß wie die Zieldatei?

Ein symbolischer Link enthält keine Daten, nur den Zielpfad; seine Größe entspricht der Pfadlänge. Wird das Ziel gelöscht, bleibt der Link deshalb kaputt.

Früher falsch beantwortete Fragen sind markiert.

Zusammenfassung

  • Eine Endung ist nur ein Name; nutze file für den echten Typ.
  • ls -l ist die schnelle Übersicht, stat die Details; Modify ist die Inhaltszeit, Change die Metadatenzeit.
  • ln -s Ziel Link legt einen symbolischen Link an; ls -l zeigt ->.
  • readlink zeigt das Ziel, realpath den vollständigen absoluten Pfad; rm link löscht das Ziel nicht.

Fachbegriffe

Eine Spezialdatei, die auf einen anderen Pfad zeigt.
inode
Der Metadaten-Eintrag einer Datei im Dateisystem.
dangling link
Ein symbolischer Link, dessen Ziel nicht existiert.
MIME type
Eine Bezeichnung für den Inhaltstyp, z. B. text/plain.

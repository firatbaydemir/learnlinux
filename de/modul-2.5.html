Startseite / Stufe 2

2.5 Dateiinformation

Lies mit file, stat, ls -l, ln -s, readlink und realpath den echten Typ, die Größe, die Zeiten und das Linkziel einer Datei.

Was lernst du in diesem Modul?

  • Du weißt, dass die Endung unter Linux nur ein Name ist und file den echten Typ zeigt.
  • Du liest Größe, Rechte, Besitzer und Zeiten mit stat und ls -l.
  • Du legst symbolische Links an und findest ihr Ziel mit ls -l, readlink und realpath.

Echter Typ: file

Unter Windows erkennst du den Typ an der Endung. Unter Linux ist .jpg nur ein Name; der Inhalt kann etwas ganz anderes sein. file schaut nicht auf die Endung, sondern auf die ersten Bytes des Inhalts.

Das hilft bei heruntergeladenen Dateien: Eine Datei bild.jpg kann in Wahrheit ein ausführbares Programm sein.

file

Wozu dient es?
Nennt den echten Dateityp anhand des Inhalts.
Wo wird es verwendet?
Bei heruntergeladenen oder verdächtigen Dateien.
Warum ist es wichtig?
Deckt falsche Endungen und getarnte Dateien auf.
file /etc/hostname

file -i

Wozu dient es?
Gibt den Typ als MIME-Typ aus (z. B. text/plain).
Wo wird es verwendet?
In Skripten und Webserver-Konfigurationen.
Warum ist es wichtig?
Liefert einen kurzen, maschinenlesbaren Typ.
file -i /etc/hostname
💡 Tipp

In der Ausgabe heißt ASCII text Text, ELF ausführbares Programm und directory Ordner.

Details: stat und ls -l

ls -l zeigt in einer Zeile Typ, Rechte, Besitzer, Größe und Datum. stat liefert mehr: Inode, Linkanzahl und drei Zeitstempel.

Zeiten: Access letzter Lesezugriff, Modify letzte Änderung des Inhalts, Change letzte Änderung der Metadaten (z. B. Rechte oder Besitzer). Das erste Zeichen zeigt den Typ: - Datei, d Ordner, l symbolischer Link.

stat

Wozu dient es?
Zeigt alle technischen Daten einer Datei.
Wo wird es verwendet?
Wenn du genaue Größe, Rechte und Zeiten brauchst.
Warum ist es wichtig?
Detaillierter als ls -l.
stat ~/info/data.txt

ls -l

Wozu dient es?
Gibt eine Liste im Langformat aus.
Wo wird es verwendet?
Beim schnellen Blick in einen Ordner.
Warum ist es wichtig?
Typ, Rechte, Besitzer, Größe und Datum in einer Zeile.
ls -l ~/info

ls -lh

Wozu dient es?
Zeigt Größen lesbar in KB/MB.
Wo wird es verwendet?
Bei großen Dateien.
Warum ist es wichtig?
Verständliche Größe statt Bytezahl.
ls -lh ~/info

ls -ld

Wozu dient es?
Listet den Ordner selbst, nicht seinen Inhalt.
Wo wird es verwendet?
Wenn du die Rechte eines Ordners prüfst.
Warum ist es wichtig?
Ordnerinfo, ohne ihn zu öffnen.
ls -ld ~/info
💡 Tipp

ls -lh rundet; für die exakten Bytes nimm stat oder wc -c.

Symbolische Links und echter Pfad

Ein symbolischer Link (Symlink) ist eine kleine Datei, die auf einen anderen Pfad zeigt. ls -l zeigt ihn als link.txt -> data.txt. Fehlt das Ziel, ist der Link kaputt: Er existiert, beim Öffnen gibt es aber einen Fehler.

Das Löschen eines Links löscht nicht das Ziel; rm link.txt entfernt nur den Link. readlink gibt das Ziel einen Schritt weit aus, realpath den vollständig aufgelösten absoluten Pfad.

ln -s

Wozu dient es?
Legt einen symbolischen Link an: erst Ziel, dann Linkname.
Wo wird es verwendet?
Für Abkürzungen oder Versionsmarker.
Warum ist es wichtig?
Zugriff unter zweitem Namen, ohne zu kopieren.
ln -s data.txt ~/info/link.txt

readlink

Wozu dient es?
Gibt das Ziel eines Links aus.
Wo wird es verwendet?
Wenn du wissen willst, wohin ein Link zeigt.
Warum ist es wichtig?
In Skripten bekommst du das Ziel sauber.
readlink ~/info/link.txt

realpath

Wozu dient es?
Gibt den absoluten Pfad mit aufgelösten Links aus.
Wo wird es verwendet?
Bei relativen Pfaden oder Linkketten.
Warum ist es wichtig?
Zeigt den echten Ort der Datei auf der Platte.
realpath ~/info/link.txt
⚠️ Achtung

Der Zielpfad wird relativ zum Ordner des Links aufgelöst. ln -s data.txt ~/info/link.txt funktioniert; ln -s data.txt ~/link.txt in einem anderen Ordner erzeugt einen kaputten Link.

Name und Größe: basename, dirname, wc

basename liefert den letzten Teil eines Pfades, dirname den Ordnerteil. Beides nutzt man oft in Skripten, um Pfade zu zerlegen.

Die Größe in Bytes liefert wc -c, die Zeilenzahl wc -l.

basename

Wozu dient es?
Gibt die letzte Komponente (Dateiname) eines Pfades aus.
Wo wird es verwendet?
In Skripten, wenn du nur den Namen brauchst.
Warum ist es wichtig?
Du musst den Pfad nicht von Hand zerschneiden.
basename ~/info/data.txt

dirname

Wozu dient es?
Gibt den Ordnerteil eines Pfades aus.
Wo wird es verwendet?
Um den Ordner einer Datei zu finden.
Warum ist es wichtig?
Du bekommst den Ordner ohne Dateinamen.
dirname ~/info/data.txt

wc -c

Wozu dient es?
Gibt die Bytezahl einer Datei aus.
Wo wird es verwendet?
Wenn du die genaue Größe brauchst.
Warum ist es wichtig?
Exakte Größe ohne Rundung.
wc -c ~/info/data.txt

Mach es in deiner VM

Die eigentliche Praxis findet auf echtem Linux statt: Führe die Befehle in deiner eigenen virtuellen Maschine (VirtualBox, UTM oder WSL) aus und vergleiche die Ausgabe.

Probiere es auf deiner VM aus. Hier gibt es keine zerstörerischen Befehle; du legst nur kleine Testdateien im Home-Verzeichnis an.

Echten Typ erfahren

Führe file für eine Textdatei, ein Programm und einen Ordner aus und füge die Ausgabe ein.

file /etc/hostname /usr/bin/ls /etc

Beispiel der erwarteten Ausgabe

/etc/hostname: ASCII text
/usr/bin/ls:  ELF 64-bit LSB pie executable, x86-64, ...
/etc:         directory
Meine Ausgabe sieht anders aus
  • Der Ort von ls hängt von der Distribution ab; finde ihn mit which ls.
  • Fehlt file, installiere es auf Ubuntu mit sudo apt install file, auf Rocky/Alma mit sudo dnf install file.

Die lügende Endung

Gib einer Textdatei den Namen .jpg und sieh, was file sagt.

echo hello > ~/fake.jpg
file ~/fake.jpg

Beispiel der erwarteten Ausgabe

/home/student/fake.jpg: ASCII text
Meine Ausgabe sieht anders aus
  • Dein Pfad kann /home/alice/fake.jpg heißen; wichtig ist das Wort text.

Details mit stat

Finde in der stat-Ausgabe die Zeilen Size, Modify und Change.

stat ~/fake.jpg

Beispiel der erwarteten Ausgabe

  File: /home/student/fake.jpg
  Size: 6   Blocks: 8   regular file
Access: (0644/-rw-r--r--) ...
Modify: 2026-01-01 10:00:00 ...
Meine Ausgabe sieht anders aus
  • Bei deutscher Ausgabe siehst du evtl. Größe statt Size; LANG=C stat ~/fake.jpg gibt Englisch aus.
  • Die Birth-Zeile ist auf manchen Dateisystemen -.

Link und echter Pfad

Lege einen symbolischen Link an und finde das Ziel mit ls -l, readlink und realpath.

ln -s fake.jpg ~/pic_link
ls -l ~/pic_link
readlink ~/pic_link
realpath ~/pic_link

Beispiel der erwarteten Ausgabe

lrwxrwxrwx 1 student student 8 ... /home/student/pic_link -> fake.jpg
fake.jpg
/home/student/fake.jpg
Meine Ausgabe sieht anders aus
  • Fehlt -> in der ls -l-Ausgabe, prüfe die Reihenfolge bei ln -s (erst Ziel, dann Linkname).
  • Gibt es realpath nicht, leistet readlink -f ~/pic_link dasselbe.

Aufräumen

Lösche die Testdateien. Wenn kein Fehler auftritt, drücke "Erledigt".

ls -l ~/fake.jpg ~/pic_link
rm ~/pic_link ~/fake.jpg
Meine Ausgabe sieht anders aus
  • rm entfernt erst den Link, dann die Zieldatei. Bei umgekehrter Reihenfolge bleibt der Link kaputt, ist aber harmlos.

Selbsttest

Woran erkennt file bild.jpg den Typ einer Datei?

Unter Linux ist die Endung nur ein Name; file prüft den Inhalt.

Was zeigt die Zeit Modify in der stat-Ausgabe?

Modify ist die Zeit des Inhalts, Change die der Metadaten, Access die des letzten Lesens.

Was passiert bei rm link.txt (symbolischer Link)?

Ein Link ist ein eigener Eintrag; sein Löschen berührt das Ziel nicht.

Welcher Befehl gibt den absoluten Pfad mit aufgelösten Links aus?

realpath löst relative Pfade und Linkketten zum echten absoluten Pfad auf.

Zusammenfassung

  • Die Endung ist nur ein Name; den echten Typ zeigt file.
  • ls -l ist die schnelle Übersicht, stat die Details; Modify ist die Inhalts-, Change die Metadatenzeit.
  • ln -s Ziel Link legt einen symbolischen Link an; ls -l zeigt ->.
  • readlink zeigt das Ziel, realpath den vollen absoluten Pfad; rm link löscht das Ziel nicht.

Fachbegriffe

Symlink
Spezielle Datei, die auf einen anderen Pfad zeigt.
Inode
Metadateneintrag einer Datei im Dateisystem.
kaputter Link
Symbolischer Link ohne vorhandenes Ziel.
MIME-Typ
Bezeichnung des Inhaltstyps, z. B. text/plain.

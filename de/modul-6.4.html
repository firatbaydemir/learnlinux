6.4 LVM — PV, VG, LV und Erweitern

Keine Panik bei voller Platte: Volume vergrößern. Übe zuerst in einem sicheren Loop-Device-Labor.

Was lernst du in diesem Modul?

  • Du erklärst die Ebenen PV → VG → LV und ihre Aufgaben.
  • Du baust mit pvcreate, vgcreate, lvcreate einen Pool und liest ihn mit pvs/vgs/lvs/lvdisplay.
  • Du vergrößerst Volume und Dateisystem zusammen mit lvextend -r und weißt, dass XFS nicht schrumpft.
  • Du übst nur mit dateibasierten Loop-Geräten in einer VM mit Snapshot.

Begriffe: PV, VG, LV

Bei klassischen Partitionen ist die Größe fest. LVM (Logical Volume Manager) fasst Platten zu einem Pool zusammen und schneidet daraus Volumes beliebiger Größe. Es gibt drei Ebenen: Ein PV (Physical Volume) ist die LVM-Signatur auf einer Platte oder Partition, eine VG (Volume Group) ist der Pool aus PVs, ein LV (Logical Volume) ist ein aus dem Pool geschnittenes Volume, das wie eine Platte aussieht.

Reihenfolge: Platte → PV → VG → LV → Dateisystem (XFS/ext4) → Mount. Beispielnamen: Pool vg_data, Volume lv_web, Pfad /dev/vg_data/lv_web. Zum Lesen reichen diese Befehle; keiner verändert etwas.

pvs

Wozu dient es?
Listet Physical Volumes in einer kurzen Tabelle.
Wo wird es verwendet?
Um zu sehen, welche Platten zu einem Pool gehören.
Warum ist es wichtig?
Die Spalte PFree zeigt den freien Platz auf dem PV.
sudo pvs

vgs

Wozu dient es?
Listet Volume Groups; VSize ist die Gesamtgröße, VFree der freie Platz.
Wo wird es verwendet?
Vor dem Erweitern, um zu prüfen, ob im Pool Platz ist.
Warum ist es wichtig?
Ist VFree 0, musst du zuerst mit vgextend ein PV hinzufügen.
sudo vgs

lvs

Wozu dient es?
Listet Logical Volumes.
Wo wird es verwendet?
Welches Volume liegt in welcher VG und wie groß ist es?
Warum ist es wichtig?
Gibt einen schnellen Überblick.
sudo lvs

lvdisplay

Wozu dient es?
Zeigt Details eines LV (Pfad, Größe, Status).
Wo wird es verwendet?
Beim Untersuchen eines einzelnen Volumes.
Warum ist es wichtig?
Du kannst LV Path und LV Size prüfen.
sudo lvdisplay /dev/vg_data/lv_web

lsblk -f

Wozu dient es?
Zeigt Platten, LVM-Ebenen, Dateisysteme und Mountpoints als Baum.
Wo wird es verwendet?
Vor jeder LVM-Aktion.
Warum ist es wichtig?
Du stellst sicher, dass du das richtige Gerät wählst.
lsblk -f
💡 Tipp

Erst lesen, dann schreiben: pvs, vgs, lvs und lsblk -f ändern nichts; führe sie vor jedem ändernden Befehl aus.

Sicheres Labor: Loop-Geräte

Fasse nie eine echte Platte an. Du erzeugst mit truncate eine Datei und bindest sie mit losetup als Loop-Gerät (/dev/loop0) ein; LVM hält es für eine echte Platte, aber bei einem Fehler geht höchstens eine Datei kaputt.

Mach zuerst einen VM-Snapshot (Modul 0.2). Werkzeuge installieren: auf Rocky/Alma sudo dnf install lvm2 xfsprogs, auf Debian/Ubuntu sudo apt install lvm2 xfsprogs. Die Dateien liegen in ~/lvm-lab; die Loop-Nummer kann abweichen, nutze die --show-Ausgabe.

truncate -s 300M

Wozu dient es?
Erzeugt eine Sparse-Datei der angegebenen Größe.
Wo wird es verwendet?
Für ein Fake-Plattenabbild.
Warum ist es wichtig?
Ein sicherer Ersatz für eine echte Platte.
truncate -s 300M ~/lvm-lab/disk1.img

losetup -f --show

Wozu dient es?
Bindet die Datei an das erste freie Loop-Gerät und gibt dessen Namen aus.
Wo wird es verwendet?
Wenn ein Abbild zum Blockgerät werden soll.
Warum ist es wichtig?
pvcreate funktioniert nur mit Blockgeräten.
sudo losetup -f --show ~/lvm-lab/disk1.img

losetup -a

Wozu dient es?
Listet aktive Loop-Geräte und ihre Dateien.
Wo wird es verwendet?
Um zu prüfen, welches Loop zu welcher Datei gehört.
Warum ist es wichtig?
Verhindert das Schreiben auf das falsche Gerät.
losetup -a

losetup -d

Wozu dient es?
Löst ein Loop-Gerät.
Wo wird es verwendet?
Beim Aufräumen des Labors.
Warum ist es wichtig?
Das Gerät muss frei sein, bevor die Datei gelöscht wird.
sudo losetup -d /dev/loop0
💡 Tipp

Ein Sparse-Abbild zeigt in ls -lh 300M, belegt aber kaum Plattenplatz.

⚠️ Achtung

pvcreate, vgcreate und mkfs löschen das Ziel. Prüfe den Gerätenamen vorher mit losetup -a; tippe in diesem Modul nie echte Plattennamen wie /dev/sda.

PV, VG und LV anlegen

Die Reihenfolge ist immer gleich: pvcreate → vgcreate → lvcreate → Dateisystem → Mount. Im Beispiel hält die Variable LOOP1 die Ausgabe von losetup.

lvcreate -L 200M bedeutet feste Größe, -l 100%FREE den ganzen Rest. Die RHEL-Familie nutzt standardmäßig XFS, Debian/Ubuntu meist ext4; beides funktioniert.

pvcreate

Wozu dient es?
Schreibt eine LVM-Signatur auf das Gerät und macht es zum PV.
Wo wird es verwendet?
Bevor du eine Platte in einen Pool aufnimmst.
Warum ist es wichtig?
Eine VG besteht nur aus PVs.
sudo pvcreate $LOOP1

vgcreate

Wozu dient es?
Erzeugt eine VG aus einem oder mehreren PVs.
Wo wird es verwendet?
Beim Aufbau des Pools.
Warum ist es wichtig?
Aus diesem Pool werden Volumes geschnitten.
sudo vgcreate vg_data $LOOP1

lvcreate

Wozu dient es?
Schneidet ein benanntes LV aus einer VG.
Wo wird es verwendet?
Wenn eine Anwendung ein eigenes Volume bekommt.
Warum ist es wichtig?
Mit -n gibst du den Namen, mit -L die Größe an.
sudo lvcreate -L 200M -n lv_web vg_data

mkfs.xfs

Wozu dient es?
Legt ein XFS-Dateisystem auf dem LV an (mkfs.ext4 für ext4).
Wo wird es verwendet?
Wenn ein neues Volume nutzbar gemacht wird.
Warum ist es wichtig?
Ohne Dateisystem lässt es sich nicht einhängen.
sudo mkfs.xfs /dev/vg_data/lv_web

mount

Wozu dient es?
Hängt das Volume in ein Verzeichnis ein.
Wo wird es verwendet?
Bevor du Daten schreibst.
Warum ist es wichtig?
Die Dateien erscheinen im Verzeichnis des Mountpoints.
sudo mount /dev/vg_data/lv_web /mnt/web
⛔ Gefahr

mkfs zerstört vorhandene Daten. Führe es nie auf einem bestehenden LV oder einer Platte aus; prüfe vorher mit lsblk -f, dass das Ziel leer ist und ein Loop-Gerät.

Erweitern: lvextend -r

Ist ein Volume voll, brauchst du zwei Schritte: erst das LV, dann das Dateisystem vergrößern. lvextend -r erledigt beides. Von Hand nimmst du xfs_growfs <Mountpoint> für XFS oder resize2fs <Gerät> für ext4; beide wachsen im eingehängten Zustand.

Hat die VG keinen freien Platz (VFree), mache das neue Gerät zuerst mit pvcreate zum PV, nimm es mit vgextend auf und führe dann lvextend aus. Verkleinern ist problematisch: XFS schrumpft nie; ext4 nur ausgehängt und nach einem Backup.

lvextend -r

Wozu dient es?
Vergrößert LV und Dateisystem in einem Schritt.
Wo wird es verwendet?
Beim Erweitern eines vollen Volumes im Betrieb.
Warum ist es wichtig?
Beseitigt das Risiko, den zweiten Schritt zu vergessen.
sudo lvextend -r -L +100M /dev/vg_data/lv_web

xfs_growfs

Wozu dient es?
Vergrößert ein eingehängtes XFS bis zur LV-Größe.
Wo wird es verwendet?
Wenn du lvextend -r nicht benutzt hast.
Warum ist es wichtig?
XFS erwartet den Mountpoint als Argument.
sudo xfs_growfs /mnt/web

resize2fs

Wozu dient es?
Vergrößert ein ext4-Dateisystem bis zur LV-Größe.
Wo wird es verwendet?
Beim manuellen Vergrößern eines ext4-Volumes.
Warum ist es wichtig?
Erwartet den Gerätepfad als Argument.
sudo resize2fs /dev/vg_data/lv_web

vgextend

Wozu dient es?
Fügt einer bestehenden VG ein neues PV hinzu.
Wo wird es verwendet?
Wenn VFree aufgebraucht ist.
Warum ist es wichtig?
Vergrößert den Pool, danach kann das LV wachsen.
sudo vgextend vg_data $LOOP2
💡 Tipp

-L +100M addiert zur aktuellen Größe, -L 300M setzt die Gesamtgröße. Für den ganzen freien Platz schreibe -l +100%FREE.

Dauerhaftes Einhängen, Entfernen und Warnungen

Damit das Volume nach einem Neustart wieder da ist, brauchst du eine Zeile in /etc/fstab: /dev/vg_data/lv_web /srv/web xfs defaults 0 0. Ein Tippfehler kann den Start verhindern; sichere die Datei vor dem Bearbeiten und teste mit sudo mount -a. Im Loop-Labor brauchst du keinen fstab-Eintrag.

Das Entfernen läuft in umgekehrter Reihenfolge: umount → lvremove → vgremove → pvremove → losetup -d. Diese Befehle fragen nach und zerstören Daten unwiederbringlich. Sieh den Namen immer erst mit lvs/vgs an.

cat /etc/fstab

Wozu dient es?
Zeigt die beim Start eingehängten Dateisysteme.
Wo wird es verwendet?
Beim Prüfen eines dauerhaften Mounts.
Warum ist es wichtig?
Eine falsche Zeile kann den Start blockieren.
cat /etc/fstab

lvremove

Wozu dient es?
Löscht ein LV samt Daten.
Wo wird es verwendet?
Nur beim Aufräumen des Labors.
Warum ist es wichtig?
Es gibt kein Zurück; vorher umount.
sudo lvremove /dev/vg_data/lv_web

vgreduce

Wozu dient es?
Entfernt ein PV aus einer VG.
Wo wird es verwendet?
Wenn du eine Platte aus dem Pool löst.
Warum ist es wichtig?
Hat das PV Daten, verschiebe sie vorher mit pvmove.
sudo vgreduce vg_data $LOOP2

pvremove

Wozu dient es?
Löscht die LVM-Signatur vom Gerät.
Wo wird es verwendet?
Letzter Schritt des Labors.
Warum ist es wichtig?
Das Gerät ist kein PV mehr; wird abgelehnt, wenn es noch in einer VG ist.
sudo pvremove $LOOP1
⚠️ Achtung

lvremove, vgreduce und pvremove können auf einem echten Server Produktivdaten zerstören. Mach vorher einen Snapshot/ein Backup und prüfe den Namen zweimal.

⛔ Gefahr

Auf einem echten System mit separater Platte verliert ein falscher Name alles. Nutze in diesem Modul nur Loop-Geräte; versuche nie, ein XFS-Volume zu verkleinern. Der Weg ist Backup, neu anlegen, zurückspielen.

Mach es in deiner VM

Die eigentliche Praxis findet auf echtem Linux statt: Führe die Befehle in deiner eigenen virtuellen Maschine (VirtualBox, UTM oder WSL) aus und vergleiche die Ausgabe.

Mach diese Aufgaben in deiner VM. Mach zuerst einen Snapshot. Nutze nur Loop-Geräte; tippe nie einen echten Plattennamen.

Aktuellen LVM-Zustand lesen

Liste ohne etwas zu ändern die vorhandenen Platten und LVM-Ebenen auf. Füge die Ausgabe ein.

lsblk -f
sudo pvs
sudo vgs
sudo lvs

Beispiel der erwarteten Ausgabe

VG   #PV #LV #SN Attr   VSize  VFree
rl     1   2   0 wz--n- <19.00g 0
Meine Ausgabe sieht anders aus
  • Fehlt LVM, führe sudo dnf install lvm2 (Rocky/Alma) oder sudo apt install lvm2 (Debian/Ubuntu) aus.
  • Nutzt eine Standardinstallation von Ubuntu kein LVM, ist eine leere Ausgabe normal; sie zeigt trotzdem, dass die Befehle laufen.

PV, VG und LV auf Loop-Geräten bauen

Erzeuge nach dem Snapshot zwei Fake-Platten, baue VG und LV, formatiere mit XFS und hänge ein. Füge die Ausgabe ein.

mkdir -p ~/lvm-lab
truncate -s 300M ~/lvm-lab/disk1.img
truncate -s 300M ~/lvm-lab/disk2.img
LOOP1=$(sudo losetup -f --show ~/lvm-lab/disk1.img)
LOOP2=$(sudo losetup -f --show ~/lvm-lab/disk2.img)
echo $LOOP1 $LOOP2
sudo pvcreate $LOOP1
sudo vgcreate vg_data $LOOP1
sudo lvcreate -L 200M -n lv_web vg_data
sudo mkfs.xfs /dev/vg_data/lv_web
sudo mkdir -p /mnt/web
sudo mount /dev/vg_data/lv_web /mnt/web
sudo vgs vg_data

Beispiel der erwarteten Ausgabe

VG      #PV #LV #SN Attr   VSize    VFree
vg_data   1   1   0 wz--n- 296.00m 96.00m
Meine Ausgabe sieht anders aus
  • Die Loop-Nummer ist evtl. nicht /dev/loop0; die Variable $LOOP1 fängt das ab.
  • Fehlt mkfs.xfs unter Debian/Ubuntu, nutze sudo apt install xfsprogs oder mkfs.ext4.
  • In einem anderen Terminal fehlen die Variablen; finde die Namen mit losetup -a und tippe sie von Hand.

Volume im Betrieb vergrößern

Auf der ersten Platte sind 96M frei: Vergrößere das LV zuerst um 90M, nimm dann die zweite Platte in den Pool auf und nutze den verbleibenden freien Platz. Prüfe die Größe mit df.

sudo lvextend -r -L +90M /dev/vg_data/lv_web
df -h /mnt/web
sudo vgextend vg_data $LOOP2
sudo lvextend -r -l +100%FREE /dev/vg_data/lv_web
sudo lvs vg_data
df -h /mnt/web

Beispiel der erwarteten Ausgabe

LV     VG      Attr       LSize
lv_web vg_data -wi-ao---- 592.00m
Meine Ausgabe sieht anders aus
  • Schlägt -r fehl, prüfe, ob das Volume eingehängt ist; vergrößere von Hand mit sudo xfs_growfs /mnt/web (resize2fs bei ext4).
  • Insufficient free space heißt, VFree ist aufgebraucht; führe zuerst vgextend aus.

Labor aufräumen

Hänge aus, entferne LV, VG und PVs der Reihe nach, löse die Loop-Geräte und lösche die Abbilder. Wenn es keine Fehler gab, drücke "Erledigt".

sudo umount /mnt/web
sudo lvremove -y /dev/vg_data/lv_web
sudo vgremove vg_data
sudo pvremove $LOOP1 $LOOP2
sudo losetup -d $LOOP1 $LOOP2
rm ~/lvm-lab/disk1.img ~/lvm-lab/disk2.img

Beispiel der erwarteten Ausgabe

Logical volume "lv_web" successfully removed.
Meine Ausgabe sieht anders aus
  • Bei target is busy zuerst cd ~ und keine offene Shell in /mnt/web lassen.
  • Ist $LOOP1 in einem anderen Terminal leer, finde die Namen mit losetup -a und tippe sie von Hand.
  • Wenn du unsicher bist, geh zum Snapshot zurück.

  1. HerausforderungSchwer

    Challenge: Schreibe in ~/lvm/runbook.txt die Befehle pvcreate, vgcreate, lvcreate, mkfs.xfs und lvextend -r in dieser Reihenfolge, je einen pro Zeile. Gerät /dev/loop0, VG vg_data, LV lv_web.

    Hinweis

    Ein printf mit \n als Trenner genügt.

    Lösung

  1. TicketSchwer

    Hinweis

    Drei Zeilen: pvcreate, vgextend, lvextend -r.

    Lösung
    printf 'pvcreate /dev/loop1\nvgextend vg_sys /dev/loop1\nlvextend -r -L +5G /dev/vg_sys/lv_root\n' > ~/lvm/ticket-fix.sh

Selbsttest

Wie ist die richtige Reihenfolge der LVM-Ebenen?

Die Platte wird zum PV, PVs bilden den VG-Pool, aus dem Pool werden Volumes (LV) geschnitten.

Welche Aussage stimmt?

XFS wächst nur; zum Verkleinern Backup, neu anlegen, zurückspielen.

Was macht lvextend -r -L +100M /dev/vg_data/lv_web?

-r (resizefs) vergrößert das Dateisystem zusammen mit dem LV.

Welche Reihenfolge ist beim Aufräumen des Loop-Labors richtig?

Erst aushängen, dann von oben nach unten entfernen: LV, VG, PV.

Zusammenfassung

  • LVM: Platte → PV → VG → LV → Dateisystem → Mount.
  • Lesebefehle: pvs, vgs, lvs, lvdisplay, lsblk -f.
  • Anlegen: pvcreate, vgcreate, lvcreate, mkfs, mount.
  • Vergrößern: lvextend -r (bei Bedarf zuerst vgextend).
  • XFS schrumpft nicht; lvremove/vgreduce/pvremove zerstören Daten.
  • Übe nur auf Loop-Geräten in einer VM mit Snapshot.

Fachbegriffe

PV
Physical Volume: Platte oder Partition mit LVM-Signatur.
VG
Volume Group: Speicherpool aus PVs.
LV

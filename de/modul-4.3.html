4.3 Identität wechseln: su, sudo und sudoers

Lerne, wann und wie du root-Rechte nutzt: Bevorzuge sudo für einzelne Befehle und verwalte Regeln sicher mit visudo.

Was lernst du in diesem Modul?

  • Erkläre, dass root die UID 0 hat, den Unterschied zwischen su - und sudo sowie welches Passwort die Befehle verlangen.
  • Führe einen einzelnen Admin-Befehl mit sudo aus und prüfe deine Rechte mit sudo -l.
  • Öffne mit sudo -i eine vollständige root-Login-Shell, schließe sie mit exit und bleibe nicht unnötig root.
  • Weiß, dass /etc/sudoers die Rechte festlegt und ausschließlich mit visudo bearbeitet werden darf.

Wer ist root? su und sudo

Unter Linux ist root der Superuser mit UID 0. Root kann Systemdateien und andere Konten verwalten; ein falscher Befehl kann großen Schaden verursachen. Bleib für alltägliche Aufgaben in deinem normalen Konto und nutze Admin-Rechte nur, wenn sie nötig sind.

su - USER wechselt zum Zielkonto und fragt nach dessen Passwort. su - wechselt zu root, aber auf Systemen wie Ubuntu kann die Passwort-Anmeldung für root deaktiviert sein. - lädt die Login-Umgebung des Zielbenutzers (zum Beispiel HOME und Profil).

sudo COMMAND ermöglicht einem berechtigten Benutzer, sich mit dem eigenen Passwort zu authentifizieren und nur den angegebenen Befehl als einen anderen Benutzer, meist root, auszuführen. Eine sudo-Regel kann auch ohne Passwortabfrage eingerichtet sein. Einen einzelnen Befehl mit sudo auszuführen ist sicherer, als eine root-Sitzung offen zu halten.

whoami

Wozu dient es?
Zeigt den aktuellen effektiven Benutzernamen.
Wo wird es verwendet?
Wenn du prüfen möchtest, unter welchem Konto ein Befehl läuft.
Warum ist es wichtig?
Verhindert Aktionen mit dem falschen Konto, besonders nach einem Rechtewechsel.
whoami

id

Wozu dient es?
Zeigt UID, primäre GID und Gruppenmitgliedschaften.
Wo wird es verwendet?
Wenn du prüfst, welche Gruppen sudo-Zugriff gewähren.
Warum ist es wichtig?
Prüft Benutzer- und Gruppenidentitäten gemeinsam.
id

su -

Wozu dient es?
Öffnet roots Login-Sitzung; dafür ist das root-Passwort nötig.
Wo wird es verwendet?
Nur wenn das root-Konto aktiviert ist und eine längere Admin-Sitzung wirklich nötig ist.
Warum ist es wichtig?
Lädt die Login-Umgebung; alle Befehle der Sitzung laufen als root.
su -

sudo COMMAND

Wozu dient es?
Führt einen erlaubten Befehl als ein anderes Konto aus.
Wo wird es verwendet?
Wenn von einem normalen Konto aus eine bestimmte administrative Aktion nötig ist.
Warum ist es wichtig?
Hält sowohl die Berechtigung als auch ihren Umfang begrenzt.
sudo whoami

exit

Wozu dient es?
Beendet eine geöffnete su- oder sudo-Login-Sitzung.
Wo wird es verwendet?
Wenn die administrative Arbeit abgeschlossen ist.
Warum ist es wichtig?
Verhindert, dass du länger als nötig in einer root-Shell bleibst.
exit
💡 Tipp

Bei der Passworteingabe im Terminal erscheinen keine Zeichen; das ist normal. Gib dein eigenes Passwort nur an einer vertrauenswürdigen sudo-Abfrage ein.

Einzelner Befehl und Admin-Sitzungen

sudo whoami gibt root aus; ein normales whoami zeigt dein eigenes Konto. Sudo erhöht nur die Berechtigung dieses Befehls. Danach bleibt deine Shell ein normaler Benutzer.

sudo -l listet die Befehle auf, die dein Konto ausführen darf. sudo -u USER COMMAND führt mit erlaubter Richtlinie einen einzelnen Befehl als angegebenen Benutzer aus. Die Regeln hängen von Distribution und Organisationsrichtlinie ab; wheel ist bei Rocky/Alma und sudo bei Ubuntu/Debian verbreitet.

sudo -i öffnet roots Login-Shell; whoami zeigt dann root und HOME ist /root. sudo -s öffnet eine root-Shell, die mehr von der aktuellen Umgebung übernimmt. Beide sind vollständige Sitzungen mit hohem Risiko: Halte sie kurz und beende sie mit exit. Sudo kann die Authentifizierung eine Weile zwischenspeichern; sudo -k verwirft diesen Cache.

sudo -l

Wozu dient es?
Listet die Befehle und Regeln auf, die deinem Konto mit sudo zur Verfügung stehen.
Wo wird es verwendet?
Bevor du Berechtigungen oder einen Zugriffsfehler untersuchst.
Warum ist es wichtig?
Zeigt die tatsächliche Richtlinie des Systems statt bloßer Annahmen.
sudo -l

sudo -u USER

Wozu dient es?
Führt einen einzelnen Befehl als den angegebenen Benutzer aus.
Wo wird es verwendet?
Wenn du das Verhalten eines Dienstes oder Auftrags unter einem anderen Konto prüfen willst.
Warum ist es wichtig?
Testet die Rechte des Zielkontos ohne root-Sitzung.
sudo -u nobody id

sudo -i

Wozu dient es?
Öffnet eine Admin-Shell mit roots Login-Umgebung.
Wo wird es verwendet?
Für eine kurze, kontrollierte Sitzung mit mehreren Admin-Befehlen.
Warum ist es wichtig?
Lädt roots HOME und Startumgebung.
sudo -i

sudo -k

Wozu dient es?
Verwirft die zwischengespeicherte sudo-Authentifizierung.
Wo wird es verwendet?
Beim Verlassen eines gemeinsam genutzten Terminals oder wenn sofort erneut authentifiziert werden soll.
Warum ist es wichtig?
Verhindert die Wiederverwendung einer vorherigen Authentifizierung für folgende Befehle.
sudo -k
⚠️ Achtung

Ein vergessener Befehl in sudo -i läuft weiterhin als root. Nutze für kurze Aufgaben lieber sudo COMMAND; prüfe nach dem Verlassen einer root-Shell mit whoami, ob du zu deinem normalen Konto zurückgekehrt bist.

sudoers: Rechte sicher verwalten

/etc/sudoers und Dateien unter /etc/sudoers.d/ legen fest, wer welche Befehle als welches Zielkonto ausführen darf. Bearbeite diese Dateien niemals direkt mit nano, vim oder echo: Ein einzelner Syntaxfehler kann den gesamten sudo-Zugriff beschädigen.

Verwende sudo visudo, um die Richtlinie zu prüfen und zu bearbeiten. Für eine separate Regeldatei öffnest du sudo visudo -f /etc/sudoers.d/NAME; visudo prüft die Syntax vor dem Speichern. Beispiel: alice ALL=(root) /usr/bin/systemctl restart nginx erlaubt nur diesen Befehl.

NOPASSWD entfernt die Passwortabfrage, zum Beispiel alice ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx. Nutze es nur bei echtem Bedarf, mit vollständigem Befehlspfad und engem Umfang. Unbeschränkter Zugriff mit ALL oder eine passwortlose allgemeine Shell ist keine sichere Regel. Prüfe das Ergebnis mit sudo -l.

sudo visudo

Wozu dient es?
Bearbeitet sudo-Richtlinien mit Sperre und Syntaxprüfung.
Wo wird es verwendet?
Beim Hinzufügen oder Ändern einer sudoers-Regel.
Warum ist es wichtig?
Verringert das Risiko, eine fehlerhafte Datei zu speichern und sudo-Zugriff zu verlieren.
sudo visudo

sudo visudo -f

Wozu dient es?
Bearbeitet die angegebene sudoers-Datei sicher.
Wo wird es verwendet?
Beim Erstellen einer separaten sudoers.d-Regel, sofern die Distribution dies unterstützt.
Warum ist es wichtig?
Hält Regeln getrennt von der Hauptdatei und prüft ihre Syntax.
sudo visudo -f /etc/sudoers.d/alice

sudo visudo -c

Wozu dient es?
Prüft die Syntax der sudoers-Dateien.
Wo wird es verwendet?
Nach der Prüfung einer Richtlinienänderung.
Warum ist es wichtig?
Bestätigt, dass die Datei gelesen und geparst werden kann.
sudo visudo -c

sudo -l

Wozu dient es?
Zeigt die aktiven sudo-Regeln.
Wo wird es verwendet?
Wenn du prüfen möchtest, ob eine Richtlinienänderung für einen Benutzer gilt.
Warum ist es wichtig?
Vergleicht die geschriebene Regel mit den wirksamen Rechten.
sudo -l
⛔ Gefahr

NOPASSWD: ALL erlaubt einem Benutzer, jeden Befehl ohne Passwort auszuführen. Begrenze die Regel auf den benötigten Benutzer, den exakten Befehlspfad und die nötigen Argumente; schreibe sie mit visudo und prüfe sie mit sudo -l.

Sicherer Admin-Ablauf

Prüfe zuerst Ziel und Auswirkungen mit deinem normalen Konto. Wenn erhöhte Rechte nötig sind, führe nur den erforderlichen Befehl mit sudo aus. Bei einem Fehler füge nicht blind sudo hinzu, sondern prüfe id, sudo -l und die Dateirechte.

Beende eine root-Sitzung nach der Arbeit mit exit. Schreibe niemals Passwörter in die Kommandozeilen-History, bearbeite sudoers nicht direkt und führe keinen unbekannten Befehl als root aus. Erstelle auf einer echten VM einen Snapshot, bevor du die Systemrichtlinie änderst.

sudo -l

Wozu dient es?
Prüft vorab den Umfang deiner Berechtigungen.
Wo wird es verwendet?
Vor Beginn einer administrativen Aufgabe.
Warum ist es wichtig?
Hilft, fehlende oder zu weit gefasste Regeln zu erkennen.
sudo -l

sudo whoami

Wozu dient es?
Prüft sicher, ob ein Befehl als root läuft.
Wo wird es verwendet?
Wenn du das Verhalten von sudo kennenlernst.
Warum ist es wichtig?
Zeigt, dass der Rechtewechsel nur für den Befehl gilt.
sudo whoami

sudo visudo -c

Wozu dient es?
Prüft die Syntax der sudoers-Konfiguration.
Wo wird es verwendet?
Nach einer Richtlinienänderung.
Warum ist es wichtig?
Erkennt eine fehlerhafte Regel, bevor sie benötigt wird.
sudo visudo -c
💡 Tipp

Wende das Prinzip der geringsten Rechte an: Erlaube nur den nötigen Benutzer, das Zielkonto, den Befehl und seine Argumente.

Mach es in deiner VM

Die eigentliche Praxis findet auf echtem Linux statt: Führe die Befehle in deiner eigenen virtuellen Maschine (VirtualBox, UTM oder WSL) aus und vergleiche die Ausgabe.

Dieser Abschnitt prüft die Rechte auf einem echten System, ändert aber keine Konfiguration. Erstelle nach Möglichkeit einen VM-Snapshot. Gib dein Passwort nur an der sudo-Abfrage im Terminal ein.

Normale Identität prüfen

Zeige dein normales Konto und seine Gruppenmitgliedschaften mit id.

id

Beispiel der erwarteten Ausgabe

uid=1000(student) gid=1000(student) groups=1000(student)
Meine Ausgabe sieht anders aus
  • Benutzername und UID hängen von der Distribution ab; deine eigenen Werte sind normal.
  • Ubuntu verwendet häufig die Gruppe sudo, Rocky/Alma häufig wheel.

Sudo für einen Befehl nutzen

Führe sudo whoami aus und prüfe, ob der effektive Benutzer root ist.

sudo whoami

Beispiel der erwarteten Ausgabe

root
Meine Ausgabe sieht anders aus
  • Beim Tippen des Passworts erscheinen keine Zeichen; das ist normal.
  • Der Fehler not in the sudoers file bedeutet, dass deinem Konto keine Berechtigung erteilt wurde; frage einen Administrator.

Effektive UID prüfen

Führe sudo id -u aus und prüfe, ob der privilegierte Befehl mit UID 0 läuft.

sudo id -u

Beispiel der erwarteten Ausgabe

0
Meine Ausgabe sieht anders aus
  • id -u gibt die effektive UID als Zahl aus; root hat UID 0.
  • Wenn der Befehl abgelehnt wird, prüfe die Rechte mit sudo -l.

Sudo-Berechtigungen lesen

Liste mit sudo -l die für dein Konto erlaubten Befehle auf; ändere keine Regeln.

sudo -l

Beispiel der erwarteten Ausgabe

User student may run the following commands
Meine Ausgabe sieht anders aus
  • Benutzername und Regeln unterscheiden sich je nach Distribution.
  • Falls die Ausgabe NOPASSWD enthält, notiere den genauen Befehl; ändere die Regel nicht.

sudoers-Syntax prüfen

Führe sudo visudo -c aus, um zu prüfen, ob die aktuelle sudo-Konfiguration eingelesen wird. Der Befehl ändert keine Dateien.

sudo visudo -c

Beispiel der erwarteten Ausgabe

/etc/sudoers: parsed OK
Meine Ausgabe sieht anders aus
  • Eine Distribution kann auch eingebundene Dateien prüfen; für jede Datei sollte eine Meldung wie parsed OK erscheinen.
  • Melde einen Fehler dem Systemadministrator, statt die Datei direkt zu bearbeiten.

Selbsttest

Was ist der Hauptunterschied zwischen sudo COMMAND und su -?

sudo gewährt Rechte für einen Befehl; su - wechselt in die Login-Shell eines anderen Kontos.

Warum verwendet man visudo, um die sudo-Richtliniendatei zu bearbeiten?

visudo sperrt die Datei während der Bearbeitung und prüft vor dem Speichern die Syntax.

Welche sudo-Regel entspricht dem Prinzip der geringsten Rechte?

Begrenze den Zugriff auf den richtigen Benutzer und den erforderlichen Befehl; vermeide weit gefasste ALL-Regeln.

Wenn su - das root-Passwort unter Ubuntu ablehnt, was ist eine wahrscheinliche Erklärung?

Bei Ubuntu-Installationen ist das root-Konto häufig gesperrt; ein berechtigter Benutzer nutzt sudo für die Administration.

Zusammenfassung

  • root hat UID 0. su - öffnet die Login-Sitzung des Zielkontos; sudo COMMAND führt einen erlaubten Befehl mit erhöhten Rechten aus.
  • sudo -l zeigt die tatsächlichen Rechte; sudo -i öffnet eine vollständige root-Login-Shell und sollte danach mit exit beendet werden.
  • Bearbeite sudoers-Richtlinien nur mit visudo und prüfe die Syntax mit visudo -c.
  • Halte NOPASSWD- und besonders ALL-Regeln eng begrenzt; erlaube nur den benötigten Benutzer, Befehl und die nötigen Argumente.

Fachbegriffe

root
Das Konto mit UID 0 und systemweiten administrativen Rechten.
sudo
Ein Werkzeug, mit dem ein berechtigter Benutzer einen bestimmten Befehl als ein anderes Konto ausführt.
su
Ein Werkzeug zum Wechsel der aktuellen Sitzung zu einem anderen Benutzerkonto.
sudoers
Die Richtlinie, die sudo-Rechte nach Benutzer, Zielkonto und Befehl festlegt.
visudo
Ein Werkzeug, das sudoers-Dateien mit Sperre und Syntaxprüfung bearbeitet.
NOPASSWD
Eine sudo-Regeloption, die für festgelegte Befehle die Passwortabfrage entfernt.

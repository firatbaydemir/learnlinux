Startseite / Stufe 1

1.3 Hilfe und Erkundung

Mit man, --help, which, type, find und history findest du ohne Internet selbst heraus, was ein unbekannter Befehl tut.

Was lernst du in diesem Modul?

  • Du öffnest eine man-Seite, navigierst darin, suchst und beendest sie; du erkennst die Abschnittsnummern (1, 5, 8).
  • Du holst dir mit --help und help eine schnelle Übersicht und liest die SYNOPSIS-Schreibweise ([ ], | und ...).
  • Du findest mit which und type heraus, wo ein Befehl liegt und welcher Art er ist, und suchst mit find nach Dateien.
  • Du siehst mit history alte Befehle an und behebst den Fehler 'command not found' (Exit-Code 127) systematisch.

man: die Handbuchseiten

Linux kennt Hunderte von Befehlen; auch Profis lernen nicht alle auswendig, sie wissen, wo sie nachschlagen. Die verlässlichste Quelle ist das Handbuch des Systems selbst, also die man-Seiten: man ls.

Die Seite öffnet sich in einem Pager: Leertaste blättert eine Seite vor, b zurück, /kernel + Enter sucht im Text, n springt zum nächsten Treffer, q beendet. Die Überschriften sind immer gleich: NAME (Kurzname), SYNOPSIS (Aufrufform), DESCRIPTION (Beschreibung), OPTIONS, EXAMPLES, SEE ALSO.

Das Handbuch ist in Abschnitte unterteilt: 1 = Benutzerbefehle, 5 = Dateiformate (z. B. /etc/passwd), 8 = Administrationsbefehle. Derselbe Name kann in mehreren Abschnitten vorkommen: man passwd zeigt den Befehl, man 5 passwd das Dateiformat. Im Simulator sind die Seiten kurz und Abschnittsnummern werden nicht unterstützt; die vollständige Seite siehst du in der echten VM.

man

Wozu dient es?
Öffnet die Handbuchseite eines Befehls.
Wo wird es verwendet?
Wenn du einen neuen Befehl oder eine Option kennenlernst.
Warum ist es wichtig?
Es sind die korrekten Informationen, die zu deiner Version passen und mit dem System mitgeliefert werden.
man ls

man <Abschnitt>

Wozu dient es?
Öffnet einen bestimmten Handbuchabschnitt.
Wo wird es verwendet?
Wenn derselbe Name sowohl Befehl als auch Dateiformat ist.
Warum ist es wichtig?
Du gelangst direkt zur richtigen Seite.
man 5 passwd

whatis

Wozu dient es?
Gibt die einzeilige Beschreibung eines Befehls aus.
Wo wird es verwendet?
Um sich schnell zu erinnern, wofür ein Befehl gut ist.
Warum ist es wichtig?
Du bekommst eine Kurzfassung, ohne die Seite zu öffnen.
whatis ls

apropos

Wozu dient es?
Sucht Handbuchseiten per Stichwort.
Wo wird es verwendet?
Wenn du den Namen des Befehls nicht kennst, aber weißt, was er tun soll.
Warum ist es wichtig?
Du suchst nach 'copy' und findest cp.
apropos copy
💡 Tipp

Wenn du dich auf der Seite verirrst, beende sie mit q. Zum Suchen tippe /, gib das Wort ein und drücke Enter; der nächste Treffer mit n.

⚠️ Achtung

whatis und apropos beruhen auf einem Index (mandb); auf frisch installierten Minimalsystemen können sie leer bleiben. Führe dann sudo mandb aus.

--help und help: schnelle Übersicht

Wenn du nicht das ganze Handbuch lesen willst, gibt ls --help eine kurze Verwendungsübersicht aus. Ist die Ausgabe lang, begrenze sie mit | head oder | less: ls --help | head -n 5.

Shell-interne Befehle wie cd haben kein eigenes Programm, daher gibt es für sie manchmal keine Seite mit man cd. Dafür gibt es Bashs help-Befehl: help cd. help allein liefert die Liste der bekannten Befehle (im Simulator ist diese Liste kurz).

Schnelle Entscheidung: bei externen Programmen zuerst --help, für Details man; bei Shell-internen Befehlen help.

--help

Wozu dient es?
Gibt eine kurze Verwendungsübersicht des Befehls aus.
Wo wird es verwendet?
Um sich schnell an eine Option zu erinnern.
Warum ist es wichtig?
Es geht viel schneller als man.
ls --help

help

Wozu dient es?
Zeigt Hilfe zu Bashs eigenen (Shell-internen) Befehlen.
Wo wird es verwendet?
Für Befehle wie cd, type, history.
Warum ist es wichtig?
Diese Befehle haben möglicherweise keine eigene man-Seite.
help

less

Wozu dient es?
Zeigt lange Ausgaben seitenweise an.
Wo wird es verwendet?
Bei langer --help- oder Dateiausgabe.
Warum ist es wichtig?
Die Navigationstasten sind dieselben wie bei man.
ls --help | less
💡 Tipp

Übersieh beim Aufruf der Hilfe nicht die oberste Zeile: Die Zeile Usage: zeigt dir die Aufrufform.

Die SYNOPSIS-Schreibweise lesen

Die SYNOPSIS-Zeile gibt das 'Muster' des Befehls an. Beispiel: ls [OPTION]... [FILE].... Lies sie so:

Was in [ ] steht, ist optional. ... besagt, dass der vorherige Teil mehrfach angegeben werden kann. a | b bedeutet entweder a oder b. < > oder GROSSBUCHSTABEN (FILE, DIR) sind Werte, die du selbst einsetzt. Fett gedruckte Teile werden unverändert eingegeben.

Beispiel: cp [OPTION]... SOURCE... DEST → Optionen sind optional, mindestens eine Quelle und ein Ziel sind Pflicht. ls läuft auch ganz ohne Argumente, weil alles in eckigen Klammern steht.

ls --help

Wozu dient es?
Zeigt das Aufrufmuster (Usage).
Wo wird es verwendet?
Um die Reihenfolge der Argumente zu erfahren.
Warum ist es wichtig?
Wenn du das Muster lesen kannst, verstehst du jeden neuen Befehl.
ls --help

man cat

Wozu dient es?
Öffnet die Seite mit dem SYNOPSIS-Abschnitt.
Wo wird es verwendet?
Ein einfaches Beispiel zum Üben.
Warum ist es wichtig?
Du siehst eckige Klammern und ... auf einer echten Seite.
man cat
💡 Tipp

Um das Pflichtige zu finden, schau auf die Teile außerhalb der eckigen Klammern.

which und type: wo liegt der Befehl?

Wenn du einen Befehl eingibst, sucht die Shell der Reihe nach in den Verzeichnissen der Variable PATH. which ls gibt den gefundenen Pfad aus (z. B. /usr/bin/ls).

type ist aufschlussreicher: Es sagt, ob der Befehl ein externes Programm, ein Shell-Builtin, ein Alias oder eine Funktion ist. type cd → cd is a shell builtin. Nutze es, um zu verstehen, welcher Befehl läuft, wenn derselbe Name mehrfach vorkommt.

Den Inhalt von PATH siehst du mit echo $PATH. alias und command -v funktionieren in der echten VM ebenfalls, im Simulator gibt es sie nicht.

which

Wozu dient es?
Zeigt den Dateipfad des Befehls.
Wo wird es verwendet?
Um herauszufinden, wo ein Programm installiert ist.
Warum ist es wichtig?
Du prüfst, dass du die richtige Version ausführst.
which ls

type

Wozu dient es?
Nennt die Art des Befehls (Programm, Builtin, Alias).
Wo wird es verwendet?
Beim Untersuchen unerwarteten Verhaltens.
Warum ist es wichtig?
Du unterscheidest Builtin und externes Programm.
type cd

echo $PATH

Wozu dient es?
Gibt die Verzeichnisse aus, in denen nach Befehlen gesucht wird.
Wo wird es verwendet?
Bei der Untersuchung von 'command not found'.
Warum ist es wichtig?
Du siehst, ob das Verzeichnis des Programms im PATH steht.
echo $PATH

command -v

Wozu dient es?
Gibt Pfad/Namen aus, wenn der Befehl existiert; sonst bleibt es still.
Wo wird es verwendet?
In Skripten für die Prüfung 'ist es installiert?'.
Warum ist es wichtig?
Es ist eine portable Existenzprüfung.
command -v ls

alias

Wozu dient es?
Listet definierte Kürzel auf.
Wo wird es verwendet?
Um zu verstehen, woher Befehle wie ll stammen.
Warum ist es wichtig?
Du siehst die Quelle dessen, was type als 'alias' meldet.
alias
💡 Tipp

Wenn sich ein Befehl seltsam verhält, prüfe zuerst mit type Befehl seine Art.

find: Grundlagen der Dateisuche

find <Startpunkt> <Bedingungen> durchläuft einen Verzeichnisbaum und gibt aus, was der Bedingung entspricht. Die beiden häufigsten Bedingungen: -name (nach Name) und -type (f Datei, d Verzeichnis).

Setze Platzhalter in Anführungszeichen: find . -name "*.txt". Ohne Anführungszeichen expandiert die Shell das Muster zuerst selbst und das Ergebnis täuscht. Als Startpunkt steht . für das aktuelle Verzeichnis und ~ für das Home-Verzeichnis.

Du kannst das Ergebnis mit | wc -l zählen und mit > Datei speichern. -maxdepth 1 begrenzt auf einem echten System die Tiefe (der Simulator ignoriert das).

find

Wozu dient es?
Sucht im Verzeichnisbaum nach Dateien, die einer Bedingung entsprechen.
Wo wird es verwendet?
Wenn du vergessen hast, wo eine Datei liegt.
Warum ist es wichtig?
Er durchsucht den Baum nach Name, Typ oder Größe.
find . -name "*.txt"

find -type

Wozu dient es?
Findet nur Dateien (f) oder Verzeichnisse (d).
Wo wird es verwendet?
Um Verzeichnisse getrennt zu zählen.
Warum ist es wichtig?
Du grenzt das Ergebnis ein.
find ~ -type d

find | wc -l

Wozu dient es?
Liefert die Anzahl der Fundstellen.
Wo wird es verwendet?
Um zu wissen, wie viele Treffer es gibt.
Warum ist es wichtig?
Du bekommst die Zahl, ohne die lange Liste zu lesen.
find ~ -name "*.txt" | wc -l
💡 Tipp

Um Fehlermeldungen auszublenden, hänge auf einem echten System 2>/dev/null an.

⚠️ Achtung

Lösche nicht mit find ... -delete oder -exec rm; sieh dir zuerst nur mit find die Liste an und entscheide dann.

history: frühere Befehle

history listet die Befehle, die du in dieser und in früheren Sitzungen eingegeben hast, nummeriert auf. Ist die Liste lang, hole dir mit history | tail -n 10 die letzten zehn Befehle.

In der echten Bash holt Pfeil nach oben den vorherigen Befehl, Strg+R sucht im Verlauf, !! führt den letzten Befehl und !42 den Befehl Nr. 42 erneut aus. Der Simulator unterstützt !! nicht; die Pfeiltasten funktionieren.

Befehle mit vertraulichen Daten (Passwörtern) werden in den Verlauf geschrieben; denk daran.

history

Wozu dient es?
Listet frühere Befehle nummeriert auf.
Wo wird es verwendet?
Um sich zu erinnern, was du zuvor eingegeben hast.
Warum ist es wichtig?
Du findest einen langen Befehl, ohne ihn neu zu tippen.
history

history | tail

Wozu dient es?
Zeigt nur die letzten Befehle.
Wo wird es verwendet?
Bei langem Verlauf.
Warum ist es wichtig?
Die Liste bleibt kurz.
history | tail -n 5

!!

Wozu dient es?
Führt den letzten Befehl erneut aus.
Wo wird es verwendet?
Mit sudo !! als erneuter Versuch mit Rechten.
Warum ist es wichtig?
Es spart Zeit.
!!
💡 Tipp

Tippe Strg+R und gib einen Teil des Befehls ein: Bash holt den Treffer.

Mit 'command not found' umgehen

Wenn du einen nicht existierenden Befehl eingibst, erhältst du nosuchcmd: command not found und der Exit-Code ist 127: nosuchcmd; echo $? → 127. Code 127 bedeutet 'Befehl nicht gefunden'.

Systematische Prüfung: (1) Tippfehler? (lss statt ls) (2) Groß-/Kleinschreibung: Linux unterscheidet sie. (3) Prüfe mit type Befehl, ob es ihn gibt. (4) Ist das Programm nicht installiert, installiere das Paket (Ubuntu sudo apt install, Rocky/Alma sudo dnf install). (5) Ist es installiert, prüfe das Verzeichnis mit echo $PATH.

Das ist etwas anderes als der Fehler 'Datei oder Verzeichnis nicht gefunden': Dort wurde der Befehl gefunden, aber die angegebene Datei existiert nicht.

echo $?

Wozu dient es?
Gibt den Exit-Code des letzten Befehls aus.
Wo wird es verwendet?
Wenn du den Erfolg eines Befehls prüfst.
Warum ist es wichtig?
0 bedeutet Erfolg, 127 bedeutet, dass der Befehl fehlt.
nosuchcmd; echo $?

type

Wozu dient es?
Gibt es den Befehl, und wo?
Wo wird es verwendet?
Erste Prüfung nach einem Fehler.
Warum ist es wichtig?
Es filtert Tippfehler heraus.
type nosuchcmd
💡 Tipp

Auf einem echten System macht Ubuntu manchmal mit 'Command 'x' not found, did you mean...' einen Vorschlag; lies den Vorschlag aufmerksam.

Mach es in deiner VM

Die eigentliche Praxis findet auf echtem Linux statt: Führe die Befehle in deiner eigenen virtuellen Maschine (VirtualBox, UTM oder WSL) aus und vergleiche die Ausgabe.

Führe in deiner VM (Ubuntu, Rocky, Alma oder WSL) die folgenden Befehle aus. Es ist kein zerstörerischer Befehl dabei; vergiss trotzdem nicht, den Pager (man) mit q zu verlassen.

Handbuchseite öffnen

Öffne man ls, suche mit / nach long und beende mit q. Füge danach die ersten Zeilen ein.

man ls | head -n 5

Beispiel der erwarteten Ausgabe

LS(1)    User Commands

NAME
       ls - list directory contents
Meine Ausgabe sieht anders aus
  • Ist deine Systemsprache Deutsch oder Türkisch, können die Überschriften übersetzt sein.
  • Wenn du 'No manual entry' erhältst, fehlt das Handbuchpaket: sudo apt install man-db oder sudo dnf install man-db.

--help-Übersicht

Füge die ersten Zeilen der Ausgabe von ls --help ein.

ls --help | head -n 5

Beispiel der erwarteten Ausgabe

Usage: ls [OPTION]... [FILE]...
List information about the FILEs (the current directory by default).
Meine Ausgabe sieht anders aus
  • Unter macOS oder BusyBox kann das --help-Format anders aussehen; führe es in der Linux-VM aus.

Befehlsarten

Füge die Art und den Pfad der Befehle cd, ls und which ls ein.

type cd
type ls
which ls

Beispiel der erwarteten Ausgabe

cd is a shell builtin
ls is aliased to `ls --color=auto'
/usr/bin/ls
Meine Ausgabe sieht anders aus
  • ls kann ein Alias sein (unter Ubuntu/Rocky wegen der Farben); das ist normal.
  • Bei manchen Distributionen erscheint /bin/ls (/bin ist ein Link auf /usr/bin).

Mit find suchen

Finde die .txt-Dateien in deinem Home. Da die Ausgabe personenbezogen ist, antworte nur mit 'Erledigt'.

find ~ -maxdepth 2 -name "*.txt" 2>/dev/null
Meine Ausgabe sieht anders aus
  • Gibt es keine Ausgabe, hast du keine .txt-Datei in deinem Home: Lege zuerst mit touch ~/notes.txt eine an.

whatis und apropos

Suche die einzeilige Beschreibung zu ls und die Befehle, die 'copy' enthalten.

whatis ls
apropos copy | head -n 5

Beispiel der erwarteten Ausgabe

ls (1) - list directory contents
cp (1) - copy files and directories
Meine Ausgabe sieht anders aus
  • Siehst du 'nothing appropriate', fehlt der Index: Führe sudo mandb aus und versuche es erneut.
  • Unter Ubuntu/Rocky kann die Ausgabe von apropos eine andere Zeilenzahl haben.

command not found

Führe einen nicht existierenden Befehl aus und füge den Exit-Code ein.

nosuchcmd; echo $?

Beispiel der erwarteten Ausgabe

bash: nosuchcmd: command not found
127
Meine Ausgabe sieht anders aus
  • Ubuntu kann mit 'Command 'nosuchcmd' not found, did you mean...' einen Vorschlag machen; die letzte Zeile muss trotzdem 127 sein.
  • Wenn du Zsh verwendest, lautet die Meldung 'zsh: command not found: nosuchcmd'.

Verlauf ansehen

Liste deine letzten fünf Befehle auf.

history | tail -n 5

Beispiel der erwarteten Ausgabe

  498  which ls
  499  nosuchcmd
  500  history | tail -n 5
Meine Ausgabe sieht anders aus
  • Die Nummern sind anders; das ist normal.
  • In einem frisch geöffneten Terminal kann die Liste kurz sein.

Handbuchabschnitte

Öffne die Seite aus Abschnitt 5, die das Format der Datei /etc/passwd beschreibt, und füge die ersten Zeilen ein.

man 5 passwd | head -n 5

Beispiel der erwarteten Ausgabe

PASSWD(5)   File Formats Manual

NAME
       passwd - password file
Meine Ausgabe sieht anders aus
  • man passwd (Abschnitt 1) ist eine andere Seite: der Befehl zum Ändern des Passworts.
  • Gibt es die Seite nicht, fehlt das Paket man-db oder man-pages.

Selbsttest

Welche Tasten verwendet man auf einer man-Seite, um im Text zu suchen und die Seite zu beenden?

/Wort sucht, n springt zum nächsten Treffer, q beendet.

Was bedeuten [ ] und ... im Muster ls [OPTION]... [FILE]...?

Eckige Klammern bedeuten optional, die drei Punkte zeigen, dass sich der vorherige Teil wiederholen kann.

Welche Zahl steht in der Ausgabe von nosuchcmd; echo $??

Bei 'command not found' liefert Bash 127 als Exit-Code zurück.

Mit welchem Befehl siehst du, dass cd kein externes Programm ist?

Die Ausgabe von type cd lautet cd is a shell builtin; es steckt also in Bash selbst.

Zusammenfassung

  • man Befehl ist das ausführliche Handbuch, Befehl --help die Kurzübersicht, help gilt für Shell-interne Befehle.
  • In man: / suchen, n nächster Treffer, q beenden; Abschnitte: 1 Befehle, 5 Dateiformate, 8 Administration.
  • SYNOPSIS: [ ] optional, ... Wiederholung, | oder.
  • which zeigt den Pfad, type die Art; find . -name "*.txt" sucht Dateien.
  • history listet den Verlauf auf; bei command not found ist der Exit-Code 127.

Fachbegriffe

man-Seite
Die mit dem System gelieferte Handbuchseite eines Befehls.
SYNOPSIS
Der man-Abschnitt, der das Aufrufmuster des Befehls zeigt.
Builtin
Ein in Bash eingebauter Befehl ohne eigenes Programm.
PATH
Die Liste der Verzeichnisse, in denen nach Befehlen gesucht wird.
Exit-Code
Die Zahl, die ein Befehl beim Beenden hinterlässt; 0 Erfolg, 127 Befehl nicht gefunden.
Pager
Ein Programm, das langen Text seitenweise anzeigt (less).

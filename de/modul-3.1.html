3.1 Streams: stdin, stdout, stderr

Jeder Linux-Befehl hat drei Standardkanäle: Eingabe, Ausgabe und Fehler. Wer sie versteht, versteht Umleitung und Pipes.

Was lernst du in diesem Modul?

  • Du unterscheidest stdin (0), stdout (1) und stderr (2).
  • Du leitest Ausgabe und Fehler mit >, >> und 2> in Dateien um.
  • Du führst Kanäle mit 2>&1 zusammen oder verwirfst sie mit /dev/null.

Die drei Standardkanäle

Ein laufendes Programm hat drei offene Kanäle: stdin (0) liest Eingaben, stdout (1) schreibt das normale Ergebnis, stderr (2) schreibt Fehlermeldungen. Standardmäßig kommt die Eingabe von der Tastatur, Ausgabe und Fehler gehen auf den Bildschirm.

Weil beide auf demselben Bildschirm landen, wirken sie vermischt, sind aber getrennte Kanäle. Diese Trennung erlaubt dir, Fehler in eine eigene Datei zu schreiben.

echo

Wozu dient es?
Schreibt Text nach stdout.
Wo wird es verwendet?
Für Tests und einfache Ausgaben.
Warum ist es wichtig?
Das einfachste stdout-Beispiel.
echo hello

cat

Wozu dient es?
Schreibt eine Datei nach stdout.
Wo wird es verwendet?
Um Dateiinhalte zu sehen.
Warum ist es wichtig?
Liest eine Datei und speist den Kanal.
cat lab/names.txt

ls

Wozu dient es?
Bei einem nicht vorhandenen Pfad geht die Fehlermeldung nach stderr.
Wo wird es verwendet?
Um den Fehlerkanal zu sehen.
Warum ist es wichtig?
Die Meldung erscheint auf dem Bildschirm, ist aber nicht auf stdout.
ls lab/missing.txt
💡 Tipp

Kanalnummern: 0 = Eingabe, 1 = Ausgabe, 2 = Fehler. Du brauchst sie bei Umleitungen.

In Dateien umleiten

> schreibt stdout in eine Datei und leert sie vorher. >> hängt an. 2> leitet nur stderr um. < übergibt eine Datei als stdin.

Sollen Ausgabe und Fehler in dieselbe Datei, schreibe > file 2>&1: Zuerst geht stdout in die Datei, dann wird stderr dorthin geleitet, wohin stdout zeigt. Die Reihenfolge zählt. /dev/null ist eine Spezialdatei, die alles Geschriebene verwirft.

>

Wozu dient es?
Schreibt stdout in eine Datei; eine vorhandene wird geleert.
Wo wird es verwendet?
Um Ausgaben zu speichern.
Warum ist es wichtig?
Du behältst das Ergebnis für später.
echo hello > out.txt

>>

Wozu dient es?
Hängt stdout ans Dateiende an.
Wo wird es verwendet?
Beim Führen von Logs.
Warum ist es wichtig?
Der alte Inhalt bleibt erhalten.
echo world >> out.txt

2>

Wozu dient es?
Schreibt nur Fehlermeldungen in eine Datei.
Wo wird es verwendet?
Um Fehler getrennt zu sammeln.
Warum ist es wichtig?
Die Ausgabe bleibt am Bildschirm, Fehler werden gespeichert.
ls lab/missing.txt 2> errors.txt

<

Wozu dient es?
Macht eine Datei zur Eingabe des Befehls.
Wo wird es verwendet?
Bei Befehlen, die Eingaben lesen.
Warum ist es wichtig?
Liest aus einer Datei statt von der Tastatur.
cat < lab/names.txt

2>&1

Wozu dient es?
Leitet stderr dorthin, wohin stdout zeigt.
Wo wird es verwendet?
Um alles in einer Datei zu sammeln.
Warum ist es wichtig?
Ausgabe und Fehler werden zusammen gespeichert.
ls lab missing_dir > all.txt 2>&1

2>/dev/null

Wozu dient es?
Verwirft Fehler.
Wo wird es verwendet?
Um harmlose Fehler zu unterdrücken.
Warum ist es wichtig?
Hält den Bildschirm sauber.
ls lab missing_dir 2>/dev/null
💡 Tipp

Gute Gewohnheit: Überlege zuerst, ob >> oder > nötig ist. Ein falsches > löscht eine vorhandene Datei stillschweigend.

⚠️ Achtung

> leert die Zieldatei, bevor der Befehl läuft. sort file > file zerstört den Inhalt der Datei.

Mach es in deiner VM

Die eigentliche Praxis findet auf echtem Linux statt: Führe die Befehle in deiner eigenen virtuellen Maschine (VirtualBox, UTM oder WSL) aus und vergleiche die Ausgabe.

Diese Befehle laufen im Home-Verzeichnis deiner VM und schreiben nur Dateien, die du selbst anlegst; benutze trotzdem keinen Namen einer wichtigen Datei.

Ausgabe und Fehler trennen

Liste eine vorhandene Datei und einen fehlenden Pfad; schreibe Ausgabe und Fehler in getrennte Dateien und zeige beide an.

ls /etc/hostname /nonexistent > out.txt 2> err.txt
cat out.txt err.txt

Beispiel der erwarteten Ausgabe

/etc/hostname
ls: cannot access '/nonexistent': No such file or directory
Meine Ausgabe sieht anders aus
  • Der Fehlertext variiert je nach Distribution und Sprache; nonexistent muss vorkommen.
  • Ist out.txt leer, gibt es /etc/hostname auf deinem System nicht; nimm /etc/hosts.

Überschreiben und anhängen

Lege mit > eine Datei an, hänge mit >> eine Zeile an und zeige das Ergebnis.

echo "line one" > ~/streams.txt
echo "line two" >> ~/streams.txt
cat ~/streams.txt

Beispiel der erwarteten Ausgabe

line one
line two
Meine Ausgabe sieht anders aus
  • Erscheint nur line two, hast du in beiden Befehlen > benutzt.

Fehler unterdrücken

Liste ein Verzeichnis, das du als normaler Benutzer nicht lesen darfst, zusammen mit einer Datei; verwirf die Fehler nach /dev/null.

ls /root /etc/hostname 2>/dev/null

Beispiel der erwarteten Ausgabe

/etc/hostname
Meine Ausgabe sieht anders aus
  • Fehlt hostname, gibt es die Datei nicht; solange keine Fehlermeldung am Bildschirm erscheint, hat es funktioniert.

Schnelle Übungen (Simulator)

Optional: Zum Aufwärmen vor der VM oder als Ersatz ohne VM nutzt du das virtuelle Terminal im Browser. Aufgaben werden automatisch geprüft.

Die Aufgaben steigen vom Aufwärmen bis zum Ticket an. Die Abzeichen zeigen den Schwierigkeitsgrad.

Aufwärmen

  1. AufwärmenLeicht

    Schreibe Text auf den Bildschirm (stdout) mit echo hello.

    Hinweis

    Die Ausgabe erscheint direkt am Bildschirm.

    Lösung
    echo hello

  2. AufwärmenLeicht

    Gib den Dateiinhalt mit cat lab/names.txt nach stdout aus.

    Hinweis

    Du solltest drei Namen sehen.

    Lösung
    cat lab/names.txt

  3. AufwärmenLeicht

    Liste den nicht vorhandenen Pfad lab/missing.txt mit ls und lies die Fehlermeldung.

    Hinweis

    Diese Meldung kommt von stderr.

    Lösung
    ls lab/missing.txt

Geführtes Lab

  1. Geführtes LabLeicht

    Schreibe den Text mit echo hello > out.txt in die Datei out.txt.

    Hinweis

    Du siehst keine Ausgabe; prüfe mit cat out.txt.

    Lösung
    echo hello > out.txt

  2. Geführtes LabMittel

    Hänge mit echo world >> out.txt eine zweite Zeile an dieselbe Datei an.

    Hinweis

    >> hängt an, > überschreibt.

    Lösung
    echo world >> out.txt

  3. Geführtes LabMittel

    Leite den Fehler mit ls lab/missing.txt 2> errors.txt nach errors.txt um.

    Hinweis

    Der Fehler erscheint nicht mehr am Bildschirm.

    Lösung
    ls lab/missing.txt 2> errors.txt

  4. Geführtes LabMittel

    Übergib die Datei mit cat < lab/names.txt als stdin.

    Hinweis

    < liest die Eingabe aus einer Datei.

    Lösung
    cat < lab/names.txt

Vorhersagen

  1. VorhersagenMittel

    Vorhersage: Erscheint bei ls lab/missing.txt > result.txt der Fehler am Bildschirm? Ist result.txt gefüllt? Führe es aus und prüfe.

    Hinweis

    > leitet nur stdout um; der Fehler liegt auf stderr.

    Lösung
    ls lab/missing.txt > result.txt

  2. VorhersagenMittel

    Vorhersage: Was gibt cat lab/names.txt | wc -l aus? Führe es aus und prüfe.

    Hinweis

    wc -l zählt Zeilen; wie viele Zeilen hat die Datei?

    Lösung
    cat lab/names.txt | wc -l

Fehler finden

  1. Fehler findenMittel

    Fehlersuche: ls lab missing_dir > all.txt zeigt den Fehler am Bildschirm, in all.txt landet er nicht. Sorge dafür, dass all.txt Liste und Fehler enthält.

    Hinweis

    Hänge 2>&1 ans Ende des Befehls.

    Lösung
    ls lab missing_dir > all.txt 2>&1

Mini-Projekt

  1. Mini-ProjektMittel

    Mini-Projekt: Baue build.log. 1) echo start > build.log 2) ls lab >> build.log 3) ls nothing 2>> build.log. Die Datei muss 3 Zeilen haben.

    Hinweis

    Der erste nutzt >, die anderen >> und 2>>.

    Lösung
    echo start > build.log
ls lab >> build.log
ls nothing 2>> build.log

Herausforderung

  1. HerausforderungSchwer

    Herausforderung: Verwirf die Fehler von ls lab missing_dir nach /dev/null und speichere die normale Ausgabe in found.txt.

    Hinweis

    Zwei Umleitungen: 2>/dev/null und > found.txt.

    Lösung
    ls lab missing_dir 2>/dev/null > found.txt

Ticket

  1. TicketSchwer

    Ticket: Der Prüfer möchte die Anzahl der Benutzer aus lab/names.txt in ~/count.txt (nur die Zahl).

    Hinweis

    wc -l < file gibt die Anzahl ohne Dateinamen aus; speichere mit >.

    Lösung
    wc -l < lab/names.txt > count.txt

Selbsttest

Welche Kanalnummer hat stderr?

0 = stdin, 1 = stdout, 2 = stderr.

Was macht echo x > file, wenn die Datei schon existiert?

> leert die Datei; zum Anhängen nimmst du >>.

Welcher Befehl speichert Fehler in einer Datei und lässt die normale Ausgabe am Bildschirm?

2> leitet nur stderr um.

Wofür ist /dev/null da?

/dev/null ist ein schwarzes Loch: Was du hineinschreibst, verschwindet.

Zusammenfassung

  • Drei Kanäle: stdin (0), stdout (1), stderr (2).
  • > überschreibt, >> hängt an, 2> leitet Fehler um, < liefert Eingaben.
  • 2>&1 führt Fehler und Ausgabe zusammen; bei > file 2>&1 zählt die Reihenfolge.
  • /dev/null verwirft Daten.

Fachbegriffe

stdin
Standardeingabe, Kanal 0; standardmäßig die Tastatur.
stdout
Standardausgabe, Kanal 1; standardmäßig der Bildschirm.
stderr
Standardfehlerausgabe, Kanal 2; Fehlermeldungen.
Umleitung
Einen Kanal mit einer Datei oder einem anderen Kanal verbinden.
/dev/null
Spezialdatei, die Geschriebenes verwirft.

Startseite / Stufe 2

2.7 Editoren

Textdateien im Terminal bearbeiten: nano für den schnellen Einstieg, vi/vim, wenn es überall und schnell gehen muss.

Was lernst du in diesem Modul?

  • Du öffnest, bearbeitest, speicherst und schließt Dateien mit nano.
  • Du kennst die Modi von vim und kommst immer wieder heraus (:q!, :wq).
  • Du nutzt grundlegende vim-Befehle: Einfügen, Zeile löschen, Rückgängig, Suchen.
  • Du bearbeitest Konfigurationsdateien sicher: erst Backup, sudo nur wenn nötig.

nano: der einfache Editor

nano ist einsteigerfreundlich: Du tippst sofort los, die Tastenkürzel stehen unten am Bildschirm. ^ steht für die Taste Strg (Ctrl); ^X heißt also Strg+X.

Existiert die Datei nicht, öffnet nano datei einen leeren Puffer und legt die Datei beim Speichern an. Unter Ubuntu ist nano meist vorinstalliert; unter Rocky/Alma installierst du es bei Bedarf mit sudo dnf install nano.

nano file

Wozu dient es?
Öffnet eine Datei im Editor nano (legt sie beim Speichern an, falls sie fehlt).
Wo wird es verwendet?
Für schnelle Änderungen an Text- und Konfigurationsdateien.
Warum ist es wichtig?
Einfach, die Hilfe steht unten im Bild.
nano todo.txt

Ctrl+O

Wozu dient es?
Schreibt (speichert) die Datei; den Namen mit ENTER bestätigen.
Wo wird es verwendet?
In nano, wann immer du speichern willst.
Warum ist es wichtig?
Sichert deine Arbeit, ohne den Editor zu verlassen.
nano todo.txt

Ctrl+X

Wozu dient es?
Beendet nano; fragt bei ungespeicherten Änderungen nach (Y/N).
Wo wird es verwendet?
In nano, wenn du fertig bist.
Warum ist es wichtig?
Der Ausgang: Y speichert, N verwirft.
nano todo.txt

Ctrl+K / Ctrl+U

Wozu dient es?
Schneidet die aktuelle Zeile aus / fügt sie wieder ein.
Wo wird es verwendet?
Zum Löschen, Verschieben oder Duplizieren von Zeilen.
Warum ist es wichtig?
Schnelles Zeilenbearbeiten ohne Maus.
nano todo.txt
💡 Tipp

Weitere nano-Tasten: Ctrl+W Suchen, Ctrl+G Hilfe, Alt+U Rückgängig, Ctrl+_ zu Zeilennummer springen.

vi / vim: Modi

vi ist auf praktisch jedem Linux-System installiert, vim ist die verbesserte Version (auf manchen Minimalsystemen ist vi einfach vim). Lerne die Grundlagen einmal, und du kannst in jeder Lage einen Server retten.

Die Kernidee: vim hat Modi. Im Normalmodus (Standard beim Start) sind Tasten Befehle — dd schreibt keinen Text, sondern löscht eine Zeile. Mit i wechselst du in den Einfügemodus (Insert) und tippst normal; Esc bringt dich zurück. Mit : gelangst du in den Kommandozeilenmodus für :w, :q, :wq, :q!.

Anfängerfehler Nummer eins: im Normalmodus Text tippen. Passieren seltsame Dinge, drücke ein- bis zweimal Esc und mach weiter.

vim file

Wozu dient es?
Öffnet eine Datei in vim (Start im Normalmodus).
Wo wird es verwendet?
Für Konfigurationsdateien, Skripte und auf Servern ohne nano.
Warum ist es wichtig?
Überall verfügbar und nach dem Lernen sehr schnell.
vim todo.txt

i / Esc

Wozu dient es?
i wechselt in den Einfügemodus, Esc zurück in den Normalmodus.
Wo wird es verwendet?
Beim Wechsel zwischen Tippen und Befehlen.
Warum ist es wichtig?
Ohne i kannst du keinen Text tippen; ohne Esc keine Befehle geben.
vim todo.txt

:wq

Wozu dient es?
Schreibt die Datei und beendet vim (auch ZZ oder :x).
Wo wird es verwendet?
Im Normalmodus nach Eingabe von :.
Warum ist es wichtig?
Speichert und beendet in einem Schritt.
vim todo.txt
⛔ Gefahr

In vim festgesteckt? Drücke Esc, tippe dann :q! und ENTER: beendet OHNE zu speichern; zum Speichern :wq. Strg+C oder Strg+X beenden vim nicht.

Wichtige vim-Befehle

Diese Normalmodus-Befehle decken den Alltag ab. Pfeiltasten funktionieren, aber h j k l (links, runter, hoch, rechts) lassen die Hände auf der Grundreihe.

Viele Befehle nehmen eine Zahl: 3dd löscht drei Zeilen, 5j geht fünf Zeilen nach unten. gg springt an den Anfang, G ans Ende, :42 zu Zeile 42. :set number zeigt Zeilennummern.

dd

Wozu dient es?
Löscht (schneidet) die aktuelle Zeile; p fügt sie darunter ein.
Wo wird es verwendet?
Im Normalmodus.
Warum ist es wichtig?
Zeilen entfernen, verschieben oder duplizieren (yy kopiert).
vim todo.txt

u

Wozu dient es?
Macht die letzte Änderung rückgängig; Ctrl+R stellt sie wieder her.
Wo wird es verwendet?
Im Normalmodus.
Warum ist es wichtig?
Korrigiert versehentliche Änderungen.
vim todo.txt

/text

Wozu dient es?
Sucht vorwärts nach text; n springt zum nächsten Treffer.
Wo wird es verwendet?
Im Normalmodus.
Warum ist es wichtig?
Findet Einstellungen in langen Konfigurationsdateien.
vim server.log

:q!

Wozu dient es?
Beendet und verwirft alle ungespeicherten Änderungen.
Wo wird es verwendet?
Vom Normalmodus, wenn du Unsinn gemacht oder nur geschaut hast.
Warum ist es wichtig?
Der Notausgang; ein einfaches :q verweigert bei Änderungen.
vim todo.txt
💡 Tipp

Starte einmal vimtutor (ca. 30 Minuten) — der beste interaktive vim-Kurs, kommt mit vim.

Sicher bearbeiten

Systemkonfigurationen liegen in /etc und gehören root. Als normaler Benutzer kannst du sie lesen, aber nicht speichern: Nutze sudo nano /etc/datei nur, wenn es sein muss. Mach zuerst ein Backup, damit du nach einem Tippfehler wiederherstellen kannst.

Wege ohne Editor: echo "Text" >> datei hängt eine Zeile an, echo "Text" > datei überschreibt die ganze Datei. Mit cp datei datei.bak entsteht in einer Sekunde ein Backup.

Ist vim abgestürzt oder das Terminal geschlossen worden, bleibt evtl. eine Swap-Datei (.datei.swp) übrig und vim warnt beim nächsten Start. Bearbeitet niemand sonst die Datei, kannst du die Swap-Datei löschen.

cp file file.bak

Wozu dient es?
Erstellt vor dem Bearbeiten eine Sicherungskopie.
Wo wird es verwendet?
Vor jeder Änderung an einer wichtigen Datei.
Warum ist es wichtig?
Den alten Stand holst du mit cp file.bak file zurück.
cp app.conf app.conf.bak

sudoedit

Wozu dient es?
Bearbeitet eine root-eigene Datei über eine temporäre Kopie mit deinem Editor.
Wo wird es verwendet?
Für Dateien in /etc.
Warum ist es wichtig?
Sicherer, als den ganzen Editor als root zu starten.
sudoedit /etc/hosts

export EDITOR

Wozu dient es?
Legt den Standardeditor fest, den Werkzeuge wie sudoedit und crontab -e benutzen.
Wo wird es verwendet?
In der Shell oder in ~/.bashrc.
Warum ist es wichtig?
Werkzeuge öffnen dann nano statt eines Editors, den du nicht kennst.
export EDITOR=nano

cat file

Wozu dient es?
Zeigt den Dateiinhalt ohne Editor.
Wo wird es verwendet?
Zum Überprüfen des Ergebnisses einer Änderung.
Warum ist es wichtig?
Schnelle Kontrolle, ob die Datei enthält, was du erwartest.
cat todo.txt
💡 Tipp

> überschreibt, >> hängt an. Ein fehlendes > kann eine Datei leeren — prüfe danach mit cat.

⚠️ Achtung

Bevor du eine Datei unter /etc bearbeitest, mach ein Backup (sudo cp datei datei.bak). Eine kaputte /etc/fstab oder /etc/ssh/sshd_config kann die Maschine unbootbar oder unerreichbar machen.

Mach es in deiner VM

Die eigentliche Praxis findet auf echtem Linux statt: Führe die Befehle in deiner eigenen virtuellen Maschine (VirtualBox, UTM oder WSL) aus und vergleiche die Ausgabe.

Auf deiner VM nutzt du jetzt die echten Editoren. Mach alle Schritte im Home-Verzeichnis mit Testdateien; erstelle einen Snapshot, bevor du Dateien in /etc anfasst.

Erste Datei mit nano

Öffne nano, tippe den Text, speichere mit Strg+O und ENTER, beende mit Strg+X. Zeige dann die Datei.

nano nano_test.txt
# tippe: hello nano   -> Ctrl+O, ENTER, Ctrl+X
cat nano_test.txt

Beispiel der erwarteten Ausgabe

hello nano
Meine Ausgabe sieht anders aus
  • command not found: installiere nano mit sudo apt install nano (Ubuntu) oder sudo dnf install nano (Rocky/Alma).
  • Fragt nano beim Beenden 'Save modified buffer?', drücke Y und ENTER.

Zeilen in nano ausschneiden und einfügen

Schreibe in nano line one und line two, speichere und beende. Öffne erneut, schneide die erste Zeile mit Strg+K aus, füge sie mit Strg+U zweimal ein, speichere. Füge das Ergebnis ein.

nano lines.txt
# zwei Zeilen tippen, speichern, beenden
nano lines.txt
# einmal Ctrl+K, zweimal Ctrl+U, Ctrl+O, ENTER, Ctrl+X
cat -n lines.txt

Beispiel der erwarteten Ausgabe

     1	line two
     2	line one
     3	line one
Meine Ausgabe sieht anders aus
  • Weicht die Reihenfolge ab, hängt es von der Cursorposition beim Einfügen ab; line one und line two müssen beide vorkommen.
  • Keine Nummerierung? Du hast -n bei cat -n vergessen.

Erste Datei mit vim

Öffne vim, drücke i, tippe den Text, dann Esc und :wq ENTER. Zeige die Datei.

vim vim_test.txt
# i  -> tippe: hello vim  -> Esc  -> :wq  -> ENTER
cat vim_test.txt

Beispiel der erwarteten Ausgabe

hello vim
Meine Ausgabe sieht anders aus
  • Text fehlt oder ist seltsam? Du hast vorher nicht i gedrückt. Esc, :q! und neu beginnen.
  • vim: command not found: nutze vi vim_test.txt oder installiere vim (sudo apt install vim / sudo dnf install vim-enhanced).

Ohne Speichern beenden

Schreibe keep in eine Datei, öffne sie dann in vim, füge eine Zeile lose hinzu und beende mit :q!. Die Datei muss weiter nur keep enthalten.

echo keep > discard.txt
vim discard.txt
# i -> tippe: lose -> Esc -> :q! -> ENTER
cat discard.txt

Beispiel der erwarteten Ausgabe

keep
Meine Ausgabe sieht anders aus
  • Steht lose in der Datei, hast du :wq statt :q! benutzt.
  • Verweigert vim das Beenden mit :q, ist das der Schutz vor ungespeicherten Änderungen: nutze :q!.

Zeile löschen und rückgängig

Erzeuge eine Datei mit 20 Zeilen, lösche Zeile 5 mit 5G und dd, mache mit u rückgängig, dann nochmal dd und speichere. Zähle die Zeilen.

seq 1 20 > numbers.txt
vim numbers.txt
# 5G -> dd -> u -> dd -> :wq
wc -l numbers.txt

Beispiel der erwarteten Ausgabe

19 numbers.txt
Meine Ausgabe sieht anders aus
  • Ergebnis 20: das letzte dd oder das Speichern fehlte; Ergebnis 18: du hast zweimal ohne u gelöscht.
  • Fehlt seq? Nutze for i in $(seq 1 20); do echo $i; done > numbers.txt oder installiere coreutils.

Standardeditor festlegen

Setze nano als Standardeditor für diese Sitzung und prüfe die Variable.

export EDITOR=nano
echo $EDITOR

Beispiel der erwarteten Ausgabe

nano
Meine Ausgabe sieht anders aus
  • Für dauerhaft füge export EDITOR=nano in ~/.bashrc ein; es wirkt in einer neuen Shell.

Backup vor Änderungen in /etc

Sichere /etc/hosts mit sudo, prüfe das Backup und öffne das Original mit sudoedit oder sudo nano. Schau nur, ändere nichts, beende ohne Speichern.

sudo cp /etc/hosts /etc/hosts.bak
ls -l /etc/hosts.bak
sudoedit /etc/hosts
# umsehen, dann Ctrl+X (nano) oder :q! (vim)

Beispiel der erwarteten Ausgabe

-rw-r--r--. 1 root root 158 ... /etc/hosts.bak
Meine Ausgabe sieht anders aus
  • sudoedit meckert über den Editor? Führe zuerst export EDITOR=nano aus oder nutze sudo nano /etc/hosts.
  • Fragt sudo nach einem Passwort, gib dein eigenes ein (beim Tippen wird nichts angezeigt).

Schnelle Übungen (Simulator)

Optional: Zum Aufwärmen vor der VM oder als Ersatz ohne VM nutzt du das virtuelle Terminal im Browser. Aufgaben werden automatisch geprüft.

Die Aufgaben steigen vom Aufwärmen bis zum Ticket an. Die Abzeichen zeigen den Schwierigkeitsgrad.

  1. AufwärmenLeicht

    Lege eine Datei ohne Editor an: echo "hello editor" > hello.txt.

    Hinweis

    Lösung
    echo "hello editor" > hello.txt

  2. AufwärmenLeicht

    Zeige den Inhalt der Datei mit cat hello.txt.

    Hinweis

    Du solltest hello editor sehen.

    Lösung

  3. AufwärmenLeicht

    Sichere todo.txt vor dem Bearbeiten: cp todo.txt todo.txt.bak.

    Hinweis

    Erst die Quelle, dann der Backup-Name.

  2. Geführtes LabMittel

    Zeige todo.txt mit Zeilennummern: cat -n todo.txt.

    Hinweis

    Lösung

  3. Geführtes LabMittel

    Hinweis

  1. VorhersagenMittel

    Vorhersage: Wie viele Zeilen hat todo.txt jetzt? Prüfe mit wc -l todo.txt.

    Hinweis

    Es waren 3 Zeilen, du hast eine angehängt.

    Lösung

  2. VorhersagenMittel

    Vorhersage: Was passiert, wenn ein normaler Benutzer echo test > /etc/motd ausführt? Probiere es.

    Hinweis

Fehler finden

  1. Fehler findenMittel

    Debug: Eine falsche Änderung hat app.conf kaputt gemacht (dort steht mode=debug). Stelle die alte Version aus app.conf.bak wieder her.

    Hinweis

    Kopiere das Backup mit cp über die Datei.

    Lösung

  2. Fehler findenMittel

    Debug: vim warnt wegen einer übrig gebliebenen Swap-Datei .todo.txt.swp im Home-Verzeichnis. Niemand bearbeitet die Datei; lösche die Swap-Datei.

    Hinweis

    Versteckte Datei: rm .todo.txt.swp; mit ls -a sichtbar.

    Lösung
    rm .todo.txt.swp

    Hinweis

Selbsttest

Du bist in vim und willst OHNE Speichern beenden. Was tippst du?

:q! beendet und verwirft Änderungen; :wq würde speichern. Strg+X ist die Ausstiegstaste von nano, nicht von vim.

Du tippst direkt nach dem Start von vim dd und eine Zeile verschwindet. Warum?

vim startet im Normalmodus, Tasten sind Befehle. dd löscht die aktuelle Zeile, u macht es rückgängig.

Was macht Ctrl+X in nano?

Strg+X beendet; bei ungespeicherten Änderungen fragt nano Y/N. Strg+K schneidet aus, Strg+G ist Hilfe, Strg+W sucht.

Was solltest du tun, bevor du /etc/ssh/sshd_config bearbeitest?

Ein Backup (sudo cp datei datei.bak) ermöglicht schnelle Wiederherstellung nach einem Fehler.

Zusammenfassung

  • nano file zum Bearbeiten, Ctrl+O speichert, Ctrl+X beendet.
  • vim hat Modi: Normal (Befehle), Insert (i, Text), Kommandozeile (:). Esc führt zurück in den Normalmodus.
  • vim beenden: :wq (speichern) oder :q! (verwerfen). Grundlagen: dd, u, /text, gg/G.
  • Systemdateien vor dem Bearbeiten sichern; sudo nur wenn nötig. > überschreibt, >> hängt an.

Fachbegriffe

Normalmodus
Standardmodus von vim, in dem Tasten Befehle sind.
Einfügemodus
Modus zum Tippen von Text; mit i betreten, mit Esc verlassen.
Swap-Datei
Eine versteckte .datei.swp, die vim beim Bearbeiten anlegt; sie bleibt nach einem Absturz.
Puffer (Buffer)
Die Kopie der Datei im Speicher, die du bis zum Speichern bearbeitest.
EDITOR
Umgebungsvariable, die den Standardeditor für andere Werkzeuge benennt.

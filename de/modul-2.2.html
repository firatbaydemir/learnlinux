Startseite / Stufe 2

2.2 Pfade und Typen

Lies absolute und relative Pfade richtig, erkenne Dateitypen mit ls -l und lege symbolische Links (Verknüpfungen) an.

Was lernst du in diesem Modul?

  • Du unterscheidest absolute (beginnen mit /) und relative Pfade und nutzt die Kürzel ., .. und ~.
  • Du liest den Dateityp am ersten Buchstaben von ls -l (-, d, l, c, b).
  • Du legst mit ln -s einen symbolischen Link an und siehst, worauf er zeigt.

Absolute und relative Pfade

Eine Datei erreichst du unter Linux nur, indem du einen Pfad angibst. Ein absoluter Pfad beginnt am Wurzelverzeichnis (/) und zeigt von überall auf dieselbe Stelle: /etc/hostname.

Ein relativer Pfad beginnt nicht mit / und wird vom aktuellen Verzeichnis aus berechnet. In /etc genügt hostname; im Home-Verzeichnis gibt derselbe Name einen Fehler, weil dort keine solche Datei liegt.

Schau zuerst mit pwd, wo du bist. Die Bedeutung eines relativen Pfads hängt immer vom aktuellen Verzeichnis ab.

pwd

Wozu dient es?
Gibt den absoluten Pfad des aktuellen Verzeichnisses aus.
Wo wird es verwendet?
Bevor du relative Pfade benutzt.
Warum ist es wichtig?
Damit du nicht im falschen Verzeichnis arbeitest.
pwd

cd

Wozu dient es?
Wechselt das Arbeitsverzeichnis; nimmt absolute oder relative Pfade.
Wo wird es verwendet?
Beim Navigieren durch Verzeichnisse.
Warum ist es wichtig?
Danach reichen kurze relative Pfade.
cd /etc

cat

Wozu dient es?
Gibt den Inhalt einer Datei aus.
Wo wird es verwendet?
Beim Lesen kleiner Textdateien.
Warum ist es wichtig?
Zum Testen, ob der Pfad auf die richtige Datei zeigt.
cat /etc/hostname
💡 Tipp

Bist du unsicher, schreib den absoluten Pfad; er funktioniert von jedem Verzeichnis.

Spezielle Pfadkürzel: . .. ~

. ist das aktuelle Verzeichnis, .. das übergeordnete, ~ dein Home-Verzeichnis (/home/student). Du kannst sie in Pfaden kombinieren: ../config.txt, ~/Documents/report.txt.

Dateien, deren Name mit . beginnt, sind versteckt; ls zeigt sie nicht, ls -a schon. In jedem Verzeichnis werden auch die Einträge . und .. aufgelistet.

cd ..

Wozu dient es?
Wechselt ins übergeordnete Verzeichnis.
Wo wird es verwendet?
Beim Zurückgehen aus einem Unterverzeichnis.
Warum ist es wichtig?
Schnell nach oben, ohne den ganzen Pfad zu tippen.
cd ..

ls -a

Wozu dient es?
Listet alle Dateien inklusive versteckter.
Wo wird es verwendet?
Beim Suchen von Konfigurationsdateien.
Warum ist es wichtig?
Versteckte Dateien erscheinen sonst nicht.
ls -a ~

Dateitypen lesen

Unter Linux ist alles eine Datei: Text, Ordner, Geräte, Verknüpfungen. In der Ausgabe von ls -l verrät der erste Buchstabe der Zeile den Typ.

- normale Datei, d Verzeichnis, l symbolischer Link, c Zeichengerät (/dev/null), b Blockgerät (Festplatte), s Socket, p Named Pipe. Die folgenden neun Zeichen sind die Rechte (kommt in späteren Modulen).

ls -l

Wozu dient es?
Lange Liste: Typ, Rechte, Besitzer, Größe, Datum, Name.
Wo wird es verwendet?
Um den Typ von etwas zu erkennen.
Warum ist es wichtig?
Du weißt vor dem Löschen oder Lesen, was es ist.
ls -l /dev/null

stat

Wozu dient es?
Zeigt ausführliche Informationen und den Typ einer Datei.
Wo wird es verwendet?
Wenn du Typ oder Zeitstempel brauchst.
Warum ist es wichtig?
Nennt den Typ als Wort statt als Buchstabe.
stat /etc/hostname
💡 Tipp

Dateien unter /dev sind Hardware-Schnittstellen, keine echten Daten; lies sie nicht wahllos mit cat.

Symbolische Links

Ein symbolischer Link ist eine kleine Verknüpfungsdatei, die auf einen anderen Pfad zeigt. ls -l zeigt ihn mit l und als link -> ziel. Den Link zu lesen heißt, das Ziel zu lesen.

Wird das Ziel gelöscht oder verschoben, bleibt der Link kaputt zurück. Ein relatives Ziel (../docs/readme.txt) wird vom Verzeichnis des Links aus aufgelöst, nicht von deinem aktuellen.

ln -s

Wozu dient es?
Legt einen symbolischen Link an: ln -s ZIEL LINK.
Wo wird es verwendet?
Um einen langen Pfad unter kurzem Namen erreichbar zu machen.
Warum ist es wichtig?
Du behältst die Datei an einer Stelle, ohne zu kopieren.
ln -s ~/Documents/report.txt ~/link.txt

readlink

Wozu dient es?
Gibt das Ziel eines Links aus.
Wo wird es verwendet?
Um zu sehen, wohin ein Link führt.
Warum ist es wichtig?
Nur das Ziel statt der ganzen ls -l-Zeile.
readlink ~/link.txt
⚠️ Achtung

Reihenfolge bei ln -s: zuerst ZIEL, dann LINK. Vertauscht entsteht ein kaputter Link. ln -sf überschreibt eine vorhandene Datei; sei vorsichtig.

⛔ Gefahr

Zeigt ein Link auf ein Verzeichnis, kann rm -r link/ (mit / am Ende) den Inhalt des Zielverzeichnisses löschen. Zum Löschen des Links schreib rm link und prüfe vorher mit ls -l.

Mach es in deiner VM

Die eigentliche Praxis findet auf echtem Linux statt: Führe die Befehle in deiner eigenen virtuellen Maschine (VirtualBox, UTM oder WSL) aus und vergleiche die Ausgabe.

Probiere auf deiner VM absolute/relative Pfade, sieh dir die Dateitypen in /dev an und lege einen symbolischen Link an. Alles harmlose Befehle.

Absoluter und relativer Pfad

Probiere dieselbe Datei erst relativ, dann aus dem falschen Verzeichnis und füge die Ausgabe ein.

pwd
cd /etc
pwd
cat hostname
cd ~
cat hostname

Beispiel der erwarteten Ausgabe

/home/student
/etc
linux-lab
cat: hostname: No such file or directory
Meine Ausgabe sieht anders aus
  • Heißt dein Host nicht linux-lab, ist das in Ordnung; du siehst deinen eigenen Hostnamen.
  • Gibt cat hostname im Home keinen Fehler, hast du dort eine Datei namens hostname angelegt.

Dateitypen lesen

Sieh dir den Typ einer Datei, eines Verzeichnisses und eines Geräts an; achte auf die ersten Buchstaben.

ls -ld /etc /etc/hostname /dev/null

Beispiel der erwarteten Ausgabe

drwxr-xr-x. ... /etc
-rw-r--r--. ... /etc/hostname
crw-rw-rw-. ... /dev/null
Meine Ausgabe sieht anders aus
  • Manche Distributionen haben kein /etc/hostname; probiere dann /etc/os-release.
  • Ein . oder + hinter den Rechten ist die SELinux-/ACL-Markierung, unwichtig.

Symbolischen Link anlegen

Lege im Home eine Datei und einen Link darauf an und lies den Link.

mkdir -p ~/practice
echo hello linux > ~/practice/notes.txt
ln -s ~/practice/notes.txt ~/practice/link.txt
ls -l ~/practice
cat ~/practice/link.txt

Beispiel der erwarteten Ausgabe

lrwxrwxrwx. 1 student student ... link.txt -> /home/student/practice/notes.txt
hello linux
Meine Ausgabe sieht anders aus
  • Fehlt -> oder ist link.txt rot, hast du eventuell die Argumente vertauscht: erst ZIEL, dann LINK.
  • Bei File exists gibt es ~/practice/link.txt schon; lösche es vorher mit rm ~/practice/link.txt.

Typname mit stat

Lass dir mit stat den Typ als Wort anzeigen und lösche danach den Übungsordner.

stat -c '%F' /etc /etc/hostname /dev/null ~/practice/link.txt
# Aufräumen: erst mit ls -l ~/practice ansehen, dann
rm -r ~/practice

Beispiel der erwarteten Ausgabe

directory
regular file
character special file
symbolic link
Meine Ausgabe sieht anders aus
  • Auf macOS oder BSD-Tools gibt es -c nicht; das gehört auf eine Linux-VM.
  • Siehst du rm: cannot remove ... Is a directory, fehlt -r.

Selbsttest

Welcher ist ein absoluter Pfad?

Ein absoluter Pfad beginnt mit / am Wurzelverzeichnis und zeigt von überall auf dieselbe Datei.

Eine Zeile in ls -l beginnt mit l. Was ist das?

l steht für symbolic link; - ist eine normale Datei, d ein Verzeichnis.

Wo bist du nach cd .. aus /etc?

.. ist das übergeordnete Verzeichnis; aus /etc kommst du nach /.

Was passiert, wenn das Ziel eines symbolischen Links gelöscht wird?

Der Link speichert nur einen Pfad; verschwindet das Ziel, bleibt der Link, ist aber kaputt.

Zusammenfassung

  • Absolute Pfade beginnen mit /, relative werden vom aktuellen Verzeichnis aus berechnet.
  • . ist aktuell, .. übergeordnet, ~ dein Home-Verzeichnis.
  • Der erste Buchstabe von ls -l nennt den Typ: -, d, l, c, b.
  • ln -s ZIEL LINK legt einen symbolischen Link an; fällt das Ziel weg, ist der Link kaputt.

Fachbegriffe

absoluter Pfad
Vollständige Adresse ab dem Wurzelverzeichnis (/).
relativer Pfad
Adresse, die vom aktuellen Verzeichnis aus berechnet wird.
symbolischer Link
Verknüpfungsdatei, die auf einen anderen Pfad zeigt.
Gerätedatei
Spezielle Datei unter /dev, die Hardware darstellt.

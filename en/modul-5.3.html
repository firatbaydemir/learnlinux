5.3 Process Control

Stop processes safely with signals, target them by PID or name, and adjust CPU priority.

What will you learn in this module?

  • You explain that kill sends signals and distinguish SIGTERM from SIGKILL.
  • You verify a PID and command line before targeting a process.
  • You understand pkill, nice, renice, and their permission limits.

Signals: kill, SIGTERM, and SIGKILL

kill PID sends SIGTERM (15) by default. It gives the process a chance to shut down cleanly and save data. If it does not respond, SIGKILL (9) is the last resort; a process cannot catch or ignore it.

kill sends a signal; it does not always mean “kill.” Verify the PID and command with ps or pgrep first. In particular, kill -9 and targeting multiple processes can cause data loss.

kill -TERM PID

What is it for?
Sends SIGTERM to the specified PID.
Where is it used?
When closing an application or stopping it cleanly.
Why does it matter?
It gives the process a chance to clean up and save data.
kill -TERM 2210

kill -KILL PID

What is it for?
Immediately terminates the process through the kernel.
Where is it used?
Only as a last resort when SIGTERM does not work.
Why does it matter?
The process cannot catch it; unsaved work may be lost.
kill -KILL 2210
💡 Tip

Name the signal explicitly: kill -TERM PID. Then check with ps -p PID to see whether the process exited.

⚠️ Warning

Do not signal a process on a production server or under a process manager without verifying its PID. Never target PID 1 or an unknown system process.

Find and target processes by name

ps gives you a process snapshot; pgrep searches for PIDs by name. pkill sends signals to matching processes. Check pgrep -a first because a name match may affect more processes than expected.

pkill -TERM -x worker targets only exact process-name matches. Use -f to match the full command line only when needed; it carries a higher risk of matching too broadly.

pgrep -a -x worker

What is it for?
Lists the PID and command for processes named exactly worker.
Where is it used?
Before sending a signal to verify the target.
Why does it matter?
It reduces the chance of targeting the wrong PID or a similarly named process.
pgrep -a -x sleep

pkill -TERM -x worker

What is it for?
Sends SIGTERM to processes named exactly worker.
Where is it used?
When stopping a verified group of processes.
Why does it matter?
It requests a graceful shutdown without entering each PID.
pkill -TERM -x sleep
💡 Tip

Run the same match with pgrep -a before using pkill so you can review every target.

⛔ Danger

pkill -f matches any part of a command line. Do not use it with a short or generic pattern.

CPU priority: nice and renice

The nice range is -20 to 19: a higher value means a lower CPU priority. Regular users can lower the priority of their own processes; raising it usually requires administrator privileges.

nice starts a new command with a chosen value; renice changes the value of a running process. This affects CPU scheduling, but does not limit memory or CPU usage.

nice -n 10 command

What is it for?
Starts a new command with nice value 10.
Where is it used?
For background work such as backups.
Why does it matter?
It lets interactive work get CPU time more easily.
nice -n 10 sleep 60

renice 10 -p PID

What is it for?
Sets a running process's nice value to 10.
Where is it used?
When lowering the priority of a running background task.
Why does it matter?
It changes CPU priority without restarting the process.
renice 10 -p 2210
💡 Tip

Nice value and process state are different; inspect them separately with ps -o pid,ni,stat,comm -p PID.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Run these commands only in your own test VM. Do not signal an arbitrary PID; verify the process name and PID.

Start a controlled process

Start a short-lived test process, note its PID, and verify it with ps. Stop it when done.

sleep 300 &
echo $!
ps -o pid,ni,comm -p $!

Expected output example

The PID and sleep command are visible.
My output looks different
  • The shell may also print a job number; the PID is on the echo $! line.
  • The PID will differ; do not expect a fixed number.

Try SIGTERM first

Use the real PID of the test process you just started. Send SIGTERM, wait briefly, and verify that it exited.

kill -TERM PID
sleep 1
ps -p PID || echo 'process stopped'

Expected output example

process stopped
My output looks different
  • Replace PID with the number from v01; do not run the literal word PID.
  • If the process remains, verify the PID; do not signal another process.

Inspect the nice value

Start a test process with lower priority, read its NI value in ps, and then stop your process.

nice -n 10 sleep 60 &
ps -o pid,ni,comm -p $!
kill -TERM $!

Expected output example

The NI column shows 10 and the command column shows sleep.
My output looks different
  • Column headings may be aligned differently by ps; the NI value should be 10.
  • Stop only the PID started by your shell.

Self-test

Which signal does kill PID send by default?

SIGTERM is the default signal; it asks the process to shut down cleanly.

When should SIGKILL be used?

SIGKILL cannot be caught and leaves no time for cleanup, so use it only as a last resort.

What happens when the nice value rises from 0 to 10?

A higher nice value means lower priority in CPU scheduling.

What should you do before targeting a process with pkill?

Reviewing the matches confirms the target and reveals possible side effects.

Summary

  • kill sends SIGTERM by default; SIGKILL is a last resort.
  • Verify the PID and command with ps or pgrep -a before sending a signal.
  • nice sets priority at launch and renice changes it for a running process; higher nice means lower priority.

Key terms

signal
A control notification the kernel sends to a process.
PID
The unique process identifier of a running process.
nice
A value that affects a process's relative priority in CPU scheduling.

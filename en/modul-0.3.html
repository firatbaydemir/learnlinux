0.3 The terminal and first steps

Learn to read the prompt, type your first commands and find help when you get stuck.

What will you learn in this module?

  • You can read the user, machine and directory shown in the prompt.
  • You run safe first commands such as whoami, hostname, pwd and ls.
  • You find help yourself with man, --help and error messages.

Terminal and prompt

The terminal is the window where you give the computer text commands. The program running inside it is the shell; the most common one is bash. The shell reads your line, runs it and prints the result.

The prompt at the start of each line tells you three things: who you are, which machine you are on and which directory you are in. Example: student@linux-lab:~$ — user student, machine linux-lab, ~ means the home directory. A trailing $ marks a normal user, # marks the administrator (root).

💡 Tip

Nothing runs until you press Enter. Use Backspace to fix typos.

First commands: who am I, where am I?

Before touching a system you must know who you are and where you are. The commands below only read information and change nothing. Click a box to paste the command into the terminal.

whoami

What is it for?
Prints the user you are working as.
Where is it used?
After login, and before and after using sudo.
Why does it matter?
Prevents actions with the wrong user.
whoami

hostname

What is it for?
Prints the machine's name.
Where is it used?
When you connect to several servers.
Why does it matter?
Makes sure you are on the right machine.
hostname

pwd

What is it for?
Prints the full path of the current directory.
Where is it used?
Whenever you feel lost.
Why does it matter?
Knowing your location prevents mistakes in file operations.
pwd

ls

What is it for?
Lists files and folders in the current directory. -l adds details.
Where is it used?
Everywhere — the most used command.
Why does it matter?
Look around before you act.
ls -l

echo

What is it for?
Prints the text you give it and expands variables like $USER.
Where is it used?
In scripts and for quick experiments.
Why does it matter?
The simplest way to see a variable's value.
echo $USER

Getting help and reading errors

Every Linux command has a manual: man command shows it in full, command --help shows a short summary. If you type an unknown command the shell says command not found — that is information, not a disaster: you probably made a typo.

The shell also saves time: Tab completes commands and file names, ↑ / ↓ recalls earlier commands, history lists them all with numbers, clear wipes the screen.

man

What is it for?
Shows a command's manual page.
Where is it used?
When you want to look up a command's options.
Why does it matter?
You get the right information straight from your own system.
man ls

--help

What is it for?
Prints a short usage summary.
Where is it used?
For a quick refresher.
Why does it matter?
Shorter than man and often enough.
ls --help

history

What is it for?
Lists earlier commands with numbers.
Where is it used?
To find an old command again.
Why does it matter?
You don't have to retype everything.
history
💡 Tip

Pressing Tab twice lists all possible completions. Try typing whoa and press Tab.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Do the tasks below on your own Linux VM (Rocky/Alma or Ubuntu). If you do not have a VM yet, see module 0.2 first.

Find your kernel version

Open a terminal in your VM and print the version of the running kernel. Paste the output below.

uname -r

Expected output example

5.14.0-427.13.1.el9_4.x86_64
My output looks different
  • Your version number may differ; what matters is a dotted version such as 5.14.0.
  • If you see command not found, check spelling (lower case, spaces).

Identify your distribution

The file /etc/os-release tells you the distribution name and version.

cat /etc/os-release

Expected output example

NAME="Rocky Linux"
VERSION="9.4 (Blue Onyx)"
ID="rocky"
My output looks different
  • On Ubuntu you will see NAME="Ubuntu"; that is normal.
  • On No such file make sure you are on a real distribution, not a bare container.

Your first file

Write and read a file in your home directory. The output must contain Hello; then press "Done".

cd ~ && echo Hello > first.txt && cat first.txt

Expected output example

Hello
My output looks different
  • If nothing shows, check with ls -l first.txt that the file was created.

Ticket

  1. TicketHard

    TICKET #1001 — Support needs system info: in your home directory write the kernel version (uname -r) and then the host name (hostname) into info.txt. The file must have 2 lines.

    Hint

    Use > for the first and >> (append) for the second; otherwise the first line is lost.

    Solution
    cd ~
uname -r > info.txt
hostname >> info.txt

Self-test

Your prompt ends with #. What does that mean?

$ means a normal user, # means root. A wrong command as root can do great damage — be careful.

How do you open a command's manual?

man command opens the full manual; command --help gives a short summary.

What does command not found usually mean?

Check the spelling first; then check whether the command is installed.

Which key completes a partly typed command or file name?

Tab completes; pressed twice it lists the options.

Summary

  • The prompt shows user, machine and directory; $ is normal, # is root.
  • whoami, hostname, pwd, ls are safe exploration commands.
  • For help use man command and command --help; error messages are clues.
  • Tab, ↑/↓ and history save time.

Key terms

terminal
The window where you type commands.
shell
The program that runs your commands, e.g. bash.
prompt
The user@machine:directory info at the start of each line.
home directory
The user's own folder, written as ~.

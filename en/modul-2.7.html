2.7 Editors

Edit text files in the terminal: nano for a quick start, vi/vim when it has to be everywhere and fast.

What will you learn in this module?

  • You open, edit, save and close files with nano.
  • You know vim's modes and can always get out of vim (:q!, :wq).
  • You use basic vim commands: insert, delete a line, undo, search.
  • You edit config files safely: backup first, sudo only when needed.

nano: the easy editor

nano is beginner friendly: you start typing right away and the shortcuts are listed at the bottom of the screen. ^ means the Ctrl key, so ^X is Ctrl+X.

If the file does not exist, nano file opens an empty buffer and creates the file when you save. On Ubuntu nano is usually preinstalled; on Rocky/Alma install it with sudo dnf install nano if needed.

nano file

What is it for?
Opens a file in the nano editor (creates it on save if missing).
Where is it used?
For quick edits of text and config files.
Why does it matter?
Simple, with visible help at the bottom.
nano todo.txt

Ctrl+O

What is it for?
Writes out (saves) the file; confirm the name with ENTER.
Where is it used?
Inside nano, whenever you want to save.
Why does it matter?
Saves your work without leaving the editor.
nano todo.txt

Ctrl+X

What is it for?
Exits nano; asks to save if there are unsaved changes (Y/N).
Where is it used?
Inside nano, when you are done.
Why does it matter?
The way out: Y saves, N discards.
nano todo.txt

Ctrl+K / Ctrl+U

What is it for?
Cuts the current line / pastes it back.
Where is it used?
To delete, move or duplicate lines.
Why does it matter?
Fast line editing without a mouse.
nano todo.txt
💡 Tip

More nano keys: Ctrl+W search, Ctrl+G help, Alt+U undo, Ctrl+_ go to line number.

vi / vim: modes

vi is installed on practically every Linux system, vim is its improved version (on some minimal systems vi is simply vim). Learn the basics once and you can fix a server in any situation.

The key idea: vim has modes. In Normal mode (default at start) keys are commands — typing dd deletes a line instead of writing text. With i you enter Insert mode and type normally; Esc takes you back. With : you enter command-line mode for :w, :q, :wq, :q!.

Beginner mistake number one: typing text while in Normal mode. If strange things happen, press Esc once or twice, then continue.

vim file

What is it for?
Opens a file in vim (starts in Normal mode).
Where is it used?
For config files, scripts and on servers without nano.
Why does it matter?
Available everywhere and very fast once learned.
vim todo.txt

i / Esc

What is it for?
i enters Insert mode, Esc returns to Normal mode.
Where is it used?
Whenever you switch between typing and commanding.
Why does it matter?
Without i you cannot type text; without Esc you cannot give commands.
vim todo.txt

:wq

What is it for?
Writes the file and quits (also ZZ or :x).
Where is it used?
From Normal mode after typing :.
Why does it matter?
Saves and leaves in one step.
vim todo.txt
⛔ Danger

Stuck in vim? Press Esc, then type :q! and ENTER to quit WITHOUT saving, or :wq to save and quit. Ctrl+C or Ctrl+X do not exit vim.

Essential vim commands

These Normal-mode commands cover most daily work. Arrow keys work, but h j k l (left, down, up, right) keep your hands on the home row.

Many commands take a number: 3dd deletes three lines, 5j moves five lines down. gg jumps to the top, G to the end, :42 to line 42. Use :set number to show line numbers.

dd

What is it for?
Deletes (cuts) the current line; p pastes it below.
Where is it used?
In Normal mode.
Why does it matter?
Remove, move or duplicate lines (yy copies).
vim todo.txt

u

What is it for?
Undoes the last change; Ctrl+R redoes it.
Where is it used?
In Normal mode.
Why does it matter?
Fixes accidental edits.
vim todo.txt

/text

What is it for?
Searches forward for text; n jumps to the next match.
Where is it used?
In Normal mode.
Why does it matter?
Find settings in long config files.
vim server.log

:q!

What is it for?
Quits and discards all unsaved changes.
Where is it used?
From Normal mode when you made a mess or just looked.
Why does it matter?
The emergency exit; plain :q refuses if there are changes.
vim todo.txt
💡 Tip

Run vimtutor once (about 30 minutes) — the best interactive vim course, installed with vim.

Editing safely

System config files live in /etc and belong to root. As a normal user you can read them but not save changes: use sudo nano /etc/file only when you must. Make a backup first so you can restore after a typo.

Non-interactive alternatives need no editor: echo "text" >> file appends a line, echo "text" > file overwrites the whole file. With cp file file.bak you create a backup in one second.

If vim crashed or the terminal closed, a leftover swap file (.file.swp) may remain and vim warns on the next start. If nobody else is editing the file, you can delete the swap file.

cp file file.bak

What is it for?
Creates a backup copy before editing.
Where is it used?
Before every change to an important file.
Why does it matter?
You can restore the old state with cp file.bak file.
cp app.conf app.conf.bak

sudoedit

What is it for?
Edits a root-owned file with your own editor via a temporary copy.
Where is it used?
For files in /etc.
Why does it matter?
Safer than running the whole editor as root.
sudoedit /etc/hosts

export EDITOR

What is it for?
Sets the default editor used by tools such as sudoedit and crontab -e.
Where is it used?
In your shell or in ~/.bashrc.
Why does it matter?
Tools then open nano instead of an editor you do not know.
export EDITOR=nano

cat file

What is it for?
Shows the file content without opening an editor.
Where is it used?
To verify the result of an edit.
Why does it matter?
Quick check that the file contains what you expect.
cat todo.txt
💡 Tip

> overwrites, >> appends. One missing > can empty a file — check with cat afterwards.

⚠️ Warning

Before editing a file under /etc, make a backup (sudo cp file file.bak). A broken /etc/fstab or /etc/ssh/sshd_config can make the machine unbootable or unreachable.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

On your VM you now use the real editors. Do all steps in your home directory with test files; take a snapshot before touching files in /etc.

First file with nano

Open nano, type the text, save with Ctrl+O and ENTER, exit with Ctrl+X. Then show the file.

nano nano_test.txt
# type: hello nano   -> Ctrl+O, ENTER, Ctrl+X
cat nano_test.txt

Expected output example

hello nano
My output looks different
  • command not found: install nano with sudo apt install nano (Ubuntu) or sudo dnf install nano (Rocky/Alma).
  • If nano asks 'Save modified buffer?' on exit, press Y and ENTER.

Cut and paste lines in nano

In nano write line one and line two, save and exit. Reopen, cut the first line with Ctrl+K, paste it twice with Ctrl+U, save. Paste the result.

nano lines.txt
# type two lines, save, exit
nano lines.txt
# Ctrl+K once, Ctrl+U twice, Ctrl+O, ENTER, Ctrl+X
cat -n lines.txt

Expected output example

     1	line two
     2	line one
     3	line one
My output looks different
  • If the order differs, it depends on where the cursor was when pasting; line one and line two must both appear.
  • No numbering shown? You forgot -n in cat -n.

First file with vim

Open vim, press i, type the text, then Esc and :wq ENTER. Show the file.

vim vim_test.txt
# i  -> type: hello vim  -> Esc  -> :wq  -> ENTER
cat vim_test.txt

Expected output example

hello vim
My output looks different
  • Typed text is missing or odd? You did not press i first. Press Esc, :q!, and start again.
  • vim: command not found: use vi vim_test.txt or install vim (sudo apt install vim / sudo dnf install vim-enhanced).

Quit without saving

Write keep into a file, then open it in vim, add a line lose and leave with :q!. The file must still contain only keep.

echo keep > discard.txt
vim discard.txt
# i -> type: lose -> Esc -> :q! -> ENTER
cat discard.txt

Expected output example

keep
My output looks different
  • If lose is in the file, you used :wq instead of :q!.
  • If vim refuses to quit with :q, that is the protection for unsaved changes: use :q!.

Delete a line and undo

Create a 20-line file, delete line 5 with 5G then dd, press u to undo, then dd again and save. Count the lines.

seq 1 20 > numbers.txt
vim numbers.txt
# 5G -> dd -> u -> dd -> :wq
wc -l numbers.txt

Expected output example

19 numbers.txt
My output looks different
  • Result 20: the final dd or the save did not happen; result 18: you deleted twice without u.
  • seq is missing? Use for i in $(seq 1 20); do echo $i; done > numbers.txt or install coreutils.

Set the default editor

Set nano as default editor for this session and check the variable.

export EDITOR=nano
echo $EDITOR

Expected output example

nano
My output looks different
  • To make it permanent add export EDITOR=nano to ~/.bashrc; it takes effect in a new shell.

Backup before editing /etc

Back up /etc/hosts with sudo, check the backup, and open the original with sudoedit or sudo nano. Look, change nothing, exit without saving.

sudo cp /etc/hosts /etc/hosts.bak
ls -l /etc/hosts.bak
sudoedit /etc/hosts
# look around, then Ctrl+X (nano) or :q! (vim)

Expected output example

-rw-r--r--. 1 root root 158 ... /etc/hosts.bak
My output looks different
  • sudoedit complains about the editor? Run export EDITOR=nano first, or use sudo nano /etc/hosts.
  • If sudo asks for a password, enter your own (nothing is displayed while typing).

Self-test

You are in vim and want to leave WITHOUT saving. What do you type?

:q! quits and discards changes; :wq would save them. Ctrl+X is nano's exit key, not vim's.

In vim you type dd right after starting and a line disappears. Why?

vim starts in Normal mode where keys are commands. dd deletes the current line; u undoes it.

What does Ctrl+X do in nano?

Ctrl+X exits; with unsaved changes nano asks Y/N. Ctrl+K cuts, Ctrl+G is help, Ctrl+W searches.

What should you do before editing /etc/ssh/sshd_config?

A backup (sudo cp file file.bak) lets you restore quickly after an error.

Summary

  • nano file to edit, Ctrl+O saves, Ctrl+X exits.
  • vim has modes: Normal (commands), Insert (i, text), command line (:). Esc returns to Normal.
  • Exit vim: :wq (save) or :q! (discard). Basics: dd, u, /text, gg/G.
  • Back up system files before editing; use sudo only when needed. > overwrites, >> appends.

Key terms

Normal mode
vim's default mode in which keys are commands.
Insert mode
vim mode for typing text, entered with i, left with Esc.
swap file
A hidden .file.swp that vim creates while editing; it remains after a crash.
buffer
The in-memory copy of the file you edit until you save.
EDITOR
Environment variable naming the default editor for other tools.

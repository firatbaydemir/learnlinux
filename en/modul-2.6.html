2.6 Reading files: cat, less, head, tail, wc

There is a right tool for every file: cat for small files, less for large ones; head for the start, tail for the end and live logs, wc for counting.

What will you learn in this module?

  • You choose the right tool by file size (cat, less, head, tail).
  • You read the start and end of a file with head and tail and the -n option.
  • You count lines, words and bytes with wc and do a small log analysis with grep -c and |.

Choosing the right tool

On Linux, settings, logs and notes are mostly plain text files. There is no single command to read them; you choose by the size and purpose of the file.

Small file: cat. Large file: less. Start: head. End: tail. Follow live: tail -f. Estimate size: wc. Checking the size with wc -l first is a good habit.

💡 Tip

When in doubt, run wc -l notes.txt for the line count first, then decide.

Reading everything: cat and less

cat prints the whole file at once; fast and handy for short files. cat -n numbers the lines.

less opens the file page by page and does not flood the terminal. Inside: Space one page down, b one page up, /word searches, q quits. In the simulator less behaves like cat; try the real effect on your VM.

cat

What is it for?
Prints the whole file.
Where is it used?
Short files (notes, /etc/hostname).
Why does it matter?
The fastest way, but it cannot be paused.
cat notes.txt

cat -n

What is it for?
Prints the file with line numbers.
Where is it used?
When you talk about a line (error on line 7).
Why does it matter?
Line numbers make discussion and debugging easier.
cat -n notes.txt

less

What is it for?
Opens the file page by page; Space, b, /search, q.
Where is it used?
Long texts and logs.
Why does it matter?
Does not fill the terminal, and you can search inside.
less /var/log/messages
⚠️ Warning

If you open a huge file with cat, the screen scrolls for minutes. Press Ctrl+C to stop it and use less next time.

⛔ Danger

Never print program (binary) files with cat: the terminal becomes garbled. Type reset to recover. If you are unsure it is text, look with less.

Start and end: head and tail

head shows the first 10 lines, tail the last 10. Change the number with -n: head -n 3 notes.txt.

New log entries are added at the end, so tail shows the newest events. tail -f follows the file and prints new lines instantly; quit with Ctrl+C. With several files each one gets a header ==> name <==.

head -n

What is it for?
Shows the first n lines.
Where is it used?
For header lines or the top of a configuration.
Why does it matter?
A quick look into a big file.
head -n 3 logs/app.log

tail -n

What is it for?
Shows the last n lines.
Where is it used?
For the newest log entries.
Why does it matter?
Errors are usually at the end.
tail -n 4 logs/app.log

tail -f

What is it for?
Follows the file and prints new lines live.
Where is it used?
Watching the log of a running service.
Why does it matter?
You catch the problem the moment it happens.
tail -f logs/app.log
💡 Tip

tail -f never ends on its own; it waits even if no new lines arrive. Quit with Ctrl+C.

Counting: wc

wc (word count) gives lines, words and bytes. -l counts only lines, -w only words, -c only bytes. Without an option all three appear side by side: 3 6 33 notes.txt.

Checking wc -l before opening a file prevents cat accidents.

wc -l

What is it for?
Prints the line count.
Where is it used?
To learn the length of a log or list.
Why does it matter?
A quick idea of the file size.
wc -l logs/app.log

wc -w

What is it for?
Prints the word count.
Where is it used?
Text length, one-word files.
Why does it matter?
Measures the size of the content.
wc -w notes.txt

wc

What is it for?
Prints lines, words and bytes together.
Where is it used?
When you need an overview.
Why does it matter?
Three measures with one command.
wc Documents/report.txt

Combining: pipe and redirection

| (pipe) feeds the output of one command into the next: head -n 6 app.log | tail -n 3 gives lines 4-6. > writes the output to a file instead of the screen.

grep ERROR app.log shows only lines containing ERROR; grep -c counts them. Details come in later modules; here we combine it with the reading tools.

head | tail

What is it for?
Selects the middle lines of a file.
Where is it used?
When you need a specific line range.
Why does it matter?
Chaining both tools gives you a range.
head -n 6 logs/app.log | tail -n 3

grep -c

What is it for?
Counts lines that contain the pattern.
Where is it used?
When asking how many errors there are.
Why does it matter?
Saves you counting by hand.
grep -c ERROR logs/app.log

>

What is it for?
Writes the output to a file.
Where is it used?
When keeping a result or attaching it to a ticket.
Why does it matter?
The output is preserved.
grep ERROR logs/app.log > errors.txt
⚠️ Warning

> erases the contents of the target file if it exists. Think twice before naming an existing file; use >> to append.

⛔ Danger

If you read and write the same file as in cat notes.txt > notes.txt, the file is emptied and the data is lost. Always redirect to a different file.

Log paths by distribution

The main system log is /var/log/syslog on Debian/Ubuntu and /var/log/messages on RHEL/Rocky/Alma. A missing file gives No such file or directory; the problem is the path, not the command.

Many logs can only be read with sudo (for example sudo less /var/log/secure). Look first with ls /var/log.

💡 Tip

If the file is missing, find the real name with ls /var/log. As a fallback sudo journalctl -n 20 shows the latest entries.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

On your VM you only read; nothing is deleted. Reading system files is safe, but be careful not to overwrite files with redirection.

Read a small file with cat

Print the distribution information and paste the output.

cat /etc/os-release

Expected output example

NAME="Ubuntu"
VERSION="24.04 LTS (Noble Numbat)"
...
My output looks different
  • On Rocky/Alma you see NAME="Rocky Linux"; the fields may differ.
  • If you get No such file you may be in WSL or a container; try cat /etc/hostname.

Read the start and end

Show the first 5 and last 3 lines of the user file.

head -n 5 /etc/passwd
tail -n 3 /etc/passwd

Expected output example

root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
...
My output looks different
  • The second line is daemon on Ubuntu and may be bin on RHEL.
  • The first line must always start with root:x:0:0.

Count lines

Find the line count of /etc/passwd and the three measures of /etc/hostname.

wc -l /etc/passwd
wc /etc/hostname

Expected output example

32 /etc/passwd
 1  1 10 /etc/hostname
My output looks different
  • Your line count depends on the installation; what matters is that a number and the file name appear.
  • In wc /etc/hostname the first number is lines, the second words, the third bytes.

Browse with less

Open the main log: /var/log/syslog on Ubuntu, /var/log/messages on RHEL/Rocky/Alma. Try Space, b, /error and q. When done press "Done".

# Ubuntu
sudo less /var/log/syslog
# Rocky / Alma
sudo less /var/log/messages
My output looks different
  • If the file is missing, look for its name with ls /var/log; some systems only have sudo journalctl -n 50.
  • If you cannot leave less, press q.

Follow live (tail -f)

Open two terminals. In the first follow the file; in the second append a line. When you see the new line, quit the first with Ctrl+C and paste the output.

# Terminal 1
touch ~/live.log
tail -f ~/live.log

# Terminal 2
echo "new entry" >> ~/live.log

Expected output example

new entry
My output looks different
  • Terminal 1 stays empty and waits; that is normal until a line is appended.
  • With only one terminal do not pause tail -f with Ctrl+Z; open a second tab or window.

Self-test

Which tool is suitable for safely viewing a 5 GB log file?

less shows only what fits the screen and lets you search; cat streams the whole file across the screen.

What does -f do in tail -f?

-f means 'follow'; quit with Ctrl+C.

Which command gives only the number of lines in a file?

wc -l counts lines; -w counts words.

What does head -n 3 notes.txt show?

head shows the start; -n 3 means the first three lines. For the end use tail.

Summary

  • Small file: cat; large file: less (Space, b, /search, q).
  • head -n shows the start, tail -n the end; tail -f follows live (quit with Ctrl+C).
  • wc -l, wc -w, wc count lines, words and bytes.
  • | chains tools, > writes the result to a file; > overwrites existing files.
  • The log path depends on the distribution: syslog or messages.

Key terms

log
A file where a program or system writes events in order.
pager
A program that shows text page by page, such as less.
pipe
The | symbol; makes the output of one command the input of the next.
redirection
Writing output to a file instead of the screen; > or >>.
follow
Watching the end of a file live with tail -f.

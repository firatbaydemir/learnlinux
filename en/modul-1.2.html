1.2 Identity and System — whoami, id, uname

Before you touch a system, answer two questions: Who am I? Which machine am I on? This module teaches you how, using safe read-only commands.

What will you learn in this module?

  • You read your user identity, UID/GID values and group memberships with whoami, id and groups.
  • You find the machine name, kernel version and architecture with hostname and uname.
  • You identify the distribution and its version with /etc/os-release.
  • You see the time and how long the system has been running with date and uptime.
  • You read disk and memory usage with df -h and free -h.
  • You use environment variables with env and $USER.

Who am I? whoami, id, groups

Before you run a command you should know which account you are using: a normal user or an administrator? A command run with the wrong account either fails or does more damage than intended because of excess privileges.

whoami prints only the user name. id says more: the numeric user ID UID, the primary group ID GID and all groups you belong to. Linux permissions look at these numbers, not at names. UID 0 is always root (the administrator); normal users usually start at 1000.

groups lists the same groups, names only. In this course the user student belongs to the groups student, wheel and devs. wheel is the administrator group that allows sudo on the RHEL family (on Ubuntu this group is called sudo).

whoami

What is it for?
Prints the current user name.
Where is it used?
After logging in, after using sudo, or inside a script.
Why does it matter?
Prevents actions with the wrong user.
whoami

id

What is it for?
Shows UID, GID and all groups.
Where is it used?
When investigating Permission denied errors.
Why does it matter?
Permissions are checked by numbers and group membership.
id

groups

What is it for?
Lists the names of the groups you belong to.
Where is it used?
To check whether you can reach a file through a group.
Why does it matter?
Shorter and easier to read than id.
groups

id -u

What is it for?
Prints only the UID number.
Where is it used?
In scripts, to test whether you are root (0 = root).
Why does it matter?
A single number is easy to compare in a script.
id -u
💡 Tip

whoami gives a name, id gives the numbers the system really uses. When in doubt, run id.

Which machine? hostname and uname

When you have several servers or VMs, their command lines all look alike. hostname tells you the machine's name on the network; it is the cheapest way to confirm you are on the right machine before a destructive command.

uname reports on the kernel. uname -r prints the kernel release, uname -m the architecture (x86_64 = 64-bit Intel/AMD, aarch64 = ARM) and uname -a everything in one line. You are asked for these values when opening a support ticket or downloading software.

hostname

What is it for?
Prints the machine's name.
Where is it used?
To tell servers apart, when writing a ticket.
Why does it matter?
Prevents working on the wrong machine.
hostname

uname -r

What is it for?
Prints the running kernel version.
Where is it used?
For bug reports or driver compatibility checks.
Why does it matter?
The kernel version decides which features exist.
uname -r

uname -m

What is it for?
Prints the machine architecture.
Where is it used?
Before downloading a package or ISO.
Why does it matter?
Packages are built per architecture.
uname -m

uname -a

What is it for?
Prints all system information on one line.
Where is it used?
To paste into a support request.
Why does it matter?
Name, kernel and architecture at once.
uname -a

hostname -I

What is it for?
Prints the machine's IP address(es).
Where is it used?
When you want to connect to your VM via SSH.
Why does it matter?
The shortest way to find the address.
hostname -I
💡 Tip

The student@linux-lab part of the prompt is user@machine; whoami and hostname give the same information.

Which distribution? /etc/os-release

Even with the same kernel, distributions differ. The distribution name and version are stored as plain text in /etc/os-release, in the same format on Ubuntu, Rocky, Alma and others. You read it with cat; you do not change it.

NAME and VERSION give the readable name, PRETTY_NAME a one-line summary, and ID_LIKE the family (debian or rhel fedora). The family tells you which package manager to use: apt or dnf.

cat /etc/os-release

What is it for?
Shows the complete distribution information.
Where is it used?
As the first step on a new system.
Why does it matter?
Decides which commands and packages apply.
cat /etc/os-release

grep PRETTY_NAME /etc/os-release

What is it for?
Shows only the readable distribution name.
Where is it used?
To put a single line into a ticket.
Why does it matter?
Filters the one line you need out of a longer file.
grep PRETTY_NAME /etc/os-release

grep ID_LIKE /etc/os-release

What is it for?
Shows the family the distribution belongs to.
Where is it used?
When you are unsure whether to use apt or dnf.
Why does it matter?
The family determines the package manager.
grep ID_LIKE /etc/os-release
💡 Tip

WSL has the same file; it shows the Linux distribution inside, not Windows.

Time and uptime: date, uptime

date prints the system time and time zone. You need it when reading logs and when putting dates in backup file names. You can change the format with a pattern starting with +: date +%F → 2026-11-12.

uptime gives three things on one line: the time, how long the system has been running and the load average for the last 1, 5 and 15 minutes. If the load is far above the number of CPU cores, the system is slow. You also notice unexpected reboots here.

date

What is it for?
Prints the current date and time.
Where is it used?
When matching log entries to times.
Why does it matter?
A wrong clock is a common cause of certificate and log problems.
date

date +%F

What is it for?
Prints the date as YYYY-MM-DD.
Where is it used?
When adding a date to file names (backup-2026-11-12).
Why does it matter?
A consistent format that sorts alphabetically.
date +%F

uptime

What is it for?
Shows uptime and load average.
Where is it used?
The first place to look when the system is slow.
Why does it matter?
Quickly shows load and the last reboot.
uptime

uptime -p

What is it for?
Prints uptime in readable form (up 2 days, 3 hours).
Where is it used?
To report the duration briefly.
Why does it matter?
Gives only the duration, without load figures.
uptime -p
💡 Tip

Compare the load average with the core count: on 4 cores, 4.0 means fully busy.

Disk and memory: df -h, free -h

df (disk free) shows how full the mounted file systems are. -h (human-readable) uses units like G and M instead of bytes. If the Use% column goes above 90%, take care: a full disk makes services crash.

free shows memory (RAM) and swap. The important column is available: the memory that can be given to new programs. A small free value is normal, because Linux uses spare memory as cache (buff/cache).

Both only read; neither changes anything.

df -h

What is it for?
Shows size and usage of all file systems.
Where is it used?
On a No space left on device error.
Why does it matter?
Finds out which partition is full.
df -h

df -h /

What is it for?
Shows only the root file system.
Where is it used?
When checking a single partition.
Why does it matter?
Keeps the output short.
df -h /

free -h

What is it for?
Shows memory and swap usage in readable units.
Where is it used?
When the system is slow.
Why does it matter?
The available column shows the memory that is really free.
free -h
💡 Tip

Do not worry about a small value in the free column of free output; look at available.

⚠️ Warning

df measures file systems, du measures folders; do not mix them up. You find a full disk with df -h and look for the cause with tools you will meet in later modules.

Environment variables: env and $USER

The shell stores information in environment variables. $USER holds the user name, $HOME the home directory, $SHELL the shell and $HOSTNAME the machine name. You use a value by putting $ in front: echo $USER.

env lists all variables as NAME=value. To pick a single one from the long output, combine it with grep using | (pipe): env | grep USER.

Variables are handy in scripts: echo "$USER@$(hostname)" combines the user and the machine. The output of the command inside $(...) is inserted in its place.

env

What is it for?
Lists all environment variables.
Where is it used?
When investigating where a setting comes from.
Why does it matter?
Shows the values you are running with.
env

echo $USER

What is it for?
Prints the value of the user name variable.
Where is it used?
In scripts and file names.
Why does it matter?
You do not have to type the user name by hand.
echo $USER

echo $HOME

What is it for?
Prints the path of the home directory.
Where is it used?
To write portable paths.
Why does it matter?
Works for every user instead of a fixed /home/student.
echo $HOME

env | grep USER

What is it for?
Filters the variables whose name contains USER.
Where is it used?
To find one variable in a long list.
Why does it matter?
A pipe and grep narrow down the output.
env | grep USER

echo "$USER@$(hostname)"

What is it for?
Combines user and machine name.
Where is it used?
When building a report line or log message.
Why does it matter?
Shows how a variable and command output are combined.
echo "$USER@$(hostname)"

printenv USER

What is it for?
Prints the value of a single variable.
Where is it used?
In a script when you need only the value.
Why does it matter?
No grep needed, the output is just the value.
printenv USER
💡 Tip

Variable names are case-sensitive: $USER works, $user is empty.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

All commands in this section are read-only; you can run them safely on your VM. Output may differ by distribution; what matters is that you recognise the structure.

Find your identity

Show your user name, UID/GID values and groups; paste the id output.

whoami
id
groups

Expected output example

student
uid=1000(student) gid=1000(student) groups=1000(student),10(wheel)
student wheel
My output looks different
  • On Ubuntu the administrator group is called sudo, not wheel; in the id output you see 27(sudo).
  • Your user name may not be student; that is fine, just see your own name.

Machine and kernel

Show the machine name and the full kernel information; paste the uname -a output.

hostname
uname -r
uname -m
uname -a

Expected output example

linux-lab
5.14.0-427.el9.x86_64
x86_64
Linux linux-lab 5.14.0-427.el9.x86_64 #1 SMP PREEMPT_DYNAMIC ... x86_64 GNU/Linux
My output looks different
  • Your kernel version may differ (6.8... on Ubuntu 24.04); what matters is that the output starts with Linux.
  • On a VM on Apple Silicon the architecture shows aarch64.

Know your distribution

Read the distribution information and paste the output.

cat /etc/os-release
grep ID_LIKE /etc/os-release

Expected output example

NAME="Rocky Linux"
VERSION="9.4 (Blue Onyx)"
PRETTY_NAME="Rocky Linux 9.4 (Blue Onyx)"
ID_LIKE="rhel centos fedora"
My output looks different
  • On Ubuntu you see ID_LIKE=debian; on Rocky/Alma it contains rhel.
  • Some distributions have no ID_LIKE line at all (for example Debian itself); grep then prints nothing.

Time and uptime

Show the date and how long the system has been running; paste the uptime output.

date
date +%F
uptime

Expected output example

Thu Nov 12 10:28:55 CET 2026
2026-11-12
 10:28:55 up 2 days,  3:12,  1 user,  load average: 0.08, 0.03, 0.01
My output looks different
  • On a freshly started VM the uptime is shown in minutes (up 12 min).
  • The date format and time zone can vary with the system language.

Disk and memory

Show disk and memory status in readable units; paste both outputs together.

df -h
free -h

Expected output example

Filesystem      Size  Used Avail Use% Mounted on
/dev/mapper/rhel-root  20G  4.1G  16G  21% /
...
               total        used        free  ...
Mem:           3.8Gi       612Mi       2.4Gi ...
My output looks different
  • On WSL the df -h output also lists the Windows drives (C:\).
  • The memory columns show different numbers depending on your VM settings.

Environment variables

Print the user variable and filter it from the env output.

echo $USER
echo $HOME
env | grep USER
echo "$USER@$(hostname)"

Expected output example

student
/home/student
USER=student
student@linux-lab
My output looks different
  • env | grep USER may return several lines (for example ones matching XDG_SESSION_...); look for the USER= line.
  • On some systems $USER is empty (for example inside a container); whoami still works.

See the administrator identity

Run whoami with sudo: the command now runs as root. If it asks for a password, type your account's password (it is not shown while typing).

whoami
sudo whoami
whoami

Expected output example

student
root
student
My output looks different
  • If you get student is not in the sudoers file, your account is not in the administrator group; try the user you created during installation.
  • root must appear in the middle; sudo elevates only that one command, afterwards you are a normal user again.

Self-test

You see uid=0(...) in the id output. What does it mean?

UID 0 always belongs to root. Normal users usually get a UID of 1000 or higher.

Which command shows the running kernel version?

uname -r prints the kernel version. hostname shows the machine name, whoami the user, df -h the disk.

Which command shows disk usage in readable units (GB, MB)?

df -h shows file systems. free -h shows memory, uptime the running time.

Which environment variable holds the current user's name?

$USER holds the user name; $HOME holds the home directory, $SHELL the shell.

Summary

  • whoami, id, groups: show who you are and which permissions you have; UID 0 = root.
  • hostname and uname -r/-m/-a: machine name, kernel version and architecture.
  • /etc/os-release: distribution name, version and family (ID_LIKE).
  • date and uptime: the time, and the uptime with the load average.
  • df -h and free -h: disk and memory status; for memory look at the available column.
  • env, $USER, $HOME: environment variables; you use a value with $.
  • Before starting any task, check who you are and which machine you are on.

Key terms

UID
User number; permission checks use this number, not names. 0 = root.
GID
Group number; identifies the user's primary group.
wheel
The administrator group that grants sudo on the RHEL family (sudo on Ubuntu).
kernel
The Linux core that manages the hardware; its version is shown by uname -r.
hostname
The machine's name on the network.
load average
Average system load over the last 1, 5 and 15 minutes; shown by uptime.
environment variable
A NAME=value pair kept by the shell, for example USER or HOME.

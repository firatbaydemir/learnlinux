4.3 Switching identity: su, sudo, and sudoers

Learn when and how to use root privileges: prefer one-command sudo and manage its policy safely with visudo.

What will you learn in this module?

  • Explain that root has UID 0, the difference between su - and sudo, and which password each command asks for.
  • Run one administrative command with sudo and inspect your permissions with sudo -l.
  • Open a full root login shell with sudo -i, close it with exit, and avoid staying root unnecessarily.
  • Know that /etc/sudoers defines privilege policy and must only be edited with visudo.

Who is root? su and sudo

On Linux, root is the superuser with UID 0. Root can manage system files and other accounts; a wrong command can cause serious damage. Stay in your normal account for everyday work and use administrator privileges only when needed.

su - USER switches to the target account and asks for that account's password. su - switches to root, but root password login may be disabled on systems such as Ubuntu. The - loads the target user's login environment (for example, HOME and profile).

sudo COMMAND lets an authorized user authenticate with their own password and run only the specified command as another user, usually root. A sudo rule can also be configured not to ask for a password. Running one command with sudo is safer than keeping a root session open.

whoami

What is it for?
Shows the current effective user name.
Where is it used?
When checking which account will run a command.
Why does it matter?
Prevents acting as the wrong user, especially after changing privileges.
whoami

id

What is it for?
Shows the UID, primary GID, and group memberships.
Where is it used?
When checking which group grants sudo access.
Why does it matter?
Verifies user and group identities together.
id

su -

What is it for?
Opens root's login session; it requires the root password.
Where is it used?
Only when the root account is enabled and a longer admin session is truly needed.
Why does it matter?
Loads the login environment; every command in the session runs as root.
su -

sudo COMMAND

What is it for?
Runs one permitted command as another user.
Where is it used?
When a specific administrative action is needed from a normal account.
Why does it matter?
Keeps both the privilege and its scope limited.
sudo whoami

exit

What is it for?
Leaves an open su or sudo login session.
Where is it used?
When the administrative work is finished.
Why does it matter?
Avoids staying in a root shell longer than necessary.
exit
💡 Tip

No characters appear while typing a password at the terminal; that is expected. Enter your own password only at a trusted sudo prompt.

One command and administrator sessions

sudo whoami prints root; plain whoami prints your own account. Sudo elevates only that command, so your shell remains a normal user when the command ends.

sudo -l lists the commands your account may run. sudo -u USER COMMAND runs one command as a specified user when the policy allows it. The rules depend on the distribution and organization; membership in wheel is common on Rocky/Alma and sudo on Ubuntu/Debian.

sudo -i opens root's login shell; whoami then prints root and HOME is /root. sudo -s opens a root shell that keeps more of the current environment. Both are full, high-risk sessions: keep them short and use exit to leave. Sudo may cache authentication for a while; sudo -k invalidates that cache.

sudo -l

What is it for?
Lists the commands and rules available to your account through sudo.
Where is it used?
Before investigating your permissions or an access error.
Why does it matter?
Shows the machine's actual policy rather than assumptions.
sudo -l

sudo -u USER

What is it for?
Runs one command as the specified user.
Where is it used?
When checking how a service or job behaves under another account.
Why does it matter?
Tests the target account's permissions without opening a root session.
sudo -u nobody id

sudo -i

What is it for?
Opens an administrator shell with root's login environment.
Where is it used?
For a brief, controlled session that needs several admin commands.
Why does it matter?
Loads root's HOME and startup environment.
sudo -i

sudo -k

What is it for?
Invalidates the cached sudo authentication.
Where is it used?
When leaving a shared terminal or requiring authentication again immediately.
Why does it matter?
Prevents a previous authentication from being reused by subsequent commands.
sudo -k
⚠️ Warning

A forgotten command inside sudo -i still runs as root. Prefer sudo COMMAND for short tasks; after leaving a root shell, use whoami to verify you returned to your normal account.

sudoers: manage privilege policy safely

/etc/sudoers and files in /etc/sudoers.d/ define who may run which commands as which target users. Never edit these files directly with nano, vim, or echo: a single syntax error can break all sudo access.

Use sudo visudo to inspect and edit the policy. To open a separate rule file, use sudo visudo -f /etc/sudoers.d/NAME; visudo checks the syntax before saving. For example, alice ALL=(root) /usr/bin/systemctl restart nginx permits only that command.

NOPASSWD removes the password prompt, for example alice ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx. Use it only when truly needed, with the full command path and a narrow scope. Granting unrestricted access with ALL or opening a general-purpose shell without a password is not a safe rule. Check the result with sudo -l.

sudo visudo

What is it for?
Edits sudo policy with locking and syntax validation.
Where is it used?
When adding or changing a sudoers rule.
Why does it matter?
Reduces the risk of saving a malformed file and breaking sudo access.
sudo visudo

sudo visudo -f

What is it for?
Safely edits the specified sudoers file.
Where is it used?
When creating a separate sudoers.d rule supported by the distribution.
Why does it matter?
Keeps rules separate from the main file and validates their syntax.
sudo visudo -f /etc/sudoers.d/alice

sudo visudo -c

What is it for?
Checks the syntax of sudoers files.
Where is it used?
After verifying a policy change.
Why does it matter?
Confirms that the file can be read and parsed.
sudo visudo -c

sudo -l

What is it for?
Shows the active sudo rules.
Where is it used?
When checking whether a policy change applies to a user.
Why does it matter?
Lets you compare the written rule with the effective permissions.
sudo -l
⛔ Danger

NOPASSWD: ALL lets a user run every command without a password. Limit the rule to the required user, exact command path, and necessary arguments; write it with visudo and verify it with sudo -l.

A safe administrator workflow

First verify the target and its impact from your normal account; when elevated access is required, run only the necessary command with sudo. If it fails, do not blindly add sudo: inspect id, sudo -l, and the file permissions.

When the work is done, leave any root session with exit. Never put passwords in command history, edit sudoers directly, or run an unfamiliar command as root. On a real VM, take a snapshot before changing system policy.

sudo -l

What is it for?
Verifies the scope of your permissions before acting.
Where is it used?
Before starting an administrative task.
Why does it matter?
Helps catch a missing or overly broad rule.
sudo -l

sudo whoami

What is it for?
Safely verifies that a command runs as root.
Where is it used?
When learning how sudo behaves.
Why does it matter?
Shows that the privilege switch applies only to the command.
sudo whoami

sudo visudo -c

What is it for?
Checks the syntax of the sudoers configuration.
Where is it used?
After a policy change.
Why does it matter?
Catches a broken rule before it is relied upon.
sudo visudo -c
💡 Tip

Apply least privilege: grant no more than the required user, target account, command, and arguments.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

This section inspects privilege policy on a real system; it does not change configuration. Take a VM snapshot if possible. Enter your password only at the terminal's sudo prompt.

Inspect your normal identity

Show your normal account and group memberships with id.

id

Expected output example

uid=1000(student) gid=1000(student) groups=1000(student)
My output looks different
  • User names and UIDs vary by distribution; your own values are expected.
  • Ubuntu commonly uses the sudo group; Rocky/Alma commonly use wheel.

Use sudo for one command

Run sudo whoami and verify that the effective user is root.

sudo whoami

Expected output example

root
My output looks different
  • No characters appear while typing the password; that is expected.
  • A not in the sudoers file error means your account has not been granted permission; ask an administrator.

Verify the effective UID

Run sudo id -u to verify that the privileged command runs with UID 0.

sudo id -u

Expected output example

0
My output looks different
  • id -u prints the effective UID as a number; root's UID is 0.
  • If the command is denied, inspect permissions with sudo -l.

Read your sudo permissions

List commands permitted for your account with sudo -l; do not change any rules.

sudo -l

Expected output example

User student may run the following commands
My output looks different
  • The user name and rules vary by distribution.
  • If the output includes NOPASSWD, note which exact command it covers; do not change the rule.

Check sudoers syntax

Run sudo visudo -c to verify that the current sudo configuration parses. This command does not edit the files.

sudo visudo -c

Expected output example

/etc/sudoers: parsed OK
My output looks different
  • A distribution may also check included files; expect a parsed OK-style line for each file.
  • If an error appears, do not edit the file directly; report it to the system administrator.

Self-test

What is the main difference between sudo COMMAND and su -?

sudo grants privilege for a command; su - switches to another account's login shell.

Why use visudo to edit the sudo policy file?

visudo locks the file while editing and checks its syntax before saving.

Which sudo rule follows least privilege?

Limit access to the right user and required command; avoid broad ALL rules.

If su - rejects the root password on Ubuntu, what is a likely explanation?

Ubuntu installations often lock the root account; an authorized user uses sudo for administration.

Summary

  • Root has UID 0. su - opens the target account's login session; sudo COMMAND runs one permitted command with elevated privileges.
  • sudo -l shows actual permissions; sudo -i opens a full root login shell and should be closed with exit when finished.
  • Edit sudoers policy only with visudo and validate its syntax with visudo -c.
  • Keep NOPASSWD and especially ALL rules narrow; grant only the required user, command, and arguments.

Key terms

root
The account with UID 0 and system-wide administrative privileges.
sudo
A tool that lets an authorized user run a specific command as another user.
su
A tool for switching the current session to another user account.
sudoers
The policy defining sudo permissions by user, target account, and command.
visudo
A tool that edits sudoers files with locking and syntax validation.
NOPASSWD
A sudo rule option that removes the password prompt for specified commands.

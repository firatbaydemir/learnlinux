3.3 Wildcards and Quoting

Before a command runs, the shell expands wildcard patterns and treats spaces as separators. Select groups of files safely by using patterns and quotes correctly.

What will you learn in this module?

  • Match filenames with *, ? and [].
  • Distinguish brace expansion from glob expansion.
  • Explain how single quotes, double quotes and backslashes behave.
  • Check matching names before running a bulk operation.

Wildcards: *, ? and []

The shell matches wildcard patterns against names in the current directory before running a command. * matches zero or more characters, while ? matches exactly one. img?.jpg matches names with one character in that position; img*.jpg also includes longer names.

[12] matches exactly one of the characters in the brackets; [0-9] matches one digit. If nothing matches, Bash usually leaves the pattern unchanged. You can notice this in the command output.

The shell expands wildcards, not ls. When you run ls *.txt, the shell passes matching names to ls as separate arguments.

ls *.jpg

What is it for?
Lists names that match *.jpg.
Where is it used?
When you want to inspect files with a particular extension together.
Why does it matter?
You can see all matches without typing every name.
ls *.jpg

ls img?.jpg

What is it for?
Lists .jpg names with exactly one character after img.
Where is it used?
When a specific part and length of a name should match.
Why does it matter?
? represents one character, so img10.jpg does not match.
ls img?.jpg

ls img[12].jpg

What is it for?
Matches names such as img1.jpg and img2.jpg.
Where is it used?
When only certain individual characters are allowed.
Why does it matter?
It limits the pattern to characters inside the brackets.
ls img[12].jpg

ls *.{jpg,png}

What is it for?
Expands the brace options into separate patterns.
Where is it used?
When you want to perform the same operation on multiple extensions.
Why does it matter?
You can write similar patterns briefly and clearly.
ls *.{jpg,png}
💡 Tip

If you are unsure what matches, first display the expansion with printf '%s\n' *.jpg. Do not run a command that changes files yet.

Quotes and escaping

Quotes control how the shell interprets spaces and special characters. Without quotes, a name containing a space is split into multiple arguments. "my file.txt" keeps it together as one argument.

Characters inside single quotes stay literal; variables such as $HOME are not expanded. Double quotes preserve spaces but still expand variables and command substitutions. A backslash removes the special meaning of the character immediately after it.

ls "my file.txt"

What is it for?
Passes a name containing a space as one argument.
Where is it used?
When listing names with spaces or passing them to commands.
Why does it matter?
It prevents the shell from splitting the name into two parts.
ls "my file.txt"

echo '$HOME'

What is it for?
Prints the literal $HOME text inside single quotes.
Where is it used?
When you want to display special characters without expansion.
Why does it matter?
You see the text as written, not the variable's value.
echo '$HOME'

echo "$HOME"

What is it for?
Expands the variable inside double quotes and prints its value.
Where is it used?
When using a variable value while preserving spaces.
Why does it matter?
The value stays together while the shell still expands the variable.
echo "$HOME"

ls my\ file.txt

What is it for?
Uses a backslash to remove the special meaning of the space.
Where is it used?
When you need to protect one special character.
Why does it matter?
It keeps the name as one argument without using quotes.
ls my\ file.txt
💡 Tip

When a filename contains a variable, usually quote it as "$NAME"; this also preserves any spaces in its value.

Use wildcards safely

A wildcard pattern can match multiple names. Before a delete command such as rm *.tmp, run the same pattern with ls and check which names are selected.

In particular, * can match a broad set of names. First use pwd to confirm the current directory, then list the matches. Do not test an unfamiliar pattern with a destructive command on a real system.

ls *.tmp

What is it for?
Shows matching names ending in .tmp before deletion.
Where is it used?
Immediately before a bulk operation using wildcards.
Why does it matter?
You can confirm which names the command would affect.
ls *.tmp

rm -i *.tmp

What is it for?
Asks for confirmation before deleting each matching file.
Where is it used?
When removing only temporary files you have checked.
Why does it matter?
You get a chance to cancel if a match is wrong.
rm -i *.tmp
⚠️ Warning

Never use wildcards in delete commands blindly. First confirm the directory and matches with pwd and ls; test destructive commands only in a safe environment.

Apply patterns in practice tasks

This module uses English ASCII names such as img1.jpg, img2.jpg, img10.png, doc1.txt and doc2.txt. The command examples can be tried safely in the virtual lab.

Brace expansion is not the same as globbing: {1,2} is split into separate strings by the shell, while * and ? match existing names. Predict which names a command receives, then verify in the lab.

echo *.txt

What is it for?
Prints matching names with the .txt extension.
Where is it used?
When testing a pattern before changing anything.
Why does it matter?
You can see how the shell expands the pattern.
echo *.txt

touch log_{1,2,3}.txt

What is it for?
Creates three separate names using brace options.
Where is it used?
When you need similar test names.
Why does it matter?
It avoids repeating nearly identical commands.
touch log_{1,2,3}.txt
💡 Tip

Names containing spaces in the lab exist only in the virtual filesystem; you do not need to try the same commands on your real system.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

You can run the commands in this section in your own VM. Create files only inside glob-lab in your home directory; do not test wildcard deletions elsewhere.

Single-character wildcard

Create glob-lab in your home directory. Add the names a1.txt and a2.txt inside it, then list the a?.txt pattern.

mkdir -p ~/glob-lab && cd ~/glob-lab && touch a1.txt a2.txt && ls a?.txt

Expected output example

a1.txt
a2.txt
My output looks different
  • a?.txt matches exactly one character; both names should appear.
  • If the names appear on one line, use ls -1 a?.txt to show each on its own line.

Single and double quotes

In the same terminal session, first set NAME=linux. Then print the variable with double quotes and with single quotes. The output should contain both linux and $NAME.

NAME=linux
echo "$NAME"
echo '$NAME'

Expected output example

linux
$NAME
My output looks different
  • If both lines show linux, you may have used double quotes instead of single quotes.
  • The NAME=linux assignment and echo commands must run in the same shell session.

Preserve a name with spaces

Create a directory named my docs inside glob-lab. Then list it with quotes; the output should contain my docs.

mkdir -p ~/glob-lab && cd ~/glob-lab && mkdir -p "my docs" && ls -d "my docs"

Expected output example

my docs
My output looks different
  • If the name is split, check the quotes in both the creation and listing commands.
  • ls -d displays the directory name instead of its contents.

Check matches before deleting

Create two temporary files inside glob-lab. First list the *.tmp matches and confirm that only those two names appear. Delete them only if you confirmed the correct directory and matches.

cd ~/glob-lab && touch sample1.tmp sample2.tmp && ls *.tmp
My output looks different
  • If other names appear, do not run the delete command; check pwd and the list first.
  • If there are no matches, confirm you are in glob-lab and that the names end in .tmp.

Self-test

What does the ? wildcard match?

? represents exactly one character; * can match zero or more.

Which form prints $HOME without expanding it?

Everything inside single quotes stays literal. In this example, a backslash also escapes the $ character.

In Bash, what does echo *.xyz do by default when no names match *.xyz?

By default, Bash passes an unmatched glob pattern to the command unchanged.

How do you correctly list the name my file.txt?

The quotes preserve the space and pass the name to ls as one argument.

Summary

  • * matches zero or more characters; ? matches exactly one.
  • [abc] matches one of the listed characters; {a,b} expands options into separate strings.
  • Single quotes preserve everything literally; double quotes preserve spaces while expanding variables.
  • Protect names with spaces using quotes or a backslash.
  • Check the directory and matches before running a destructive command with wildcards.

Key terms

glob
A wildcard pattern that the shell matches against filenames.
wildcard
A special character representing one or more characters in filename patterns.
quoting
Controlling how the shell interprets spaces and special characters.
escape character
A backslash (\) that removes the special meaning of the character after it.

2.10 Remote connections and file transfer

Use SSH for encrypted access to remote Linux systems, SCP for file copies, and rsync for repeatable synchronization. Verify host keys and protect your private key before connecting.

What will you learn in this module?

  • Use the SSH client with the correct user, host, and port.
  • Explain the different purposes of host keys and user keys.
  • Distinguish one-off copies with scp from synchronization with rsync.
  • Protect private keys and never blindly accept an unknown host key.

A secure session with SSH

ssh user@host opens an interactive shell on a remote machine. The default port is 22; use -p for a different port. ssh -G host displays the effective client configuration without connecting.

On first connection, verify the server's host-key fingerprint. Compare it with the fingerprint provided by the server administrator through a trusted channel; do not accept a key just because a prompt appears. A saved host record helps detect identity changes on later connections.

ssh user@host

What is it for?
Opens an encrypted terminal session on a remote machine.
Where is it used?
When administering remote servers.
Why does it matter?
Runs remote commands securely over the network.
ssh student@linux-lab

ssh -p PORT

What is it for?
Connects SSH to the specified TCP port.
Where is it used?
When the server uses a non-default SSH port.
Why does it matter?
Directs the client to the correct service.
ssh -p 2222 student@linux-lab

ssh -G HOST

What is it for?
Prints effective SSH client settings without connecting.
Where is it used?
When verifying an entry in ~/.ssh/config.
Why does it matter?
Shows the resolved host, user, and port.
ssh -G linux-lab | grep -E '^(hostname|user|port) '
💡 Tip

Do not dismiss a host-key-changed warning. If a server was reinstalled, verify its fingerprint through an authorized channel.

Key pairs and access security

An SSH key consists of a private and a public key. Keep the private key in your own account, never share it, and protect it with suitable file permissions. Add the public key to the target account. A key does not magically eliminate passwords: a passphrase protects the private key.

ssh-keygen creates a key pair. ssh-copy-id adds the public key to a remote account; use it only for accounts and servers you are authorized to access. Changing server authentication can lock out access.

ssh-keygen -t ed25519

What is it for?
Generates an Ed25519 public/private key pair.
Where is it used?
In your own account when preparing key-based login.
Why does it matter?
Allows key-based authentication instead of repeated password entry.
ssh-keygen -t ed25519 -a 64

ssh-keygen -lf

What is it for?
Displays the fingerprint of a public key.
Where is it used?
When comparing a key with a trusted reference.
Why does it matter?
Provides a short, comparable identity for the public key.
ssh-keygen -lf ~/.ssh/id_ed25519.pub

ssh-copy-id

What is it for?
Adds a public key to the remote user's authorized-key list.
Where is it used?
Only for your own account and an authorized server.
Why does it matter?
Enables key authentication on later connections.
ssh-copy-id student@linux-lab
⚠️ Warning

Never send the private-key file (id_ed25519) to anyone. Only the .pub file may be shared; get permission from the server and account owner.

Copy with SCP, synchronize with rsync

scp copies a file or directory over SSH to or from a remote host. The source/destination form is user@host:/path; directories require -r. Check in advance whether a destination file will be overwritten.

rsync can transfer only changed parts, preserve file attributes, and be run repeatedly. The trailing / matters: copying the contents of a source directory to a destination differs from copying the directory itself. Preview the plan with --dry-run; --delete can remove extra destination files.

scp

What is it for?
Transfers copies over SSH.
Where is it used?
When sending or retrieving a small number of files.
Why does it matter?
Provides a simple encrypted transfer command.
scp report.txt student@linux-lab:/home/student/

scp -r

What is it for?
Copies a directory and its contents recursively.
Where is it used?
When sending a directory to a remote system.
Why does it matter?
Transfers a directory tree in one command.
scp -r reports/ student@linux-lab:/home/student/

rsync -av

What is it for?
Transfers files in archive mode, synchronizes changes, and shows progress.
Where is it used?
For repeated backups and directory synchronization.
Why does it matter?
Avoids copying every file on every run.
rsync -av --dry-run reports/ student@linux-lab:/home/student/reports/

rsync --delete

What is it for?
Also deletes destination files that do not exist in the source.
Where is it used?
Only when the destination must exactly match the source.
Why does it matter?
Removes stale target files; data is lost if the target is wrong.
rsync -av --delete source/ backup/
⛔ Danger

rsync --delete and a misdirected scp/rsync command can delete or overwrite destination files. Check the target, make a backup, and use --dry-run.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

These commands display the client version and configuration. They do not connect to a remote host or transfer files; use only authorized servers for real connections.

SSH client version

Verify that the SSH client is installed; do not start a connection to a remote system.

ssh -V

Expected output example

OpenSSH_9.6p1
My output looks different
  • The version number varies by distribution; seeing OpenSSH is enough.
  • The output is often written to stderr, but it is visible in the terminal.

Effective SSH settings

Display the resolved host, user, and port values for localhost without opening a connection.

ssh -G localhost | grep -E '^(hostname|user|port) '

Expected output example

user student
hostname localhost
port 22
My output looks different
  • Your user name may not be student; that is normal.
  • Settings in ~/.ssh/config can affect the output.

rsync version

Display the rsync version and feature summary; this command does not start a transfer.

rsync --version

Expected output example

rsync  version 3
My output looks different
  • The version varies by distribution. If the command is missing, rsync may not be installed.
  • Follow administrator policy for installation; installing a package is not required for this exercise.

Self-test

Which tool opens a remote Linux shell?

ssh opens an encrypted interactive remote session.

Which item must remain secret and must not be shared?

The private key stays with its owner; the public key can be added to the target account.

Which option previews an rsync operation without making changes?

--dry-run shows the planned transfer without making changes.

Which tool is better suited to repeated, changing file transfers and synchronization?

rsync is designed for incremental, repeatable synchronization.

Summary

  • SSH opens an encrypted terminal session; inspect settings without connecting using ssh -G.
  • Protect the private key and verify the host-key fingerprint through a trusted source.
  • Use scp for straightforward copies and rsync for repeated synchronization.
  • Check direction and target; always use --dry-run and a backup before rsync --delete.

Key terms

SSH
An encrypted network protocol for remote shells and transfers.
Host key
A key the server uses to prove its identity to the client.
Public key
The shareable part of a key pair added to the remote account.
Private key
The secret part of a key pair that must remain protected by its owner.
Dry run
A preview of planned changes without applying them.

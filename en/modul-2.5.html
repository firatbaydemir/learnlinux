2.5 File information

Use file, stat, ls -l, ln -s, readlink and realpath to read a file's real type, size, times and link target.

What will you learn in this module?

  • You know that on Linux an extension is just a name and file shows the real type.
  • You read size, permissions, owner and times with stat and ls -l.
  • You create symbolic links and find their target with ls -l, readlink and realpath.

Real type: file

On Windows you tell the type from the extension. On Linux .jpg is only a name; the content can be something else entirely. file ignores the extension and looks at the first bytes of the content.

This helps with downloaded files: a file called image.jpg may really be an executable program.

file

What is it for?
Tells the real file type from its content.
Where is it used?
On downloaded or suspicious files.
Why does it matter?
Exposes wrong extensions and disguised files.
file /etc/hostname

file -i

What is it for?
Prints the type as a MIME type (e.g. text/plain).
Where is it used?
In scripts and web server configuration.
Why does it matter?
Gives a short, machine-readable type.
file -i /etc/hostname
💡 Tip

In the output, ASCII text means text, ELF an executable program and directory a folder.

Details: stat and ls -l

ls -l shows type, permissions, owner, size and date on one line. stat gives more: inode, link count and three timestamps.

Times: Access last read, Modify last change of the content, Change last change of metadata such as permissions or owner. The first character shows the type: - file, d folder, l symbolic link.

stat

What is it for?
Shows all technical details of a file.
Where is it used?
When you need exact size, permissions and times.
Why does it matter?
More detailed than ls -l.
stat ~/info/data.txt

ls -l

What is it for?
Prints a long-format listing.
Where is it used?
For a quick look into a folder.
Why does it matter?
Type, permissions, owner, size and date on one line.
ls -l ~/info

ls -lh

What is it for?
Shows sizes in readable KB/MB.
Where is it used?
With larger files.
Why does it matter?
A readable size instead of a byte count.
ls -lh ~/info

ls -ld

What is it for?
Lists the folder itself, not its contents.
Where is it used?
When checking a folder's permissions.
Why does it matter?
Folder info without opening it.
ls -ld ~/info
💡 Tip

ls -lh rounds; for exact bytes use stat or wc -c.

Symbolic links and the real path

A symbolic link (symlink) is a small file that points to another path. ls -l shows it as link.txt -> data.txt. If the target is missing the link is broken: it exists, but opening it gives an error.

Deleting a link does not delete the target; rm link.txt removes only the link. readlink prints the target one step, realpath the fully resolved absolute path.

ln -s

What is it for?
Creates a symbolic link: target first, then link name.
Where is it used?
For shortcuts or version markers.
Why does it matter?
Access under a second name without copying.
ln -s data.txt ~/info/link.txt

readlink

What is it for?
Prints the target a link points to.
Where is it used?
When you want to know where a link goes.
Why does it matter?
In scripts you get the target cleanly.
readlink ~/info/link.txt

realpath

What is it for?
Prints the absolute path with all links resolved.
Where is it used?
With relative paths or chains of links.
Why does it matter?
Shows the file's real location on disk.
realpath ~/info/link.txt
⚠️ Warning

The target path is relative to the link's folder. ln -s data.txt ~/info/link.txt works; ln -s data.txt ~/link.txt from another folder creates a broken link.

Name and size: basename, dirname, wc

basename returns the last part of a path, dirname the folder part. Both are common in scripts for splitting paths.

wc -c gives the size in bytes, wc -l the number of lines.

basename

What is it for?
Prints the last component (file name) of a path.
Where is it used?
In scripts when you only need the name.
Why does it matter?
No need to cut the path by hand.
basename ~/info/data.txt

dirname

What is it for?
Prints the folder part of a path.
Where is it used?
To find the folder of a file.
Why does it matter?
You get the folder without the file name.
dirname ~/info/data.txt

wc -c

What is it for?
Prints the byte count of a file.
Where is it used?
When you need the exact size.
Why does it matter?
Exact size without rounding.
wc -c ~/info/data.txt

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Try it on your VM. There are no destructive commands here; you only create small test files in your home directory.

Find the real type

Run file on a text file, a program and a folder and paste the output.

file /etc/hostname /usr/bin/ls /etc

Expected output example

/etc/hostname: ASCII text
/usr/bin/ls:  ELF 64-bit LSB pie executable, x86-64, ...
/etc:         directory
My output looks different
  • The location of ls depends on the distribution; find it with which ls.
  • If file is missing, install it with sudo apt install file on Ubuntu or sudo dnf install file on Rocky/Alma.

The lying extension

Give a text file the name .jpg and see what file says.

echo hello > ~/fake.jpg
file ~/fake.jpg

Expected output example

/home/student/fake.jpg: ASCII text
My output looks different
  • Your path may be /home/alice/fake.jpg; the word text is what matters.

Details with stat

Find the Size, Modify and Change lines in the stat output.

stat ~/fake.jpg

Expected output example

  File: /home/student/fake.jpg
  Size: 6   Blocks: 8   regular file
Access: (0644/-rw-r--r--) ...
Modify: 2026-01-01 10:00:00 ...
My output looks different
  • On a localised system labels may be translated; LANG=C stat ~/fake.jpg prints English.
  • The Birth line is - on some file systems.

Link and real path

Create a symbolic link and find the target with ls -l, readlink and realpath.

ln -s fake.jpg ~/pic_link
ls -l ~/pic_link
readlink ~/pic_link
realpath ~/pic_link

Expected output example

lrwxrwxrwx 1 student student 8 ... /home/student/pic_link -> fake.jpg
fake.jpg
/home/student/fake.jpg
My output looks different
  • If -> is missing in the ls -l output, check the order of ln -s (target first, then link name).
  • If realpath is missing, readlink -f ~/pic_link does the same.

Clean up

Delete the test files. If there were no errors, press "Done".

ls -l ~/fake.jpg ~/pic_link
rm ~/pic_link ~/fake.jpg
My output looks different
  • rm removes the link first, then the target file. In reverse order the link stays broken, which is harmless.

Self-test

What does file image.jpg use to determine a file's type?

On Linux the extension is only a name; file checks the content.

What does the Modify time in stat output show?

Modify is the content time, Change the metadata time, Access the last read.

What happens when you run rm link.txt on a symbolic link?

A link is its own entry; deleting it does not touch the target.

Which command prints the absolute path with all links resolved?

realpath resolves relative paths and link chains into the real absolute path.

Summary

  • An extension is only a name; use file for the real type.
  • ls -l is the quick overview, stat the details; Modify is content time, Change metadata time.
  • ln -s target link creates a symbolic link; ls -l shows ->.
  • readlink shows the target, realpath the full absolute path; rm link does not delete the target.

Key terms

symlink
A special file that points to another path.
inode
The metadata record of a file in the file system.
dangling link
A symbolic link whose target does not exist.
MIME type
A label for the content type, e.g. text/plain.

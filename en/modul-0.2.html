0.2 Setting up your own Linux VM

Install Rocky/Alma Linux or Ubuntu in VirtualBox, UTM or WSL, verify the download, take a snapshot and connect over SSH.

What will you learn in this module?

  • You pick the right tool for your computer (VirtualBox, UTM or WSL).
  • You verify the ISO with a SHA-256 checksum before installing.
  • You create a VM, take a snapshot and connect to it over SSH.

Why your own VM?

Real skills come from a real Linux. A virtual machine (VM) is a complete computer inside your computer: you can break it, reinstall it and nothing on your real system is touched.

Pick the tool that fits your hardware: VirtualBox (Windows, Intel Mac, Linux), UTM (Apple Silicon Macs, needs an ARM64 ISO) or WSL 2 (Windows 10/11, fastest to start, Ubuntu only). For distributions use Rocky Linux 9 / AlmaLinux 9 (the RHEL family used in companies) and optionally Ubuntu 24.04 LTS.

💡 Tip

Plan for 2 CPU cores, 4 GB RAM and 25 GB disk per VM.

Download the ISO and verify it

Download the ISO only from the official site of the distribution (rockylinux.org, almalinux.org, ubuntu.com). Next to the ISO there is a checksum (SHA-256). Compute the checksum of your file and compare: if one character differs, the file is damaged or tampered with — download again.

sha256sum (Linux/macOS: shasum -a 256)

What is it for?
Computes the SHA-256 checksum of a file.
Where is it used?
On your host machine after the download.
Why does it matter?
Proves the ISO is complete and unmodified.
sha256sum Rocky-9-latest-x86_64-minimal.iso

Get-FileHash (Windows PowerShell)

What is it for?
Same checksum on Windows.
Where is it used?
PowerShell on Windows hosts.
Why does it matter?
Windows has no sha256sum.
Get-FileHash .\Rocky-9-latest-x86_64-minimal.iso -Algorithm SHA256
⚠️ Warning

Never install from an ISO whose checksum does not match, even if the installer starts.

Create the VM and install

In VirtualBox/UTM create a new VM, attach the ISO and give it 2 CPUs, 4 GB RAM and 25 GB disk. Start it and follow the installer: choose your language, select the disk (automatic partitioning is fine), set a root password, create a normal user and tick "administrator" (this adds the user to the wheel/sudo group).

Choose the Minimal install first; you will add tools yourself. After the reboot remove the ISO and log in with your normal user. Finish with cat /etc/os-release to see which system you built.

On WSL this is one command in PowerShell (administrator): wsl --install -d Ubuntu-24.04. Then restart and create your user name when asked.

💡 Tip

Choose a short lowercase user name without spaces; you will type it a lot.

Snapshots: your undo button

A snapshot saves the complete state of the VM. Take one called clean-install right after the first successful boot and before every risky experiment. If you break something, restore the snapshot in seconds.

In VirtualBox: Machine ▸ Take Snapshot; in UTM: clone the VM or use the QEMU snapshot option. For WSL export a backup: wsl --export Ubuntu-24.04 backup.tar.

⛔ Danger

A snapshot is not a backup of your real files; if the host disk fails, snapshots are lost with it.

Networking basics

NAT (default) lets the VM reach the internet but hides it from your network; use port forwarding to reach it. Bridged puts the VM on your LAN with its own IP address. Host-only connects only the VM and your computer.

For learning, NAT with a port-forward rule (host port 2222 → guest port 22) or bridged are both fine. Inside the VM check your address with ip -brief a.

ip -brief a

What is it for?
Shows interfaces with state and IP address.
Where is it used?
Inside the VM.
Why does it matter?
You need the IP address to connect over SSH.
ip -brief a

Connect with SSH

The VM window is clumsy. Connect from your host terminal over SSH instead: copy/paste works and it is how servers are managed in real life. First make sure the SSH service is running in the VM (sudo systemctl enable --now sshd on Rocky/Alma, ssh on Ubuntu).

Then from your host: ssh user@IP (bridged) or ssh -p 2222 user@127.0.0.1 (NAT with port forward). Accept the host key with yes.

ssh user@host

What is it for?
Opens a secure remote shell.
Where is it used?
From your host to the VM or any server.
Why does it matter?
Standard way to administer Linux.
ssh student@192.168.1.50

ssh-keygen -t ed25519

What is it for?
Creates a key pair for password-less login.
Where is it used?
Once on your host.
Why does it matter?
Safer and more convenient than passwords.
ssh-keygen -t ed25519

ssh-copy-id user@host

What is it for?
Installs your public key on the VM.
Where is it used?
After ssh-keygen.
Why does it matter?
Next logins need no password.
ssh-copy-id student@192.168.1.50
💡 Tip

Take a snapshot after SSH works — it is the best state to return to.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

This is the main path of this module: work through the steps on your computer. Tick "Done" or paste an output to be checked.

Download the ISO

Download Rocky Linux 9 or AlmaLinux 9 (minimal ISO; ARM64 for Apple Silicon) or Ubuntu 24.04 and note the published SHA-256 value.

My output looks different
  • Apple Silicon needs the aarch64/arm64 ISO; x86_64 will not boot in UTM natively.

Verify the checksum

Compute the SHA-256 of your ISO and paste the output. Compare it manually with the published value.

sha256sum Rocky-9-latest-x86_64-minimal.iso

Expected output example

3f2b...c9a1  Rocky-9-latest-x86_64-minimal.iso
shasum -a 256 Rocky-9-latest-aarch64-minimal.iso

Expected output example

(macOS) 64 hex characters followed by the file name
My output looks different
  • 64 hexadecimal characters are expected; a shorter output means the command failed.
  • Windows: Get-FileHash file.iso -Algorithm SHA256 prints a table; paste the Hash column.
  • Different from the published value? Delete the file and download again.

Create and install the VM

Create the VM (2 CPU, 4 GB RAM, 25 GB disk), install the system, create an administrator user and boot into the login prompt.

My output looks different
  • Boot loop or "no bootable medium": check the ISO is attached and the boot order starts with the optical drive.
  • VirtualBox on Windows: enable virtualization (VT-x/AMD-V) in the BIOS and disable Hyper-V conflicts.

First login

Log in with your user and show which system you installed. Paste the output.

cat /etc/os-release

Expected output example

NAME="Rocky Linux"
VERSION="9.4 (Blue Onyx)"
My output looks different
  • On Ubuntu NAME="Ubuntu" appears; both are fine for this course.
  • On WSL the file exists too; the text is the same.

Take a snapshot

Shut down cleanly with sudo poweroff, take a snapshot named clean-install, then start the VM again.

sudo poweroff

Expected output example

(the VM window closes)
My output looks different
  • Snapshots greyed out? Power the VM off first (in VirtualBox the snapshot button is in the machine tools).

Find the IP address

Show your interfaces and paste the output.

ip -brief a

Expected output example

lo     UNKNOWN  127.0.0.1/8
enp0s3 UP       10.0.2.15/24
My output looks different
  • 10.0.2.15 means NAT; use the port-forward rule to reach it from the host.
  • No IPv4 address on enp0s3? Run nmcli device and connect the interface, or check the VM network adapter is enabled.

Connect over SSH

Connect from your host terminal to the VM and run the command below. Paste the output.

ssh student@192.168.1.50

Expected output example

(you get a prompt on the VM)
echo $SSH_CONNECTION

Expected output example

192.168.1.10 51234 192.168.1.50 22
My output looks different
  • Connection refused: sshd is not running (sudo systemctl enable --now sshd).
  • Connection timed out: wrong IP or no port-forward rule (NAT).
  • Permission denied: wrong user name or password.

Update the system

Bring the system up to date, reboot and tick "Done" when the update finished without errors.

sudo dnf -y update   # Rocky/Alma

Expected output example

Complete!
sudo apt update && sudo apt -y upgrade   # Ubuntu

Expected output example

(no E: errors)
My output looks different
  • Could not resolve host: the VM has no internet; check the network adapter.

Self-test

What does a matching SHA-256 checksum tell you?

A checksum is a fingerprint; equal fingerprints mean the file is identical to the published one.

Which network mode hides the VM from your LAN but allows internet access?

NAT shares the host connection; use port forwarding to reach the VM.

When should you take a snapshot?

A snapshot is a quick undo point; take one before changes you may regret.

Which tool is the usual choice on an Apple Silicon Mac?

Apple Silicon is ARM; UTM runs ARM64 guests natively.

Summary

  • A VM is a safe, disposable Linux that you can fully control.
  • Always verify the ISO checksum before installing.
  • Snapshot after a clean install and before experiments.
  • SSH from the host terminal is the professional way to work.

Key terms

VM
Virtual machine: a complete computer simulated by software.
ISO
Disk image file of an installation medium.
checksum
Fingerprint of a file used to detect damage or tampering.
snapshot
Saved state of a VM you can return to.
SSH
Secure Shell: encrypted remote terminal protocol.
NAT
Network address translation: VM shares the host connection.

6.3 firewalld — Zone, Service, Port

Listening is not the same as reachable: learn to read firewalld, change rules safely (runtime vs permanent) and meet ufw, the Debian/Ubuntu counterpart.

What will you learn in this module?

  • You check whether firewalld is running and read the default and active zones.
  • You explain runtime vs --permanent and what --reload does.
  • You open and close services and ports, and test rules safely with --timeout.
  • You write a simple rich rule for one source network.
  • You use ufw on Ubuntu and always allow SSH before enabling it.

Zones, services, ports

With ss you see that a program listens. Whether others can reach it depends on the firewall in between. firewalld (Rocky/Alma/RHEL/Fedora) sorts every network interface into a zone: a trust level with its own list of allowed services and ports. public is the usual default; trusted allows everything, drop silently discards everything.

A service is a predefined bundle (ssh = 22/tcp, http = 80/tcp, https = 443/tcp). A port is an explicit number such as 8080/tcp. Use a service when one exists, a port for non-standard numbers.

Always read before you change: first the state, then the zone, then the whole list.

firewall-cmd --state

What is it for?
Prints running or not running.
Where is it used?
As the very first check on a Rocky/Alma VM.
Why does it matter?
If the daemon is stopped, all other firewall-cmd commands fail.
sudo firewall-cmd --state

firewall-cmd --get-default-zone

What is it for?
Shows the zone used for new interfaces.
Where is it used?
Before adding any rule.
Why does it matter?
Rules without --zone go to the default zone.
sudo firewall-cmd --get-default-zone

firewall-cmd --get-active-zones

What is it for?
Lists zones that currently have interfaces or sources.
Where is it used?
When you wonder which zone really handles your traffic.
Why does it matter?
The default zone can differ from the active one on an interface.
sudo firewall-cmd --get-active-zones

firewall-cmd --list-all

What is it for?
Shows services, ports, rich rules and interfaces of a zone.
Where is it used?
Before and after every change.
Why does it matter?
Verify first, change, verify again.
sudo firewall-cmd --list-all
💡 Tip

--list-all shows the runtime state. Add --permanent to see what is stored on disk.

Runtime vs permanent, --reload, --timeout

firewalld has two configurations. Runtime is active right now and is lost on --reload or reboot. Permanent is written to disk and survives reboots, but --permanent alone does not change the running firewall.

Typical safe workflow: test in runtime with --timeout, check, and only then write it permanently and run --reload. --reload applies the permanent configuration and discards runtime-only rules.

A good test: if a rule works in runtime and you want to keep it, use firewall-cmd --runtime-to-permanent.

firewall-cmd --add-service=http --timeout=60

What is it for?
Adds a runtime rule that disappears after 60 seconds.
Where is it used?
For tests, especially over SSH.
Why does it matter?
If you made a mistake, it fixes itself.
sudo firewall-cmd --add-service=http --timeout=60

firewall-cmd --permanent --add-service=http

What is it for?
Writes the rule to disk only; not active yet.
Where is it used?
For rules that must survive a reboot.
Why does it matter?
Runtime and permanent are separate lists.
sudo firewall-cmd --permanent --add-service=http

firewall-cmd --reload

What is it for?
Loads the permanent configuration into runtime.
Where is it used?
After --permanent changes.
Why does it matter?
Activates permanent rules; runtime-only rules are dropped.
sudo firewall-cmd --reload

firewall-cmd --runtime-to-permanent

What is it for?
Saves the current runtime rules as permanent.
Where is it used?
After you tested a rule and it works.
Why does it matter?
No need to type the rule twice.
sudo firewall-cmd --runtime-to-permanent
⚠️ Warning

Take a VM snapshot first (module 0.2). On a remote machine keep a second SSH session open while you change firewall rules.

⛔ Danger

SSH lockout: never remove the ssh service from the active zone, never set the zone to drop, and never run --panic-on over SSH. Your session dies at once and you only get back in through the VM console. Test with --timeout, verify with --list-all, and keep the order: verify, change, verify.

Opening and closing ports and services

For a web app on port 8080 use --add-port=8080/tcp. To close it again use --remove-port or --remove-service. Remember: every --permanent change needs --reload.

A port in the firewall does not start the program. Check with ss that something listens. On Rocky/Alma with SELinux a non-standard port may also need a label (module 6.2).

firewall-cmd --get-services

What is it for?
Lists all predefined service names.
Where is it used?
To find the right service name.
Why does it matter?
A service is clearer than a bare number.
sudo firewall-cmd --get-services

firewall-cmd --permanent --add-port=8080/tcp

What is it for?
Opens 8080/tcp permanently (after reload).
Where is it used?
For apps on non-standard ports.
Why does it matter?
Services only cover standard ports.
sudo firewall-cmd --permanent --add-port=8080/tcp

firewall-cmd --list-ports

What is it for?
Lists explicitly opened ports.
Where is it used?
To verify a port change.
Why does it matter?
Confirms the rule is active in runtime.
sudo firewall-cmd --list-ports

firewall-cmd --permanent --remove-port=8080/tcp

What is it for?
Removes the port rule from the permanent config.
Where is it used?
When the app is gone.
Why does it matter?
Open ports you no longer need are risk.
sudo firewall-cmd --permanent --remove-port=8080/tcp
💡 Tip

Write the commands into a small script first and read it twice before you run it.

Rich rules (briefly)

A rich rule adds conditions: source address, port, protocol and action (accept, reject, drop). Example: allow PostgreSQL (5432) only from the network 192.168.1.0/24.

Quote the whole rule in single quotes and the values inside in double quotes. Add --timeout while testing.

firewall-cmd --add-rich-rule

What is it for?
Adds a conditional rule.
Where is it used?
When a port must be open only for one network.
Why does it matter?
More precise than opening the port for everyone.
sudo firewall-cmd --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" port port="5432" protocol="tcp" accept' --timeout=60

firewall-cmd --list-rich-rules

What is it for?
Shows the rich rules of the zone.
Where is it used?
To verify or audit.
Why does it matter?
Rich rules are not shown in --list-services.
sudo firewall-cmd --list-rich-rules

firewall-cmd --remove-rich-rule

What is it for?
Removes a rich rule; give the exact same text.
Where is it used?
When the exception is no longer needed.
Why does it matter?
Keeps the rule set small.
sudo firewall-cmd --remove-rich-rule='rule family="ipv4" source address="192.168.1.0/24" port port="5432" protocol="tcp" accept'
⚠️ Warning

A reject or drop rule for your own admin network can cut your SSH session. Use --timeout and keep a second session.

Debian/Ubuntu: ufw

Ubuntu uses ufw (Uncomplicated Firewall). It is usually installed but disabled. The golden rule: allow SSH first, enable second. ufw enable with default deny incoming and no SSH rule locks you out.

OpenSSH is an application profile, equal to 22/tcp. Rules are active at once and persistent; there is no runtime/permanent split.

ufw allow OpenSSH

What is it for?
Allows SSH (22/tcp).
Where is it used?
Before the very first ufw enable.
Why does it matter?
Prevents locking yourself out.
sudo ufw allow OpenSSH

ufw enable

What is it for?
Turns the firewall on and keeps it on after reboot.
Where is it used?
Only after SSH is allowed.
Why does it matter?
The default policy blocks incoming traffic.
sudo ufw enable

ufw status verbose

What is it for?
Shows state, default policy and rules.
Where is it used?
After each change.
Why does it matter?
Check that 22/tcp is ALLOW.
sudo ufw status verbose

ufw delete allow 80/tcp

What is it for?
Removes an allow rule.
Where is it used?
When a port is no longer needed.
Why does it matter?
Keeps exposure small.
sudo ufw delete allow 80/tcp
⛔ Danger

Never run ufw enable over SSH before ufw allow OpenSSH (or ufw allow 22/tcp). If your SSH port is not 22, allow that port. Snapshot the VM first.

Reading listening ports and logs

Before you open anything, find out what really listens: ss -tulpn on the VM. In the simulator you practise with sample files in ~/fw: ss.txt is a fake ss output, blocked.log a fake firewall log.

With grep, cut, sort and uniq -c you can count and rank. This is the same technique you use on real logs.

ss -tulpn

What is it for?
Lists listening TCP/UDP sockets with the process.
Where is it used?
To see which ports are in use.
Why does it matter?
Open firewall ports without a listener are pointless.
sudo ss -tulpn

grep -c

What is it for?
Counts matching lines.
Where is it used?
To count listeners or events.
Why does it matter?
A fast number instead of scrolling.
grep -c LISTEN ~/fw/ss.txt

cut | sort | uniq -c

What is it for?
Extracts a column and counts equal values.
Where is it used?
To rank blocked source addresses.
Why does it matter?
Shows the noisiest source at a glance.
cut -d' ' -f3 ~/fw/blocked.log | sort | uniq -c | sort -rn

grep -i

What is it for?
Finds lines ignoring case.
Where is it used?
To read ALLOW rules in a ufw status file.
Why does it matter?
No need to know the exact capitalisation.
grep -i allow ~/fw/ufw-status.txt
💡 Tip

The sample scripts in ~/fw are only text files. They are never executed against a real firewall.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Use a Rocky/Alma VM for v01–v04 and an Ubuntu VM for v05. Take a snapshot first (module 0.2) and work from the VM console or keep a second SSH session open.

Read the firewall state

Check that firewalld runs, read the default zone and the full list. Paste the output.

sudo firewall-cmd --state
sudo firewall-cmd --get-default-zone
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all

Expected output example

running
public
public
  interfaces: enp0s3
public (active)
  services: cockpit dhcpv6-client ssh
  ports:
My output looks different
  • If it says not running: sudo systemctl enable --now firewalld.
  • On Ubuntu firewalld is usually not installed; use ufw (v05).
  • Your zone or interface name may differ (enp0s3, ens160).

Runtime rule with a timeout

Add http for 120 seconds, list the services, wait, list again. The rule vanishes by itself.

sudo firewall-cmd --add-service=http --timeout=120
sudo firewall-cmd --list-services

Expected output example

success
cockpit dhcpv6-client http ssh
My output looks different
  • ssh must still be in the list; if not, add it back immediately: sudo firewall-cmd --add-service=ssh.
  • After 120 seconds http disappears again.

Permanent vs runtime

Write http permanently, compare the permanent and runtime list before and after --reload.

sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --list-services --permanent
sudo firewall-cmd --reload
sudo firewall-cmd --list-services

Expected output example

success
cockpit dhcpv6-client http ssh
success
cockpit dhcpv6-client http ssh
My output looks different
  • After --reload the runtime list now equals the permanent list.
  • Without --reload the runtime list would not contain http (unless v02 is still active).

Open and close a port

Open 8080/tcp permanently, reload and check. Then remove it again and reload.

sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports
sudo firewall-cmd --permanent --remove-port=8080/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports

Expected output example

success
success
8080/tcp
success
success
My output looks different
  • The last --list-ports output should be empty.

Ubuntu: ufw with SSH first

On Ubuntu allow SSH first, then enable ufw and read the status. Paste the status output.

sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status verbose

Expected output example

Status: active
Default: deny (incoming), allow (outgoing)

To            Action      From
22/tcp        ALLOW IN    Anywhere
My output looks different
  • ufw may ask Command may disrupt existing ssh connections — fine, because SSH is allowed.
  • If ufw is not found: sudo apt install ufw.

Self-test

What does firewall-cmd --permanent --add-service=http do on its own?

--permanent only changes the stored configuration. The running firewall changes after --reload.

You are connected over SSH to a new Ubuntu server. What must come before ufw enable?

ufw blocks incoming traffic by default. Without an SSH rule you lock yourself out.

What does --timeout=60 do with --add-service?

Timeout rules are runtime only and remove themselves — a safety net for tests.

What happens to runtime-only rules on firewall-cmd --reload?

--reload reloads the permanent configuration and drops runtime-only changes.

Summary

  • firewalld sorts interfaces into zones; --list-all shows what a zone allows.
  • Runtime is active now; --permanent is stored and needs --reload; --reload drops runtime-only rules.
  • Test with --timeout, verify before and after, keep a second SSH session and a snapshot.
  • Use services for standard ports and --add-port for the rest; rich rules limit a rule to a source network.
  • On Ubuntu: ufw allow OpenSSH first, ufw enable second.

Key terms

zone
A trust level with its own allowed services and ports; each interface belongs to one zone.
service
A predefined firewalld bundle of ports, such as http = 80/tcp.
port
An explicit number plus protocol, for example 8080/tcp.
runtime
The configuration active right now; lost on reload or reboot.
permanent
The configuration stored on disk; applied by --reload or reboot.
--reload
Loads the permanent configuration and discards runtime-only rules.
--timeout
Makes a runtime rule expire automatically after the given time.
rich rule
A conditional rule with source, port, protocol and action.
ufw
Uncomplicated Firewall, the default front end on Ubuntu.
lockout
Losing your own SSH access because of a firewall change.

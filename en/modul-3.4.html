3.4 Searching: grep and find

grep searches lines inside files, while find searches for files and directories in a directory tree. Combine them to inspect logs and project files quickly.

What will you learn in this module?

  • Search file contents with grep.
  • Explain the effects of -i, -n, -v and -c.
  • Find files by name and type with find.
  • Use search results with pipes and redirection.

Search file contents with grep

grep PATTERN FILE prints matching lines. The pattern can be plain text or a regular expression. Use -i to ignore case, -n to show line numbers, -v to select non-matching lines and -c to count matching lines.

grep can also read text from a pipe when no filename is given. This lets you filter long output with command | grep pattern.

grep -n

What is it for?
Shows line numbers alongside matching lines.
Where is it used?
When locating a match in a file.
Why does it matter?
Makes it easier to find and inspect the result.
grep -n ERROR logs/app.log

grep -i

What is it for?
Ignores upper- and lowercase differences.
Where is it used?
When log messages use different capitalization.
Why does it matter?
error, Error and ERROR all match.
grep -i error logs/app.log

grep -v

What is it for?
Shows lines that do not match the pattern.
Where is it used?
When excluding unwanted lines from results.
Why does it matter?
Filters the inverse of a match.
grep -v INFO logs/app.log

grep -c

What is it for?
Prints the number of matching lines.
Where is it used?
When counting events in a log.
Why does it matter?
Gives a total without printing every line.
grep -c ERROR logs/app.log
💡 Tip

Pass the pattern and filename as separate arguments. Quote a search string that contains special characters.

Search the file system with find

find START ... searches downwards from the given directory. -name selects a name pattern, -type f selects regular files and -type d selects directories. Quote filename patterns so the shell does not expand * before find receives it.

find can search by more than name, and its output can be piped to another command. locate searches a prebuilt filename index; it is fast, but newly created files may not be indexed yet. Starting from a focused directory avoids scanning unrelated system paths.

find . -name

What is it for?
Searches by name in a directory tree.
Where is it used?
When you know a filename or extension inside a project.
Why does it matter?
It also searches subdirectories.
find project -name "*.conf"

find . -type f

What is it for?
Selects regular files only.
Where is it used?
When you need to distinguish files from directories.
Why does it matter?
Limits results to one kind of filesystem object.
find project -type f -name "*.txt"

find . -type d

What is it for?
Selects directories only.
Where is it used?
When locating folders inside a project.
Why does it matter?
Keeps directory names separate from filenames.
find project -type d

locate

What is it for?
Searches an indexed database of filenames quickly.
Where is it used?
When looking for the path of a known file across the system.
Why does it matter?
It is fast when the index is current; new files may not appear yet.
locate sshd_config
⚠️ Warning

find / can scan the entire system and produce permission warnings. Start with a narrow path such as your project or home directory.

Combine searches and save results

grep and find answer different questions: grep finds text inside files, while find locates files by name and path. Save results with > or pass them to another filter with |.

Inspect search results before changing important files. The commands in this module search and read; redirection creates a report only in your working directory.

grep -r

What is it for?
Searches file contents recursively in a directory.
Where is it used?
When finding where a setting or word appears in a project.
Why does it matter?
Avoids opening files one by one.
grep -r TODO project

find . -type f -name "*.txt" > list.txt

What is it for?
Writes paths of matching text files to a list.
Where is it used?
When you want to inspect search results later.
Why does it matter?
Keeps results in a reusable report.
find project -type f -name "*.txt" > text_files.txt
💡 Tip

Run a search and inspect its output first; then redirect it to a report if needed.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Read existing text and paths on your own VM. These commands do not change system files; use your home directory when creating a report.

Search a log

Search a system log for error, ignoring case, and paste one matching line.

grep -i error /var/log/messages | head -n 3

Expected output example

error
My output looks different
  • If that log does not exist, choose a log on your distribution or create ~/lab/app.log with sample lines.

Show line numbers

Find the root line in /etc/passwd and include its line number.

grep -n '^root:' /etc/passwd

Expected output example

1:root:
My output looks different
  • The line number may vary by system; the output should contain root with a number before it.

Search by filename

Find the file named hostname under /etc.

find /etc -type f -name hostname

Expected output example

/etc/hostname
My output looks different
  • The output should contain the full path. find takes the starting directory and name as separate arguments.

Save results safely

Create lab in your home directory, make a report listing .txt files there, and inspect the report.

mkdir -p ~/lab && cd ~/lab && touch notes.txt readme.txt && find . -type f -name '*.txt' > files.txt && cat files.txt
My output looks different
  • If the report is empty, check that cd ~/lab succeeded and the filenames are correct. Do not search the whole system.

Self-test

What does grep -i error file do?

-i makes the search case-insensitive.

What does grep -n add to its output?

-n shows the line number for each match.

What does find project -type f -name '*.txt' search for?

The starting path is project, the type is regular file, and the name pattern ends in .txt.

Which command searches file contents recursively for TODO?

grep -r searches file contents recursively in a directory tree.

Summary

  • grep searches file contents; find locates files and directories in a tree.
  • grep -i ignores case, -n shows line numbers, -v inverts matches and -c counts them.
  • find -name selects a name pattern; -type f selects regular files and -type d directories.
  • Quote filename patterns so the shell does not expand * before the search.
  • Start from a narrow directory instead of searching a large tree unnecessarily.

Key terms

grep
A search tool that finds matching lines in text files.
find
A filesystem search tool that starts at a directory and descends through its tree.
regular expression
A pattern syntax for matching text.
recursive search
A search that also visits subdirectories.

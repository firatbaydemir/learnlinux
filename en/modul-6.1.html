6.1 Network Basics — ip, ss, DNS, Ports

Read your network identity: address, gateway, port and name. Almost every command in this module is read-only.

What will you learn in this module?

  • You read the IP address, prefix and default gateway with ip a and ip r.
  • You see which service listens on which port and interface with ss -tulpn.
  • You know the name resolution chain: /etc/hosts → /etc/resolv.conf → DNS server.
  • You read the firewall (firewalld / ufw) first and change it without locking yourself out.
  • You diagnose "no internet" layer by layer (address → gateway → IP → name).

Address and routing: ip a, ip r

Every network interface (eth0, ens3, enp0s3, lo) has an IP address and a prefix. 192.168.1.42/24 means: the first 24 bits are the network, the rest identifies the host (/24 = 255.255.255.0). lo is the loopback interface (127.0.0.1): the machine itself, it never leaves the host.

If the destination is not on the local network, the packet goes to the default gateway. The line default via 192.168.1.1 in ip r tells you which. Use the modern ip command instead of the old ifconfig and route; it exists on Rocky/Alma and Ubuntu/Debian alike.

Interface names vary by distribution and VM; your output may show ens3 or enp0s3 instead of eth0.

ip a

What is it for?
Lists all interfaces with their IP addresses and state (UP/DOWN).
Where is it used?
To learn the machine's address or verify an interface is up.
Why does it matter?
First stop in network trouble; without an address nothing above it works.
ip a

ip -br a

What is it for?
Shows the same information as a short one-line-per-interface table.
Where is it used?
For a quick look at which interface has which address.
Why does it matter?
Saves you from reading long output; it fits on the screen.
ip -br a

ip r

What is it for?
Shows the routing table; the default via line is the gateway.
Where is it used?
When investigating why you cannot reach outside networks.
Why does it matter?
Without a default route no packet leaves the local network.
ip r

grep default

What is it for?
Filters lines by text; here it finds the gateway in saved route output.
Where is it used?
When you want a single line out of long output.
Why does it matter?
The same filtering works on ss output; in the simulator you practise with sample files.
grep default ~/net/routes.txt
💡 Tip

Chain it with cutting: grep default ~/net/routes.txt | cut -d' ' -f3 returns just the gateway address.

⚠️ Warning

Changing an interface address by hand with ip addr add/del can cut your connection (including SSH) instantly. In this module we only read.

Ports and listening services: ss

The IP address selects the machine, the port selects the service on it: 22 SSH, 80 HTTP, 443 HTTPS, 53 DNS. A running service listens (LISTEN) on a specific address and port.

ss -tulpn letters: t TCP, u UDP, l listening only, p process name, n numeric output (no name lookup). You need sudo to see process names.

Watch the local address: 0.0.0.0:22 means reachable on every interface. 127.0.0.1:5432 is reachable only from the machine itself. A database listening on 0.0.0.0 may be exposed to the network, which is a security finding.

ss replaced the old netstat -tulpn; the options are nearly the same.

ss -tulpn

What is it for?
Lists listening TCP/UDP sockets with ports and processes.
Where is it used?
To answer "is the service really listening, and on which address?"
Why does it matter?
A service may look running yet listen on the wrong address, so connections fail.
sudo ss -tulpn

ss -tln

What is it for?
Shows only TCP listeners, without process info (no sudo needed).
Where is it used?
For quick checks or in scripts.
Why does it matter?
Short and unprivileged; enough to see whether a port is open.
ss -tln | grep 8080

curl -I

What is it for?
Fetches only the response headers of a web server.
Where is it used?
To test whether the service really answers over HTTP.
Why does it matter?
A port can be open while the application does not answer; a code like 200 or 301 shows it does.
curl -I http://127.0.0.1:8080
💡 Tip

Filter ss output: ss -tln | grep LISTEN | wc -l counts how many TCP ports listen.

⚠️ Warning

Do not port-scan servers you do not own. It is unethical and noticeable; work on 127.0.0.1 of your own VM.

Name resolution: hosts, resolv.conf, DNS

A name (example.com) is turned into an IP in this order: first /etc/hosts is checked, then the DNS server listed in /etc/resolv.conf is asked (the order is set by the hosts: line in /etc/nsswitch.conf).

/etc/hosts holds local, hand-written mappings: 192.168.1.50 intranet.lab. Great for tests, but it only affects that machine.

/etc/resolv.conf is usually generated by NetworkManager or systemd-resolved; hand edits can be overwritten on reboot. On Ubuntu you often see 127.0.0.53 in it; resolvectl status shows the real server.

Key distinction: if ping 1.1.1.1 works but ping example.com does not, your network is fine and the problem is DNS.

cat /etc/hosts

What is it for?
Shows local name-to-address mappings.
Where is it used?
When a name goes to an unexpected address.
Why does it matter?
/etc/hosts is read before DNS; a wrong line overrides all resolution.
cat /etc/hosts

cat /etc/resolv.conf

What is it for?
Shows the DNS servers (nameserver) and search domain (search) in use.
Where is it used?
First file to check when names do not resolve.
Why does it matter?
A wrong or unreachable nameserver line breaks all name resolution.
cat /etc/resolv.conf

getent hosts

What is it for?
Resolves a name the way the system really does (hosts + DNS).
Where is it used?
To test what applications will see.
Why does it matter?
It also honours /etc/hosts, so it is more accurate than tools that only query DNS.
getent hosts localhost

resolvectl status

What is it for?
Shows per-interface DNS servers on systemd-resolved systems.
Where is it used?
On Ubuntu and newer Rocky/Alma when resolv.conf does not tell enough.
Why does it matter?
Reveals the real DNS server behind 127.0.0.53.
resolvectl status
💡 Tip

Back up before changing: sudo cp /etc/hosts /etc/hosts.bak.

⚠️ Warning

One wrong nameserver line breaks all name resolution. On a production machine configure DNS via NetworkManager (nmcli) or netplan instead of editing /etc/resolv.conf.

Firewall: firewalld and ufw

Even if a service listens, the firewall may block the port. Rocky/Alma/RHEL use firewalld (firewall-cmd), Ubuntu/Debian use ufw.

In firewalld changes are runtime by default: effective immediately but lost on reload or reboot. To make them permanent add --permanent and run --reload. ufw rules are permanent automatically.

Read first: firewall-cmd --list-all or ufw status verbose. Then change.

SELinux (Rocky) and AppArmor (Ubuntu) are a separate layer; opening the port does not always mean the service may use it, but that is outside this module.

firewall-cmd --list-all

What is it for?
Shows allowed services and ports of the active zone.
Where is it used?
On Rocky/Alma/RHEL when a port is not reachable from outside.
Why does it matter?
You see at a glance which services or ports are allowed; read-only and safe.
sudo firewall-cmd --list-all

firewall-cmd --add-port

What is it for?
Opens a port; without --permanent it is runtime only.
Where is it used?
When you must expose a service to the outside.
Why does it matter?
Try at runtime first and make permanent once it works; mistakes disappear with a reload.
sudo firewall-cmd --add-port=8080/tcp --timeout=300

ufw status verbose

What is it for?
Shows the firewall state and rules on Ubuntu/Debian.
Where is it used?
When auditing rules on an Ubuntu server.
Why does it matter?
inactive means the firewall is off; active shows the default policy.
sudo ufw status verbose
💡 Tip

On Rocky a rule added with --timeout=300 disappears after 5 minutes; if you make a mistake it heals itself.

⚠️ Warning

When changing the firewall over SSH keep a second SSH session open and use --timeout first. Before ufw enable allow SSH with sudo ufw allow 22/tcp.

⛔ Danger

Applying a rule remotely that closes the SSH port or sets the default policy to deny locks you out. Take a VM snapshot first (module 0.2) and keep console access ready.

Diagnosis ladder: bottom to top

Solve "no internet" layer by layer; the first failing step is where the problem is: (1) is the interface UP with an address? (2) does a ping to the gateway work? (3) does a ping to an outside IP (1.1.1.1) work? (4) does the name resolve? (5) does the service listen and does the firewall allow it?

ping uses ICMP; some networks block ICMP, so a failed ping does not always mean no connectivity. Also try the real service with curl -I.

Constant ping needlessly burdens the target; limit the count with -c 3.

ping -c 3

What is it for?
Sends 3 ICMP packets to the target and measures the reply time.
Where is it used?
To test gateway, outside IP and name separately.
Why does it matter?
Shows which layer is broken, one at a time.
ping -c 3 1.1.1.1

cut -d

What is it for?
Splits a line into fields by a delimiter and takes the field you want.
Where is it used?
To pull one value such as address, port or prefix out of output.
Why does it matter?
You pass the value into a file or the next command without copying by hand.
echo 192.168.1.42/24 | cut -d/ -f2

sort -n | uniq

What is it for?
Sorts lines numerically and removes duplicates.
Where is it used?
When producing a clean list of listening ports.
Why does it matter?
Gives a tidy, duplicate-free list for reports and comparison.
sort -n ~/net/ports.txt | uniq
💡 Tip

Write your findings into a report: hostname > ~/net/report.txt, then append with >>. It makes pasting into a support ticket easy.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

These steps run on your own VM and only read. Outputs are specific to you; IPs and interface names may differ. If a command is missing, install sudo dnf install iproute bind-utils on Rocky or sudo apt install iproute2 dnsutils on Ubuntu.

Address and gateway

Read your interfaces and route and paste the output.

ip -br a
ip r

Expected output example

lo      UNKNOWN  127.0.0.1/8
ens3    UP       192.168.1.42/24
default via 192.168.1.1 dev ens3 proto dhcp metric 100
192.168.1.0/24 dev ens3 proto kernel scope link src 192.168.1.42
My output looks different
  • The interface may be called eth0, ens3 or enp0s3; what matters is the address and the default via line.
  • If there is no default line the machine has no gateway; check the VM's network mode (NAT/Bridge).

Listening services

List which services listen and find SSH.

sudo ss -tulpn
ss -tln

Expected output example

Netid State  Local Address:Port Process
tcp   LISTEN 0.0.0.0:22         users:(("sshd",pid=812,fd=3))
...
My output looks different
  • Without sudo the process name (Process column) stays empty.
  • If ss is missing install iproute/iproute2; if there is no LISTEN line the service is not running.

Name resolution chain

Read hosts and resolv.conf, then resolve a name the way the system does.

cat /etc/hosts
cat /etc/resolv.conf
resolvectl status | head -n 15
getent hosts localhost

Expected output example

127.0.0.1 localhost
nameserver 127.0.0.53
...
::1             localhost
My output looks different
  • If resolvectl is missing (old or minimal system) skip that line; resolv.conf is enough.
  • Seeing nameserver 127.0.0.53 on Ubuntu is normal; the real server is listed in resolvectl status.

Diagnosis ladder

Ping the gateway, an outside IP and a name, 2 packets each. Replace 192.168.1.1 with your own gateway.

ping -c 2 192.168.1.1
ping -c 2 1.1.1.1
ping -c 2 example.com

Expected output example

2 packets transmitted, 2 received, 0% packet loss
My output looks different
  • If the IP answers but the name does not, the problem is DNS (/etc/resolv.conf).
  • If none answer, check address/gateway with ip a and ip r first; some networks block ICMP, so also try curl -I https://example.com.

Create your own listener and see it

Start a temporary web server on 127.0.0.1 only, see it with ss, test it with curl, then stop it.

python3 -m http.server 8080 --bind 127.0.0.1 &
sleep 1
ss -tln | grep 8080
curl -I http://127.0.0.1:8080
kill %1

Expected output example

LISTEN 0 5 127.0.0.1:8080 0.0.0.0:*
HTTP/1.0 200 OK
My output looks different
  • If python3 is missing it needs installing; you can skip and paste your ss -tln output instead.
  • If the port is busy use 8081. When done, verify with jobs that no background job remains.

Read the firewall (do not change it)

Read your distribution's firewall state. Add no rule for now. Before changing rules take a VM snapshot (module 0.2) and keep a second SSH session open.

# Rocky / Alma / RHEL
sudo firewall-cmd --state
sudo firewall-cmd --list-all
# Ubuntu / Debian
sudo ufw status verbose

Expected output example

running
public (active)
  services: cockpit dhcpv6-client ssh
# or: Status: inactive
My output looks different
  • The command that does not belong to your distribution prints command not found; that is normal, run the other one.
  • not running or inactive means the firewall is off; you do not need to change that in this lab.

Self-test

Which command shows the default gateway?

ip r shows the routing table; the default via ... line is the gateway. ip a shows addresses, ss listening ports, /etc/hosts name mappings.

In ss -tulpn output a database listens on 127.0.0.1:5432. Who can connect to it?

127.0.0.1 is the loopback address; the service is reachable locally only. Exposed to the outside is 0.0.0.0 or an external interface address.

In which order is a name usually resolved?

The hosts: line in nsswitch.conf sets the order; by default the file (/etc/hosts) comes first, then DNS.

What happens if you run firewall-cmd --add-port=8080/tcp without --permanent?

The default is the runtime configuration: effective at once, not persistent. To make it permanent you need --permanent and --reload.

Summary

  • ip a shows addresses, ip r the routes and the default gateway.
  • ss -tulpn shows listening services; 127.0.0.1 is local only, 0.0.0.0 is every interface.
  • Name resolution: /etc/hosts → /etc/resolv.conf → DNS server.
  • Read the firewall first; in firewalld separate runtime from permanent, and over SSH use --timeout and a second session.
  • Diagnosis: address → gateway → outside IP → name → service and firewall.

Key terms

IP address
The address of an interface on the network, e.g. 192.168.1.42.
prefix / subnet mask
Separates the network and host part of an address; /24 = 255.255.255.0.
gateway
The router address to which packets for destinations outside the local network are sent.
loopback
The machine itself: the lo interface, 127.0.0.1.
port
A number that selects a service on a machine; 22 SSH, 80 HTTP, 443 HTTPS.
LISTEN
A service waiting for connections on a specific address and port.
DNS
The system that translates names into IP addresses.
nameserver
A DNS server defined in /etc/resolv.conf.
runtime / permanent
Temporary (until reload) and persistent configuration in firewalld.
ICMP / ping
A simple network protocol that measures reachability and latency.

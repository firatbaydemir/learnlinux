2.4 Copy and Move

Copy files and folders with cp, move or rename them with mv, and protect yourself from overwrite traps with -i, -n and -v.

What will you learn in this module?

  • You copy files and (with -r) folders using cp; for backups you use cp -a.
  • You move or rename files and folders with mv.
  • You think about whether the target exists and control overwriting with -i, -n and -v.

Copying: cp

cp SOURCE TARGET creates a copy of the source; the source stays where it is. If the target is an existing folder, the copy goes inside it; otherwise the target becomes the new file name.

Copying folders needs -r (recursive); without it cp skips the folder and prints an error. If you also want to keep ownership, permissions and timestamps, use cp -a (archive), the safest choice for backups.

cp

What is it for?
Copies a file; the source is unchanged.
Where is it used?
To make a backup before editing a file or to put it elsewhere.
Why does it matter?
If the original breaks, you still have a copy.
cp draft.txt draft_copy.txt

cp -r

What is it for?
Copies a folder including its contents.
Where is it used?
When backing up a project or photo folder.
Why does it matter?
Without -r a folder is not copied.
cp -r photos backup/

cp -a

What is it for?
Archive copy: keeps subfolders, permissions, owner and timestamps.
Where is it used?
For real backups and when copying system files.
Why does it matter?
The copy is as identical to the original as possible.
cp -a photos backup/
💡 Tip

After copying, check both the source and the target with ls.

Moving and renaming: mv

mv SOURCE TARGET moves a file: the source disappears and shows up at the target. Linux has no separate 'rename' command; moving within the same folder is renaming (mv old.txt new.txt).

Folders need no -r. With several sources the last argument must be an existing folder: mv a.txt b.txt folder/. Within one filesystem mv does not copy data, it only changes the entry, so it is very fast.

mv

What is it for?
Moves a file or folder to another folder.
Where is it used?
When organising files or fixing a misplaced file.
Why does it matter?
Leaves no copy behind and takes no extra space.
mv wrong/report.txt inbox/

mv old new

What is it for?
Renames in the same folder (if the target does not exist).
Where is it used?
To fix a file or folder name.
Why does it matter?
Renaming = moving within the same place.
mv todo.txt tasks.txt

mv a b folder/

What is it for?
Moves several files into a folder in one command.
Where is it used?
Bulk organising.
Why does it matter?
One command, fewer mistakes.
mv inbox/mail1.txt inbox/mail2.txt backup/
💡 Tip

Make sure the target folder exists before moving: if it does not, mv a.txt folder renames the file to folder!

Overwriting and safety options

If a file with the same name exists at the target, cp and mv overwrite it without asking; the old content does not come back. This is the most common way to lose data silently.

Three safety options: -i (interactive) asks before overwriting, -n (no-clobber) leaves existing files alone, -v (verbose) prints what it does line by line. On many distributions cp and mv are aliased to -i for root, but not for a normal user.

cp -i

What is it for?
Asks for confirmation (y/n) before overwriting an existing target.
Where is it used?
When you are not sure whether the target exists.
Why does it matter?
Prevents accidental data loss.
cp -i tasks.txt draft.txt

cp -n

What is it for?
Never overwrites an existing file.
Where is it used?
In bulk copies, to protect older files.
Why does it matter?
Quiet but safe: the target stays unchanged.
cp -n tasks.txt draft.txt

cp -v

What is it for?
Prints every file that is copied.
Where is it used?
In multi-file operations to see what happened.
Why does it matter?
Makes it easy to verify the result.
cp -v tasks.txt tasks_v.txt

mv -i

What is it for?
Asks before overwriting when moving.
Where is it used?
When moving into a folder that may hold a file with the same name.
Why does it matter?
The file at the target is not lost.
mv -i draft.txt backup/
💡 Tip

For permanent safety you can define alias cp='cp -i' and alias mv='mv -i' (added to your shell configuration file).

⚠️ Warning

cp a b and mv a b overwrite b without asking if it exists. Look with ls b first or add -i / -n.

⛔ Danger

Typing a wrong target (for example mv notes.txt /etc/hosts) can destroy an important system file. Take a VM snapshot before experimenting near system folders; without privileges the command simply fails.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

On your VM work in a safe folder called ~/vmlab; never experiment with cp and mv in folders that hold real data.

Copy a file

Create a file, copy it and paste the ls -l output.

mkdir -p ~/vmlab && cd ~/vmlab
echo "original content" > original.txt
cp original.txt copy.txt
ls -l

Expected output example

total 8
-rw-r--r--. 1 student student 17 Jan 10 10:00 copy.txt
-rw-r--r--. 1 student student 17 Jan 10 10:00 original.txt
My output looks different
  • Date, time and owner may differ; copy.txt and original.txt must appear.
  • The . mark (SELinux) appears only on Rocky/Alma, not on Ubuntu.

Copy a folder

Create a project folder, back it up with cp -r and paste the ls -R output.

cd ~/vmlab
mkdir -p project/src
touch project/src/main.c
cp -r project project_backup
ls -R

Expected output example

.:
copy.txt  original.txt  project  project_backup

./project:
src
...
My output looks different
  • If you get cp: -r not specified you forgot -r.
  • The order may differ; both project and project_backup must appear.

Move and rename

Rename the file, then move it into a new folder and paste the result.

cd ~/vmlab
mv copy.txt renamed.txt
mkdir moved
mv renamed.txt moved/
ls . moved

Expected output example

.:
moved  original.txt  project  project_backup

moved:
renamed.txt
My output looks different
  • If you see mv: cannot stat the source name is wrong; look with ls first.
  • Without creating moved/ first, mv renamed.txt moved/ fails.

Prevent overwriting

Show with -n that an existing file is kept. Careful: without -n the content would be lost.

cd ~/vmlab
echo "keep me" > keep.txt
echo "new" > other.txt
cp -n other.txt keep.txt
cat keep.txt

Expected output example

keep me
My output looks different
  • If you see new, -n was not typed or your cp is very old; try cp -i and answer n.
  • With -i, answer the overwrite 'keep.txt'? question with n.

Clean up

Delete the working folder. Look inside first; if no errors, press "Done".

ls -R ~/vmlab
rm -r ~/vmlab
ls ~/vmlab

Expected output example

ls: cannot access '/home/student/vmlab': No such file or directory
My output looks different
  • If you see rm: cannot remove ... Is a directory, you forgot -r.

Self-test

Why does cp photos backup/ fail for a folder?

cp skips folders by default; use cp -r (or cp -a) to copy them with their contents.

Which command renames a file within the same folder?

On Linux renaming is moving within the same folder: mv old new.

What does cp -i a b do when the target already exists?

-i (interactive) asks for confirmation before overwriting. To never overwrite without asking, use -n.

Which option best keeps permissions and timestamps when making a backup?

cp -a (archive) copies recursively and preserves permissions, owner and timestamps.

Summary

  • cp source target copies, cp -r copies folders, cp -a also keeps permissions.
  • mv source target moves; in the same folder it renames, and folders need no -r.
  • If the target exists, cp and mv overwrite without asking; -i asks, -n protects, -v shows.
  • Check with ls whether the target exists and where things end up.

Key terms

source / target
The item being copied or moved / where it goes.
recursive (-r)
Processing a folder with its subfolders and contents.
overwrite
Replacing the content of a same-named target file with new content.
archive copy (-a)
A recursive copy that preserves permissions, owner and timestamps.
rename
Changing a name with mv within the same folder.

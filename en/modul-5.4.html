5.4 Job Control

Manage shell jobs in the foreground or background, cancel with Ctrl+C, pause with Ctrl+Z, and use nohup when appropriate.

What will you learn in this module?

  • You distinguish foreground, background, and stopped shell jobs.
  • You manage the current terminal's jobs with jobs, bg, and fg.
  • You understand what nohup does and what it does not replace.

Foreground, Ctrl+C, and Ctrl+Z

A foreground command occupies the terminal. Ctrl+C usually sends SIGINT to cancel it; Ctrl+Z sends SIGTSTP and pauses the job. A stopped job is not finished and may still hold resources.

Adding & to the end of a command starts it in the background. That does not make it independent of the terminal; closing the session can still affect it.

sleep 300

What is it for?
Waits for five minutes in the foreground and keeps the terminal busy.
Where is it used?
To safely try how a foreground job behaves.
Why does it matter?
It demonstrates the difference between Ctrl+C and Ctrl+Z.
sleep 300

sleep 300 &

What is it for?
Starts the sleep command in the background.
Where is it used?
When you want to keep entering commands in the terminal.
Why does it matter?
The shell prints a job number and PID.
sleep 300 &
💡 Tip

Do not forget a stopped job: find it with jobs -l and resume or stop it according to its purpose.

jobs, bg, and fg

jobs -l lists jobs only in the current shell session. bg %1 resumes a job in the background; fg %1 brings it to the foreground. %1 is the shell job number from jobs, not a PID.

A background job may continue writing to the terminal. The shell reports when it finishes. Do not guess the job number; check jobs first.

jobs -l

What is it for?
Lists the current shell's jobs with their states and PIDs.
Where is it used?
When looking for stopped or background jobs.
Why does it matter?
You can see the job number and state before choosing the correct job.
jobs -l

bg %1 / fg %1

What is it for?
Resumes a selected job in the background or brings it to the foreground.
Where is it used?
When resuming a job or reclaiming terminal control.
Why does it matter?
It changes how the same job interacts with the terminal.
bg %1
💡 Tip

jobs gives the job number; ps or jobs -l shows the PID. They are not interchangeable.

Session independence: nohup

nohup starts a command so that it ignores SIGHUP, which can help it continue after a session closes. A common pattern redirects output to a file and starts the command with &.

nohup is not a job monitor or service manager. Use systemd for long-running production services; use tmux or screen for interactive work across disconnected SSH sessions. Stop test jobs and inspect their output.

nohup command > job.log 2>&1 &

What is it for?
Protects the command from SIGHUP, redirects output to a file, and starts it in the background.
Where is it used?
When a short, non-interactive job needs to outlive a session.
Why does it matter?
Terminal output is retained and the shell is freed.
nohup ./backup.sh > backup.log 2>&1 &

tail -n 20 job.log

What is it for?
Shows the job's most recent output lines.
Where is it used?
When checking progress or error messages.
Why does it matter?
You can inspect the log without bringing the job to the foreground.
tail -n 20 backup.log
⚠️ Warning

Test only in your own VM with a short job. nohup does not stop the job automatically; track its PID and log file.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Run the examples in your own test VM. A shell job belongs to that shell session; stop test jobs you no longer need.

Stop a job

Start sleep in the foreground. Press Ctrl+Z while it runs, then check the shell job with the command below.

sleep 300
# After pressing Ctrl+Z:
jobs -l

Expected output example

[1]+ Stopped sleep 300
My output looks different
  • The job number may not be 1; use your own jobs -l output.
  • Make sure your terminal emulator sends Ctrl+Z to the shell.

Background and clean up

First verify the job number with jobs -l. Replace %1 in the example with the correct number, resume it in the background, and then clean it up.

bg %1
jobs -l
kill %1

Expected output example

The job appears as Running.
My output looks different
  • Replace %1 if your job number is different.
  • kill %1 signals this shell job; use it only for the test sleep job.

A short nohup job

Redirect the output of a short command with nohup, wait for it to finish, and read the file.

nohup sh -c 'sleep 2; echo done' > ~/job-output.txt 2>&1 &
sleep 3
cat ~/job-output.txt

Expected output example

done
My output looks different
  • If the command is still running, wait a few seconds and run cat ~/job-output.txt again.
  • If you get a path or permission error, make sure the destination is inside your home directory.

Self-test

What does Ctrl+Z do to a running job?

Ctrl+Z usually sends SIGTSTP; the job pauses but is not complete.

What does %1 mean in bg %1?

The percent-prefixed number is the shell job number shown by jobs.

What does nohup provide?

nohup starts a command to ignore SIGHUP; it is not a service manager by itself.

What is the difference between a job number and a PID?

A shell job number belongs to the current session; a PID identifies the system process.

Summary

  • Ctrl+C usually cancels a job; Ctrl+Z pauses it.
  • jobs, bg, and fg manage the current shell's jobs; %N is a shell job number.
  • nohup protects against SIGHUP but does not replace a service manager; redirect output and monitor the job.

Key terms

foreground
An interactive job that owns terminal control.
background job
A job running in the shell without terminal control.
SIGHUP
A signal processes may receive when a session or terminal connection closes.

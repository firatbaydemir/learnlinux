3.2 Redirection and Pipes

A pipe connects the output of one command to the input of the next. Small tools combined this way solve big problems.

What will you learn in this module?

  • You chain commands with | into pipelines.
  • You count, sort and deduplicate with wc, sort and uniq.
  • You combine pipes and redirection, and split a stream with tee.

The pipe: command | command

| connects stdout of the left command to stdin of the right one. Nothing is written to disk in between. Each tool does one thing; the pipe combines them.

Only stdout travels through a pipe. Error messages (stderr) still go to the screen unless you add 2>&1 before the pipe.

wc -l

What is it for?
Counts lines.
Where is it used?
At the end of a pipeline to count results.
Why does it matter?
Answers 'how many?'.
cat logs/app.log | wc -l

grep

What is it for?
Keeps only lines that match a pattern.
Where is it used?
To filter logs and lists.
Why does it matter?
Reduces a big stream to the interesting lines.
grep ERROR logs/app.log | wc -l

head / tail

What is it for?
Shows the first / last lines.
Where is it used?
To see the top or bottom of a result.
Why does it matter?
Keeps output short.
sort -n data/nums.txt | tail -n 1
Tip

Build a pipeline step by step: run the first command, check the output, then add the next |.

sort, uniq and tee

uniq only collapses adjacent duplicate lines, so you almost always run sort first. uniq -c prefixes each line with its count; sort -rn then ranks them by that number.

sort compares text by default, so 10 comes before 9. Use sort -n for numbers. tee file writes the stream to a file and passes it on, like a T-junction.

sort

What is it for?
Sorts lines; -n numeric, -r reverse, -u unique.
Where is it used?
Before uniq or to rank values.
Why does it matter?
Brings similar lines together.
sort data/fruits.txt

uniq -c

What is it for?
Collapses adjacent duplicates and counts them.
Where is it used?
To build frequency tables.
Why does it matter?
Shows how often each line occurs.
sort data/fruits.txt | uniq -c

tee

What is it for?
Saves the stream to a file and also passes it on.
Where is it used?
To keep an intermediate result of a pipeline.
Why does it matter?
You see and store the data in one go.
grep ERROR logs/app.log | tee all_errors.txt | wc -l
Tip

The classic ranking: sort | uniq -c | sort -rn.

Warning

uniq without sort leaves duplicates that are not next to each other.

Error stream and pipelines

A pipe only carries stdout. With ls missing 2>&1 | wc -l the error line is counted too; 2>&1 sends stderr to wherever stdout goes. Order matters: 2>&1 comes before the pipe.

tee normally overwrites the file; tee -a appends. In a long pipeline, saving an intermediate result with tee lets you inspect it when a stage looks wrong without rerunning everything.

2>&1 |

What is it for?
Feeds error messages into the pipe as well.
Where is it used?
When filtering output and errors as one stream.
Why does it matter?
Errors do not vanish on screen; grep/wc see them too.
ls data nofile 2>&1 | wc -l

tee -a

What is it for?
Appends the stream to a file and passes it on.
Where is it used?
When accumulating a record of a repeated job.
Why does it matter?
Older records are not erased.
grep ERROR logs/app.log | tee -a all_errors.txt | wc -l

sort -u

What is it for?
Sorts and removes duplicates in one step.
Where is it used?
When you want a unique value list and no counts.
Why does it matter?
Shorter than sort | uniq.
sort -u data/fruits.txt
Tip

When debugging: first cmd 2>&1 | head, then silence unwanted errors with 2>/dev/null.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

On your VM these pipelines only read; the only files written are ones you create in your home directory.

Count with a pipe

Count how many entries /etc has and paste the number.

ls /etc | wc -l

Expected output example

187
My output looks different
  • The number depends on your system; any number is fine.

Extract and sort users

Take the first field of /etc/passwd, sort it and show the first five names.

cut -d: -f1 /etc/passwd | sort | head -n 5

Expected output example

_apt
backup
bin
daemon
games
My output looks different
  • Names differ per distribution; only the alphabetical order matters. Use | grep root to check that root exists.
  • cut is covered in detail in module 3.5; here it is enough to know -d: (delimiter) and -f1 (1st field).

Frequency table

Count which login shells are used in /etc/passwd and rank them.

cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn

Expected output example

     24 /usr/sbin/nologin
      3 /bin/bash
      1 /bin/sync
My output looks different
  • Counts and shells vary per system.
  • If you see only one line, check that sort comes before uniq -c.
  • cut -d: -f7 takes the seventh field (login shell); cut is covered in module 3.5.

Keep a copy with tee

Save a listing with tee while counting it; check the file. If it worked press "Done".

ls /etc | tee ~/etc_list.txt | wc -l
head -n 3 ~/etc_list.txt
My output looks different
  • If etc_list.txt is empty, check that you wrote ~/etc_list.txt after tee.

Quick exercises (simulator)

Optional: warm up before the VM, or practise without one, in the in-browser virtual terminal. Tasks are verified automatically.

Tasks get harder from warm-up to ticket. Badges show the difficulty.

Warm-up

  1. Warm-upEasy

    Count the lines of logs/app.log; read the file with cat and pipe its output to the counter.

    Hint

    Join cat and wc -l with |.

    Solution
    cat logs/app.log | wc -l

  2. Warm-upEasy

    Sort data/fruits.txt alphabetically with sort.

    Hint

    Equal lines appear next to each other.

    Solution
    sort data/fruits.txt

  3. Warm-upEasy

    Count how many entries the data folder has.

    Hint

    ls -1 writes each name on its own line; count its output with wc -l.

    Solution
    ls -1 data | wc -l

Guided lab

  1. Guided labMedium

    Find the number of ERROR lines in the log.

    Hint

    Filter with grep first, then count with wc -l.

    Solution
    grep ERROR logs/app.log | wc -l

  2. Guided labMedium

    Remove the duplicates from data/fruits.txt.

    Hint

    Use sort, then uniq; duplicates must be adjacent.

    Solution
    sort data/fruits.txt | uniq

  3. Guided labMedium

    Count how often each fruit appears in data/fruits.txt.

    Hint

    sort, then uniq -c; the number in front is the count.

    Solution
    sort data/fruits.txt | uniq -c

  4. Guided labMedium

    Save all ERROR lines to the file errors.txt.

    Hint

    Redirect the grep output with >; check with cat errors.txt.

    Solution
    grep ERROR logs/app.log > errors.txt

Predict

First predict the result (in your head or on paper), then run the command. The gap between prediction and real output is the best learning moment.

  1. PredictMedium

    Predict: what is the first line of sort data/nums.txt | head -n 1? 2 or 10? Run it to verify.

    Hint

    Plain sort compares text, not numbers.

    Solution
    sort data/nums.txt | head -n 1

  2. PredictMedium

    Predict: which number does sort -n data/nums.txt | tail -n 1 print? Run it to verify.

    Hint

    -n sorts numerically; the last line is the largest.

    Solution
    sort -n data/nums.txt | tail -n 1

Debug

  1. DebugMedium

    Debug: uniq data/unsorted.txt still shows duplicates. Write the unique lines (a, b) to ~/unique.txt.

    Hint

    First sort, then uniq, the result into the file with >.

    Solution
    sort data/unsorted.txt | uniq > unique.txt

Mini project

  1. Mini projectHard

    Mini project: build the report report.txt with the ERROR lines of the log counted, most frequent first.

    Hint

    Four stages: filter with grep, sort, count with uniq -c, rank with sort -rn; then redirect with >.

    Solution
    grep ERROR logs/app.log | sort | uniq -c | sort -rn > report.txt

Challenge

  1. ChallengeHard

    Challenge: in a single pipeline save all ERROR lines to all_errors.txt and also print how many there are (use tee).

    Hint

    grep ... | tee all_errors.txt | wc -l.

    Solution
    grep ERROR logs/app.log | tee all_errors.txt | wc -l

Ticket

  1. TicketHard

    Ticket: Management wants to know how many different users appear in data/access.txt. Write only the number into ~/users_count.txt.

    Hint

    sort | uniq | wc -l, then redirect with >.

    Solution
    sort data/access.txt | uniq | wc -l > users_count.txt

Self-test

What does the pipe | connect?

The pipe feeds the left command's stdout into the right command's stdin.

Why is sort used before uniq?

Sorting makes identical lines adjacent.

What does tee out.txt do in a pipeline?

tee splits the stream like a T-piece.

Which command prints the largest number of a file with one number per line?

sort -n ranks numerically; the last line is the largest.

What does sort | uniq -c produce?

sort groups identical lines, uniq -c prefixes each group with its count.

Which command prints the first 3 lines of a file?

head -n N prints the first N lines, tail -n N the last N.

What is the difference between cmd | tee -a log.txt and tee log.txt?

tee overwrites by default; -a (append) adds to the existing content.

What is the difference between sort -n and plain sort?

Plain sort sorts as text (10 < 2); -n sorts numerically (2 < 10).

With ls no_such_dir | wc -l the error message still shows on screen. Why?

| connects only channel 1 (stdout) to the next command's input. stderr is a separate channel and goes to the screen unless merged with 2>&1.

Summary

  • cmd1 | cmd2 passes stdout of cmd1 as stdin to cmd2.
  • sort | uniq -c | sort -rn builds a frequency ranking.
  • sort -n sorts numerically; plain sort sorts as text.
  • tee stores a stream in a file while passing it on.

Key terms

pipe
Connects the output of one command to the input of another.
pipeline
A chain of commands joined by pipes.
filter
A command that reads stdin and writes a changed stream to stdout.
tee
Writes a stream to a file and to stdout.

4.4 Permission Basics

Read ls -l output and manage file and directory permissions correctly with chmod, chown and umask.

What will you learn in this module?

  • You read the type character, the three permission triplets, owner and group in ls -l.
  • You explain that r, w, x mean different things for files and for directories.
  • You know that deleting a file depends on the w+x permission of the parent directory, not of the file.
  • You set permissions with chmod (octal and symbolic) and change ownership with chown/chgrp.
  • You show by calculation that umask is a bit mask, not a subtraction.

Reading ls -l output

ls -l prints one line per file: -rw-r----- 1 student devs 120 Nov 12 10:00 report.txt. The first character is the type: - file, d directory, l symbolic link. The next nine characters are three triplets: owner (u), group (g), others (o). Each triplet is rwx for read, write, execute; a missing permission shows as -.

The two names after the number are owner and group (student devs); the 1 before them is the hard link count. The system checks in order: if you are the owner, only the owner triplet applies; otherwise, if you are in the group, the group triplet applies; otherwise the others triplet. root and processes with relevant capabilities can bypass many discretionary access-control (DAC) checks; other controls such as SELinux or a read-only mount may still deny access.

id shows your groups. A new group membership only reaches your process after a fresh login (or with newgrp).

ls -l

What is it for?
Lists files with type, permissions, owner, group, size and date.
Where is it used?
First stop for any permission problem.
Why does it matter?
Shows at a glance who may do what.
ls -l

ls -ld

What is it for?
Shows the permissions of the directory itself (not its contents).
Where is it used?
When checking directory permissions.
Why does it matter?
ls -l shared lists the contents; for the directory itself you need -d.
ls -ld shared

stat

What is it for?
Shows file details; permissions in octal and symbolic form.
Where is it used?
When you want to verify the octal value.
Why does it matter?
No need to convert between ls -l and octal in your head.
stat secret.txt

id

What is it for?
Shows user and group IDs.
Where is it used?
For the question 'why can't I access this?'.
Why does it matter?
Determines which triplet applies to you.
id
💡 Tip

Split the permission string into groups of three: rw- r-- --- means owner reads and writes, group reads, others nothing.

r, w, x: on files and on directories

On files: r reads the content, w changes the content, x runs the file as a program. New files are never created executable; for ./script.sh you first need chmod +x.

On directories: r lists the names, x allows entering and reaching entries by name (cd, cat vault/data.txt), w allows creating, deleting and renaming entries. w alone is useless; w needs x too. To reach a path you need x on every directory along it.

Key rule: to delete or move a file, the file's own permissions do not matter; you need w+x on the parent directory. File permissions only control reading and writing the content. So a 644 file inside a 555 directory cannot be deleted, and neither can a 777 file there.

cat

What is it for?
Reads file content; needs r on the file and x on the directories in the path.
Where is it used?
When testing read permission.
Why does it matter?
Unauthorized reads stop with Permission denied.
cat secret.txt

rm

What is it for?
Deletes a file; success depends on w+x of the parent directory.
Where is it used?
When understanding delete failures.
Why does it matter?
The directory permission decides, not the file permission.
rm locked/old.txt

cd

What is it for?
Enters a directory; needs x on the directory.
Where is it used?
For access problems.
Why does it matter?
Without x you cannot get in.
cd vault
💡 Tip

When you say 'I can't delete it', don't look at the file; look at the directory with ls -ld ..

⚠️ Warning

chmod -R 777 is not a fix. It gives everyone write and execute rights, hides the real cause and opens a security hole. First find the real reason with ls -l and id.

chmod: changing permissions

In octal notation you add r=4, w=2, x=1: 7=rwx, 6=rw-, 5=r-x, 4=r--, 0=---. The three digits are for owner, group, others. Common values: 644 (regular file), 755 (program and directory), 600 (private file), 700 (private directory), 664 and 775 (group work).

In symbolic notation you write who (u, g, o, a), operation (+, -, =) and permission (r, w, x): chmod g+w,o-rx shared. Capital X sets x only on directories and on files that are already executable; chmod -R u=rwX,go=rX data makes directories 755 and previously non-executable files 644, while preserving x on files that were already executable.

Only the owner (or root) may change permissions; on someone else's file you get Operation not permitted.

chmod 640

What is it for?
Sets octal permissions: owner rw-, group r--, others ---.
Where is it used?
When you define permissions in one step.
Why does it matter?
The result is explicit and repeatable.
chmod 640 notes.txt

chmod +x

What is it for?
Adds the execute permission.
Where is it used?
When making a script executable.
Why does it matter?
Changes only x, leaves other bits (subject to umask).
chmod +x script.sh

chmod g+w,o-rx

What is it for?
Symbolic: group gains write, others lose read and execute.
Where is it used?
For small corrections.
Why does it matter?
Changes only the bits you name.
chmod g+w,o-rx shared

chmod -R u=rwX,go=rX

What is it for?
Fixes a tree recursively: files 644, directories 755.
Where is it used?
For bulk corrections.
Why does it matter?
Thanks to X, files don't get needless x.
chmod -R u=rwX,go=rX data
💡 Tip

Look at the target with ls -l first; with -R, double-check the end of the path.

⛔ Danger

Running chmod -R with a wrong value on / or ~ breaks the system or your home (e.g. SSH key permissions, sudo). In the VM take a snapshot first and work only inside the practice folder.

chown and chgrp: owner and group

Every file has an owner and a group. Only root may change the owner (sudo chown). A regular user may only set a file's group to a group they belong to; in the simulator we use sudo chgrp for that.

chown alice:devs report.txt sets owner and group together. A typical team setup: group devs, mode 660 on files or 770 on directories; only devs members get access. Finer rules (per-user permissions) use ACLs (getfacl/setfacl); those come in later modules.

sudo chown

What is it for?
Changes the owner (and optionally the group).
Where is it used?
When handing a file over to another user.
Why does it matter?
Only root can do this.
sudo chown alice:devs report.txt

sudo chgrp

What is it for?
Changes only the group.
Where is it used?
When assigning a group to a shared directory.
Why does it matter?
Keeps the owner and controls group access.
sudo chgrp devs team.txt
💡 Tip

Be careful with chown -R on real systems too; verify the path with ls -ld first.

umask: default permissions

New files start from 666, new directories from 777; umask removes bits using a mask: new mode = base & ~umask. This is not subtraction. Examples (file, base 666): umask 022 → 644; 027 → 640; 077 → 600; 002 → 664.

The difference shows when the umask has bits the base lacks: for 025, 666 & ~025 = 642, while subtraction would give 641 (wrong). For 001 the result is 666, subtraction would give 665. Because x is not in the base, files are never created executable.

umask is per process: it applies only in that shell and the programs started from it. To make it permanent, put it in ~/.bashrc (user) or /etc/profile (system).

umask

What is it for?
Shows the current mask in octal (e.g. 0022).
Where is it used?
To understand permissions of new files.
Why does it matter?
Explains why files are created as 644.
umask

umask -S

What is it for?
Shows the mask symbolically: u=rwx,g=rx,o=rx.
Where is it used?
When you want to see the allowed bits directly.
Why does it matter?
Shows what is granted instead of what is removed.
umask -S

umask 027

What is it for?
Sets the mask for this shell: new files 640, directories 750.
Where is it used?
When working closed to outsiders.
Why does it matter?
Affects every new file that follows.
umask 027
💡 Tip

In shared project folders use umask 002: new files 664, directories 775.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Work in your own VM inside the ~/permlab practice folder. Paste the commands in order and paste the output on this page. Take a snapshot before destructive steps.

Read permissions

Read the permission strings of system files and check your identity.

ls -l /etc/passwd /etc/shadow /usr/bin/passwd
ls -ld /tmp /home
id

Expected output example

-rw-r--r-- 1 root root  2345 Nov 12 10:00 /etc/passwd
-rw-r----- 1 root shadow 1234 Nov 12 10:00 /etc/shadow
-rwsr-xr-x 1 root root 59976 Nov 12 10:00 /usr/bin/passwd
drwxrwxrwt 15 root root 4096 Nov 12 10:00 /tmp
My output looks different
  • On Rocky/Alma /etc/shadow may show ----------; that is normal (root bypasses the check).
  • s (setuid) and t (sticky) are special bits; for now just treat them as 'x-like'.

Practice with chmod

Create the practice folder and a file, set the mode to 640 and show the result.

mkdir -p ~/permlab
cd ~/permlab
touch notes.txt
chmod 640 notes.txt
ls -l notes.txt
stat -c '%a %A %U:%G' notes.txt

Expected output example

-rw-r----- 1 student student 0 Nov 12 10:00 notes.txt
640 -rw-r----- student:student
My output looks different
  • stat -c exists only in GNU stat; it does not work on macOS/BSD, you can ignore it.
  • If your user is not student, you will see your own name; that is fine.

Deleting depends on directory permission

Set the directory to 555, try to delete the file inside, then restore the directory permission.

cd ~/permlab
mkdir locked
touch locked/old.txt
chmod 555 locked
rm locked/old.txt
ls -ld locked
chmod 755 locked
rm locked/old.txt
ls locked

Expected output example

rm: cannot remove 'locked/old.txt': Permission denied
dr-xr-xr-x 2 student student 4096 Nov 12 10:00 locked
My output looks different
  • As root the delete succeeds because root bypasses permissions; test as a normal user.
  • The message may be translated (Zugriff verweigert, Erişim engellendi).

Effect of umask

Set the mask to 027 and look at the permissions of a new file and a new directory. Note: this change affects only this terminal session.

cd ~/permlab
umask
umask 027
touch f027.txt
mkdir d027
ls -ld f027.txt d027
umask 022

Expected output example

0022
-rw-r----- 1 student student 0 Nov 12 10:00 f027.txt
drwxr-x--- 2 student student 4096 Nov 12 10:00 d027
My output looks different
  • Your starting umask may be 0002 (Ubuntu with a per-user group); that is normal.
  • In a new terminal the old value returns: umask is per process.

chown and cleanup

Make root the owner of the file, then delete the directory: since you may write to the parent directory, the root-owned file is deleted too.

cd ~/permlab
touch owned.txt
sudo chown root:root owned.txt
ls -l owned.txt
cd ~
rm -r ~/permlab
ls ~/permlab

Expected output example

-rw-r--r-- 1 root root 0 Nov 12 10:00 owned.txt
ls: cannot access '/home/student/permlab': No such file or directory
My output looks different
  • If sudo asks for a password, enter your own.
  • If rm: remove write-protected regular file? appears, type y: deleting the root-owned file depends on the directory permission, not the file permission.
  • Type the rm -r path carefully; never try it on / or ~.

Self-test

Which permission is needed to delete notes.txt?

Deleting removes the directory entry, so you need w+x on the parent directory. The file's own permission does not decide.

With umask 027, what mode does a new file get?

666 & ~027 = 640. For a directory, 777 & ~027 = 750.

What does x on a directory allow?

x on a directory is the traverse permission (cd, passing through a path). Listing needs r.

Why is chmod -R 777 the wrong fix for 'Permission denied'?

777 grants everyone read, write and execute and weakens security. First find the cause with ls -l and id, then grant only the minimum needed.

Summary

  • ls -l: type character + owner/group/others triplets; r=4, w=2, x=1.
  • On directories: r=list, w=create/delete/rename (with x), x=enter/access; deleting a file depends on w+x of its parent directory.
  • chmod works in octal (640) or symbolic (g+w, u=rwX); only root can chown.
  • umask is a mask, not a subtraction: new mode = base & ~umask (file 666, directory 777).
  • chmod -R 777 is not a fix; apply the principle of least privilege.

Key terms

permission triplet
A separate rwx set for owner, group and others.
octal mode
Permissions written as the sum r=4, w=2, x=1, e.g. 644.
umask
Bit mask that defines which permission bits are removed from new files and directories.
owner
The user the file belongs to; may change permissions.
group
A set of users sharing permissions, e.g. devs.
traverse permission
The x bit on a directory; allows passing through the path and access by name.

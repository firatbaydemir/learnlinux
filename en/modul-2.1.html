2.1 The Linux Directory Tree

In Linux everything has its place: fixed directories for configuration, logs, user files and programs. Learn where to look for which file.

What will you learn in this module?

  • You explain that Linux has no C: or D: drive and everything branches under one root directory /.
  • You tell apart the roles of /etc, /home, /root, /var/log, /usr, /bin, /dev, /tmp, /proc and /opt.
  • You move safely through the system with ls, cd and cat and build the "ID card" of a server.

The root of the tree: /

Windows has drives like C: and D:. Linux has just one tree whose root is / (the root directory). Even a new disk or USB stick is mounted onto a branch of this tree.

Where things live is defined by the FHS (Filesystem Hierarchy Standard). That is why you find config files in the same place on Ubuntu and Rocky. You see the root directory with ls /; you change nothing by doing so.

Quick map: /etc configuration, /home users, /var variable data (logs), /usr programs, /tmp temporary files, /proc and /sys virtual kernel files, /dev devices.

ls /

What is it for?
Lists the folders inside the root directory.
Where is it used?
When you first enter a system.
Why does it matter?
You get to know the main branches of the tree.
ls /

cd /

What is it for?
Moves to the root directory.
Where is it used?
As the starting point for absolute paths.
Why does it matter?
Paths starting with / work from anywhere.
cd /

pwd

What is it for?
Prints the full path of the current directory.
Where is it used?
After navigating, to be sure where you are.
Why does it matter?
Prevents actions in the wrong directory.
pwd
💡 Tip

A path starting with / is absolute (/etc/hostname); without it, the path starts in the current directory.

Configuration and users: /etc, /home, /root

/etc holds the configuration files of the system and installed programs: /etc/passwd (users), /etc/hostname (machine name), /etc/fstab (disks), /etc/os-release (distribution). They are plain text files you read with cat.

Personal files of normal users live under /home/<user>, for example /home/student. The administrator root has its own home, /root; only root may enter, others get Permission denied.

/etc/shadow stores password hashes and is readable by root only. cat /etc/shadow as a normal user fails; that is not a fault but protection.

cat /etc/os-release

What is it for?
Shows the name and version of the distribution.
Where is it used?
To find out which Linux you are on; same path on every distribution.
Why does it matter?
You pick the right commands for that distribution.
cat /etc/os-release

cat /etc/hostname

What is it for?
Shows the machine's name.
Where is it used?
When working with several servers, to confirm you are on the right one.
Why does it matter?
Reduces the risk of working on the wrong server.
cat /etc/hostname

ls /home

What is it for?
Lists the home directories of normal users.
Where is it used?
To quickly see which users exist.
Why does it matter?
You see where user data lives.
ls /home
💡 Tip

Always make a backup before changing a config file; in this module you only read.

Logs and virtual files: /var, /proc, /sys

/var holds data that changes while the system runs. Most important is /var/log: system and service logs live here. On RHEL, Rocky and Alma the main log is /var/log/messages, on Ubuntu it is /var/log/syslog. Do not look for logs in /etc: configuration is in /etc, logs in /var/log.

/proc and /sys are not real files on disk. The kernel generates them in RAM on the fly. The numbers in ls /proc are the IDs of running processes (PIDs). cat /proc/cpuinfo shows live CPU data, cat /proc/meminfo memory data.

Use these files for reading only. Browsing around in them or writing to them is not a safe habit.

ls /var/log

What is it for?
Lists the log files.
Where is it used?
The first place to look when troubleshooting.
Why does it matter?
You follow the trail of a problem in the logs.
ls /var/log

cat /proc/cpuinfo

What is it for?
Reads the CPU information from the kernel.
Where is it used?
For hardware and resource checks.
Why does it matter?
As a virtual file it is always up to date.
cat /proc/cpuinfo

find

What is it for?
Searches for files by name below a directory.
Where is it used?
When you do not know which directory a file is in.
Why does it matter?
Instead of guessing, you find the exact path.
find /etc -name sshd_config
💡 Tip

Is the file called messages or syslog? It depends on the distribution; look first with ls /var/log.

⛔ Danger

Writing to files under /proc and /sys, or opening /proc/kcore with cat, can make the system unstable. Only read known files such as cpuinfo, meminfo or version.

Programs and devices: /usr, /bin, /dev, /tmp, /opt

/usr is the big library of installed programs. Most commands live in /usr/bin. On modern distributions /bin is not a separate directory but a symbolic link (symlink) to /usr/bin: ls -ld /bin shows bin -> usr/bin.

/dev holds device files: /dev/sda is a disk, /dev/null is a "black hole" that swallows everything written to it. In ls -l their lines start with c (character device) or b (block device).

/tmp is for temporary files and is usually cleared on reboot. /opt is for third-party software, /srv for data the server publishes. If you cannot find an application, look in /opt, /usr/local and /etc in turn.

ls -ld /bin

What is it for?
Shows the /bin entry itself; the link target appears after ->.
Where is it used?
To tell whether a path is a directory or a link.
Why does it matter?
Explains why the tree can look different between distributions.
ls -ld /bin

ls -l /dev/null

What is it for?
Shows the type and permissions of a device file.
Where is it used?
When examining how hardware appears as a file.
Why does it matter?
You see that in Linux everything is a file.
ls -l /dev/null

ls /opt

What is it for?
Lists the directory for third-party software.
Where is it used?
When looking for a manually installed application.
Why does it matter?
Software outside the package manager often lives here.
ls /opt
💡 Tip

To learn where a command lives, you can type which ls.

⚠️ Warning

/tmp is accessible to everyone. Do not store secrets such as passwords there, and read the path twice before using rm -r even in /tmp.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

In this section you only read; no command changes system files. Output may differ slightly by distribution (Ubuntu / Rocky / Alma / WSL); that is normal.

Explore the root directory

List the contents of the root directory and paste the output.

ls /

Expected output example

bin  boot  dev  etc  home  lib  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
My output looks different
  • The number and order of folders depend on the distribution; etc, var and usr must appear.
  • If the output is a single column, widen the terminal; the content is the same.

Which distribution am I on?

Read the distribution info and paste the output.

cat /etc/os-release

Expected output example

NAME="Rocky Linux"
VERSION="9.4 (Blue Onyx)"
ID="rocky"
...
My output looks different
  • On Ubuntu you see NAME="Ubuntu" and ID=ubuntu; the lines differ but NAME= and ID= are always there.
  • If the file is missing the system is very old; try cat /etc/issue.

Is /bin really a link?

List / in long format and look at the bin line.

ls -l / | grep ' bin'

Expected output example

lrwxrwxrwx. 1 root root 7 ... bin -> usr/bin
My output looks different
  • If the output is empty try ls -ld /bin; on very old distributions /bin is a real directory.
  • If the line starts with l it is a symbolic link.

Virtual files: /proc

Read the first lines of the kernel's CPU information.

head -n 5 /proc/cpuinfo
ls /proc | head -n 10

Expected output example

processor	: 0
vendor_id	: GenuineIntel
...
1
10
...
My output looks different
  • On ARM CPUs (UTM on Apple Silicon) the fields differ; the processor line still appears.
  • On WSL the contents of /proc may be somewhat restricted.

Look at the log directory

List the log files and paste the output.

ls /var/log

Expected output example

anaconda  audit  dnf.log  messages  secure  wtmp ...
My output looks different
  • On Ubuntu you see syslog and auth.log, on Rocky messages and secure.
  • Some files need sudo to read; listing does not.

A file in the temporary directory

Create a test file in /tmp, look at it and delete it right away. Deleting a single file is safe.

echo test > /tmp/lab-test.txt
ls -l /tmp/lab-test.txt
rm /tmp/lab-test.txt

Expected output example

-rw-r--r--. 1 student student 5 ... /tmp/lab-test.txt
My output looks different
  • If you mistyped the name, rm says "No such file"; the name must be lab-test.txt.
  • Do not use -r or wildcards (*) with rm.

A device file

List /dev/null in long format and paste the output.

ls -l /dev/null

Expected output example

crw-rw-rw-. 1 root root 1, 3 ... /dev/null
My output looks different
  • If the line starts with c it is a character device; other permission letters are no problem.
  • If the file is missing you may be in a container; a normal VM always has it.

Self-test

In which directory do you look for system logs?

Logs are constantly growing data and live under /var/log. /etc is for configuration files.

Why is /proc a "virtual" directory?

/proc and /sys are a live interface of the kernel and take no disk space.

In which directory are the configuration files of the system and programs?

/etc is the standard place for configuration files (passwd, hostname, fstab...).

Where are the personal files of student, and where those of root?

Normal users live under /home/<name>; root's home is separately /root.

Summary

  • Linux has a single tree; the root is / and everything hangs below it.
  • /etc configuration, /var/log logs, /home and /root home directories, /usr programs.
  • /proc and /sys are virtual kernel files; /dev is for devices, /tmp for temporary files, /opt for third-party software.
  • When searching, first think about what a directory is for, then verify with ls, cat and find.

Key terms

FHS
Filesystem Hierarchy Standard: defines what each directory is used for.
root directory
The top of the tree, /; all paths branch from here.
absolute path
A full path starting with /, independent of where you are.
symbolic link
A special file pointing to another path; shown with -> in ls -l.
PID
The numeric ID of each running process; appears as a directory name under /proc.

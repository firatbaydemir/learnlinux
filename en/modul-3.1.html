3.1 Streams: stdin, stdout, stderr

Every Linux command has three standard channels: input, output and error. Understanding them is the foundation of redirection and pipes.

What will you learn in this module?

  • You tell stdin (0), stdout (1) and stderr (2) apart.
  • You redirect output and errors to files with >, >> and 2>.
  • You merge or discard streams with 2>&1 and /dev/null.

The three standard channels

A running program has three open channels: stdin (0) reads input, stdout (1) writes the normal result, stderr (2) writes error messages. By default input comes from the keyboard, output and errors go to the screen.

Because both land on the same screen they look mixed, yet they are separate channels. That separation lets you send errors to their own file.

echo

What is it for?
Writes text to stdout.
Where is it used?
For tests and simple output.
Why does it matter?
The simplest stdout example.
echo hello

cat

What is it for?
Writes a file to stdout.
Where is it used?
To see file contents.
Why does it matter?
Reads a file and feeds the channel.
cat lab/names.txt

ls

What is it for?
When asked to list a missing path, the error goes to stderr.
Where is it used?
To see the error channel.
Why does it matter?
The message appears on screen but is not on stdout.
ls lab/missing.txt
💡 Tip

Channel numbers: 0 = input, 1 = output, 2 = error. You use them in redirections.

Redirecting to files

> writes stdout to a file and truncates it. >> appends. 2> redirects only stderr. < feeds a file as stdin.

If output and errors should go to the same file write > file 2>&1: stdout goes to the file first, then stderr is attached to wherever stdout goes. Order matters. /dev/null is a special file that discards everything written to it.

>

What is it for?
Writes stdout to a file; an existing file is emptied.
Where is it used?
To save output.
Why does it matter?
You keep the result for later.
echo hello > out.txt

>>

What is it for?
Appends stdout to the end of a file.
Where is it used?
When keeping logs.
Why does it matter?
Preserves the old content.
echo world >> out.txt

2>

What is it for?
Writes only error messages to a file.
Where is it used?
To collect errors separately.
Why does it matter?
Output stays on screen, errors are saved.
ls lab/missing.txt 2> errors.txt

<

What is it for?
Makes a file the command's input.
Where is it used?
For commands that read input.
Why does it matter?
Reads from a file instead of the keyboard.
cat < lab/names.txt

2>&1

What is it for?
Sends stderr to wherever stdout goes.
Where is it used?
To collect everything in one file.
Why does it matter?
Output and errors are saved together.
ls lab missing_dir > all.txt 2>&1

2>/dev/null

What is it for?
Discards errors.
Where is it used?
To silence harmless errors.
Why does it matter?
Keeps the screen clean.
ls lab missing_dir 2>/dev/null
💡 Tip

Safe habit: decide first whether you need >> or >. A wrong > silently wipes an existing file.

⚠️ Warning

> empties the target file before the command runs. sort file > file destroys the file's content.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

These commands run in your VM's home directory and only write files you create yourself; still, do not reuse the name of an important file.

Separate output and errors

List an existing file and a missing path; write output and errors to separate files, then show both.

ls /etc/hostname /nonexistent > out.txt 2> err.txt
cat out.txt err.txt

Expected output example

/etc/hostname
ls: cannot access '/nonexistent': No such file or directory
My output looks different
  • The error text varies slightly by distribution and language; nonexistent must appear.
  • If out.txt is empty, /etc/hostname does not exist on your system; use /etc/hosts.

Overwrite and append

Create a file with >, append a line with >> and show the result.

echo "line one" > ~/streams.txt
echo "line two" >> ~/streams.txt
cat ~/streams.txt

Expected output example

line one
line two
My output looks different
  • If only line two appears you used > in both commands.

Silence errors

List a directory you cannot read as a normal user together with a file; discard the errors to /dev/null.

ls /root /etc/hostname 2>/dev/null

Expected output example

/etc/hostname
My output looks different
  • If hostname is missing your system has no such file; as long as no error message appears on screen it worked.

Quick exercises (simulator)

Optional: warm up before the VM, or practise without one, in the in-browser virtual terminal. Tasks are verified automatically.

Tasks get harder from warm-up to ticket. Badges show the difficulty.

Warm-up

  1. Warm-upEasy

    Write text to the screen (stdout) with echo hello.

    Hint

    The output appears directly on screen.

    Solution
    echo hello

  2. Warm-upEasy

    Print the file's content to stdout with cat lab/names.txt.

    Hint

    You should see three names.

    Solution
    cat lab/names.txt

  3. Warm-upEasy

    List the missing path lab/missing.txt with ls and read the error message.

    Hint

    That message comes from stderr.

    Solution
    ls lab/missing.txt

Guided lab

  1. Guided labEasy

    Write the text to the file out.txt with echo hello > out.txt.

    Hint

    You see no output; check with cat out.txt.

    Solution
    echo hello > out.txt

  2. Guided labMedium

    Append a second line to the same file with echo world >> out.txt.

    Hint

    >> appends, > overwrites.

    Solution
    echo world >> out.txt

  3. Guided labMedium

    Put the error into errors.txt with ls lab/missing.txt 2> errors.txt.

    Hint

    The error no longer shows on screen.

    Solution
    ls lab/missing.txt 2> errors.txt

  4. Guided labMedium

    Feed the file as stdin with cat < lab/names.txt.

    Hint

    < reads input from a file.

    Solution
    cat < lab/names.txt

Predict

  1. PredictMedium

    Predict: when ls lab/missing.txt > result.txt runs, does the error appear on screen? Is result.txt filled? Run it to verify.

    Hint

    > redirects stdout only; the error is on stderr.

    Solution
    ls lab/missing.txt > result.txt

  2. PredictMedium

    Predict: what does cat lab/names.txt | wc -l print? Run it to verify.

    Hint

    wc -l counts lines; how many lines does the file have?

    Solution
    cat lab/names.txt | wc -l

Debug

  1. DebugMedium

    Debug: ls lab missing_dir > all.txt prints the error on screen and it does not reach all.txt. Make all.txt contain both the listing and the error.

    Hint

    Add 2>&1 at the end of the command.

    Solution
    ls lab missing_dir > all.txt 2>&1

Mini project

  1. Mini projectMedium

    Mini project: build build.log. 1) echo start > build.log 2) ls lab >> build.log 3) ls nothing 2>> build.log. The file must have 3 lines.

    Hint

    The first uses >, the others >> and 2>>.

    Solution
    echo start > build.log
ls lab >> build.log
ls nothing 2>> build.log

Challenge

  1. ChallengeHard

    Challenge: discard the errors of ls lab missing_dir into /dev/null and save the normal output to found.txt.

    Hint

    Two redirections: 2>/dev/null and > found.txt.

    Solution
    ls lab missing_dir 2>/dev/null > found.txt

Ticket

  1. TicketHard

    Ticket: the auditor wants the number of users in lab/names.txt in ~/count.txt (number only).

    Hint

    wc -l < file prints the count without a file name; save with >.

    Solution
    wc -l < lab/names.txt > count.txt

Self-test

Which channel number is stderr?

0 = stdin, 1 = stdout, 2 = stderr.

What does echo x > file do when the file already exists?

> truncates the file; use >> to append.

Which command saves errors to a file and keeps normal output on screen?

2> redirects only stderr.

What is /dev/null for?

/dev/null is a black hole: whatever you write there vanishes.

Summary

  • Three channels: stdin (0), stdout (1), stderr (2).
  • > overwrites, >> appends, 2> redirects errors, < supplies input.
  • 2>&1 merges errors into output; order matters in > file 2>&1.
  • /dev/null discards data.

Key terms

stdin
Standard input, channel 0; keyboard by default.
stdout
Standard output, channel 1; screen by default.
stderr
Standard error, channel 2; error messages.
redirection
Connecting a channel to a file or another channel.
/dev/null
Special file that discards what is written.

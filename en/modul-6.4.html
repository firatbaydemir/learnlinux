6.4 LVM — PV, VG, LV and Extending

No panic when the disk fills up: grow the volume. Practise first in a safe loop-device lab.

What will you learn in this module?

  • You explain the PV → VG → LV layers and what each one does.
  • You build a pool with pvcreate, vgcreate, lvcreate and read it with pvs/vgs/lvs/lvdisplay.
  • You grow a volume and its filesystem together with lvextend -r, and you know XFS cannot shrink.
  • You practise only on file-backed loop devices in a snapshotted VM.

Concepts: PV, VG, LV

With classic partitions the size is fixed. LVM (Logical Volume Manager) pools disks and cuts volumes of any size from the pool. There are three layers: a PV (Physical Volume) is the LVM signature on a disk or partition, a VG (Volume Group) is the pool made of PVs, an LV (Logical Volume) is a volume cut from the pool that looks like a disk.

Order: disk → PV → VG → LV → filesystem (XFS/ext4) → mount. Example names: pool vg_data, volume lv_web, path /dev/vg_data/lv_web. To read the state, these commands are enough; none of them changes anything.

pvs

What is it for?
Lists Physical Volumes in a short table.
Where is it used?
To see which disks belong to a pool.
Why does it matter?
The PFree column shows free space on the PV.
sudo pvs

vgs

What is it for?
Lists Volume Groups; VSize is the total, VFree the free space.
Where is it used?
Before extending, to check the pool has room.
Why does it matter?
If VFree is 0 you must add a PV with vgextend first.
sudo vgs

lvs

What is it for?
Lists Logical Volumes.
Where is it used?
Which volume is in which VG and how big?
Why does it matter?
Gives a quick overview.
sudo lvs

lvdisplay

What is it for?
Shows details of an LV (path, size, status).
Where is it used?
When inspecting a single volume.
Why does it matter?
Lets you verify the LV Path and LV Size fields.
sudo lvdisplay /dev/vg_data/lv_web

lsblk -f

What is it for?
Shows disks, LVM layers, filesystems and mount points as a tree.
Where is it used?
Before every LVM operation.
Why does it matter?
Makes sure you pick the right device.
lsblk -f
💡 Tip

Read first, write second: pvs, vgs, lvs and lsblk -f change nothing; run them before every command that does.

Safe lab: loop devices

Never touch a real disk. You create a file with truncate and attach it with losetup as a loop device (/dev/loop0); LVM treats it as a real disk, but a mistake costs you at most one file.

First take a VM snapshot (module 0.2). Install the tools: on Rocky/Alma sudo dnf install lvm2 xfsprogs, on Debian/Ubuntu sudo apt install lvm2 xfsprogs. Files live in ~/lvm-lab; the loop number may differ, so use the --show output.

truncate -s 300M

What is it for?
Creates a sparse file of the given size.
Where is it used?
For a fake disk image.
Why does it matter?
A safe stand-in for a real disk.
truncate -s 300M ~/lvm-lab/disk1.img

losetup -f --show

What is it for?
Attaches the file to the first free loop device and prints its name.
Where is it used?
When turning an image into a block device.
Why does it matter?
pvcreate only works on block devices.
sudo losetup -f --show ~/lvm-lab/disk1.img

losetup -a

What is it for?
Lists active loop devices and their files.
Where is it used?
To confirm which loop belongs to which file.
Why does it matter?
Prevents writing to the wrong device.
losetup -a

losetup -d

What is it for?
Detaches a loop device.
Where is it used?
When cleaning up the lab.
Why does it matter?
The device must be released before the file is deleted.
sudo losetup -d /dev/loop0
💡 Tip

A sparse image shows 300M in ls -lh but uses almost no disk space.

⚠️ Warning

pvcreate, vgcreate and mkfs erase the target. Check the device name with losetup -a before the command; never type real disk names like /dev/sda in this module.

Creating PV, VG and LV

The order is always the same: pvcreate → vgcreate → lvcreate → filesystem → mount. In the example below the variable LOOP1 holds the losetup output.

lvcreate -L 200M means a fixed size, -l 100%FREE means all remaining space. The RHEL family defaults to XFS, Debian/Ubuntu usually to ext4; both work.

pvcreate

What is it for?
Writes an LVM signature to the device, making it a PV.
Where is it used?
Before adding a disk to a pool.
Why does it matter?
A VG is built only from PVs.
sudo pvcreate $LOOP1

vgcreate

What is it for?
Creates a VG from one or more PVs.
Where is it used?
When building the pool.
Why does it matter?
Volumes are cut from this pool.
sudo vgcreate vg_data $LOOP1

lvcreate

What is it for?
Cuts a named LV from a VG.
Where is it used?
When giving an application its own volume.
Why does it matter?
-n sets the name, -L the size.
sudo lvcreate -L 200M -n lv_web vg_data

mkfs.xfs

What is it for?
Creates an XFS filesystem on the LV (mkfs.ext4 for ext4).
Where is it used?
When preparing a new volume for use.
Why does it matter?
Without a filesystem it cannot be mounted.
sudo mkfs.xfs /dev/vg_data/lv_web

mount

What is it for?
Attaches the volume to a directory.
Where is it used?
Before you start writing data.
Why does it matter?
Files appear in the directory it is mounted on.
sudo mount /dev/vg_data/lv_web /mnt/web
⛔ Danger

mkfs destroys existing data. Never run it on an existing LV or disk; first confirm with lsblk -f that the target is empty and a loop device.

Extending: lvextend -r

When a volume fills up you need two steps: grow the LV, then grow the filesystem. lvextend -r does both. By hand use xfs_growfs <mountpoint> for XFS or resize2fs <device> for ext4; both can grow while mounted.

If the VG has no free space (VFree), first make the new device a PV with pvcreate, add it with vgextend, then run lvextend. Shrinking is problematic: XFS can never shrink; ext4 only when unmounted and after a backup.

lvextend -r

What is it for?
Grows the LV and the filesystem in one go.
Where is it used?
When extending a full volume online.
Why does it matter?
Removes the risk of forgetting the second step.
sudo lvextend -r -L +100M /dev/vg_data/lv_web

xfs_growfs

What is it for?
Grows a mounted XFS up to the LV size.
Where is it used?
When you did not use lvextend -r.
Why does it matter?
XFS takes the mount point as argument.
sudo xfs_growfs /mnt/web

resize2fs

What is it for?
Grows an ext4 filesystem up to the LV size.
Where is it used?
When growing an ext4 volume by hand.
Why does it matter?
Takes the device path as argument.
sudo resize2fs /dev/vg_data/lv_web

vgextend

What is it for?
Adds a new PV to an existing VG.
Where is it used?
When VFree runs out.
Why does it matter?
Grows the pool so the LV can grow.
sudo vgextend vg_data $LOOP2
💡 Tip

-L +100M adds to the current size, -L 300M sets the total size. To take all free space write -l +100%FREE.

Persistent mounts, removal and warnings

To have the volume back after a reboot you need an /etc/fstab line: /dev/vg_data/lv_web /srv/web xfs defaults 0 0. A typo can break booting; back up the file before editing, then test with sudo mount -a. You do not need fstab in the loop lab.

Removal goes in reverse: umount → lvremove → vgremove → pvremove → losetup -d. These commands ask for confirmation and destroy data irrecoverably. Always see the name first with lvs/vgs.

cat /etc/fstab

What is it for?
Shows the filesystems mounted at boot.
Where is it used?
When checking a persistent mount.
Why does it matter?
A wrong line can block booting.
cat /etc/fstab

lvremove

What is it for?
Deletes an LV and its data.
Where is it used?
Only when cleaning up the lab.
Why does it matter?
There is no way back; umount first.
sudo lvremove /dev/vg_data/lv_web

vgreduce

What is it for?
Removes a PV from a VG.
Where is it used?
When detaching a disk from the pool.
Why does it matter?
If the PV holds data, move it first with pvmove.
sudo vgreduce vg_data $LOOP2

pvremove

What is it for?
Wipes the LVM signature from a device.
Where is it used?
Last step of the lab.
Why does it matter?
The device is no longer a PV; refused if still in a VG.
sudo pvremove $LOOP1
⚠️ Warning

lvremove, vgreduce and pvremove can destroy production data on a real server. Take a snapshot/backup first and check the name twice.

⛔ Danger

On a real system with a separate disk a wrong name loses everything. In this module use loop devices only; never try to shrink an XFS volume. The way is backup, recreate, restore.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Do these tasks on your VM. Take a snapshot first. Use loop devices only; never type a real disk name.

Read the current LVM state

Without changing anything, list the existing disks and LVM layers. Paste the output.

lsblk -f
sudo pvs
sudo vgs
sudo lvs

Expected output example

VG   #PV #LV #SN Attr   VSize  VFree
rl     1   2   0 wz--n- <19.00g 0
My output looks different
  • If LVM is missing run sudo dnf install lvm2 (Rocky/Alma) or sudo apt install lvm2 (Debian/Ubuntu).
  • If a default Ubuntu install does not use LVM, empty output is normal; it still proves the commands work.

Build PV, VG and LV on loop devices

After the snapshot, create two fake disks, build a VG and LV, format with XFS and mount. Paste the output.

mkdir -p ~/lvm-lab
truncate -s 300M ~/lvm-lab/disk1.img
truncate -s 300M ~/lvm-lab/disk2.img
LOOP1=$(sudo losetup -f --show ~/lvm-lab/disk1.img)
LOOP2=$(sudo losetup -f --show ~/lvm-lab/disk2.img)
echo $LOOP1 $LOOP2
sudo pvcreate $LOOP1
sudo vgcreate vg_data $LOOP1
sudo lvcreate -L 200M -n lv_web vg_data
sudo mkfs.xfs /dev/vg_data/lv_web
sudo mkdir -p /mnt/web
sudo mount /dev/vg_data/lv_web /mnt/web
sudo vgs vg_data

Expected output example

VG      #PV #LV #SN Attr   VSize    VFree
vg_data   1   1   0 wz--n- 296.00m 96.00m
My output looks different
  • The loop number may not be /dev/loop0; the $LOOP1 variable handles that.
  • If mkfs.xfs is missing on Debian/Ubuntu run sudo apt install xfsprogs, or use mkfs.ext4.
  • In another terminal the variables are gone; find the names with losetup -a and type them by hand.

Grow the volume online

The first disk has 96M free: grow the LV by 90M, then add the second disk to the pool and grow again with the remaining free space. Verify the size with df.

sudo lvextend -r -L +90M /dev/vg_data/lv_web
df -h /mnt/web
sudo vgextend vg_data $LOOP2
sudo lvextend -r -l +100%FREE /dev/vg_data/lv_web
sudo lvs vg_data
df -h /mnt/web

Expected output example

LV     VG      Attr       LSize
lv_web vg_data -wi-ao---- 592.00m
My output looks different
  • If -r fails check that the volume is mounted; grow by hand with sudo xfs_growfs /mnt/web (resize2fs for ext4).
  • Insufficient free space means VFree is used up; run vgextend first.

Clean up the lab

Unmount, remove LV, VG and PVs in order, detach the loop devices and delete the images. If there were no errors, press "Done".

sudo umount /mnt/web
sudo lvremove -y /dev/vg_data/lv_web
sudo vgremove vg_data
sudo pvremove $LOOP1 $LOOP2
sudo losetup -d $LOOP1 $LOOP2
rm ~/lvm-lab/disk1.img ~/lvm-lab/disk2.img

Expected output example

Logical volume "lv_web" successfully removed.
My output looks different
  • On target is busy run cd ~ first and leave no open shell inside /mnt/web.
  • If $LOOP1 is empty in another terminal, find the names with losetup -a and type them by hand.
  • If unsure, revert to the snapshot.

Self-test

What is the correct order of the LVM layers?

A disk becomes a PV, PVs form the VG pool, volumes (LV) are cut from the pool.

Which statement is true?

XFS only grows; to shrink it, back up, recreate and restore.

What does lvextend -r -L +100M /dev/vg_data/lv_web do?

-r (resizefs) grows the filesystem together with the LV.

What is the correct order when cleaning up the loop lab?

Unmount first, then remove from the top down: LV, VG, PV.

Summary

  • LVM: disk → PV → VG → LV → filesystem → mount.
  • Read commands: pvs, vgs, lvs, lvdisplay, lsblk -f.
  • Create: pvcreate, vgcreate, lvcreate, mkfs, mount.
  • Grow: lvextend -r (vgextend first if needed).
  • XFS cannot shrink; lvremove/vgreduce/pvremove destroy data.
  • Practise only on loop devices in a snapshotted VM.

Key terms

PV
Physical Volume: a disk or partition carrying an LVM signature.
VG
Volume Group: a storage pool made of PVs.
LV
Logical Volume: a volume cut from a VG and used like a disk.
VFree
Free space in a VG not yet assigned to any LV.
loop device
A kernel feature that presents a file as a block device.
sparse file
A file that looks large but uses little real disk space.
lvextend -r
Grows the LV and the filesystem on it together.
xfs_growfs
Grows a mounted XFS filesystem.
resize2fs
Resizes an ext2/3/4 filesystem.
fstab
The list of filesystems mounted at boot: /etc/fstab.

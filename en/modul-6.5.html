6.5 Bash Script 1 — Variables, Arguments, Conditions

Write your first Bash script, make it executable, and work with variables, arguments, exit codes and conditions.

What will you learn in this module?

  • You write a script with a shebang, make it executable with chmod +x and start it with ./script.sh.
  • You assign variables and know the difference between single and double quotes, read, $(command) and $(( )).
  • You read arguments with $1, $# and "$@" and check exit codes with $? and exit.
  • You make decisions with if/elif/else, [[ ]] and test, and you use set -euo pipefail as a safety net.

The first script: shebang and execute permission

A script is a text file with commands. The first line, the shebang #!/bin/bash, tells the system which interpreter runs the file. Without the execute bit the file cannot be started directly: ./hello.sh then gives *Permission denied*.

./ means 'the file in this folder'. Linux does not search the current folder for commands, so hello.sh alone gives *command not found*. In this module you create scripts with printf (or a heredoc on your VM) so you can see exactly what is in the file.

#!/bin/bash

What is it for?
The shebang: first line of the file, names the interpreter.
Where is it used?
At the top of every Bash script.
Why does it matter?
The script runs with Bash and not with another shell such as sh.
printf '#!/bin/bash\necho "Hello, Linux!"\n' > ~/bin/hello.sh

chmod +x

What is it for?
Sets the execute bit on a file.
Where is it used?
Once after you create a script.
Why does it matter?
Without it ./script.sh fails with Permission denied.
chmod +x ~/bin/hello.sh

./script.sh

What is it for?
Runs an executable script by path.
Where is it used?
When you start your own scripts.
Why does it matter?
The path (./ or full path) tells the shell where the file is.
~/bin/hello.sh

bash script.sh

What is it for?
Runs a script with Bash directly, no execute bit needed.
Where is it used?
For quick tests and on volumes mounted noexec.
Why does it matter?
Handy for debugging; the shebang is ignored.
bash ~/bin/hello.sh
💡 Tip

Put your own scripts in ~/bin. On Ubuntu and Rocky this folder is added to PATH at login once it exists, so you can start them by name.

⚠️ Warning

Never run a script you downloaded or do not understand. Read it first with cat script.sh. Be especially careful with curl ... | bash and with sudo on a first attempt.

Variables, quoting and arithmetic

A variable is set with NAME=value — no spaces around =. You read it with $NAME. NAME = value does not work: Bash thinks NAME is a command.

Double quotes "..." expand variables, single quotes '...' do not: echo '$HOME' prints the text $HOME. Always quote variables ("$NAME") so file names with spaces stay one word.

$(command) inserts the output of a command, $(( )) calculates integers, read asks the user for input (VM only).

NAME=value

What is it for?
Sets a variable (no spaces around the equals sign).
Where is it used?
At the top of a script for settings and paths.
Why does it matter?
You change a value in one place instead of ten.
NAME=student; echo "Hello $NAME"

"$VAR" and '$VAR'

What is it for?
Double quotes expand the variable, single quotes keep the text.
Where is it used?
In every command that uses variables.
Why does it matter?
Quoting protects against spaces and glob characters in values.
echo '$HOME' "$HOME"

read -r -p

What is it for?
Reads a line of input into a variable.
Where is it used?
In interactive scripts that ask questions.
Why does it matter?
-r keeps backslashes, -p shows a prompt.
read -r -p "Name: " NAME

$(command)

What is it for?
Replaces itself with the output of the command.
Where is it used?
To store output in a variable or use it in text.
Why does it matter?
Lets scripts react to system state.
echo "Host: $(hostname)"

$(( ))

What is it for?
Integer arithmetic.
Where is it used?
Counters, sizes, simple calculations.
Why does it matter?
Bash has no decimals; for those use bc.
echo $((6 * 7))
💡 Tip

A default value is written ${NAME:-default}: it is used when NAME is empty or unset.

Arguments and exit codes

A script receives arguments: $0 is the script name, $1, $2, ... are the arguments, $# is their number and "$@" is the list of all of them, each kept as one word. Quote "$@", otherwise my file becomes two words.

Every command ends with an exit code: 0 means success, anything else means failure. $? holds the code of the last command. In a script you end with exit 0 or exit 1. The simulator cannot run arguments in scripts reliably, so the real runs are in the VM section.

$0 $1 $2

What is it for?
Script name and the first arguments.
Where is it used?
When the script needs input from the caller.
Why does it matter?
One script works for many files or names.
./args.sh alice bob

$# and "$@"

What is it for?
Number of arguments and the list of all arguments.
Where is it used?
To check the count or loop over arguments.
Why does it matter?
"$@" keeps every argument intact, even with spaces.
./args.sh "my file" bob

${1:-guest}

What is it for?
First argument, or guest if none was given.
Where is it used?
For optional arguments.
Why does it matter?
The script does not break when the argument is missing.
NAME="${1:-guest}"

$? and exit

What is it for?
$? is the last exit code, exit N ends a script with code N.
Where is it used?
After commands you want to check, and at the end of scripts.
Why does it matter?
Other scripts, cron and CI decide based on this code.
false; echo $?
💡 Tip

grep returns 1 when nothing matches. That is not an error in the program, just a 'no' answer: grep carol ~/users.txt; echo $? prints 1.

Conditions: if, elif, else

if runs a command and looks at its exit code. The command is usually [ ... ] (the same as test) or Bash's [[ ... ]]. Spaces inside the brackets are required: [ -f "$1" ].

Useful tests: -f regular file, -d directory, -x executable, -z string is empty, -n string is not empty. For numbers use -eq -ne -lt -le -gt -ge, for text == and !=. [[ ]] is safer than [ ] (no word splitting) but exists only in Bash, not in plain sh.

Short forms: cmd1 && cmd2 runs the second only on success, cmd1 || cmd2 only on failure.

if / elif / else / fi

What is it for?
Runs different commands depending on a test.
Where is it used?
Whenever a script must decide.
Why does it matter?
Scripts react to input and state instead of running blindly.
if [ -f "$1" ]; then echo exists; else echo missing; fi

[ ] / test

What is it for?
Tests files, strings and numbers; the result is the exit code.
Where is it used?
In the condition of if, or alone with && / ||.
Why does it matter?
The portable form that works in every shell.
test -f ~/notes.txt && echo yes

[[ ]]

What is it for?
Bash conditions with patterns and && / || inside.
Where is it used?
In scripts with #!/bin/bash.
Why does it matter?
Fewer quoting traps than [ ].
[[ $score -ge 50 && -n $name ]] && echo ok

&& and ||

What is it for?
Chains commands by success or failure.
Where is it used?
For short checks on one line.
Why does it matter?
Quick alternative to a full if.
test -d ~/Documents && echo dir || echo nodir
💡 Tip

Check first, act second: [ -f "$1" ] || { echo "no such file"; exit 1; } stops early with a clear message.

Safe scripts: set -euo pipefail and debugging

By default Bash continues after errors. The line set -euo pipefail at the top changes that: -e stops at the first failing command, -u treats an unset variable as an error, -o pipefail makes a pipe fail if any part fails.

To debug use bash -n script.sh (syntax check only) and bash -x script.sh (prints every command with a + before running it). shellcheck finds typical mistakes before you run the script. Install it with sudo apt install shellcheck on Debian/Ubuntu or sudo dnf install epel-release && sudo dnf install ShellCheck on RHEL/Rocky.

On hardened systems a script can fail although chmod +x was done: the folder may be mounted noexec, or SELinux (RHEL/Rocky) / AppArmor (Ubuntu) may block it when a service starts it. Then use bash script.sh for a test and look at the audit/journal logs.

set -euo pipefail

What is it for?
Strict mode: stop on errors, unset variables and failed pipes.
Where is it used?
Second line of almost every script.
Why does it matter?
Errors are not silently ignored, so the script does less damage.
set -euo pipefail

bash -n / bash -x

What is it for?
-n checks syntax, -x traces each command.
Where is it used?
When a script misbehaves.
Why does it matter?
You see exactly which line and which values are used.
bash -x ~/bin/hello.sh

shellcheck

What is it for?
Static analysis of shell scripts.
Where is it used?
Before you share or schedule a script.
Why does it matter?
Finds quoting bugs and typos early.
shellcheck ~/bin/vars.sh

${VAR:?message}

What is it for?
Aborts with a message if the variable is empty or unset.
Where is it used?
Before destructive commands that use a variable.
Why does it matter?
Prevents rm from running on the wrong path.
rm -r "${TARGET:?TARGET is not set}/cache"
💡 Tip

Print first, delete later: replace rm with echo rm in a test run and check the paths with your eyes.

⚠️ Warning

Only -e is no guarantee: it is ignored inside conditions (if, &&, ||). Test every script with harmless sample data first.

⛔ Danger

An empty variable is dangerous: rm -rf "$DIR"/* becomes rm -rf /* when DIR is empty. Use set -u and ${DIR:?}, test in a VM and take a snapshot first (module 0.2).

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

On your VM (Ubuntu or Rocky) you run the scripts for real. Use only your own ~/bin folder and harmless test data. For destructive experiments take a snapshot first (module 0.2).

First script and execute bit

Create the script with a heredoc, try to run it before and after chmod +x, and paste the output.

mkdir -p ~/bin
cat > ~/bin/hello.sh <<'EOF'
#!/bin/bash
echo "Hello, Linux!"
EOF
~/bin/hello.sh
chmod +x ~/bin/hello.sh
ls -l ~/bin/hello.sh
~/bin/hello.sh

Expected output example

bash: /home/student/bin/hello.sh: Permission denied
-rwxr-xr-x. 1 student student 38 Nov 12 10:00 /home/student/bin/hello.sh
Hello, Linux!
My output looks different
  • On Ubuntu ls -l has no dot after the permissions; on Rocky there is one (SELinux context).
  • If the first run already works, your umask or file system gives the execute bit; that is fine.

Variables, quoting, read and arithmetic

Write a script that shows the quoting difference, reads a number and doubles it. Feed the number through a pipe.

cat > ~/bin/vars.sh <<'EOF'
#!/bin/bash
NAME="student"
echo 'single: $NAME'
echo "double: $NAME"
read -r -p "Number: " N
echo "Double: $((N * 2))"
echo "Year: $(date +%Y)"
EOF
chmod +x ~/bin/vars.sh
echo 21 | ~/bin/vars.sh

Expected output example

single: $NAME
double: student
Double: 42
Year: 2026
My output looks different
  • The prompt Number: is not shown because input comes from a pipe; that is normal.
  • If you see unbound variable or syntax error, check that there are no spaces around =.

Arguments with spaces

Write a script that prints the argument count and every argument, then call it with a file name that contains a space.

cat > ~/bin/args.sh <<'EOF'
#!/bin/bash
echo "Script: $0"
echo "Count: $#"
echo "First: $1"
for item in "$@"; do
  echo "Arg: $item"
done
EOF
chmod +x ~/bin/args.sh
~/bin/args.sh "my file" bob

Expected output example

Script: /home/student/bin/args.sh
Count: 2
First: my file
Arg: my file
Arg: bob
My output looks different
  • If Count is 3, you called it without quotes around my file.
  • Replace "$@" with $@ and run again: my and file become separate arguments.

if / elif / else and exit codes

Build a small grading script with [[ ]], run it with three inputs and look at exit codes of test.

cat > ~/bin/grade.sh <<'EOF'
#!/bin/bash
score="${1:-0}"
if [[ $score -ge 90 ]]; then
  echo "top"
elif [[ $score -ge 50 ]]; then
  echo "pass"
else
  echo "fail"
fi
EOF
chmod +x ~/bin/grade.sh
~/bin/grade.sh 95
~/bin/grade.sh 60
~/bin/grade.sh
test -f /etc/passwd; echo "rc=$?"
test -f /nonexistent; echo "rc=$?"

Expected output example

top
pass
fail
rc=0
rc=1
My output looks different
  • If you get [[: not found, you started the script with sh script.sh; use bash or run it directly.
  • If every input prints fail, check the spaces inside [[ ... ]].

Strict mode in action

Compare what set -euo pipefail does with a failing command and with an unset variable.

cat > ~/bin/strict.sh <<'EOF'
#!/bin/bash
set -euo pipefail
echo "before"
false
echo "after"
EOF
chmod +x ~/bin/strict.sh
~/bin/strict.sh; echo "exit=$?"
bash -c 'set -u; echo "$UNDEFINED_VAR"'; echo "exit=$?"

Expected output example

before
exit=1
bash: line 1: UNDEFINED_VAR: unbound variable
exit=1
My output looks different
  • after must not appear. If it does, check the set line.
  • The exact wording of the unbound variable message depends on the Bash version.

Debugging: bash -n, bash -x, shellcheck

Check the syntax, trace a script and install ShellCheck (choose your distribution). If the install is not possible, skip the third block and paste the first two outputs.

bash -n ~/bin/hello.sh; echo "syntax=$?"
bash -x ~/bin/hello.sh

Expected output example

syntax=0
+ echo 'Hello, Linux!'
Hello, Linux!
# Ubuntu / Debian
sudo apt install -y shellcheck
# Rocky / RHEL
sudo dnf install -y epel-release && sudo dnf install -y ShellCheck
shellcheck ~/bin/vars.sh

Expected output example

(no output means no findings)
My output looks different
  • syntax=0 means the syntax is fine; any other number means a syntax error and Bash prints the line.
  • If ShellCheck prints hints like SC2086, they usually point to missing quotes around a variable.

Self-test

What does echo '$HOME' print?

Single quotes prevent expansion; the text $HOME is printed. Only double quotes expand variables.

What does $# contain inside a script?

$# is the argument count; $0 is the script name, $? the last exit code and "$@" the list of arguments.

What does set -euo pipefail do?

-e stops on errors, -u on unset variables and pipefail on failing pipe parts. Printing commands is -x.

You start ./run.sh and the file has no execute bit. What happens?

Without the x bit the kernel refuses to start the file: Permission denied. Fix it with chmod +x run.sh.

Summary

  • A script starts with the shebang #!/bin/bash, needs chmod +x and is started with ./script.sh.
  • Variables: NAME=value without spaces; "$NAME" expands, '$NAME' does not. Always quote.
  • $1, $# and "$@" read arguments; ${1:-default} sets a default.
  • $? is the last exit code (0 = success); exit N ends a script with a code.
  • if with [ ], [[ ]] or test decides; -f -d -z -eq are the most common tests.
  • set -euo pipefail plus bash -x and shellcheck make scripts safer and easier to debug.

Key terms

shebang
The first line #!/bin/bash; names the interpreter of the script.
execute bit
The x permission that allows a file to be started as a program.
variable
A named value, set with NAME=value and read with $NAME.
quoting
Single quotes keep text literally, double quotes expand variables.
positional argument
A value passed to the script: $1, $2, ...
exit code
A number returned by a command; 0 is success, everything else is failure.
test / [ ]
A command that evaluates a condition and answers with an exit code.
strict mode
set -euo pipefail: stop on errors, unset variables and failed pipes.
heredoc
<<'EOF' passes several lines of text to a command, often to create a file.

1.4 Command success: $?, &&, || and error messages

No output does not mean an error. Every command leaves an exit status; in this module you learn to read it, chain commands based on it and understand error messages.

What will you learn in this module?

  • You read the last command's exit status with echo $? and tell 0 from non-zero.
  • You chain commands conditionally with true, false, &&, || and ;.
  • You know the difference between stdout and stderr and separate errors with 2>.
  • You read Permission denied, No such file or directory and command not found and find the cause.
  • You test files, numbers and strings with test and [ ].

Exit status: $?

When a command finishes it produces an exit status. 0 = success, any other number = failure. A silent command (such as mkdir) may have succeeded or failed; to be sure, type echo $?.

Common codes: 1 general error, 2 misuse or missing path (ls), 126 not executable, 127 command not found, 130 interrupted with Ctrl+C.

Careful: $? is overwritten after every command. An echo $? typed right afterwards leaves its own result (0); read the code immediately after the command in question.

echo $?

What is it for?
Prints the exit status of the last command.
Where is it used?
Checking commands that print nothing.
Why does it matter?
Shows with a number whether the command really worked.
pwd; echo $?

true

What is it for?
Does nothing and always ends with 0.
Where is it used?
Testing chains and loops when you need a 'successful' command.
Why does it matter?
Easily produces the success state.
true; echo $?

false

What is it for?
Does nothing and always ends with 1.
Where is it used?
Trying the error path.
Why does it matter?
Easily produces the failure state.
false; echo $?
💡 Tip

No output is not an error. Most Unix commands are silent on success.

Chaining: &&, || and ;

A && B: B runs only if A succeeded (0). A || B: B runs only if A failed. A ; B: B runs in every case.

The classic pattern: mkdir lab && cd lab (enter the folder if it was created). A && B || C acts like an if/else, but if B fails C runs too, so use it only for simple cases.

&&

What is it for?
Runs the right side if the left side succeeded.
Where is it used?
Steps that depend on each other.
Why does it matter?
Prevents carrying on after a failed step.
mkdir lab && cd lab

||

What is it for?
Runs the right side if the left side failed.
Where is it used?
Error messages or fallback plans.
Why does it matter?
Reacts to failure automatically.
cd /nonexistent || echo failed

;

What is it for?
Runs commands in order regardless of success.
Where is it used?
Writing independent commands on one line.
Why does it matter?
Keeps the order, ignores the result.
pwd; whoami; hostname
⚠️ Warning

In chains like rm -r old_project ; ... using ; runs the destructive command even if the previous step failed. Join destructive steps with &&.

stdout and stderr

Every command has two output channels: stdout (channel 1, normal output) and stderr (channel 2, error messages). Both appear on screen, but they can be redirected separately.

> sends only stdout to a file; the error stays on screen. 2> sends errors to a file. 2>/dev/null throws errors away. 2>&1 sends stderr to wherever stdout goes. Note: redirection does not change the exit status; even if the error is hidden, the command still failed.

2>

What is it for?
Writes error messages (stderr) to a file.
Where is it used?
Inspecting errors later.
Why does it matter?
Separates normal output from errors.
ls /nonexistent 2> errors.txt

2>/dev/null

What is it for?
Discards error messages.
Where is it used?
Silencing expected, harmless errors.
Why does it matter?
Keeps output clean, but also hides real problems.
ls /nonexistent 2>/dev/null; echo $?

2>&1

What is it for?
Redirects stderr to the same place as stdout.
Where is it used?
Collecting output and errors in one file or pipeline.
Why does it matter?
Keeps the complete record in one place.
ls ~ /nonexistent > all.txt 2>&1

Reading error messages

An error message usually looks like program: argument: reason. The first word is the program that failed, the second the problem path, the last the reason.

No such file or directory: the path does not exist or has a typo; check where you are with ls and pwd. Permission denied: the path exists but you lack permission; look at ls -l. command not found (code 127): wrong command name or not installed; check with type / which. Is a directory: you gave a folder to a command that expects a file.

ls -l

What is it for?
Shows file permissions and owner.
Where is it used?
Looking for the cause of Permission denied.
Why does it matter?
You see which permission is missing.
ls -l locked.txt

type

What is it for?
Tells you whether a name is a command, builtin or alias.
Where is it used?
On command not found errors.
Why does it matter?
Shows whether the command exists.
type ls
⛔ Danger

When you see Permission denied, do not reflexively type sudo or chmod 777. Understand the cause first; needlessly wide permissions are a security hole.

Testing conditions: test and [ ]

test (and its equivalent [ ... ]) checks a condition and prints nothing; it reports the result only through its exit status: 0 if true, 1 if false. That is why it fits so well with && / ||.

Common ones: -f regular file, -d directory, -e exists, -r/-w/-x readable/writable/executable, -z string empty. For numbers -eq -ne -gt -lt, for strings = and !=. Inside [ ] the spaces next to the brackets are mandatory.

test -f

What is it for?
Succeeds if the path exists and is a regular file.
Where is it used?
Checking that a file exists.
Why does it matter?
You avoid running a command on a missing file and getting an error.
test -f notes.txt && echo yes

[ -d ]

What is it for?
Succeeds if the path is a directory.
Where is it used?
E.g. creating a folder only if it is missing.
Why does it matter?
Lets you act conditionally.
[ -d Documents ] && echo dir

[ -gt ]

What is it for?
Compares numbers (-eq -ne -gt -lt).
Where is it used?
Numeric checks.
Why does it matter?
Turns numeric conditions into an exit status.
[ 3 -gt 2 ] && echo gt
💡 Tip

Classic pattern: test -d backup || mkdir backup. It creates the folder if missing and leaves it alone otherwise.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Run the following commands on your own VM (Ubuntu/Rocky/Alma or WSL); we only use safe, read-only commands. Paste the output and check it.

Success and failure codes

Run one successful and one failing command and read the code after each. Paste the whole output.

ls /
echo $?
ls /nonexistent
echo $?

Expected output example

bin  boot  dev  etc ...
0
ls: cannot access '/nonexistent': No such file or directory
2
My output looks different
  • A failing ls gives 2 (GNU ls); other commands may give 1. That is fine, what matters is that it is not 0.
  • If the message is localised it may be in another language; the code is the same.

command not found: 127

Run a command that does not exist and read the exit status.

nonexistentcmd
echo $?

Expected output example

bash: nonexistentcmd: command not found
127
My output looks different
  • Ubuntu sometimes suggests a package with 'Command not found'; the code is still 127.
  • If you type echo $? twice the second gives 0; read it only right after the first command.

How && and || behave

Try the chains and see which side runs.

true && echo ok
false && echo never
false || echo fallback
true ; echo always

Expected output example

ok
fallback
always
My output looks different
  • If never appears you may have typed ; instead of &&.
  • If nothing prints, look for a quote or spacing mistake.

Permission denied

Open a file you cannot read as a normal user and paste the error and status (read-only, nothing changes).

cat /etc/shadow
echo $?

Expected output example

cat: /etc/shadow: Permission denied
1
My output looks different
  • If you are root the file opens; switch to a normal user (su - student or a new user).
  • On older systems you can try /etc/sudoers instead of /etc/shadow.

Conditions with test

Test file and directory conditions. Paste the result as yes / no.

test -d /etc && echo yes || echo no
test -f /etc/nonexistent && echo yes || echo no

Expected output example

yes
no
My output looks different
  • If both print yes you may have typed -e instead of -f.
  • When you write [ -d /etc ], do not forget the spaces around [ and ].

Quick exercises (simulator)

Optional: warm up before the VM, or practise without one, in the in-browser virtual terminal. Tasks are verified automatically.

Tasks get harder from warm-up to ticket. Badges show the difficulty.

Warm-up

  1. Warm-upEasy

    Run pwd first, then read its exit status right away with echo $?.

    Hint

    Type two separate lines; the code should be 0.

    Solution
    pwd
echo $?

  2. Warm-upEasy

    List a path that does not exist: ls /nonexistent, and read the error message.

    Hint

    The error goes to stderr; it still shows on screen.

    Solution
    ls /nonexistent

  3. Warm-upEasy

    Run false, then read its status with echo $?. What number do you get?

    Hint

    false always fails.

    Solution
    false
echo $?

Guided lab

  1. Guided labMedium

    In a single line write mkdir lab && cd lab to create the folder and enter it.

    Hint

    && runs the second command only if the first succeeded.

    Solution
    mkdir lab && cd lab
cd ~

  2. Guided labMedium

    Type cd /nonexistent || echo failed and think about why failed is printed.

    Hint

    When cd fails, || runs the right-hand side.

    Solution
    cd /nonexistent || echo failed

Predict

  1. PredictMedium

    Predict: what does cat missing.txt; echo $? print and what is the code? Then run it to verify.

    Hint

    cat prints an error when it cannot find the file and exits with 1.

    Solution
    cat missing.txt; echo $?

  2. PredictMedium

    Predict: what does test -f notes.txt && echo yes || echo no print? Run it to verify.

    Hint

    notes.txt exists in home and is a regular file.

    Solution
    test -f notes.txt && echo yes || echo no

Debug

  1. DebugMedium

    cat locked.txt gives 'Permission denied'. Understand why, fix it with chmod and read the file.

    Hint

    Give yourself read permission: chmod u+r locked.txt.

    Solution
    chmod u+r locked.txt
cat locked.txt

  2. DebugMedium

    cp notes.txt backup/ fails because backup does not exist. Chain it: create the folder and copy the file.

    Hint

    mkdir backup && cp notes.txt backup/.

    Solution
    mkdir backup && cp notes.txt backup/

Mini project

  1. Mini projectHard

    Mini project: (1) write the error of ls /nonexistent to errors.txt, (2) write the output of ls ~ to files.txt, (3) read the last command's status with echo $?.

    Hint

    Use 2> for the error and > for the output.

    Solution
    ls /nonexistent 2> errors.txt
ls ~ > files.txt
echo $?

  2. Mini projectMedium

    Mini project: in one line create the project folder, enter it, create the file main.txt and finally print built.

    Hint

    Join four commands with &&; you can use mkdir -p project.

    Solution
    mkdir -p project && cd project && touch main.txt && echo built
cd ~

Challenge

  1. ChallengeHard

    Challenge: create the backup folder if it is missing; copy notes.txt into it; if the copy succeeded write saved into status.txt, otherwise failed.

    Hint

    test -d backup || mkdir backup and cp ... && echo saved > status.txt || echo failed > status.txt.

    Solution
    test -d backup || mkdir backup
cp notes.txt backup/ && echo saved > status.txt || echo failed > status.txt

  2. ChallengeHard

    Challenge: does notes.txt contain hello? Test it in one line and print found or missing; discard grep's own output to /dev/null.

    Hint

    grep hello notes.txt > /dev/null && echo found || echo missing.

    Solution
    grep hello notes.txt > /dev/null && echo found || echo missing

Ticket

  1. TicketHard

    Ticket: A colleague says 'I cannot read my report' and tried cat Documents/raport.txt. Find the right name with ls Documents, read the file with cat and write the exit status to exit.txt.

    Hint

    The right name is report.txt. cat Documents/report.txt; echo $? > exit.txt.

    Solution
    ls Documents
cat Documents/report.txt; echo $? > exit.txt

Self-test

What is the exit status of a command that finished successfully?

0 means success; every non-zero value indicates a failure.

When does B run in the line A && B?

&& acts like AND; B runs only if A ends with 0.

What does exit status 127 indicate?

127 = command not found. A permission problem is 126, Ctrl+C is 130.

What does ls /nonexistent 2>/dev/null; echo $? do?

2>/dev/null only discards the message; the command still failed and $? is not 0.

Summary

  • Exit status: 0 is success, anything else is an error. Read it immediately with echo $?.
  • && continues on success, || on failure, ; in every case.
  • stdout is redirected with >, stderr with 2>; redirection does not change the exit status.
  • Error message: program, path, reason. 127 = no such command, Permission denied = no permission.
  • test and [ ] turn conditions into an exit status.

Key terms

exit status
The number a command leaves when it finishes; 0 = success.
stdout
Standard output (channel 1); normal results.
stderr
Standard error (channel 2); error messages.
&&
Operator that runs the right side if the left side succeeded.
||
Operator that runs the right side if the left side failed.
/dev/null
A special file that swallows everything written to it.

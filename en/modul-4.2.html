4.2 User management: add, modify, lock, delete

Manage the lifecycle of an account safely with useradd, passwd, usermod, groupadd, chage and userdel.

What will you learn in this module?

  • You create an account with a home directory and shell using useradd -m -s and set its password with passwd.
  • You add users to groups with usermod -aG and know what happens if the -a is forgotten.
  • You lock accounts with usermod -L and manage password policy with chage.
  • You know the difference between userdel and userdel -r and think about preserving data before deleting.

Creating accounts: useradd and passwd

When a new employee arrives you create an account for them. These actions change system files (/etc/passwd, /etc/shadow, /etc/group), so they need root privileges, i.e. sudo.

useradd does not create a home directory on every distribution by default, so add -m. -s /bin/bash sets the login shell. The new home is filled with template files from /etc/skel. passwd sets the password; nothing is shown while you type, which is normal.

Debian/Ubuntu also have the interactive adduser wrapper; Rocky/Alma do not (use useradd there). In scripts prefer useradd, which works everywhere.

useradd

What is it for?
Creates a new user account.
Where is it used?
When adding a new employee or service account.
Why does it matter?
Everyone gets separate files and permissions.
sudo useradd -m -s /bin/bash testuser

passwd

What is it for?
Sets or changes the account's password.
Where is it used?
After the account is created.
Why does it matter?
An account without a password cannot log in.
sudo passwd testuser

chage

What is it for?
Manages password aging (-d 0 forces a change at first login).
Where is it used?
To force a new account to change its password at first login.
Why does it matter?
The temporary password set by the admin does not become permanent.
sudo chage -d 0 testuser

getent passwd

What is it for?
Verifies that the account exists.
Where is it used?
After every addition.
Why does it matter?
Catches typos immediately.
getent passwd testuser
💡 Tip

Keep account names lowercase ASCII (alice, testuser). Spaces, accented characters and capitals cause trouble.

⚠️ Warning

Adding users on a real VM changes the system. Take a snapshot of your VM first (module 0.2). Do not type passwords on the command line (chpasswd leaves them in history).

Modifying: usermod, groupadd, groups

usermod changes an existing account. Most used: -aG group (append to group), -s (shell), -L (lock), -U (unlock). Use groupadd to create a group; after a group change the user must log in again.

The classic mistake: usermod -G devs alice without -a. It wipes all of alice's supplementary groups and leaves only devs, including wheel. The user loses sudo rights. Always use -aG.

Sudo rights come from membership in wheel on Rocky/Alma and sudo on Ubuntu. Do not edit /etc/sudoers by hand; use visudo, which checks the syntax.

groupadd

What is it for?
Creates a new group.
Where is it used?
When creating a shared group for a project team.
Why does it matter?
You grant access to the group, not to each person.
sudo groupadd labteam

usermod -aG

What is it for?
Adds the user to a group while keeping existing groups.
Where is it used?
When putting someone in a team or the sudo group.
Why does it matter?
Without -a the old groups are removed.
sudo usermod -aG labteam testuser

usermod -L

What is it for?
Locks the account (password login is disabled); -U unlocks.
Where is it used?
When an employee leaves or an account looks suspicious.
Why does it matter?
Cuts access at once while data stays intact.
sudo usermod -L testuser

passwd -S

What is it for?
Shows account status (L/LK = locked).
Where is it used?
To verify the lock.
Why does it matter?
Confirms the lock was really applied.
sudo passwd -S testuser

id

What is it for?
Verifies the group change.
Where is it used?
After each usermod.
Why does it matter?
Shows the membership was added and old ones were not removed.
id testuser
💡 Tip

After a group change an open session keeps using the old groups; the user must log out and back in.

⛔ Danger

usermod -G (without -a) removes all of a user's supplementary groups. On an admin account this can remove sudo access and lock you out of the system. Always write -aG and check with id.

Deleting: userdel and the home directory

userdel NAME removes the account from /etc/passwd, /etc/shadow and /etc/group, but leaves the home directory and its files. The directory then belongs to a UID with no owner. userdel -r also deletes the home directory and mail spool permanently.

The safe order in real life: (1) lock with usermod -L, (2) check running processes and cron jobs, (3) back up the home directory, (4) only then delete. You can find files of a deleted user with find / -user UID.

If the user has a session or running process, userdel errors out; end the session first.

userdel

What is it for?
Deletes the account, keeps the home directory.
Where is it used?
After the employee left and data was backed up.
Why does it matter?
Closes the account without risk of data loss.
sudo userdel testuser

userdel -r

What is it for?
Deletes account, home directory and mail spool permanently.
Where is it used?
Only when the data is truly not needed.
Why does it matter?
Cleans up disk space and leftovers.
sudo userdel -r testuser

ls -ld

What is it for?
Shows the home directory still exists.
Where is it used?
After userdel.
Why does it matter?
You see that leftover directories remain ownerless.
ls -ld /home/testuser
⚠️ Warning

userdel -r cannot be undone: photos, documents and keys are gone. Back up first, snapshot your VM, lock the account, and re-read the user name before pressing ENTER.

⛔ Danger

With sudo rm -r /home/NAME, a wrong path (a stray space or missing name) deletes other data. Run it only for the testuser you created and type the full path.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

This section changes the system. Take a snapshot of your VM first. Work only on testuser and labteam from this section; do not touch your own account.

Create an account

Create the testuser account with a home directory and bash shell and paste its record.

sudo useradd -m -s /bin/bash testuser
getent passwd testuser

Expected output example

testuser:x:1001:1001::/home/testuser:/bin/bash
My output looks different
  • If you see user already exists the account was created earlier; getent passwd testuser is enough.
  • On Ubuntu the UID may be a number other than 1001.

Set a password

Set a password for testuser. Nothing is shown while typing. Paste the success message.

sudo passwd testuser

Expected output example

passwd: password updated successfully
My output looks different
  • On Rocky/Alma the message is passwd: all authentication tokens updated successfully.
  • A too short/simple password triggers a warning but is still accepted (as root).

Add to a group

Create the labteam group, add testuser with -aG and paste the id output.

sudo groupadd labteam
sudo usermod -aG labteam testuser
id testuser

Expected output example

uid=1001(testuser) gid=1001(testuser) groups=1001(testuser),1002(labteam)
My output looks different
  • If the group exists you get groupadd: group 'labteam' already exists; continue.
  • If labteam is missing next to the primary group, check the letters -a and -G.

Lock the account

Lock testuser and show its status.

sudo usermod -L testuser
sudo passwd -S testuser

Expected output example

testuser L 2026-11-12 0 99999 7 -1
My output looks different
  • On Rocky/Alma the status is shown as LK.
  • To unlock: sudo usermod -U testuser.

Password policy

Paste the chage -l output; force a password change at first login.

sudo chage -d 0 testuser
sudo chage -l testuser

Expected output example

Last password change                : password must be changed
Password expires                    : never
...
My output looks different
  • The output must contain the Last password change line; the value may be password must be changed or a date.
  • If chage: command not found, the shadow-utils (Rocky) or passwd (Ubuntu) package is missing.

userdel keeps the home

Delete the account WITHOUT -r; then show that the account is gone but its home directory remains.

sudo userdel testuser
getent passwd testuser
ls -ld /home/testuser

Expected output example

drwx------ 2 1001 1001 62 Nov 12 10:00 /home/testuser
My output looks different
  • getent prints nothing; the account is deleted.
  • The home directory's owner now shows as a number (1001) instead of a name; that means an ownerless directory.
  • On user is currently used by process, end the user's session.

Cleanup

Clean up the now unneeded test directory and group. Type the full path in the commands. Press "Done" when finished.

sudo rm -r /home/testuser
sudo groupdel labteam
ls /home

Expected output example

student
My output looks different
  • groupdel: group 'labteam' does not exist means it is already gone.
  • If you notice you mistyped the path, do not press ENTER; be sure of the full path /home/testuser.

Self-test

What does sudo usermod -G devs alice (without -a) do?

-G replaces the supplementary group list; without -a (append) old groups such as wheel are lost.

What happens after userdel alice (without -r)?

The records are removed; /home/alice and its files stay on disk. Deleting them needs -r.

How do you cut an account's access immediately without deleting it?

usermod -L disables password login; the account and data stay and -U brings it back.

Membership in which group gives sudo rights on Rocky/Alma?

On the RHEL family the sudo group is wheel; on Debian/Ubuntu it is sudo.

Summary

  • sudo useradd -m -s /bin/bash NAME creates an account; passwd sets a password; chage -d 0 forces a change at first login.
  • When adding to a group always use usermod -aG; forgetting -a removes the old groups.
  • usermod -L locks, -U unlocks; locking is the safe first step before deleting.
  • userdel keeps the home directory, userdel -r deletes it permanently; back up and snapshot first.

Key terms

wheel
The administrator group that grants sudo on the RHEL family (sudo on Debian).
/etc/skel
Template files copied into a new home directory.
locked account
An account whose password login is disabled (usermod -L).
ownerless directory
A directory that still belongs to the UID of a deleted user.
snapshot
A restorable point-in-time image of a VM.

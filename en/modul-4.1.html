4.1 User information: who, where, when?

Use whoami, id, who, w, last, lastb and getent to see who exists on the system, who is logged in, and where accounts are stored.

What will you learn in this module?

  • You read your own identity (UID, GID, groups) with whoami, id and groups.
  • You know what /etc/passwd, /etc/group and /etc/shadow hold and what their fields mean.
  • You see who is connected now with who and w, successful logins with last and failed ones with lastb.
  • You query accounts with getent, no matter whether they live in a file or a central directory (LDAP/SSSD).

Who am I? whoami, id, groups

Linux is a multi-user system. Every process runs as some user and permissions depend on it. To understand why a command fails, first find out who you are and which groups you belong to.

The id output looks like uid=1000(student) gid=1000(student) groups=.... The UID is the numeric identity of the user; the kernel works with numbers, not names. root is always UID 0. Usually UIDs from 1000 up belong to human users and lower ones to system accounts.

whoami

What is it for?
Prints the effective user name.
Where is it used?
To confirm who you are after sudo or su.
Why does it matter?
Prevents working as the wrong user.
whoami

id

What is it for?
Shows UID, primary GID and all groups.
Where is it used?
For permission problems and checking new accounts.
Why does it matter?
Shows which groups give a user access.
id alice

groups

What is it for?
Lists the names of the groups you belong to.
Where is it used?
For a quick group check.
Why does it matter?
Gives a more readable summary than id.
groups
💡 Tip

id username also works for other users; if the account does not exist you get no such user. It is the quickest way to test whether an account exists.

Account files: passwd, group, shadow

Local accounts live in three plain-text files. /etc/passwd is world-readable; each line has 7 colon-separated fields: name:x:UID:GID:comment:home:shell. The x means the password is not stored here.

Password hashes are in /etc/shadow, readable only by root. /etc/group holds group name, GID and members. The /sbin/nologin shell means the account cannot log in interactively (a service account).

getent queries the same information from all configured sources (files, LDAP, SSSD). In corporate environments users may not be in /etc/passwd at all, so scripts should prefer getent passwd over cat /etc/passwd.

cat /etc/passwd

What is it for?
Shows the local account list.
Where is it used?
When you need home directory and shell information.
Why does it matter?
Shows how accounts are defined.
cat /etc/passwd

cut -d: -f1

What is it for?
Extracts field 1 (user name) from colon-separated data.
Where is it used?
To list only the names.
Why does it matter?
Pulls the column you need from large files.
cut -d: -f1 /etc/passwd

grep

What is it for?
Finds the line of one specific user.
Where is it used?
When checking a single account record.
Why does it matter?
Faster than reading the whole list.
grep student /etc/passwd

getent passwd

What is it for?
Looks the account up in all sources (file, LDAP, SSSD).
Where is it used?
On corporate servers and in scripts.
Why does it matter?
Also finds users from the central directory.
getent passwd student

getent group

What is it for?
Queries a group and its members.
Where is it used?
To check who is in which group.
Why does it matter?
Helps solve access problems.
getent group devs
💡 Tip

cut -d: -f1,7 /etc/passwd shows user name and shell side by side; entries with nologin are service accounts.

⚠️ Warning

Do not edit /etc/passwd or /etc/shadow by hand in a text editor. One wrong character can break everyone's login. Manage accounts with tools like useradd and usermod (module 4.2).

Who is connected now? who and w

Before maintenance, a reboot or stopping a service, check whether someone else is working on the server. who shows connected users, their terminal (tty1, pts/0) and login time; for remote logins the IP appears in parentheses.

w is more detailed: the first line shows uptime and the load average, then for each session the idle time (IDLE) and the command being run (WHAT).

who

What is it for?
Shows logged-in users, terminals and times.
Where is it used?
Before maintenance.
Why does it matter?
You will not interrupt someone's work by accident.
who

w

What is it for?
Shows sessions, idle time, running command and load average.
Where is it used?
When the server is slow or you look for suspicious sessions.
Why does it matter?
Answers who is doing what in one command.
w
💡 Tip

If only one session is open on your VM, only you appear. Open a second terminal tab and run who again; the count goes up.

Login history: last and lastb

last reads /var/log/wtmp and lists successful logins, logouts and reboots (reboot). A common mistake: searching last for failed attempts. Failed logins do not appear in last.

Failed login attempts are stored in /var/log/btmp and read with lastb; only root can read it. If you suspect brute-forcing, run sudo lastb | head first. On some distributions the btmp file may not exist and the command errors; that can simply mean no failed attempts were ever recorded.

last

What is it for?
Lists successful logins/logouts and reboot records.
Where is it used?
When investigating who logged in at night.
Why does it matter?
Reveals account misuse.
last -n 10

lastb

What is it for?
Lists failed login attempts (needs root).
Where is it used?
During security audits.
Why does it matter?
Shows attack attempts.
sudo lastb -n 10
💡 Tip

last -n 5 student shows only the last 5 logins of the student account.

⚠️ Warning

Login records are sensitive (user names, IP addresses). Remove IPs and names before sharing output on public forums.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

These commands only read, so you can run them safely on your VM. lastb needs sudo. Remove IPs and user names before sharing output.

Who is connected?

Paste the output of who and w.

who
w

Expected output example

student  pts/0   2026-11-12 09:00 (192.168.1.10)
 09:20:01 up 1 day,  2:30,  1 user,  load average: 0.00, 0.01, 0.05
USER     TTY      FROM      LOGIN@   IDLE   WHAT
...
My output looks different
  • If there are no lines you may be in a graphical session's fake terminal; try a real terminal.
  • On WSL who may be empty; the load average line of w is enough.

Successful logins

List the latest logins and paste the output.

last -n 5

Expected output example

student  pts/0  192.168.1.10  Wed Nov 12 09:00   still logged in
reboot   system boot  5.14.0  Wed Nov 12 08:55 still running

wtmp begins Mon Nov 10 08:00:00 2026
My output looks different
  • If you see command not found: sudo apt install util-linux (Ubuntu) or sudo dnf install util-linux (Rocky/Alma).
  • In containers or WSL wtmp may be empty; the final wtmp begins line is enough.

Failed logins

Look at the lastb output. The list may be empty; that is normal. Then press "Done".

sudo lastb -n 5

Expected output example

(if empty) btmp begins Wed Nov 12 08:55:00 2026
My output looks different
  • No such file or directory (no btmp): no failed login was ever recorded.
  • You can generate an entry by entering a wrong password in a second terminal (e.g. su - alice) and looking again.

Query an account with getent

Get the record of the student account; numbers and home directory must be visible.

getent passwd student

Expected output example

student:x:1000:1000:Student:/home/student:/bin/bash
My output looks different
  • If your user name is not student, use your own: getent passwd $(whoami).
  • If the output is empty that account does not exist; check your name with whoami.

Your identity

Paste your id output.

id

Expected output example

uid=1000(student) gid=1000(student) groups=1000(student),10(wheel)
My output looks different
  • On Ubuntu the sudo group is called sudo; on Rocky/Alma it is wheel.
  • If the UID is 0 you are running as root; switch to a normal user.

Account list and shells

List user name and shell side by side (first 8 lines).

getent passwd | cut -d: -f1,7 | head -n 8

Expected output example

root:/bin/bash
bin:/sbin/nologin
daemon:/sbin/nologin
...
My output looks different
  • On Ubuntu the shell path may be /usr/sbin/nologin.
  • If cut fails, make sure you wrote the delimiter as -d: (no space).

Self-test

Which command shows failed login attempts?

last shows only successful logins; failed attempts are in /var/log/btmp and read with lastb.

What does field 7 of a /etc/passwd line show?

Fields: name, x, UID, GID, comment, home, shell. Field 7 is the shell (e.g. /bin/bash or /sbin/nologin).

In which file are password hashes stored?

Hashes are in /etc/shadow, readable only by root; the x in passwd indicates this.

Why do scripts prefer getent passwd?

getent queries all sources through NSS, so it returns users from the central directory too.

Summary

  • whoami, id and groups show who you are and which groups you are in.
  • /etc/passwd has 7 fields (name, x, UID, GID, comment, home, shell); password hashes are in /etc/shadow.
  • who and w show current sessions, last successful and lastb failed past logins.
  • getent queries accounts without caring whether they come from a file or a central directory.

Key terms

UID / GID
Numeric identity of a user and a group; root has UID 0.
nologin
A shell that blocks interactive login; used for service accounts.
wtmp / btmp
Log files of successful and failed logins (last / lastb).
load average
Average system load over the last 1, 5 and 15 minutes.
NSS / getent
The layer that resolves account info from files or directory services, and the command to query it.

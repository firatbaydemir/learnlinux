1.5 Shell Tools and Environment

Make the shell work for you: history, completion, shortcuts, quoting, variables, PATH, wildcards and command substitution.

What will you learn in this module?

  • You reuse old commands with history, !! and Ctrl+R.
  • You work fast with Tab completion and the Ctrl+C/L/A/E shortcuts.
  • You know the difference between double quotes, single quotes and the backslash.
  • You define variables, pass them on with export, and read and extend PATH.
  • You shorten commands with wildcards (*, ?, []), brace expansion and $().

Command history

The shell remembers what you type. history shows a numbered list; history 5 shows only the last 5 commands. The Up arrow (↑) recalls the previous command.

!! runs the previous command again. Its most common use is sudo !!, which adds the sudo you forgot. Ctrl+R searches the history: type a few letters, the matching old command appears, press Enter to run it.

history

What is it for?
Lists the commands you ran, with numbers.
Where is it used?
When you want to recall a long command from yesterday.
Why does it matter?
Saves retyping and shows what you did.
history

history 5

What is it for?
Shows only the last 5 commands.
Where is it used?
When a short overview is enough.
Why does it matter?
You don't drown in a long list.
history 5

!!

What is it for?
Runs the previous command again, unchanged.
Where is it used?
Like sudo !! after a permission error.
Why does it matter?
No need to retype the same command.
echo hello

Ctrl+R

What is it for?
Searches backwards through the history.
Where is it used?
Finding a very old, long command.
Why does it matter?
Much faster than scrolling with the arrow key.
history
💡 Tip

After pressing Ctrl+R, press Ctrl+R again to jump to the next older match.

Tab completion and shortcuts

The Tab key completes command, file and folder names. With one match it completes; with several, press Tab twice to list the options. It saves time and prevents typos.

A few shortcuts cover half of daily work: Ctrl+C stops a running command, Ctrl+L clears the screen (same as clear), Ctrl+A jumps to the start of the line, Ctrl+E to the end. With alias you can give long commands a short name.

Tab

What is it for?
Completes the name you typed or lists the options.
Where is it used?
Long file and folder names.
Why does it matter?
Speed and accuracy.
ls Doc

Ctrl+C

What is it for?
Interrupts the running command (sends SIGINT).
Where is it used?
A command that hangs or never ends.
Why does it matter?
You leave the command without closing the terminal.
sleep 100

Ctrl+A / Ctrl+E

What is it for?
Moves the cursor to the start / end of the line.
Where is it used?
Editing a long command.
Why does it matter?
Faster than stepping with the arrow keys.
ls -l Documents

clear

What is it for?
Clears the screen; Ctrl+L does the same.
Where is it used?
When the screen gets cluttered.
Why does it matter?
Keeps output readable.
clear

alias

What is it for?
Gives a command a short alias.
Where is it used?
Commands you type often.
Why does it matter?
Less typing. To make it permanent, put it in ~/.bashrc.
alias ll='ls -l'
💡 Tip

Never type a long file name by hand; type the first letters and press Tab.

Quotes and escaping

Before running a command the shell interprets special characters. Quotes control that. Inside double quotes $variable and $(command) are expanded. Inside single quotes everything stays literal. A backslash (\) removes the special meaning of one character.

File names with spaces also need quotes: cat "my notes.txt". Without quotes the shell sees two separate arguments.

echo "..."

What is it for?
Double quotes: variables expand, spaces are kept.
Where is it used?
Messages with variables.
Why does it matter?
Flexible and safe.
echo "Hello $USER"

echo '...'

What is it for?
Single quotes: nothing expands, text is printed literally.
Where is it used?
Fixed text that contains $.
Why does it matter?
Stops the shell from interfering.
echo 'Hello $USER'

\

What is it for?
Removes the special meaning of the next character.
Where is it used?
Protecting a single $ or space.
Why does it matter?
A short alternative to quotes.
echo \$HOME
💡 Tip

When in doubt, put variables in double quotes: "$FILE" also works with names containing spaces.

Variables and export

Define a variable with NAME=alice; no spaces around the equals sign. Read it with $NAME. A variable defined this way lives only in this shell.

To let programs you start see it, use export NAME=alice. env shows all exported environment variables (HOME, USER, PATH, SHELL...). Changes made with export are lost when the terminal closes; to keep them, write them into ~/.bashrc.

NAME=alice

What is it for?
Defines a shell variable (no spaces).
Where is it used?
Values you will reuse.
Why does it matter?
You don't retype the same value.
NAME=alice

echo $NAME

What is it for?
Prints the value of the variable.
Where is it used?
Checking a value.
Why does it matter?
Confirms what the shell sees.
echo $HOME

export

What is it for?
Passes the variable on to child programs.
Where is it used?
Settings that programs read.
Why does it matter?
Without export the variable stays in this shell only.
export GREETING=hello

env

What is it for?
Lists environment variables.
Where is it used?
Inspecting or debugging the environment.
Why does it matter?
Shows which setting is active.
env | grep GREETING

unset

What is it for?
Removes a variable.
Where is it used?
Dropping a variable you no longer need.
Why does it matter?
Keeps the environment clean.
unset GREETING
💡 Tip

Don't write NAME = alice (with spaces): the shell looks for a command called NAME and fails.

PATH: where commands are found

When you type a command, the shell searches the folders in the PATH variable in order. Folders are separated by :. which ls shows the path found, type ls shows the kind of command (program, builtin).

To add a folder with your own tools, append it to PATH. Keep the old value: export PATH=$PATH:~/bin. If you only write PATH=~/bin, even ls can no longer be found.

echo $PATH

What is it for?
Shows the search folders.
Where is it used?
First place to look on 'command not found'.
Why does it matter?
You see why a command isn't found.
echo $PATH

which

What is it for?
Shows the full path of a command.
Where is it used?
Finding out which program runs.
Why does it matter?
Avoids mixing up programs with the same name.
which ls

type

What is it for?
Tells whether a command is a program or a builtin.
Where is it used?
Builtins such as cd.
Why does it matter?
Explains differences in behaviour.
type cd

export PATH=$PATH:~/bin

What is it for?
Adds ~/bin to the search path.
Where is it used?
Calling your own scripts by name.
Why does it matter?
No need to type the full path each time.
export PATH=$PATH:~/bin
💡 Tip

To make it permanent, add the same export line to ~/.bashrc.

⚠️ Warning

Never assign something like PATH=/new/dir that throws away the old value; no command, ls included, will be found. Close and reopen the terminal to recover.

Wildcards (globbing)

The shell expands wildcards, not the command. * matches anything (including nothing), ? exactly one character, [abc] one of the characters in brackets. For ls *.txt the shell first turns the pattern into file names, then hands them to ls.

If nothing matches, the shell leaves the pattern as it is. Before delete commands, test the pattern with echo: echo *.log.

*

What is it for?
Any sequence of characters.
Where is it used?
Selecting files of the same type.
Why does it matter?
Many files with one command.
echo lab/*.txt

?

What is it for?
Exactly one character.
Where is it used?
Names of fixed length.
Why does it matter?
Matches more narrowly than *.
echo lab/?.txt

[ ]

What is it for?
One of the characters in brackets.
Where is it used?
Selecting a few specific files.
Why does it matter?
Gives full control.
echo lab/[ab].txt
💡 Tip

Hidden files (starting with .) are not matched by *.

⚠️ Warning

rm * deletes every file in the current folder. First check what matches with echo *, then run rm.

Brace expansion and command substitution

Brace expansion generates text: file{1,2,3}.txt becomes three names, f{1..3} becomes f1 f2 f3. The files don't have to exist, which makes it ideal for bulk touch and mkdir.

$(command) runs the command and substitutes its output: echo "Today: $(date)". You can also store output in a variable: USERNAME=$(whoami).

{a,b,c}

What is it for?
Multiplies a comma-separated list.
Where is it used?
Creating many files and folders.
Why does it matter?
Three files in one line.
touch ~/lab/file{1,2,3}.txt

{1..3}

What is it for?
Generates a number or letter range.
Where is it used?
Numbered names.
Why does it matter?
No manual typing.
echo f{1..3}

$(...)

What is it for?
Puts a command's output inside another command.
Where is it used?
Dynamic values like date, user, host name.
Why does it matter?
You use the live value instead of hard-coding it.
echo "User: $(whoami)"
💡 Tip

The old ` command form works too, but $()` is far more readable when nested.

echo, printf and exit code

echo prints text and variables. For formatted output use printf: %s is text, %d a number, \n a newline. printf adds no newline automatically.

Every command leaves an exit code: 0 means success, anything else an error. Read the last one with $?. In scripts this is how you check for success.

echo

What is it for?
Prints text or a variable's value.
Where is it used?
Giving messages and quick checks.
Why does it matter?
The simplest output tool.
echo "Hello Linux"

printf

What is it for?
Produces formatted output.
Where is it used?
Aligned output or exact control over newlines.
Why does it matter?
More predictable than echo.
printf "Name: %s\n" alice

echo $?

What is it for?
Prints the exit code of the last command.
Where is it used?
Telling whether a command succeeded.
Why does it matter?
0 is success, non-zero is an error.
echo $?

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Run the commands below on your own VM (Ubuntu, Rocky, Alma or WSL). The commands in this module are harmless; still, extend PATH with export and never overwrite it with PATH=.

Explore the history

Run a few commands, then show the last lines of the history. Then try !! and Ctrl+R.

echo one
echo two
history | tail -n 5

Expected output example

  101  echo one
  102  echo two
  103  history | tail -n 5
# Press Ctrl+R, type 'echo', press Enter; then:
!!
My output looks different
  • The numbers will differ with your history; the order of the lines matters.
  • If !! doesn't work, make sure you are in Bash: echo $SHELL.

Variable and export

Define a variable, export it, and check whether a child shell can see it.

MYVAR=hello
bash -c 'echo "child: [$MYVAR]"'
export MYVAR
bash -c 'echo "child: [$MYVAR]"'
env | grep MYVAR

Expected output example

child: []
child: [hello]
MYVAR=hello
My output looks different
  • If the first line isn't child: [], MYVAR was exported earlier; reopen the terminal.
  • Copy all three lines when pasting the output.

Quote difference

Print the same text with double and single quotes and see the difference.

echo "Hello $USER"
echo 'Hello $USER'
echo Hello \$USER

Expected output example

Hello student
Hello $USER
Hello $USER
My output looks different
  • If your user isn't student, your own name appears; that is normal.
  • If $USER is empty, try echo $LOGNAME.

Wildcards and braces

In a safe folder, create files with braces and match them with wildcards.

mkdir -p ~/lab
touch ~/lab/{a,b,c}.txt ~/lab/d.log
echo ~/lab/*.txt
echo ~/lab/?.log
echo ~/lab/[ab].txt

Expected output example

/home/student/lab/a.txt /home/student/lab/b.txt /home/student/lab/c.txt
/home/student/lab/d.log
/home/student/lab/a.txt /home/student/lab/b.txt
My output looks different
  • If your home isn't /home/student, the path looks different; the file names must be the same.
  • In WSL, ~ is your Linux home, not the Windows side.

Add your own tool to PATH

Write a tiny script, add its folder to PATH and call it by name.

mkdir -p ~/tools
printf '#!/bin/bash\necho tool works\n' > ~/tools/hello
chmod +x ~/tools/hello
export PATH=$PATH:~/tools
hello
which hello

Expected output example

tool works
/home/student/tools/hello
My output looks different
  • On command not found, check with echo $PATH that the tools path was added.
  • On Permission denied, run chmod +x ~/tools/hello again.

Try the shortcuts

Type sleep 100 and stop it with Ctrl+C. Then type a long command and move around with Ctrl+A and Ctrl+E, clear the screen with Ctrl+L. Type ~/Doc and complete it with Tab. When finished, press "Done".

sleep 100
# Ctrl+C
ls ~/Doc
# Tab
My output looks different
  • If your terminal emulator grabs Ctrl+L, type clear instead.
  • If Tab does nothing, press it twice; with several matches they are listed.

Self-test

What does !! do?

!! is replaced by the previous command; sudo !! is very common.

What does echo '$HOME' print?

Variables are not expanded inside single quotes; the text is printed as is.

Which command makes a variable visible to child programs?

export puts the variable into the environment; env then shows it.

What is the output of echo f{1..3}?

The shell performs brace expansion and produces three separate words.

Summary

  • history, !! and Ctrl+R let you reuse commands.
  • Tab completes; Ctrl+C interrupts, Ctrl+L clears, Ctrl+A/E move within the line.
  • $ expands in double quotes, not in single quotes, and \ protects one character.
  • NAME=value has no spaces; child programs need export.
  • PATH holds the folders searched for commands; extend it with export PATH=$PATH:....
  • *, ?, [] are wildcards; {a,b} is brace expansion; $() substitutes command output.

Key terms

history
The list of commands the shell remembers.
environment variable
A variable carrying settings for the shell and child programs (HOME, PATH, USER).
PATH
A :-separated list of folders searched for commands.
globbing
Expansion of *, ?, [] patterns into file names.
command substitution
Replacing $(command) with the command's output.
exit code
The number a command leaves behind; 0 is success, anything else an error.

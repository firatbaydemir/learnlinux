2.2 Paths and Types

Read absolute and relative paths correctly, recognise file types with ls -l and create symbolic links (shortcuts).

What will you learn in this module?

  • You tell absolute (start with /) from relative paths and use the shortcuts ., .. and ~.
  • You read the file type from the first letter of ls -l (-, d, l, c, b).
  • You create a symbolic link with ln -s and see what it points to.

Absolute and relative paths

On Linux the only way to reach a file is to give a path. An absolute path starts at the root directory (/) and points to the same place from anywhere: /etc/hostname.

A relative path does not start with / and is worked out from the current directory. Inside /etc, hostname is enough; in your home directory the same name fails, because no such file is there.

Check where you are with pwd first. The meaning of a relative path always depends on the current directory.

pwd

What is it for?
Prints the absolute path of the current directory.
Where is it used?
Before using relative paths.
Why does it matter?
So you do not work in the wrong directory.
pwd

cd

What is it for?
Changes the working directory; takes absolute or relative paths.
Where is it used?
When moving between directories.
Why does it matter?
Afterwards short relative paths are enough.
cd /etc

cat

What is it for?
Prints the contents of a file.
Where is it used?
When reading small text files.
Why does it matter?
To test that a path points to the right file.
cat /etc/hostname
💡 Tip

When unsure, type the absolute path; it works from every directory.

Special path shortcuts: . .. ~

. is the current directory, .. the parent directory, ~ your home directory (/home/student). You can combine them in paths: ../config.txt, ~/Documents/report.txt.

Files whose name starts with . are hidden; ls does not show them, ls -a does. Every directory also lists the entries . and ...

cd ..

What is it for?
Moves up to the parent directory.
Where is it used?
When returning from a subdirectory.
Why does it matter?
Go up quickly without typing the full path.
cd ..

ls -a

What is it for?
Lists all files including hidden ones.
Where is it used?
When looking for configuration files.
Why does it matter?
Hidden files do not appear otherwise.
ls -a ~

Reading file types

On Linux everything is a file: text, folders, devices, shortcuts. In ls -l output the first letter of the line tells the type.

- regular file, d directory, l symbolic link, c character device (/dev/null), b block device (disk), s socket, p named pipe. The next nine characters are permissions (covered in later modules).

ls -l

What is it for?
Long listing: type, permissions, owner, size, date, name.
Where is it used?
To find out what something is.
Why does it matter?
You know what it is before deleting or reading it.
ls -l /dev/null

stat

What is it for?
Shows detailed information and the type of a file.
Where is it used?
When you need the type or timestamps.
Why does it matter?
Gives the type as a word instead of a letter.
stat /etc/hostname
💡 Tip

Files under /dev are hardware interfaces, not real data; do not read them randomly with cat.

Symbolic links

A symbolic link is a small shortcut file that points to another path. ls -l shows it with l and as link -> target. Reading the link means reading the target.

If the target is deleted or moved, the link stays behind broken. A relative target (../docs/readme.txt) is resolved from the link's directory, not from your current one.

ln -s

What is it for?
Creates a symbolic link: ln -s TARGET LINK.
Where is it used?
To reach a long path under a short name.
Why does it matter?
You keep the file in one place without copying.
ln -s ~/Documents/report.txt ~/link.txt

readlink

What is it for?
Prints the target of a link.
Where is it used?
To see where a link leads.
Why does it matter?
Just the target instead of the whole ls -l line.
readlink ~/link.txt
⚠️ Warning

Argument order for ln -s: TARGET first, then LINK. Swapped, you get a broken link. ln -sf overwrites an existing file; be careful.

⛔ Danger

If a link points to a directory, rm -r link/ (with a trailing /) can delete the contents of the target directory. To remove the link type rm link and check with ls -l first.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

On your VM, try absolute/relative paths, look at the file types in /dev and create a symbolic link. All commands are harmless.

Absolute and relative path

Try the same file relatively, then from the wrong directory, and paste the output.

pwd
cd /etc
pwd
cat hostname
cd ~
cat hostname

Expected output example

/home/student
/etc
linux-lab
cat: hostname: No such file or directory
My output looks different
  • If your host is not called linux-lab that is fine; you see your own host name.
  • If cat hostname in home does not fail, you created a file named hostname there.

Read file types

Look at the type of a file, a directory and a device; watch the first letters.

ls -ld /etc /etc/hostname /dev/null

Expected output example

drwxr-xr-x. ... /etc
-rw-r--r--. ... /etc/hostname
crw-rw-rw-. ... /dev/null
My output looks different
  • Some distributions have no /etc/hostname; try /etc/os-release instead.
  • A . or + after the permissions is the SELinux/ACL marker, not important.

Create a symbolic link

Create a file in home and a link to it, then read the link.

mkdir -p ~/practice
echo hello linux > ~/practice/notes.txt
ln -s ~/practice/notes.txt ~/practice/link.txt
ls -l ~/practice
cat ~/practice/link.txt

Expected output example

lrwxrwxrwx. 1 student student ... link.txt -> /home/student/practice/notes.txt
hello linux
My output looks different
  • If -> is missing or link.txt is red you may have swapped the arguments: TARGET first, then LINK.
  • On File exists, ~/practice/link.txt is already there; remove it first with rm ~/practice/link.txt.

Type name with stat

Show the type as a word with stat, then delete the practice folder.

stat -c '%F' /etc /etc/hostname /dev/null ~/practice/link.txt
# cleanup: look first with ls -l ~/practice, then
rm -r ~/practice

Expected output example

directory
regular file
character special file
symbolic link
My output looks different
  • On macOS or BSD tools -c does not exist; this belongs on a Linux VM.
  • If you see rm: cannot remove ... Is a directory, you forgot -r.

Self-test

Which is an absolute path?

An absolute path starts with / at the root and points to the same file from anywhere.

A line in ls -l starts with l. What is it?

l means symbolic link; - is a regular file, d a directory.

Where are you after cd .. from /etc?

.. is the parent directory; from /etc you go up to /.

What happens when the target of a symbolic link is deleted?

The link only stores a path; when the target disappears the link remains but is broken.

Summary

  • Absolute paths start with /; relative paths are resolved from the current directory.
  • . is current, .. parent, ~ your home directory.
  • The first letter of ls -l gives the type: -, d, l, c, b.
  • ln -s TARGET LINK creates a symbolic link; if the target goes away the link breaks.

Key terms

absolute path
Full address starting at the root directory (/).
relative path
Address worked out from the current directory.
symbolic link
Shortcut file that points to another path.
device file
Special file under /dev that represents hardware.

2.8 Disk and network health

When a server slows down, check two things first: disk usage and the network. Do a quick health check with df, du, free, uptime, ip, ping and ss.

What will you learn in this module?

  • Find which partition is full with df -h and which folder takes the space with du.
  • Read memory and load with free -h and uptime.
  • Narrow down a network problem layer by layer with ip, ping and ss.
  • Save health output to a file and prepare a report for a support ticket.

Disk usage: df and du

When a disk hits 100%, writes fail with No space left on device; services and logs stop. So first ask which partition is full: df -h. Columns: Size total, Used, Avail free, Use% percentage, Mounted on the mount point.

Once you know the partition, find which folder uses the space with du. du -sh folder gives a total; du -h --max-depth=1 folder | sort -h lists subfolders from small to large. Sometimes space looks free but files cannot be created: inodes ran out, check with df -i.

df -h

What is it for?
Shows size and usage of partitions in readable units.
Where is it used?
First command on slowness or 'disk full' errors.
Why does it matter?
Shows at a glance which mount point has the problem.
df -h

du -sh

What is it for?
Shows the total size of a folder.
Where is it used?
After df shows the full partition.
Why does it matter?
Narrows down the culprit folder.
du -sh /var/log

du --max-depth=1

What is it for?
Lists sizes of folders one level down; sort with sort -h.
Where is it used?
When hunting the biggest folder.
Why does it matter?
Drills down without walking the whole tree.
du -h --max-depth=1 /var | sort -h

df -i

What is it for?
Shows inode (file count) usage.
Where is it used?
Space is free but files cannot be created.
Why does it matter?
Millions of tiny files can exhaust inodes.
df -i
💡 Tip

df finds the partition, du finds the folder. Do df first, then du.

⚠️ Warning

Check what a file is with ls -l before deleting. For a log of a running service, truncating it (: > file) is often better than deleting; if unsure, ask your administrator.

Memory and load: free and uptime

free -h shows RAM and swap. Watch the available column: memory that can really be given to new programs. Even if free looks small, cache (buff/cache) is released when needed, so do not panic.

uptime shows how long the system has been up and the load average (1, 5, 15 minutes). If load constantly exceeds your CPU core count, work is queuing up.

free -h

What is it for?
Shows RAM and swap usage in readable units.
Where is it used?
When you suspect memory pressure.
Why does it matter?
available tells the real free memory.
free -h

uptime

What is it for?
Shows uptime, user count and load average.
Where is it used?
Quick check on a slow server.
Why does it matter?
Load average shows a trend, not a snapshot.
uptime
💡 Tip

To make a report, use df -h > report.txt, and >> to append.

Network: ip, ping and ss

Narrow a network problem from the bottom up: 1) Is the interface up and does it have an IP? ip -br a. 2) Is there a default route (gateway)? ip route. 3) Is the gateway reachable? ping -c 3 <gateway>. 4) An internet IP? ping -c 3 1.1.1.1. 5) Name resolution? ping -c 3 example.com.

If ping works for an IP but not for a name, the problem is DNS (/etc/resolv.conf). If nothing works, check the cable, VM network setting or gateway. ss -tuln shows which ports the machine listens on (e.g. 22 for SSH).

ip -br a

What is it for?
Lists interfaces, their state and IP addresses briefly.
Where is it used?
First step in a network problem.
Why does it matter?
Without an IP there is no point checking higher layers.
ip -br a

ip route

What is it for?
Shows the routing table and default gateway.
Where is it used?
When you cannot reach the outside.
Why does it matter?
Without a default via line, traffic cannot leave.
ip route

ping -c 3

What is it for?
Sends 3 test packets to a target; reports loss and latency.
Where is it used?
Testing connectivity and DNS.
Why does it matter?
Without -c, ping runs forever.
ping -c 3 1.1.1.1

ss -tuln

What is it for?
Lists listening TCP/UDP ports numerically.
Where is it used?
To see if a service listens on its port.
Why does it matter?
Checks the server side of 'I cannot connect'.
ss -tuln
⛔ Danger

On a remote server, commands like ip link set eth0 down cut your SSH connection and lock you out. Make sure you have console access before changing network settings.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

The commands here only read information, so they are safe on your VM. Paste the output and we will check it automatically.

Disk usage

Run df -h and paste the output. Note the usage percentage of the root (/) partition.

df -h
df -i /

Expected output example

Filesystem      Size  Used Avail Use% Mounted on
/dev/sda2        19G  4.1G   14G  23% /
My output looks different
  • The partition may be /dev/vda1, /dev/mapper/... or /dev/nvme0n1p2; the Use% column is what matters.
  • Many tmpfs/loop lines are normal (Ubuntu snap); focus on the / line.

Space hunt

Sort the sizes of your home directory and of the folders under /var. Paste the largest 5 lines.

du -sh ~
sudo du -xh /var --max-depth=1 2>/dev/null | sort -h | tail -5

Expected output example

120M	/var/cache
1.1G	/var/lib
1.4G	/var
My output looks different
  • If sort -h is missing (very old system) use sort -n and du -k.
  • If sudo asks for a password, enter your VM user password; it is not shown while typing.

IP and routing

Show your interfaces and default gateway; paste the output.

ip -br a
ip route

Expected output example

lo      UNKNOWN  127.0.0.1/8
enp0s3  UP       10.0.2.15/24
default via 10.0.2.2 dev enp0s3
My output looks different
  • The interface name may be eth0, enp0s3 or ens160.
  • On VirtualBox NAT the IP is usually 10.0.2.15; with bridged networking it comes from your router's range.
  • If there is no IP at all, check that the VM network card is connected and set to NAT/Bridged.

Connectivity and DNS test

Ping an IP first, then a name. Paste both outputs.

ping -c 3 1.1.1.1
ping -c 3 example.com

Expected output example

3 packets transmitted, 3 received, 0% packet loss
My output looks different
  • If the IP works but the name does not, it is a DNS problem; look at cat /etc/resolv.conf.
  • Some networks block ICMP; if ping fails but the web works, the problem is ping itself.

Listening ports

List the ports your machine listens on and paste the output.

ss -tuln

Expected output example

tcp   LISTEN  0  128  0.0.0.0:22  0.0.0.0:*
My output looks different
  • If SSH is not installed, 22 will not appear; that is fine for this module.
  • If ss is missing, try netstat -tuln on old systems.

Self-test

Which command shows which partition is full?

df shows partition usage, du shows folder sizes.

/var is 95% full. How do you find the biggest subfolder?

du gives subfolder sizes, sort -h orders them small to large.

ping 1.1.1.1 works but ping example.com does not. Most likely problem?

The IP is reachable but names are not resolved: check DNS settings.

Which command shows the ports the machine listens on?

ss -tuln lists listening TCP/UDP ports numerically.

Summary

  • df -h answers which partition, du -sh / du --max-depth=1 which folder is full.
  • In free -h watch available; in uptime the load average.
  • Narrow network problems bottom-up: ip -br a, ip route, ping an IP, ping a name.
  • Turn output into a report with > and >>; check with ls -l before deleting.

Key terms

inode
A record holding information about a file; their number is limited.
load average
Average number of runnable jobs over 1, 5 and 15 minutes.
gateway
The exit from the local network to the outside (usually the router).
DNS
The system that translates names into IP addresses.

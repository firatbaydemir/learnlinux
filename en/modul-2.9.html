2.9 Disk management

Identify a new disk, distinguish partitions from file systems, and inspect mount points safely. Backups and verifying the target device are essential before changing a real disk.

What will you learn in this module?

  • Read disks, partitions, file systems, and UUIDs with lsblk and lsblk -f.
  • Learn what fdisk -l and blkid display.
  • Distinguish the roles of mkfs, mount, umount, and /etc/fstab.
  • Verify the target and recovery path before running destructive disk commands.

Identify disks and partitions

Device names vary by machine: a disk may be /dev/sda, /dev/vda, or /dev/nvme0n1; a partition may look like /dev/sda1. Do not trust the name alone; verify size, type, and mount point.

lsblk displays a tree. lsblk -f adds file system type, UUID, and mount points. fdisk -l lists partition tables; blkid displays file-system identifiers.

lsblk

What is it for?
Lists disks and partitions as a tree.
Where is it used?
When identifying a new device or inspecting disk status.
Why does it matter?
Shows the relationship between disks, partitions, and mount points.
lsblk

lsblk -f

What is it for?
Lists file-system types, UUIDs, and mount points.
Where is it used?
When matching a partition to an fstab entry.
Why does it matter?
Shows identifiers such as UUIDs for persistent references.
lsblk -f

fdisk -l

What is it for?
Lists partition tables without changing them.
Where is it used?
When inspecting a partition layout before opening an interactive menu.
Why does it matter?
Provides an overview of disk capacity and partition boundaries.
sudo fdisk -l

blkid

What is it for?
Displays file-system types and UUID values.
Where is it used?
When verifying a partition's identity.
Why does it matter?
UUIDs reduce dependence on device-name ordering in fstab.
sudo blkid
💡 Tip

Start with lsblk -f, then use sudo fdisk -l if needed. A device name alone is not reliable identification.

Partitions and file systems

Partitioning divides free disk space into partitions; formatting writes a file system to a selected partition. mkfs.ext4 and mkfs.xfs are common examples. A formatted partition is not automatically accessible as a directory.

In the interactive fdisk menu, p prints the table, n creates a partition, and w writes changes. Writing to the wrong disk can destroy data. Practice only on a disposable virtual disk with a recovery plan.

mkfs.ext4

What is it for?
Creates an ext4 file system on a partition and erases existing data.
Where is it used?
Only on a verified, empty partition with a backup.
Why does it matter?
Linux needs a file system to store files on the partition.
sudo mkfs.ext4 /dev/sdb1

mkfs.xfs

What is it for?
Creates XFS on a partition and erases existing data.
Where is it used?
On an empty test partition when XFS is intended.
Why does it matter?
Choose a file-system type that fits the workload and distribution.
sudo mkfs.xfs /dev/sdb1
⛔ Danger

mkfs or w in fdisk can destroy data. Never try these on the system disk, a real USB drive, or an unverified device. The VM tasks in this module only read information and do not format anything.

Mounting and persistent configuration

mount attaches a file system to a directory; umount detaches it. Create the mount point first. findmnt shows current mounts, while df -hT shows file-system type and usage.

Use /etc/fstab for mounts that should persist across reboots. Prefer UUIDs over device names. Its fields are source, target, type, options, dump, and fsck order. nofail can keep a missing optional disk from blocking boot; choose options for the actual situation.

mount

What is it for?
Shows mounted file systems; with a device and directory, it mounts one.
Where is it used?
When inspecting current mounts or performing an approved mount operation.
Why does it matter?
Linux exposes disk contents through directories.
findmnt /

umount

What is it for?
Detaches a mounted file system.
Where is it used?
Before removing external storage or beginning maintenance.
Why does it matter?
Allows writes to finish and the file system to be detached safely.
sudo umount /mnt/archive

findmnt

What is it for?
Lists mounted file systems with their source and target.
Where is it used?
When verifying where a partition is mounted.
Why does it matter?
Presents the mount table in a readable form.
findmnt /
💡 Tip

Back up /etc/fstab before editing. Afterward, use sudo mount -a to check the syntax instead of rebooting immediately; it can perform mounts.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

These tasks only read disk information; they do not change partition tables or file systems. Run them in your VM and review the output before sharing device names.

Disk and file-system tree

List disks, partitions, and file-system types. Check mount points instead of guessing which disk is the system disk from its name.

lsblk -f

Expected output example

NAME FSTYPE FSVER LABEL UUID FSAVAIL FSUSE% MOUNTPOINTS
My output looks different
  • Columns and device names vary by distribution; you may see sda, vda, or nvme0n1.
  • A blank extra disk may have empty FSTYPE and MOUNTPOINTS columns.

Mounted space usage

Show the size and usage of mounted file systems, including their types.

df -hT

Expected output example

Filesystem Type Size Used Avail Use% Mounted on
My output looks different
  • Containers and WSL may show multiple overlay or tmpfs lines.
  • Pay particular attention to the Use% value for mount point /.

Verify the root mount

Find the source and file-system type used to mount the root directory (/).

findmnt -no SOURCE,FSTYPE,TARGET /

Expected output example

/dev/vda2 xfs /
My output looks different
  • The source may be /dev/mapper/... or /dev/nvme0n1p...; the sample output need not match exactly.
  • This command does not change the disk.

Self-test

Which command displays disks and partitions as a tree?

lsblk lists disks and their partitions.

Which command can destroy existing data?

mkfs writes a new file system to the selected device and erases existing data.

What do we call the directory through which a mounted file system is accessed?

A mount point is the path in the Linux directory tree where a file system is accessible.

Which identifier is generally more persistent in fstab than a device name?

A UUID identifies the file system even if device names change.

Summary

  • lsblk -f shows the disk tree along with file-system types and UUIDs.
  • mkfs erases data; use it only on a verified empty test device with a backup.
  • mount attaches, umount detaches; findmnt and df -hT are read-only checks.
  • Use UUIDs in /etc/fstab, back up the file, and verify changes carefully.

Key terms

Partition
A region of a physical or virtual disk defined in its partition table.
File system
The structure that defines how files and directories are stored on a partition.
Mount point
The directory through which a mounted file system is accessed.
UUID
A unique identifier for a file system.

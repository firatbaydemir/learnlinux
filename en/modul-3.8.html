3.8 Archiving and compression

Bundle files with tar, gzip and zip, compress them, restore them safely and verify your backups.

What will you learn in this module?

  • You explain the difference between archiving (tar: bundling) and compression (gzip, bzip2, xz).
  • You create archives with tar -czf, list them with tar -tf and extract into a new directory with tar -xzf -C.
  • You know the risks of tar bombs and overwriting, and always list before extracting.
  • You use gzip -k and zip/unzip and compare compression ratios.
  • You make a dated backup and verify it with sha256sum.

Archiving and compression are different things

Archiving means bundling many files and directories, with their paths and permissions, into one file; the size does not shrink. tar (tape archive) does this. Compression shrinks a single file: gzip (fast, common), bzip2 (smaller, slower), xz (smallest, slowest).

In practice you use both: tar bundles, then gzip compresses. The result is a .tar.gz or .tgz file. tar does both in one command with -z (gzip), -j (bzip2) or -J (xz).

Important detail: gzip notes.txt deletes the original file and leaves only the .gz file. Use -k (keep) to preserve the original.

gzip -k

What is it for?
Compresses a file and keeps the original (adds .gz).
Where is it used?
For large logs or text files.
Why does it matter?
Without -k the original is deleted; with -k you can experiment safely.
gzip -k logs/app.log

gunzip

What is it for?
Decompresses a .gz file and deletes the .gz file (same as gzip -d).
Where is it used?
When you restore a single compressed file.
Why does it matter?
gunzip -k keeps the .gz as a safety copy.
gunzip logs/app.log.gz

zcat

What is it for?
Prints the content of a compressed file without decompressing it on disk.
Where is it used?
When reading old compressed logs or searching them with grep.
Why does it matter?
No disk space or extra time spent on unpacking.
zcat logs/app.log.gz | head
💡 Tip

Compare sizes with ls -lh. Text and logs compress very well; already compressed JPG, MP4 or ZIP files barely shrink.

⚠️ Warning

gzip notes.txt deletes the original. Back up data that exists only once first, or use -k.

tar: create, list, extract

tar options can be combined in one word: c (create), x (extract), t (list), v (verbose), f (file, the archive name; always the last letter, the name follows immediately), z/j/J (gzip/bzip2/xz).

Always add relative paths to an archive (project, not /home/student/project). GNU tar strips a leading / and warns, so extracting cannot overwrite system files.

-C directory makes tar change into that directory first: when extracting it is the destination, when creating it is the root of the source. The target directory must already exist.

tar -czf

What is it for?
Bundles a directory into one gzip-compressed archive.
Where is it used?
When making backups and before sending a project.
Why does it matter?
One file is much easier to copy, transfer and store.
tar -czf backups/project.tar.gz project

tar -tf

What is it for?
Lists the paths inside the archive without extracting (-z not needed, tar detects the type).
Where is it used?
Before extracting, to see the content.
Why does it matter?
Prevents tar bombs and overwrite surprises.
tar -tf backups/project.tar.gz

tar -xzf -C

What is it for?
Extracts the archive into the given (existing) directory.
Where is it used?
When restoring, to keep the current directory clean.
Why does it matter?
Always extract into a new, empty directory, then check.
tar -xzf backups/project.tar.gz -C restore

tar -xzf ... member

What is it for?
Extracts only the named file or directory from the archive.
Where is it used?
When rescuing a single file from a backup.
Why does it matter?
You do not extract everything or overwrite current files. The path must be written as in the tar -tf output.
tar -xzf backups/project.tar.gz -C restore project/notes.txt

tar --exclude

What is it for?
Leaves files matching the pattern out of the archive.
Where is it used?
To keep logs, temporary files or .git out of a backup.
Why does it matter?
The backup gets smaller and faster. Put --exclude before the path to archive.
tar -czf backups/lab-nologs.tar.gz --exclude='*.log' .

tar -cJf

What is it for?
Creates an archive with xz compression, the strongest level (-j is for bzip2).
Where is it used?
For archives that are rarely used and kept long.
Why does it matter?
Smaller file, but slower and more CPU load.
tar -cJf backups/project.tar.xz project
💡 Tip

Mnemonic: create, extract, list; then f and the file name. tar detects the compression type itself when extracting, so tar -xf is often enough.

⚠️ Warning

The archive name must directly follow f. With tar -cfz backup.tgz project, z is taken as the archive name and the file ends up wrongly named.

Extracting safely: tar bombs and overwriting

Some archives have no top-level directory; extracting dumps hundreds of files straight into your current directory (a tar bomb). Cleaning up is painful because you cannot tell which files came from the archive. Solution: list first with tar -tf (or tar -tvf), then extract into a new, empty directory.

tar -x silently overwrites existing files with the same name. Never extract directly into your working directory.

Permissions and owners: tar stores permissions in the archive. As root, owners and permissions are restored faithfully; as a normal user the umask applies. Use -p to explicitly preserve permissions. Restoring files owned by another user requires sudo.

tar -tvf

What is it for?
Lists the archive verbosely: permissions, owner, size, date and path.
Where is it used?
Before extracting, to check permissions and whether there is a top-level directory.
Why does it matter?
You spot tar bombs and absolute paths in advance.
tar -tvf backups/project.tar.gz

tar -xpf

What is it for?
Extracts the archive and preserves file permissions.
Where is it used?
For backups where permissions matter.
Why does it matter?
Stops the umask from altering permissions.
tar -xpf backups/project.tar.gz -C restore

sudo tar -xpf

What is it for?
Extracts as root; owner and group are restored too.
Where is it used?
For system backups or files belonging to other users.
Why does it matter?
Ownership is kept, but root also magnifies mistakes.
sudo tar -xpf backups/project.tar.gz -C restore
💡 Tip

Habit: look with tar -tf backup.tar.gz | head, run mkdir restore, then tar -xzf backup.tar.gz -C restore.

⛔ Danger

Never extract an archive you do not trust as root, least of all with target / (-C /). Members with absolute paths or .. can overwrite system files. Snapshot first, list first.

zip and unzip

zip bundles and compresses at once and is compatible with Windows/macOS; ideal for exchanging files. Directories need -r (recursive). Install with sudo apt install zip unzip on Ubuntu or sudo dnf install zip unzip on Rocky/Alma.

Difference from .tar.gz: zip compresses each file separately, so extracting single files is fast; but it preserves Linux permissions and owners less reliably than tar. For Linux backups prefer tar.

zip -r

What is it for?
Adds a directory with its subdirectories to a zip archive.
Where is it used?
When sending files to Windows/macOS users.
Why does it matter?
Opens everywhere; without -r the directory content is not added.
zip -r backups/project.zip project

unzip -l

What is it for?
Lists the content of a zip archive without extracting.
Where is it used?
For checking before extracting.
Why does it matter?
The same safety habit as tar -tf.
unzip -l backups/project.zip

unzip -d

What is it for?
Extracts the zip archive into the given directory (created if needed).
Where is it used?
When restoring.
Why does it matter?
You do not scatter files into the current directory.
unzip backups/project.zip -d restore

A simple backup and verification

A simple backup: a name with the date, one command to bundle, plus a checksum. date +%F prints today as 2026-11-12, so each backup gets its own name and never overwrites an older one. $(...) inside the command runs first and its output becomes part of the name.

sha256sum produces a file's fingerprint. If you check the backup with sha256sum -c after copying it, you know it is intact. A backup only counts once a copy lives on another disk or machine; also try a restore once.

Automatic backups use a scheduler (cron or a systemd timer). That is a topic for another module; here we run the command by hand.

sha256sum

What is it for?
Prints the SHA-256 checksum of a file.
Where is it used?
When verifying backups or downloaded files.
Why does it matter?
Even one changed bit changes the sum, so corruption shows up.
sha256sum backups/project.tar.gz > backups/SHA256SUMS

sha256sum -c

What is it for?
Compares stored sums with the files; prints OK or FAILED.
Where is it used?
After copying a backup or before restoring it.
Why does it matter?
You find a broken backup right away, not in a crisis.
sha256sum -c backups/SHA256SUMS

tar -czf ... $(date +%F)

What is it for?
Creates a backup archive with today's date in its name.
Where is it used?
For regular, manually made backups.
Why does it matter?
Old backups are not overwritten and versions stay distinguishable.
tar -czf backups/project-$(date +%F).tar.gz project

date +%F

What is it for?
Prints today's date as 2026-11-12.
Where is it used?
For date stamps in file names.
Why does it matter?
Produces names that sort by date.
date +%F
💡 Tip

The 3-2-1 rule: 3 copies, 2 different media, 1 off-site.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Run the commands below on your own VM (Ubuntu/Rocky/Alma). Everything stays in ~/lab; your real data is untouched. No step is destructive, but archives overwrite files of the same name: do not experiment outside lab. Taking a snapshot before bigger experiments is a good habit.

Set up the test project

Create a small project and a big log file under ~/lab, then list the project files.

mkdir -p ~/lab/project/{src,docs}
cd ~/lab
echo 'int main(void) { return 0; }' > project/src/main.c
echo 'Demo project' > project/docs/readme.txt
echo 'todo: backup' > project/notes.txt
seq 1 200000 > big.log
find project -type f | sort

Expected output example

project/docs/readme.txt
project/notes.txt
project/src/main.c
My output looks different
  • The order may differ; all three files showing up is enough.
  • If seq is missing (very rare), use yes line | head -n 200000 > big.log.

Archive and list without extracting

Pack project into backup.tar.gz, list its content without extracting and check the size.

cd ~/lab
tar -czf backup.tar.gz project
tar -tzf backup.tar.gz
ls -lh backup.tar.gz

Expected output example

project/
project/docs/
project/docs/readme.txt
project/notes.txt
project/src/
project/src/main.c
-rw-r--r--. 1 student student 300 Nov 12 10:00 backup.tar.gz
My output looks different
  • The order of the list may differ.
  • Size and date differ; what matters is that paths start with project/.
  • The warning Removing leading '/' appears with absolute paths; it should not appear here.

Restore safely

Extract the archive into a new directory, then extract only a single file.

cd ~/lab
mkdir restore restore2
tar -xzf backup.tar.gz -C restore
tar -xzf backup.tar.gz -C restore2 project/notes.txt
ls -R restore restore2

Expected output example

restore:
project
...
restore2:
project

restore2/project:
notes.txt
My output looks different
  • If you see Cannot open: No such file or directory, the -C directory is missing; create it with mkdir first.
  • If tar says Not found in archive, write the path as shown by tar -tf.

Compare compression ratios

Compress big.log with gzip, bzip2 and xz, keeping the original. Compare the sizes.

cd ~/lab
gzip -k big.log
bzip2 -k big.log
xz -k big.log
ls -l big.log*

Expected output example

-rw-r--r--. 1 student student 1228895 Nov 12 10:01 big.log
-rw-r--r--. 1 student student  580000 Nov 12 10:01 big.log.bz2
-rw-r--r--. 1 student student  480000 Nov 12 10:01 big.log.gz
-rw-r--r--. 1 student student  400000 Nov 12 10:01 big.log.xz
My output looks different
  • The numbers differ; usually xz < bzip2 < gzip < original.
  • If you get bzip2: command not found, install it: Ubuntu sudo apt install bzip2, Rocky/Alma sudo dnf install bzip2.
  • If an old gzip does not know -k, make a copy first with cp big.log big2.log.

Dated backup and checksum

Make a dated backup, save its checksum and verify it. Optionally try zip.

cd ~/lab
tar -czf backup-$(date +%F).tar.gz project
sha256sum backup-*.tar.gz > SHA256SUMS
sha256sum -c SHA256SUMS

Expected output example

backup-2026-11-12.tar.gz: OK
# Optional (without zip: sudo apt install zip unzip or sudo dnf install zip unzip)
zip -r project.zip project
unzip -l project.zip

Expected output example

  adding: project/ (stored 0%)
...
---------
  4 files
My output looks different
  • If you see FAILED, you changed the archive after computing the sum; run sha256sum again.
  • On a German or Turkish system the output may be translated instead of OK.
  • If backup-*.tar.gz matches several files, you get one line for each.

Self-test

Which command only lists an archive's content without extracting?

t lists (list). x extracts, c creates; gzip -d decompresses.

What happens after gzip notes.txt?

gzip replaces the original with the compressed file. Use gzip -k to keep it.

Why do you list an archive with tar -tf before extracting?

Without a top-level directory the files scatter into the current directory, and existing files can be overwritten.

What does -C restore do in tar -xzf backup.tar.gz -C restore?

-C (change directory) sets the target directory; it must exist beforehand.

Summary

  • Archiving (tar) bundles, compression (gzip, bzip2, xz) shrinks; .tar.gz is the combination.
  • Create: tar -czf backup.tar.gz project; list: tar -tf; extract: tar -xzf ... -C restore.
  • List first, then extract into a new directory: protects against tar bombs and overwriting.
  • gzip deletes the original, gzip -k keeps it; zip is compatible with Windows/macOS.
  • Make dated backups, verify them with sha256sum and test a restore.

Key terms

archive
Many files and directories, with their paths, bundled into one file (tar).
compression
Reducing the size of data; gzip, bzip2, xz.
tarball
An archive made with tar, usually .tar.gz.
tar bomb
An archive without a top-level directory that scatters files into the current directory when extracted.
relative and absolute path
Absolute paths start with /; relative paths are preferred inside archives.
checksum
A file's fingerprint (sha256sum); makes corruption visible.

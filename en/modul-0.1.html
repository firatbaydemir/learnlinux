0.1 What Is Linux? — Kernel, Distribution, Philosophy

Understand what Linux really is: a kernel, the distributions built around it, and the ideas that make the command line so powerful.

What will you learn in this module?

  • You can explain the difference between the kernel, a distribution and the shell.
  • You know the two big distribution families (Debian and RHEL) and their package tools.
  • You find kernel version, distribution and architecture with uname and /etc/os-release.
  • You know the principle "everything is a file" and the purpose of the main top-level directories.

Kernel, distribution and shell

Linux is strictly only the kernel: the core that talks to the hardware, schedules processes and manages memory. Linus Torvalds started it in 1991. Alone the kernel is not usable — you need tools, libraries and a way to type commands.

A distribution (distro) bundles the kernel with the GNU tools, a package manager, an installer and defaults. Ubuntu, Debian, Fedora, Rocky Linux and AlmaLinux are distros. The shell (usually bash) is the program that reads your commands and asks the kernel to run them.

Two files tell you what you are running: uname reports kernel and architecture, /etc/os-release reports the distribution. You will use both whenever you ask for help or read documentation.

uname -r

What is it for?
Prints the kernel release.
Where is it used?
When checking the kernel version for support or bug reports.
Why does it matter?
The kernel version decides which hardware and features you have.
uname -r

uname -a

What is it for?
Prints all system information in one line.
Where is it used?
When you paste system details into a ticket.
Why does it matter?
Shows host name, kernel and architecture at once.
uname -a

uname -m

What is it for?
Prints the machine architecture (x86_64, aarch64, ...).
Where is it used?
Before downloading software or an ISO.
Why does it matter?
Packages are built per architecture.
uname -m

cat /etc/os-release

What is it for?
Shows distribution name and version.
Where is it used?
On any modern distribution.
Why does it matter?
A standard file, same format on Ubuntu, Rocky, Alma and others.
cat /etc/os-release
💡 Tip

Kernel and distribution are versioned separately: Ubuntu 24.04 ships kernel 6.8, Rocky Linux 9 ships 5.14 with many backports.

Distribution families and licences

Distros group into families. The Debian family (Debian, Ubuntu, Mint) uses .deb packages and apt. The RHEL family (Red Hat Enterprise Linux, Rocky, AlmaLinux, Fedora) uses .rpm packages and dnf. Commands you learn in this course work on both; only package management differs.

The Linux kernel is released under GPL-2.0-only; tools and applications bundled in a distribution may use different licences. This openness supports many distros, while enterprise vendors may offer support and services as well as software. The ID_LIKE line in /etc/os-release tells you the family: Rocky reports rhel fedora, Ubuntu reports debian.

In this course your reference system is a Rocky/Alma Linux VM, with Ubuntu as an equal alternative. Use whichever you installed in module 0.2.

grep ID_LIKE /etc/os-release

What is it for?
Shows only the family line of the release file.
Where is it used?
When you are unsure whether to use apt or dnf.
Why does it matter?
Turns a long file into the one fact you need.
grep ID_LIKE /etc/os-release
💡 Tip

If ID_LIKE contains debian use apt; if it contains rhel or fedora use dnf.

Philosophy and the directory tree

Unix thinking in four lines: everything is a file (disks, devices and processes show up as paths), small tools do one thing well, tools are combined with pipes, and configuration is plain text you can read and edit.

All files live in one tree starting at / (root directory). There are no drive letters. /etc holds configuration, /home the users' files, /var changing data such as logs, /usr programs and libraries, /tmp temporary files, /dev devices, /proc live kernel information. On modern systems /bin is just a link to /usr/bin.

A normal user works in the home directory /home/student. The administrator account is root; you will meet it carefully in later modules.

ls /

What is it for?
Lists the top level of the directory tree.
Where is it used?
When getting oriented on an unknown system.
Why does it matter?
Shows the standard directories described above.
ls /

ls /etc

What is it for?
Lists the configuration directory.
Where is it used?
When looking for a system setting.
Why does it matter?
Nearly all system configuration is a text file here.
ls /etc

cat /etc/shells

What is it for?
Lists the shells installed on the system.
Where is it used?
When asking which shell programs exist.
Why does it matter?
Shows that the shell is just a replaceable program.
cat /etc/shells
💡 Tip

When something is configurable, look in /etc first, then read the file — it is text.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

These commands are harmless and read-only. Run them in the terminal of your VM (Rocky/Alma or Ubuntu) and compare.

Identify your system

Show kernel release and distribution, and paste both outputs.

uname -r
cat /etc/os-release

Expected output example

5.14.0-427.el9.x86_64
NAME="Rocky Linux"
VERSION="9.4 (Blue Onyx)"
ID="rocky"
ID_LIKE="rhel centos fedora"
...
My output looks different
  • On Ubuntu you see NAME="Ubuntu" and a kernel like 6.8.0-...-generic — that is correct.
  • On WSL the kernel name contains microsoft-standard-WSL2.

Walk the directory tree

List the top level and the configuration directory and paste the output of the first command.

ls /
ls /etc | head -n 15

Expected output example

afs  bin  boot  dev  etc  home  lib  lib64  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
My output looks different
  • The exact list varies by distribution, but etc, home, usr and var must be present.
  • bin appears as a link to usr/bin on modern systems; check with ls -ld /bin.

Meet process 1

Every system starts one first process. Find out its name.

ps -p 1 -o comm=

Expected output example

systemd
My output looks different
  • In some containers you may see bash or init; on a normal VM it is systemd.
  • If ps is missing, run cat /proc/1/comm instead.

Check the link and your family

Check that /bin is a link and decide whether your system uses apt or dnf.

ls -ld /bin
grep ID_LIKE /etc/os-release
which apt dnf

Expected output example

lrwxrwxrwx. 1 root root 7 ... /bin -> usr/bin
My output looks different
  • which prints only the tool that exists: apt on Ubuntu, dnf on Rocky/Alma.
  • If which prints nothing for both, try command -v dnf or install which first.

Self-test

What is the Linux kernel?

Linux strictly means the kernel. A distribution adds tools, packages and an installer around it.

Which package tool belongs to the Rocky Linux / RHEL family?

RHEL-family systems use rpm packages managed by dnf; Debian and Ubuntu use apt.

Which file shows the name and version of the distribution?

/etc/os-release is the standard file on all modern distributions.

What does "everything is a file" mean?

Disks appear under /dev and processes under /proc; the same tools such as cat and ls work on them.

Summary

  • Linux is the kernel; a distribution adds tools, packages and an installer; the shell reads your commands.
  • Debian family uses apt, RHEL family uses dnf; ID_LIKE in /etc/os-release tells you which.
  • uname -r, uname -m and cat /etc/os-release identify any system.
  • One tree from /: /etc configuration, /home users, /var data, /usr programs.
  • Unix philosophy: everything is a file, small tools, plain text configuration.

Key terms

kernel
The core of the operating system that controls hardware, memory and processes.
distribution
A complete system: kernel plus tools, packages, installer and defaults.
shell
The program that reads and runs your commands, usually bash.
package manager
The tool that installs and updates software: apt or dnf.
root directory
The top of the file tree, written /.
GPL
A family of free-software licences; the Linux kernel is licensed under GPL-2.0-only.

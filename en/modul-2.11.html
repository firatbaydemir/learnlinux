2.11 Scheduled tasks

Use cron to run commands repeatedly at specific times. Read the five time fields correctly, define the environment explicitly, and monitor generated output.

What will you learn in this module?

  • Know the five cron fields in order: minute, hour, day of month, month, and day of week.
  • Inspect and edit user jobs with crontab -l and crontab -e.
  • Use absolute paths, PATH, and log redirection in cron's limited environment.
  • Account for distribution differences and the impact of deleting jobs.

Cron time and expression format

A user crontab line has five time fields and a command: minute (0–59), hour (0–23), day of month (1–31), month (1–12), and day of week (0–7; both 0 and 7 mean Sunday). * means every value, */15 every 15 intervals, and 1-5 a range.

0 3 * * * runs every day at 03:00; */15 * * * 1-5 runs every 15 minutes on weekdays. Combining day-of-month and day-of-week can create unexpected matches; verify the schedule you intend.

crontab -l

What is it for?
Lists the current user's cron table.
Where is it used?
When checking whether a job is already scheduled.
Why does it matter?
Helps you avoid adding a duplicate without inspecting existing schedules.
crontab -l

crontab -e

What is it for?
Opens the user's cron table in the default editor.
Where is it used?
When adding or changing a user's scheduled tasks.
Why does it matter?
Manages cron entries without directly editing the system file.
crontab -e

crontab -r

What is it for?
Removes the current user's entire crontab.
Where is it used?
Only when all schedules for that user should deliberately be removed.
Why does it matter?
Deletes every scheduled job; accidental use can cause an outage.
crontab -r
⚠️ Warning

crontab -r deletes all jobs for the current user. To remove one job, delete only that line in crontab -e; save the output of crontab -l first.

Cron environment, paths, and logs

Cron does not run in an interactive terminal. Profile files may not be loaded, PATH may be limited, and the working directory may not be what you expect. Use absolute paths for executables and files; define PATH=... at the top of the crontab if needed.

Redirect standard output and errors to a log file, and manage its growth separately. The time zone depends on system configuration. Test the script manually as the same user first, then verify its permissions and dependencies.

command -v

What is it for?
Shows the full path of a command.
Where is it used?
When finding the path of a program for a cron entry.
Why does it matter?
Prevents command-not-found errors caused by cron's limited PATH.
command -v date

date

What is it for?
Shows the system's local date and time.
Where is it used?
When investigating schedule or time-zone problems.
Why does it matter?
Lets you compare the system clock that cron uses.
date

systemctl status cron

What is it for?
Shows the cron service status on Debian/Ubuntu.
Where is it used?
When scheduled user jobs do not appear to run.
Why does it matter?
Jobs cannot start if the scheduler service is not running.
systemctl status cron
💡 Tip

Use an absolute log path such as >> /home/student/cron.log 2>&1; > overwrites the file each run, while >> appends.

Observe and manage jobs safely

A user crontab applies only to that user. System-wide cron directories and the root crontab are separate and privileged; do not change their files without authorization. The service is usually cron on Debian/Ubuntu and crond on RHEL-based systems.

A schedule alone does not prove that a job succeeded: check its log file, service logs, and expected result. A test job that runs every minute creates noise and uses resources; remove it after testing.

crontab -l

What is it for?
Displays the user's scheduled jobs again.
Where is it used?
When verifying an entry after editing.
Why does it matter?
Confirms the entry that was actually saved.
crontab -l

systemctl status crond

What is it for?
Shows the cron service status on RHEL-based systems.
Where is it used?
When checking the service and distribution differences.
Why does it matter?
Reminds you that the service name varies across distributions.
systemctl status crond

journalctl -u cron

What is it for?
Displays logs for the specified systemd unit.
Where is it used?
When service logs are written to the systemd journal.
Why does it matter?
Shows scheduler errors and startup records.
sudo journalctl -u cron --since today
⛔ Danger

Commands in the root crontab run with administrator privileges. Do not run an unfamiliar line; verify its owner and target files. Cron jobs are not suitable for password prompts or interactive input.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

These tasks inspect the current scheduler; they do not add or remove cron jobs. The service name may differ by distribution.

User crontab

List the current user's crontab. If no jobs exist, the message is normal; you do not need to add a job.

crontab -l

Expected output example

0 3 * * * /usr/local/bin/backup
My output looks different
  • A no crontab for ... message means this user has no entries; you have not done anything wrong.
  • Only the current user's table is read.

Cron service

Check the status of your distribution's cron or crond service.

systemctl status cron

Expected output example

Active: active (running)
My output looks different
  • Debian/Ubuntu usually use cron; the RHEL family uses crond.
  • Some WSL/container installations may not run systemd; this is an environment difference.

Scheduler logs

On systems using the systemd journal, inspect today's cron service records.

sudo journalctl -u cron --since today

Expected output example

cron
My output looks different
  • The service may be called crond on your system; adjust the command.
  • No log records alone do not prove that a scheduled task failed.

Self-test

What is the order of the five cron time fields?

A user crontab uses minute, hour, day of month, month, and day of week.

When does 0 3 * * * run?

Minute 0, hour 3, and all other time fields * means daily at 03:00.

What is a good first approach if a cron job cannot find date?

Cron may have a limited PATH; use an absolute command path or set PATH explicitly.

What is the safe way to remove one incorrect job?

Removing one line with crontab -e leaves the user's other jobs intact.

Summary

  • A user cron entry contains minute, hour, day of month, month, day of week, and command.
  • Use crontab -e to edit and crontab -l to list and verify.
  • Absolute paths, an explicit PATH, and log redirection matter in cron's environment.
  • crontab -r deletes all user jobs; edit one line carefully and monitor its output.

Key terms

Crontab
A table of scheduled jobs for a user or the system.
Cron field
A time field specifying a minute, hour, day, or month.
PATH
The list of directories where the shell searches for commands.
Redirection
Sending command output to a file or another stream.

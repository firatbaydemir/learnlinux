6.6 Bash Script 2 — Loops, Functions, Pitfalls

Do not do the same work a hundred times: build loops, case and functions, clean up temporary files with trap and write safe scripts without quoting traps.

What will you learn in this module?

  • You write repeated work with for and while.
  • You read a file safely line by line with while IFS= read -r.
  • You route arguments and menus with case and structure code with functions and local.
  • You clean up with mktemp and trap and prevent the empty-variable disaster with "${DIR:?}".
  • You find script errors with shellcheck, bash -n and bash -x.

Loops: for and while

A script is more than commands running in order. If you do the same work for several servers or files, you use a loop. for runs once per item in a list, while runs as long as a condition stays true.

The source of the list must be safe: file patterns (./*.txt), fixed lists or "$@". Never feed the output of $(ls) into a loop; names with spaces get split.

Note: The built-in simulator cannot execute loops; you write them into script files and run them in your VM.

for

What is it for?
Runs the commands once for each item in the list.
Where is it used?
When running the same check on several servers or processing the files of a folder.
Why does it matter?
Shortens repeated code and reduces mistakes.
for i in 1 2 3; do echo "n=$i"; done

while

What is it for?
Repeats the commands as long as the condition is true.
Where is it used?
When waiting for something or reading files.
Why does it matter?
You do not need to know the number of rounds in advance.
while [ -e /tmp/lock ]; do sleep 1; done

echo {1..5}

What is it for?
Brace expansion: produces 1 2 3 4 5 (no spaces inside the range).
Where is it used?
For number ranges or numbered series of files.
Why does it matter?
Makes short lists without a loop; also used in for i in {1..5}.
echo {1..5}

break / continue

What is it for?
break ends the loop, continue jumps to the next round.
Where is it used?
When skipping empty lines or leaving once the item is found.
Why does it matter?
Avoids needless work and nested if blocks.
[ -n "$line" ] || continue
💡 Tip

If a file pattern matches nothing, ./*.txt stays literal. Put [ -e "$f" ] || continue at the start of the loop body.

Reading a file line by line

The correct pattern for line-by-line reading is while IFS= read -r line; do ... done < file. IFS= keeps leading and trailing spaces, -r does not interpret backslashes.

Do not write for line in $(cat file): lines are split at spaces and every word becomes a round. The redirection done < ~/lab/servers.txt makes the file the input of the loop.

while IFS= read -r

What is it for?
Reads input line by line and puts each line into a variable.
Where is it used?
With server lists, logs or CSV files.
Why does it matter?
Reads safely without altering spaces or backslashes.
while IFS= read -r host; do echo "$host"; done < servers.txt

done < file

What is it for?
Redirects the loop's input from a file.
Where is it used?
On the last line of a while read block.
Why does it matter?
A pipe (cat | while) runs in a subshell and variables vanish after the loop; a redirection does not.
done < ~/lab/servers.txt

wc -l

What is it for?
Prints the number of lines.
Where is it used?
When you want to know how many rounds the loop will run.
Why does it matter?
You compare your expectation with the real number.
wc -l ~/lab/servers.txt
⚠️ Warning

If the last line does not end with \n, read may skip it. If needed, add || [ -n "$host" ].

Branching with case

case compares a value with patterns and is far more readable than a long if/elif chain. Each branch starts with pattern) and ends with ;;; *) runs when nothing matches. The block closes with esac.

Typical uses: branching on the first argument ($1) as in ./menu.sh start, or acting differently by the prefix of a server name.

case ... esac

What is it for?
Branches a value according to patterns.
Where is it used?
In service scripts (start/stop/status) and menus.
Why does it matter?
Readable; you catch unknown input with *).
case "$1" in start) echo go ;; *) echo usage ;; esac

$1 $@ $#

What is it for?
First argument, all arguments and the number of arguments.
Where is it used?
When passing values to the script from outside.
Why does it matter?
The script becomes reusable; "$@" preserves arguments with spaces.
echo "first: $1, count: $#"

chmod +x

What is it for?
Gives the script execute permission.
Where is it used?
Before running it as ./menu.sh.
Why does it matter?
Without the permission you get Permission denied.
chmod +x ~/scripts/menu.sh
💡 Tip

Combine several patterns with |, for example start|restart).

Functions, local and arrays

A function names repeated code: name() { ...; }. In Bash variables are global by default; without local inside a function you overwrite variables from outside.

return only gives an exit code of 0–255. For text use echo and capture it with $(function). An array collects several values under one name; always write "${arr[@]}" in loops so elements with spaces stay intact.

name() { ...; }

What is it for?
Gives a block of code a name that you call later.
Where is it used?
When the same check runs in several places in the script.
Why does it matter?
Structures the code, ends repetition and makes testing easier.
log() { echo "[log] $1"; }

local

What is it for?
Limits a variable to the function.
Where is it used?
For temporary variables inside functions.
Why does it matter?
You do not accidentally overwrite a variable of the same name outside.
local msg=$1

arr=(a b c)

What is it for?
Defines an array with three elements.
Where is it used?
For lists of servers or options.
Why does it matter?
The list lives in one variable; ${#arr[@]} gives the count.
hosts=(web01 web02 db01)

"${arr[@]}"

What is it for?
Expands each element as a separate quoted word.
Where is it used?
When building a for loop over an array.
Why does it matter?
Elements with spaces are not split.
for h in "${hosts[@]}"; do echo "$h"; done
💡 Tip

Arrays exist only in Bash, not in sh (dash). Put #!/usr/bin/env bash on the first line.

Safe scripts: set, mktemp, trap

Create temporary files not with a fixed name but with mktemp: the name is unique and unpredictable. With trap ... EXIT the cleanup function runs however the script ends (error, Ctrl+C, normal); kill -9 is the exception.

set -euo pipefail makes the script stricter: stop on errors (-e), stop on undefined variables (-u), do not hide failures inside pipelines (pipefail).

mktemp -d

What is it for?
Creates a temporary directory with a unique name and prints its path.
Where is it used?
When the script needs intermediate files.
Why does it matter?
Prevents collisions and attacks through predictable names.
tmp=$(mktemp -d)

trap cleanup EXIT

What is it for?
Runs the cleanup function when the script ends.
Where is it used?
With temporary directories, lock files or connections.
Why does it matter?
Everything is cleaned up even after an error.
trap cleanup EXIT

set -euo pipefail

What is it for?
Stops the script on errors, undefined variables and pipeline failures.
Where is it used?
In the first lines of the script.
Why does it matter?
You stop at once instead of silently continuing wrongly.
set -euo pipefail
⛔ Danger

If you delete inside trap, the same rule applies: write rm -rf "${tmp:?}". If tmp is empty, rm -rf $tmp/ really becomes rm -rf /. Test first with echo rm -rf "$tmp".

Pitfalls and debugging

The most common mistake is the unquoted variable: touch $F with F="my notes.txt" creates two files (my and notes.txt). Rule: always quote variables as "$F".

The most dangerous line is rm -rf $DIR/*: if DIR is empty it becomes rm -rf /*. "${DIR:?}" stops the script with an error on an empty or undefined value. Show the path with echo before deleting.

Debugging: bash -n checks the syntax without running, bash -x shows every command with a + prefix, shellcheck finds common traps.

"$var"

What is it for?
Quotes the variable; no word splitting and no glob expansion.
Where is it used?
Every time you use a variable.
Why does it matter?
File names with spaces stay in one piece.
touch "$F"

"${DIR:?}"

What is it for?
Aborts with an error if DIR is empty or undefined.
Where is it used?
With rm -rf and other destructive commands.
Why does it matter?
Prevents an empty variable from deleting the path /.
rm -rf "${DIR:?}/"*

shellcheck

What is it for?
Statically analyses the script and reports traps with a code (SC2086).
Where is it used?
After writing a script, before committing.
Why does it matter?
Catches unquoted variables and similar mistakes without running anything.
shellcheck ~/scripts/bad.sh

bash -n

What is it for?
Checks only the syntax without running the script.
Where is it used?
When you suspect a missing done, fi or esac.
Why does it matter?
Harmless; no command runs.
bash -n ~/scripts/loop.sh

bash -x

What is it for?
Prints every command with its expansions and a + prefix.
Where is it used?
When the script behaves unexpectedly.
Why does it matter?
You see what the variables really contain.
bash -x ~/scripts/loop.sh
💡 Tip

Run a destructive command first with echo in front: echo rm -rf "$DIR". If the output is right, remove the echo.

⚠️ Warning

Install ShellCheck on Ubuntu/Debian with sudo apt install shellcheck, on Rocky/Alma via EPEL: sudo dnf install epel-release, then sudo dnf install ShellCheck.

Do it on your own VM

The real practice happens on real Linux: run the commands in your own virtual machine (VirtualBox, UTM or WSL) and compare the output.

Do these tasks in your own VM (Ubuntu, Rocky/Alma or WSL). Everything happens under ~/scripts; do not touch system files. Before trying anything with rm, take a VM snapshot (Module 0.2) and put echo in front of the delete command.

First loop and bash -n

Write a for loop, check it first with bash -n, then run it. Paste the output.

mkdir -p ~/scripts && cd ~/scripts
printf '#!/usr/bin/env bash\nfor i in 1 2 3; do\n  echo "n=$i"\ndone\n' > loop.sh
chmod +x loop.sh
bash -n loop.sh && ./loop.sh

Expected output example

n=1
n=2
n=3
My output looks different
  • If bash -n reports an error, check the do and done lines with cat loop.sh.
  • If you see Permission denied, you forgot chmod +x loop.sh.

Loop over a file and case

Read the server list line by line and print a role with case according to each name.

cd ~/scripts
printf 'web01\nweb02\ndb01\ncache01\nmail01\n' > servers.txt
cat > readlines.sh <<'EOF'
#!/usr/bin/env bash
while IFS= read -r host; do
  case "$host" in
    web*) echo "$host: web" ;;
    db*) echo "$host: database" ;;
    *) echo "$host: other" ;;
  esac
done < servers.txt
EOF
bash readlines.sh

Expected output example

web01: web
web02: web
db01: database
cache01: other
mail01: other
My output looks different
  • If the output is empty, check with ls that servers.txt is in the same folder.
  • If everything says other, you have a typo in the case patterns (web*)).

Function, local, mktemp, trap

Run a script that creates a temporary directory and cleans it up on exit. Paste the output.

cd ~/scripts
cat > safe.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
tmp=$(mktemp -d)
cleanup() {
  rm -rf "${tmp:?}"
  echo "cleanup: removed $tmp"
}
trap cleanup EXIT
log() {
  local msg=$1
  echo "work in $tmp: $msg"
}
log "hello"
EOF
bash safe.sh

Expected output example

work in /tmp/tmp.Ab12Cd: hello
cleanup: removed /tmp/tmp.Ab12Cd
My output looks different
  • The directory name differs on every run; what matters is that both lines appear.
  • If the cleanup line is missing, check that trap cleanup EXIT comes after the function.

Catching traps with shellcheck

Install ShellCheck and scan a script that has an unquoted variable. Paste the warning.

# Ubuntu/Debian
sudo apt install -y shellcheck
# Rocky/Alma (needs EPEL)
sudo dnf install -y epel-release && sudo dnf install -y ShellCheck

Expected output example

...
cd ~/scripts
printf '#!/usr/bin/env bash\nF="my notes.txt"\ntouch $F\n' > bad.sh
shellcheck bad.sh

Expected output example

In bad.sh line 3:
touch $F
      ^-- SC2086 (info): Double quote to prevent globbing and word splitting.
My output looks different
  • If the install fails, on Rocky check with dnf repolist that epel-release is active.
  • The message differs slightly between ShellCheck versions; the code SC2086 is enough.

bash -x and a safe test

Trace every step of the script with bash -x; then try rm with an empty DIR only through echo (no real deleting).

cd ~/scripts
bash -x loop.sh 2>&1 | head -8
DIR=""
echo rm -rf $DIR/*

Expected output example

+ for i in 1 2 3
+ echo n=1
n=1
...
rm -rf /bin /boot /etc ...
My output looks different
  • Lines starting with + are the bash -x trace; several + signs mean nested commands.
  • The last line is only echo, so nothing is deleted; it just shows that the empty variable becomes /*.

    Hint

    Inside single quotes the shell does not expand $i. Use \n for line breaks.

    Solution

  1. TicketHard

    Ticket: The nightly cleanup script deleted more than expected on a server because the variable was empty. Write ~/scripts/cleanup.sh: set -euo pipefail, DIR=/home/student/tmpwork, a trap on exit, "${DIR:?}/"* for deleting; make it executable.

  2. TicketHard

    Ticket: The team wants a script that checks every server in ~/lab/servers.txt. Write ~/scripts/check_all.sh: a check_host() function using local, a while IFS= read -r host; do loop, done < ~/lab/servers.txt; make it executable.

    Hint

Self-test

What happens with rm -rf $DIR/* when DIR is empty, and which notation protects?

The empty variable disappears and the command becomes rm -rf /*. ${DIR:?} stops the script on an empty value.

Which pattern reads a file safely line by line?

for with $(cat) splits lines into words. while IFS= read -r reads the line unchanged.

What does local x=1 do inside a function?

local limits the scope to the function; a variable of the same name outside is left untouched.

When does trap cleanup EXIT run?

The EXIT trap runs on normal exit, on errors and on most signals; SIGKILL cannot be caught.

Summary

  • for runs once per list item, while as long as the condition is true; choose a safe source.
  • Read files with while IFS= read -r line; do ... done < file, not with $(cat).
  • case ... esac routes arguments and menus readably; *) is the default branch.
  • Use local in functions; walk arrays with "${arr[@]}".
  • Create temporary files with mktemp and clean up with trap cleanup EXIT.
  • Quote every variable; write "${DIR:?}" when deleting and test with echo first.
  • bash -n, bash -x and shellcheck show errors without running or step by step.

Key terms

loop
A construct that repeats a block of commands: for, while.
word splitting
Splitting an unquoted variable at whitespace.
IFS
The characters the shell uses to separate words (field separator).
case
Multi-way branch that compares a value with patterns.
local
Keyword that limits a variable to a function.
array
A Bash variable holding several values under one name.
trap
Defines a command to run on a signal or at exit.
mktemp
Creates a temporary file or directory with a unique name.
shellcheck
Static analysis tool for shell scripts.
bash -x
Trace mode that prints every command with its expansions before running it.

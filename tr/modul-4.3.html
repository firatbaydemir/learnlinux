4.3 Kimlik değiştirme: su, sudo ve sudoers

Root yetkisini ne zaman ve nasıl kullanacağını öğren; tek komutluk sudo'yu tercih et, kuralları visudo ile güvenle yönet.

Bu modülde neler öğreneceksin?

  • Root'un UID 0 olduğunu, su - ile sudo arasındaki farkı ve iki komutun hangi parolayı istediğini açıklarsın.
  • Tek bir yönetim komutunu sudo ile çalıştırır, yetkilerini sudo -l ile incelersin.
  • sudo -i ile tam root oturumunu açıp exit ile kapatır; gereksiz yere root kalmazsın.
  • /etc/sudoers dosyasının yetki politikası olduğunu ve yalnızca visudo ile düzenlenmesi gerektiğini bilirsin.

Root kimdir? su ve sudo

Linux'ta root, UID'si 0 olan süper kullanıcıdır. Sistem dosyalarını ve diğer hesapları yönetebilir; yanlış bir komut ciddi hasar verebilir. Günlük işler için normal hesabında kal, yönetici yetkisini yalnızca gereken iş için kullan.

su - USER hedef hesaba geçer ve hedef hesabın parolasını ister. su - root'a geçer; ancak Ubuntu gibi sistemlerde root hesabı parola ile girişe kapalı olabilir. - hedef kullanıcının login ortamını (ör. HOME ve profil) yükler.

sudo COMMAND ise izinli kullanıcıya kendi parolasını doğrulattıktan sonra yalnızca belirtilen komutu başka kullanıcı olarak çalıştırır (çoğunlukla root). sudo kuralı parola istemeyecek şekilde ayarlanmış da olabilir. Root oturumu açık tutmak yerine tek komut için sudo kullanmak daha güvenlidir.

Root kabuğunda gereğinden uzun kalmazsın.

💡 İpucu

Tek komut ve yönetici oturumu

sudo whoami çıktısı root olur; normal whoami ise kendi hesabını gösterir. Sudo, yalnızca komutu yetkiyle çalıştırır; komut bittikten sonra kabuğun normal kullanıcı olarak kalır.

sudo -l kendi hesabının hangi komutları çalıştırabileceğini listeler. sudo -u USER COMMAND ise izin verildiğinde tek komutu belirtilen kullanıcı olarak çalıştırır. Uygulama kuralları dağıtıma ve kurum politikasına göre değişir; wheel yaygın olarak Rocky/Alma'da, sudo ise Ubuntu/Debian'da kullanılır.

sudo -i root'un login kabuğunu açar; bu sırada whoami root, HOME ise /root olur. sudo -s daha çok mevcut ortamı koruyan bir root kabuğu açar. İkisi de yüksek riskli tam oturumdur: gerekiyorsa kısa tut ve exit ile çık. Sudo parola doğrulamasını bir süre önbellekte tutabilir; sudo -k bu önbelleği temizler.

sudo -l

Nerede kullanılır?

Neden önemli?
Root'un HOME ve başlangıç ortamını yükler.

⚠️ Dikkat

sudo -i içinde unutulan bir komut da root olarak çalışır. Kısa yönetim işlerinde sudo COMMAND kullan; root kabuğundan çıkınca whoami ile normal hesaba döndüğünü doğrula.

sudoers: yetki politikasını güvenle düzenle

/etc/sudoers ve /etc/sudoers.d/ dosyaları kimin hangi hedef kullanıcı olarak hangi komutları çalıştırabileceğini belirler. Bu dosyaları doğrudan nano, vim veya echo ile düzenleme: tek bir sözdizimi hatası tüm sudo erişimini bozabilir.

Politikayı denetlemek ve düzenlemek için sudo visudo kullan. Ek bir kural dosyası için sudo visudo -f /etc/sudoers.d/NAME açılır; visudo kaydetmeden önce sözdizimini kontrol eder. Bir kural örneği: alice ALL=(root) /usr/bin/systemctl restart nginx — yalnızca belirtilen komuta izin verir.

NOPASSWD parola istemini kaldırır; örneğin alice ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx. Bunu yalnızca gerçekten gerekiyorsa, tam komut yoluyla ve dar kapsamda kullan. ALL ile tüm komutlara sınırsız yetki vermek veya genel amaçlı bir kabuğu parolasız açmak güvenli bir kural değildir. Değişiklik sonrası sudo -l ile sonucu denetle.

sudo visudo

⛔ Tehlike

NOPASSWD: ALL kullanıcıya parola sormadan tüm komutları çalıştırma yetkisi verir. Gereken tek komutu tam yolu ve gerekli argümanlarıyla sınırla; her kuralı visudo ile yazıp sudo -l ile doğrula.

Güvenli yönetici iş akışı

Önce normal hesabında hedefi ve etkisini doğrula; yetki gerekiyorsa yalnızca gerekli komutu sudo ile çalıştır. Hata alırsan körlemesine sudo eklemek yerine id, sudo -l ve dosyanın izinlerini incele.

Yönetim işi bittiğinde root oturumunu exit ile kapat. Komut geçmişine parola yazma, sudoers dosyasını doğrudan değiştirme ve anlamadığın komutu root olarak çalıştırma. Gerçek VM'de sistem politikasını değiştirmeden önce snapshot al.

Yetkisiz veya gereğinden geniş kuralı fark ettirir.

Kendi VM'inde yap

Asıl uygulama gerçek Linux'ta yapılır: kendi sanal makinende (VirtualBox, UTM veya WSL) komutları çalıştır, çıktıyı karşılaştır.

Bu bölüm gerçek sistemde yetki denetimini inceler; yapılandırmayı değiştirmez. Mümkünse VM snapshot'ı al. Parolanı yalnızca terminalin sudo istemine gir.

Normal kimliğini gör

id ile normal hesabını ve grup üyeliklerini göster.

id

Beklenen çıktı örneği

uid=1000(student) gid=1000(student) groups=1000(student)
Çıktım farklı çıktı
  • Kullanıcı adı ve UID dağıtıma göre değişir; kendi değerlerin normaldir.
  • Ubuntu'da sudo grubu, Rocky/Alma'da çoğunlukla wheel grubu kullanılır.

Tek komutta sudo

sudo whoami çalıştır ve etkin kullanıcının root olduğunu doğrula.

sudo whoami

Beklenen çıktı örneği

root
Çıktım farklı çıktı
  • Parola yazarken karakter görünmez; bu beklenir.
  • not in the sudoers file hatasında hesabına izin verilmiyordur; yöneticiye danış.

Etkin UID'yi doğrula

sudo id -u ile ayrıcalıklı komutun UID 0 olarak çalıştığını doğrula.

sudo id -u

Beklenen çıktı örneği

0
Çıktım farklı çıktı
  • id -u etkin UID'yi sayı olarak verir; root'un UID'si 0'dır.
  • Komut reddedilirse sudo -l ile izinleri kontrol et.

Sudo yetkilerini oku

sudo -l ile hesabının izinli komutlarını listele; hiçbir kuralı değiştirme.

sudo -l

Beklenen çıktı örneği

User student may run the following commands
Çıktım farklı çıktı
  • Kullanıcı adı ve kurallar dağıtıma göre farklıdır.
  • Çıktıda NOPASSWD varsa yalnızca hangi komutla sınırlı olduğunu not et; kuralı değiştirme.

Sudoers sözdizimini denetle

sudo visudo -c ile mevcut sudo yapılandırmasının ayrıştırıldığını doğrula. Bu komut dosyayı değiştirmez.

sudo visudo -c

Beklenen çıktı örneği

/etc/sudoers: parsed OK
Çıktım farklı çıktı
  • Dağıtım ek dosyaları da denetleyebilir; her dosya için parsed OK benzeri bir satır beklenir.
  • Hata çıkarsa dosyayı kendin doğrudan düzenleme; sistem yöneticisine bildir.

Öz test

sudo COMMAND ile su - arasındaki temel fark nedir?

sudo bir komut için yetki verir; su - başka hesabın login kabuğuna geçer.

Sudo kural dosyasını değiştirmek için neden visudo kullanılır?

visudo düzenleme sırasında kilit kullanır ve kaydetmeden önce sözdizimini kontrol eder.

En az yetki ilkesine uygun sudo kuralı hangisidir?

Yetkiyi doğru kullanıcıya ve gereken tek komuta sınırla; geniş ALL kurallarından kaçın.

Ubuntu'da su - root parolasını kabul etmiyorsa en olası açıklama nedir?

Ubuntu kurulumlarında root hesabı çoğu zaman kilitlidir; yönetim için sudo yetkili kullanıcı kullanılır.

Özet

  • Root UID 0'dır. su - hedef hesabın login oturumunu açar; sudo COMMAND izinli tek komutu yetkiyle çalıştırır.
  • sudo -l gerçek izinleri gösterir; sudo -i tam root login kabuğu açar ve iş bitince exit ile kapatılmalıdır.
  • Sudoers politikasını yalnızca visudo ile düzenle ve visudo -c ile sözdizimini doğrula.
  • NOPASSWD ve özellikle ALL kapsamını dar tut; yalnızca gerekli kullanıcıya, komuta ve argümanlara izin ver.
